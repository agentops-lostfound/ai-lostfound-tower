# LF-3 탑뷰 실제 점유와 관제탑 보관 기록 비교

`vision/topview_bridge`에 로컬 읽기 전용 브리지를 추가했다.
사용자가 제공한 `top-view-locator-20261111.zip`의 OWLv2/SigLIP2 검출을 사용하며
원본 ZIP·참조 사진·가중치는 로컬에 보관한다.

## 구현·실물 확인

- 기존 Physical AI Studio 탑뷰 공유 WebSocket에서 1280×720 프레임을 수신했다.
  USB를 직접 다시 열거나 로봇 세션을 재시작하지 않는다.
- 프레임의 8개 칸에 물품 중심·박스 겹침을 배정하고, 관제탑 `/api/admin/storage`를
  분석 전후 조회해 개수·품목을 비교한다. 모의 운영에서는 메모리 운영 저장소를 조회한다.
- 휴대폰 1·보조배터리 1·핸드크림 2·립밤 2, accepted 6개를 실제 프레임에서 관측했다.
  당시 비어 있는 DB 칸과 미기록 후보를 대조했고, R4-1 립밤 배정 후 일치도 확인했다.
  이후 배정 변경은 이전 결과를 재검증 대기로 바꾸는 것을 확인했다.
- 첫 전체 실행 약40.19초, 후속 약22.39초 사례가 있다. 카메라는 표시용 저주기 영상이며
  모델을 매 프레임 실행하지 않는다. 고정 성능이나 전체 인식 정확도 수치를 뜻하지 않는다.
- 자동 감시는 이전 분석이 끝난 뒤 15초 대기 후 재분석한다.
- loopback 검증 화면 `http://127.0.0.1:8770`과 JSON 상태/결과를 제공한다.

## 불확실성 처리

review/경계 검출, 다중 검출, 반환 전환, DB 변경·끊김, 오래된 프레임은 확정 일치로 표시하지 않는다.
영역 편집은 고정 사진과 같은 시점의 마커를 사용하고, 저장 전 움직임을 다시 확인한다.
현재 영상에서는 마커 0·1만 보여 4마커 mm 좌표 대신 픽셀 영역을 사용했다.
개체 ID는 참조 DB와 관제탑 ID가 연결되지 않아 항상 미확인이다.
미검출 후보를 실제 분실로 확정하거나 로봇 실행 허가로 사용하지 않는다.

## 검증·남은 일

로컬 개발 스냅샷의 전체 시험은 1,575개 실행, 실패0·스킵23이었다.
칸 이동·품목/개수 불일치·전환 상태·DB 변경·보정 사진/현재판 불일치를 검증했다.
최신 main 통합 시험은 PR 기록을 따른다.

카테고리별 가림/경계·다중 적재 정확도 평가, 관제탑 영속 검증 기록 연동,
canonical item_id 참조 등록과 동일 물품 확인은 후속 작업이다.
자동 재배정·DB 쓰기·로봇 제어는 구현하지 않았다.
