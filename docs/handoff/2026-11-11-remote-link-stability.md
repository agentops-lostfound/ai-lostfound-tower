# 관제탑 원격 로봇 통신 지연 대응

2026-11-11. 브랜치 `LF-21-geontae-remote-link-stability`, 기준 커밋 `2d88070`.

## 변경

관제탑 `robot/remote_client.py`의 일반 HTTP 응답 대기를 **2초 → 5초**로 늘렸다.
하트비트는 별도 스레드가 **0.25초 간격**으로 보내므로 상태 GET과 진행 콜백이
지연돼도 연결 유지가 함께 멈추지 않는다.

로봇 실행기 `Executor`의 **하트비트 유예 5초는 변경하지 않았다**.
하트비트 요청 자체는 1초 제한으로 보내고 일시적 네트워크 오류만 마지막 성공 후
3초 미만 범위에서 재시도한다. 인증 실패·잘못된 작업 응답 등은 재시도하지 않는다.
일반 상태 요청이 5초를 넘거나 하트비트 실패가 지속되면 기존 실패·정지 경로로 끝낸다.
동작 요청 POST는 자동 재전송하지 않는다. 완료/정지 후 하트비트를 종료하고,
늦은 응답은 원래 instance/job_id에만 묶인다.

실물 팔 이동, 자세·도착 오차, 보정값, 이동 3초, 실행 허용, DB 상태는 이 변경에서 건드리지 않는다.

## 관제탑 PC에 적용

**로봇 PC 파일만 바꾸면 운영 관제탑에는 적용되지 않는다.**
수정 대상은 재원님 PC에서 실행되는 관제탑의 `robot/remote_client.py` 한 파일이다.
기존 인증값·접속 주소·관제탑 실행 옵션은 그대로 사용한다. `.env`를 읽거나 바꾸지 않는다.

전달 ZIP의 `apply.ps1`은 다음을 수행한다.

1. 관제탑 `/health`가 `busy=false`인지 확인한다. 조회 실패나 실행 중이면 적용하지 않는다.
2. 현재 클라이언트 해시가 검증된 이전 버전과 같은지 확인한다. 다른 수정이 있으면 덮지 않는다.
3. 새 소스의 해시/구문을 검증하고 기존 파일을 `outputs/remote_link_backup/`에 백업한 후 복사한다.
4. 새 파일의 응답 대기 5초와 독립 하트비트 존재를 확인한다.

관제탑 저장소 루트에서 압축을 푼 경로를 지정해 실행한다.

```powershell
& '압축을푼경로\apply.ps1' -RepoRoot (Get-Location).Path -TowerUrl http://127.0.0.1:8080
```

복사 후 **기존 관제탑 실행 방식으로 관제탑 프로세스를 재시작해야 한다**.
기존 프로세스에는 이전 Python 모듈이 남아 있다. 다른 Python 작업자나 로봇 Studio를 종료하지 않는다.
메모리 모의 운영의 재시작은 진행 중인 시연 상태에 영향을 줄 수 있으므로 실행 중인 반환이 없는 때 적용한다.

새 파일을 검증하는 모의 HTTP 시험은 저장소 루트에서 다음처럼 실행한다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s '압축을푼경로\tests' -p test_remote_robot.py -v
```

이 시험은 임시 loopback 서버·모의 로봇만 사용한다. 실제 로봇과 운영 DB에는 명령을 보내지 않는다.
실패한 반환 건을 새 ID로 자동 재시도하거나 기존 정지 보호를 해제하지 않는다.

## 검증 범위

- 2.2초 지연된 상태 응답을 기다리면서 별도 하트비트를 계속 보내고 동작은 1회만 실행.
- 진행 콜백이 묶인 동안 5초 lease 갱신 유지.
- 짧은 하트비트 시간 초과는 연결 유지 요청만 재시도.
- 지속 하트비트 손실은 정지하고 자동 동작 재전송 없음.
- 상태 GET이 대기 중이어도 별도 정지 요청은 동작 취소.
- 완료 후 하트비트 종료, 이전 인스턴스 차단, 정지 선행 경합 등 기존 보호 회귀.

운영 관제탑의 재시작 후 LAN 재검증은 별도 확인이 필요하다.
