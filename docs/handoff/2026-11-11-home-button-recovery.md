# 정지 후 원점 복귀 버튼 연결

## 문제와 수정

기존 `TowerRobot.robot_home()`은 항상 미구현 오류를 반환했다. 정지는 원격 실행을 disarm하고
클라이언트에도 정지 래치를 남기므로, 원점 복귀 역시 일반 명령 차단에 걸렸다.
앞서 현장 홈 복귀는 로컬에서 별도 수행했고, 관제탑의 완료 확인은 일회성 처리였다.

새 구현은 **명시적으로 요청한 빈 집게 원점 복귀**를 일반 집기와 분리한다.

- 실행 중 작업이 없고 정지가 확인된 경우에만 disarm 상태의 HOME 전용 작업을 허용한다.
- 기존 취소된 작업을 되살리지 않고 새 복귀 작업·새 취소 이벤트를 만든다.
- 홈 복귀는 기존 로컬 arm 상태를 유지한다. 이미 허용된 상태에서 원점 버튼을 반복해도 disarm하지 않는다.
  정지로 arm이 꺼져 있었다면 HOME이 새로운 arm을 자동 부여하지 않는다. 새 정지는 복귀 중에도 유효하다.
- 현재 Studio의 같은 팔·최신 관절·HOLD·녹화 꺼짐·정지 상태를 확인한다.
- 티칭된 칸 자세에 있으면 집게를 유지해 해당 접근 자세로 후퇴한 뒤 home으로 간다.
  배출 구간은 outlet_return_1을 거친다. 홈에 있으면 홈 도착만 다시 확인한다.
- 현재 자세가 해당 티칭 구간 밖이거나 제어 소유가 불명확하면 이동을 거부한다.
- 관제탑 화면은 먼저 **집게의 물건 제거**와 복귀 경로 확인을 안내한다.
- 호출 결과가 성공일 때만 관제탑의 기존 서비스가 정지 플래그를 지운다.

홈 복귀 이후에는 사용자가 초기화 대기/기존 명령 재개 중 하나를 선택한다.
현재 채팅에서는 실제 홈 복귀 후 이 선택을 물으며, 물품을 뺐다면 원래 칸 재배치도 확인한다.
**관제탑 화면의 자동 재개/재개 선택 API는 이번 변경에 구현하지 않았다.**
정지 요청이나 홈 성공을 자동 재실행의 승인으로 바꾸지 않는다.

## 로봇 PC 적용 상태

`remote-home-worktree`의 실행기로 갱신했다. 기존 팔/Studio 세션, 티칭 파일, 이동 3초,
인증·허용 IP·8칸 권한·관절 관측은 유지한다. 임시 일회성 home 확인 패치는 제거했다.

새 RPC로 정지 → 홈 복귀를 2회 반복해 성공했다. 실제 비홈 위치의 복귀는 이번 세션에서
별도 로컬 경로로 `pose_7 → home`을 먼저 수행했다. 새 RPC의 비홈 복귀는 모의 시험으로 검증했으며
실물에서 모든 칸·중단 위치를 검증했다고 주장하지 않는다.

전체 테스트 1,606개 실행, 실패 0개, 23개 스킵.

## 관제탑 PC에 필요한 수정

운영 관제탑 파일에 직접 접근할 경로가 없어 다음 3개를 전달한다.

1. `robot/remote_client.py`: 통신 안정화 수정과 HOME 전용 복구 호출. 중단 래치가 있어도
   명시적인 HOME 호출을 수행하고, 요청 본문에 `empty_gripper_confirmed=true`를 넣는다.
2. `web/live/index.html`: 빈 집게 확인 안내.
3. `web/staff-desk/index.html`: 빈 집게 확인 안내.

기존 원점 복귀 API의 `{staff_confirmed:true}` 입력은 유지한다.
`/api/admin/robot/home` → `RemoteTowerRobot.robot_home()` → 새 로봇 RPC 순으로 연결된다.
원격 arm 제한은 집기 작업에 계속 적용되며 정지 미확인 상태의 HOME도 거부한다.

구버전 HOME 요청은 최신 관절 6축이 모두 저장된 홈의 2 이내이고 HOLD인 경우에만
이동 없이 실제 홈 완료를 확인한다. 홈 밖에서는 빈 집게 확인을 임의로 만들지 않고 거부한다.
현재 관제탑 공식 API의 ok 응답과 정지 해제 표시까지 확인했다.

기존 관제탑 클라이언트가 구버전이면 버튼이 계속 차단되므로 **클라이언트 병합·관제탑 재시작이 필요하다**.
최근 관절 표시 등 다른 수정이 있을 수 있으므로 파일을 통째로 강제 덮어쓰지 말고 전달 diff와 병합한다.
기존 `.env`·인증값은 읽거나 바꾸지 않는다. 로봇 Studio를 재시작하지 않는다.

적용 확인은 반환이 실행 중이지 않을 때 수행한다.
빈 집게·HOLD 상태에서 버튼으로 정지 → 홈을 확인하고 결과가 ok인지 확인한다.
원점 복귀 후에는 다음 동작을 자동 실행하지 않는다.

## 실제 시퀀스 시험 기록

- R4-1 원래 립밤 재배치 후 `A-20261111-0124` 재실행: 11단계 완료·home 도착.
- 사용자 추가 요청 R4-2: 11단계 완료·home 도착.
- 사용자 추가 요청 R4-1: 11단계 완료·home 도착.

이는 동작 완료 기록이며 파지·물품 인계·DB 반환 완료를 확정한 기록이 아니다.

## 원점에서 원점 복귀 반복 후 실행 불가 수정

HOME 작업 등록 시 기존 arm을 false로 바꾸던 코드를 제거했다. 관제탑 공식 HOME API를
연속 2회 호출해 매회 ok=true 및 armed=true 유지까지 확인했다.
