# Studio 저장 자세 통합과 리더 자동 정렬 조사 인계

작성일 2026-11-06. 다른 자리/PC에서 다음 Codex가 이어받기 위한 기록이다.

> 2026-11-09 후속 상태: 현재 PC의 Studio에 설치·재시작·실물 runtime 재연결을 확인했다. 이동·복귀 시험 중 발견한 문제를 보완했고 3·4·5초 이동 시간 선택을 추가했다. 시간 초과만으로 실패하지 않는다.
> 현재 자세는 12개이고 그리퍼 포함 저장된 6축 값을 적용한다. 리더·팔로워 실시간 비교 표시를 사용해 수동 정렬한다. 최신 [통합 사용법](../../robot/studio_extension/README.md)과 [설치 결과](../reports/2026-11-06-studio-pose-installed.md)가 아래 설치 전 기록보다 우선한다.
> 기존 이동용 ZIP은 설치 전 기록을 담고 있다. 리더 자동 정렬의 미구현·미확인 상태는 그대로다.

## 먼저 알아야 할 결론

**팔로워 저장 자세 이동의 Studio 통합은 현재 PC에 설치했다. 아래 나머지 설명은 11/6 설치 준비 당시의 기록이다.**
**리더 자동 정렬은 구현하지 않았다. 현재 설치 드라이버는 리더 이동 명령을 거부하며, 하드웨어 구동 가능 여부는 미확인이다.**

이전 답변에서 “리더 자동 정렬도 구현할 수 있다”고 확정적으로 말한 내용을 정정했다.
드라이버의 제한이 확인됐다고 해서 하드웨어 구동 불가가 증명되는 것도, 제한만 풀면 구동 가능이 증명되는 것도 아니다.
다음 담당자는 리더 자동 이동을 지원 완료 기능으로 설명하지 말아야 한다.

마지막 작업 범위는 사용자가 선택한 **“코드와 설치 준비까지만 해줘”**다.
이 문서 전달 자체가 장치 연결·토크 활성화·자동 이동·Studio 재시작 요청은 아니다.
새 자리에서 사용자가 요청한 범위에 맞춰 진행한다.

## 사용자 목표와 확정된 흐름

사용자는 Physical AI Studio와 Windows LIVE GUI를 번갈아 연결하는 시간을 없애고 싶다.
Studio 안에서 저장 자세로 초기 위치를 잡고 에피소드를 수집하며, 학습 후 운영에서도 같은 로봇 연결을 유지하고 싶다.

학습 대상은 **어프로치에서 내려가 집고, 물건을 안전한 높이까지 들어 올리는 구간**이다.
어프로치 복귀와 운반은 저장된 관절 자세로 제어한다. Cartesian XYZ/IK 이동이 아니다.

현재 구현의 사용 흐름은 다음과 같다.

1. 텔레가 꺼진 HOLD 상태에서 `pose_1`~`pose_8` 중 어프로치를 선택하고 팔로워 이동.
2. 도착 확인 후 사용자가 리더를 팔로워와 비슷한 자세로 직접 정렬. 집게도 포함.
3. 텔레 켜기 → 녹화 시작 → 집기·들어 올리기.
4. `집기 완료 · 저장 후 복귀` → HOLD → 저장 ACK 확인 → 같은 어프로치로 복귀.
5. 다음 에피소드도 같은 연결에서 준비.

운영 화면에서는 모델로 집기·들어 올리기를 수행한 뒤 완료 버튼으로 저장 자세 복귀를 시작한다.
모델의 집기 성공/종료 자동 판정과 배출구 전체 경로 자동 실행은 아직 없다.

## 구현 방식과 검증 범위

- 기존 Studio의 `RuntimeSession`이 로봇·카메라 연결을 소유한다.
- `StudioActionSource`의 기존 제어 루프에 저장 자세 이동을 추가했다. 별도 serial 제어기를 붙이지 않는다.
- 녹화·Model Run 화면에 컨트롤을 추가했다. 일반 Environments 화면 자체에는 새 버튼을 넣지 않았다.
- 일반 이동은 마지막으로 송신한 그리퍼 명령을 유지한다. 물건 때문에 달라진 실측 그리퍼 값으로 덮어쓰지 않는다.
- 어프로치 도착은 팔 관절 피드백으로 확인한다. 이동 시작 ACK와 도착은 구분한다.
- 텔레 진입 시 리더와 팔로워 6축의 차이가 각각 5 normalized 이내인지 검사한다. 5도/5mm가 아니다.
- 이동 중 다른 제어 명령, 녹화 중 자세 이동, 저장 중 새 녹화·이동을 차단한다.
- 저장 실패·정지·연결 해제 시 자동 복귀하지 않는다. 이동 heartbeat 누락·관측 노후·추종 오차도 검사한다.
- 모의 backend 테스트 18개, 새 UI/흐름 및 기존 모델 화면 테스트 19개 통과.
- 타입·lint·format·production build 통과. 팀 저장소 테스트 304개 중 303 통과, 1 skip.
- 전체 Studio UI 테스트 최초 실행의 기존 6개 실패는 별도 재실행에서 통과했다. 일괄 실행 전부 통과로 과장하지 않는다.
- **실제 적용, 연결 전환, 팔 떨림, 충돌 없는 경로, 물건을 든 복귀, 실제 저장 영상은 미검증**이다.

11/9 정리 후 자세는 `home`, `pose_1`~`pose_8`, `close`, `open`, `outlet_return_1`의 총 12개다.
자세 JSON은 시연 에피소드나 학습 데이터가 아니다.
상세 구현·동작 제한·설치·복구 명령은 [통합 README](../../robot/studio_extension/README.md)를 먼저 읽는다.

## 리더에 대해 실제 확인한 근거

실행 컨테이너 `physical-ai-studio-cuda`에서 아래 설치 소스를 읽었다. 로봇에는 명령을 보내지 않았다.

```text
/app/application/backend/.venv/lib/python3.13/site-packages/physicalai_so101_plugin/so101.py
```

이 드라이버는 `role="leader"`를 토크 비활성·텔레용 읽기 전용으로 정의한다.
`send_action()`에는 다음 제한이 있다.

```python
if self.role == "leader":
    msg = "Cannot send actions to a leader arm. Leader arms are read-only for teleoperation."
    raise RuntimeError(msg)
```

`set_torque(enabled=...)` 메서드와 보정값 기반 normalized↔ticks 변환 코드도 존재한다.
**메서드가 존재한다는 사실은 현재 리더의 구동 검증 결과가 아니다.**
역할 문자열만 follower로 바꾸거나 제한을 삭제하는 방식으로 실물에 시험하지 않는다.
리더 드라이버/owner가 위치 명령을 받을 경로와 토크 전환의 실패 처리까지 조사해야 한다.

## 다음 담당자가 할 일

### 1. 현재 장비와 설치 환경 확인

같은 PC인지, 같은 양팔·보정·고정 위치를 옮긴 것인지, 팀원의 다른 장비인지 구분한다.
현재 프로젝트·Follower/Leader ID, USB 장치 식별, 보정 파일의 장치 대응, 설치 이미지 revision을 읽기 전용으로 확인한다.
포트 번호나 `/dev/ttyACM0`만 보고 팔을 판정하지 않는다. 과거 COM4/COM5와 BUSID는 바뀔 수 있다.

### 2. 리더 자동 정렬의 가능성 조사

- 실제 리더 모터 모델·정격 전압·전원 공급·기구 조건을 확인한다. 팔로워와 동일하다고 가정하지 않는다.
- 모델별 공식 사양에서 위치 제어·토크 활성화 가능 여부와 제한을 확인한다.
- 설치 드라이버의 리더 역할, 소유 프로세스, 토크 API, 통신 오류 처리 경로를 확인한다.
- 팔로워 목표를 **리더 자신의 보정**으로 변환할 수 있는지 확인한다. 원시 tick 값을 그대로 복사하지 않는다.
- 자동 정렬 도중 사람이 리더를 잡는 상황과, 정렬 후 토크 해제 때 처지는 상황의 전환 절차를 설계한다.
- 결론을 지원 가능 / 추가 변경 필요 / 조건 불충족 / 아직 미확인으로 근거와 함께 보고한다.

가능성이 확인되고 사용자가 구현을 요청하면, 별도의 정렬 모드에서 천천히 이동하고
사용자 인계·토크 해제·자세 재확인 후 텔레로 전환하는 흐름을 설계한다.
우선 기존의 **팔로워 자동 이동 + 리더 수동 정렬** 기능은 독립적으로 검증할 수 있다.

### 3. Studio 통합 적용과 실물 검증

사용자가 설치를 요청하면 README의 읽기 전용 preflight부터 실행한다.
현재 bundle은 이 PC의 **기존 v4 backend 수정본**을 기준으로 원본 해시를 기록했다.
같은 Studio revision의 순정 설치라도 해시가 다를 수 있다. 실패하면 검사를 우회하지 말고 소스 차이를 비교해 새 묶음을 준비한다.

실물은 사용자가 준비한 상태에서 빈 집게·짧은 이동부터 확인하고,
정지 → 도착 → 리더 수동 정렬 → 텔레 → 짧은 에피소드 → 저장 후 복귀를 검증한다.
저장된 에피소드에 복귀 구간이 빠졌는지 재생하고, 여러 회차에서 세션·카메라가 유지되는지 확인한다.

기준 저장소는 `https://github.com/agentops-lostfound/ai-lostfound-tower`, 브랜치는 `LF-3-yolo-aruco`다.
**이 인계 작성 시점에 이번 통합 코드와 문서는 미커밋·미푸시다. GitHub에서 받는 것만으로는 포함되지 않는다.**
기존 작업 파일 `run_vision_adapter_full.py.pre_unify.bak`는 이번 작업과 무관하므로 공유 묶음에서 제외한다.

함께 전달할 자료는 다음과 같다. 이동용 ZIP은 아래 구조를 유지한다.


ZIP은 전체 저장소·Studio 설치·Python/npm 환경·보정 파일·카메라 설정·학습 데이터·가중치를 포함하지 않는다.

다른 로봇·보정·장착 위치라면 기존 자세를 실행하지 말고 호환성을 확인하거나 다시 티칭한다.
