# 학습 인수인계 · 2026-11-06

## 11/9 최신 학습 범위: 아래에서 집기까지만

사용자가 실제 수집 중인 데이터는 접근해서 집게를 닫은 지점에서 끝난다. 들기·어프로치 복귀는 VLA 학습 범위에서 제외한다.
운영 목표는 `pose_N → VLA 집기 → 제어 종료·HOLD → 같은 pose_N 복귀 → 파지 검증 → 배출구 순서`다.
정책 종료 후 그리퍼의 직전 파지 명령을 유지하며 복귀하는 연결부와 미구현 범위는 [최신 로봇 연결 인계](2026-11-09-tower-robot-part.md)를 따른다.
아래 최초 문서의 학습 범위와 다르면 이 변경 사항을 우선한다. 실제 VLA 실행 어댑터와 복귀 경로는 아직 실물 검증하지 않았다.

### 사진·라벨 준비

Windows에서 탑뷰를 촬영하려면 Studio의 로봇 세션과 탑뷰 사용을 정상 종료한 뒤, 현재 탑뷰 BUSID를 확인하고 `usbipd detach --busid <탑뷰 BUSID>`로 Windows에 돌려준다. OpenCV 촬영 도구를 쓸 때는 Windows 카메라 앱도 닫는다. 저장된 사진으로만 실험할 때는 장치 연결을 바꿀 필요가 없다.

1. 같은 고정 탑뷰에서 **빈 구역 / 단일 물품 / 여러 물품**을 별도 세션으로 촬영한다. 특히 작은 USB·립밤, 검은 지갑, 폰 가로·세로와 반사 조건을 포함한다. 비슷한 연속 프레임은 같은 split에 둔다. 비교용 실사진은 라벨을 확인해 학습과 분리한다.
2. Label Studio에서 화면에 보이는 대상마다 박스 하나씩 붙인다. 의도한 빈 사진은 빈 라벨로 표시하고, 물품이 있는 사진에 라벨이 빠졌는지 확인한다. `prepare_dataset.py`는 라벨 파일이 없으면 빈 라벨로 취급한다.
3. 6종 준비 도구의 export 구조는 `images/`, `labels/`, `classes.txt`다. 입력 사진명 예시는 `card_wallet_W01_s1_000.jpg`. Windows 카메라의 `WIN_*.jpg`는 준비 도구에서 건너뛰므로, 사용하려면 사본을 규칙에 맞추고 대응 라벨도 맞추거나 수동 데이터셋 구조를 만든다. 검증 세션을 `--val-sessions`에 지정하고 별도 테스트 사진을 남긴다.

```powershell
cd C:\Users\user\AI-LostFound\team-repo
$py = '..\.venv-vision\Scripts\python.exe'
# 탑뷰 장치 번호를 확인한 뒤 --source를 지정한다. 스페이스 저장, q 종료.
& $py vision/capture_images.py --category card_wallet --object W01 --session s1 --source 0
# Label Studio에서 YOLO로 export한 뒤 실행한다. 입력 경로와 검증 세션은 실제 값으로 바꾼다.
& $py vision/prepare_dataset.py --export 'D:\ls_export' --out datasets/vision_six_v1 --val-sessions s2
# 데이터 준비 후 첫 2 epoch 시험. 매번 새로운 --name을 사용한다.
& $py vision/train_yolo.py --dataset vision_six_v1 --name six_smoke_v1 --model models/yolo26n.pt --epochs 2 --imgsz 640 --batch 4 --device cpu --no-export --no-notify
```

단일 클래스 실험은 `datasets/lostfound_item/{images,labels}/{train,val}/`에 사진과 YOLO txt 라벨을 넣고 진행한다.

```powershell
& $py -m vision.scripts.train_item --dry-run
& $py -m vision.scripts.train_item --name item_smoke_v1 --epochs 2 --imgsz 640 --batch 4 --device cpu
```

Windows `.venv-vision`은 Python 3.11.18, PyTorch 2.9.1 CPU, Ultralytics 8.4.199다. 실제 GPU 학습은 CUDA가 되는 별도 학습 환경에서 `torch.cuda.is_available()`가 참인지 확인한 뒤 `--device 0`을 쓴다. 6종 결과는 `models/<name>/best.pt`, `metrics.json` 및 설정에 따른 내보내기 결과, item 결과는 `models/<name>/best.pt`에 남는다. Hub 이동은 승인된 저장소와 범위에서 별도로 진행한다.

### 기존 모델과 비교

- 기준은 `models/yolo26l.pt`, `imgsz=640`, `confidence=0.25`다. 최신 풀샷 표본은 실물 5개 중 4개 검출, 검은 지갑 누락, 네 박스 모두 `cell phone`으로 분류됐다. 입력 크롭·조명·방향에 따른 관찰이며, 단일 표본으로 원인을 확정하지 않는다.
- 같은 홀드아웃 이미지와 조건에서 기본/학습 모델을 비교한다. 6종은 품목별 precision·recall·mAP, 보관함은 구역별 **정확한 개수 비율·미검출·중복 박스·빈 구역 오검출**을 기록한다. 풀샷과 구역 크롭 결과를 구분한다.
- 예시 사진은 `C:\Users\user\Pictures\Camera Roll\WIN_20261106_12_49_55_Pro.jpg`, 결과는 `outputs/camera_handoff/WIN_20261106_12_49_55_Pro-full-yolo/`에 있다. `vision/configs/vision.yaml`을 복사한 로컬 YAML에서 `model`만 새 가중치 경로로 바꿔 `--config`로 전달하면 기본값과 나란히 시험할 수 있다.

```powershell
$photo = 'C:\Users\user\Pictures\Camera Roll\WIN_20261106_12_49_55_Pro.jpg'
& $py -m vision.scripts.test_vision --image $photo --device cpu
$layout = 'outputs/camera_handoff/training-reference-regions.json'
& $py -m vision.scripts.preview_section --image $photo --regions $layout --draw
# phone 구역을 저장한 경우
& $py -m vision.scripts.preview_section --image $photo --regions $layout --region phone --show
```

픽셀 구역은 기준 사진과 카메라 구도·해상도를 일치시킨다. 실제 보관함 재고 검사 CLI는 `run_storage_check.py`, 오프라인 시험 입력은 `outputs/storage-check-demo/`에 있다. 연결 결과는 검사 리포트이며 운영 DB·촬영 트리거·로봇 연동의 실제 적용 범위는 후속 작업에서 확인한다. [촬영·학습 안내](../../vision/README.md) · [탑뷰 검증](../../vision/TOPVIEW.md) · [로봇 GUI](../../robot/README-panel.md)
