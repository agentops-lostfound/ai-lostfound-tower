# 기존 V1 보존과 테이블 인식 V2 개발 분리 계획

작성일: 2026-11-12 (한국 시간)

**현재 동작을 V1으로 고정해 다시 실행할 수 있게 보존하고, 새 기능은 별도 V2에서 개발한다.**
이 문서는 보존·복구 계획과 실행 기록이다. 2026-11-12 로컬 백업·격리 복구 검증을 수행했다. 실제 결과와 남은 범위는 6~7장을 따른다.

## 1. 보존 목적과 새 개발 목표

### V1 — 기존 8칸 시연

- DB 칸 R1-1~R4-2와 저장된 로봇 자세를 연결하는 반환 흐름.
- 휴대폰·보조배터리·핸드크림·립밤 4종과 공용 11단계 티칭 시퀀스.
- 확정한 립밤 7·8번 자세와 고정 명령 보정, 도착 마진, 이동 3초 설정.
- 원격 heartbeat, 정지 후 빈 집게 HOME 복구, 실제 관절 조회.
- Studio 공유 탑뷰 영상의 OWLv2/SigLIP2 관측과 칸별 DB 개수·품목 비교.

V1은 시연에 사용할 수 있는 기준으로 남긴다. 8칸 전체 파지·물품 ID·DB 인계가 모두 검증된 완성본이라는 뜻은 아니다.
탑뷰 비교는 읽기 전용이며, 동일 물품 확정·자동 DB 배정·로봇 실행 허가를 제공하지 않는다.

### V2 — 테이블 실물과 자연어 특징으로 대상 특정·집기

직원이 테이블에 물품을 올리면 비전이 물품별 위치와 특징을 관측한다.
찾으러 온 사람의 설명과 관측 정보를 비교해 대상을 좁히고, 대상이 이동했으면 새 위치에서 다시 확인해 로봇이 집는다.
수동으로 물품마다 사진을 먼저 등록하는 절차나 고정 칸 배치에 의존하는 것을 목표로 하지 않는다.

- OWLv2: 물품 후보 위치 검출.
- SigLIP2: 이미지·설명 및 이동 전후 외형 유사도 비교 보조.
- Qwen3-VL: 관측 특징 추출, 사용자 설명 해석, 후보 간 일치·불일치 근거 정리.
- 위치·동작 처리: 이동/정지 감지, 최신 위치·방향 추정과 로봇 집기 연결.
- 후보를 구별할 근거가 부족하면 추가 질문·관측으로 이어간다.

모델의 비교 점수는 동일 물품일 확률이나 실제 파지 성공을 뜻하지 않는다.
테이블 임의 위치 집기는 현재 저장 자세 방식에 더해 좌표·집게 보정과 접근 경로 구현이 필요한 신규 범위다.

## 4. V1과 V2를 함께 유지하는 방식

1. 현재 V1 실행 경로와 실행 설정을 유지한다. 게시를 위해 실행 중 worktree를 switch/reset/merge하지 않는다.
2. V1 기준 커밋은 태그로 고정한다. 브랜치가 이후 움직이거나 삭제돼도 기준 커밋과 복구 기록을 찾을 수 있게 한다.
3. V2는 관련 Jira 업무를 정한 뒤 `LF-번호-geontae-영문설명` 형식의 새 브랜치와 별도 worktree에서 개발한다.
4. V2의 설정·출력·참조 DB·모델 캐시 또는 읽기 전용 모델 참조 경로·포트를 명시적으로 분리한다. V1 데이터를 덮어쓰지 않는다.
5. 카메라는 기존 Studio 공유 영상을 재사용한다. 로봇 제어 소유권과 GPU 사용권은 조정하며 두 실행기가 같은 팔에 동시에 명령하지 않는다.
6. V2 구현 중 V1 티칭·보정·도착 마진은 변경하지 않는다. 실물 검증이 끝날 때까지 V1 실행 경로를 남긴다.
7. V2를 실제 시연에 사용할 때도 선택한 버전과 코드·설정·데이터 버전을 표시한다. V1 복귀는 검증된 조합으로 수행한다.

worktree들은 공통 Git 저장소를 공유한다. worktree 폴더만 복사해서 독립 백업이 됐다고 보지 않는다.
Git bundle은 Git 이력을 보존하지만 무시된 파일, 미커밋 변경, 가상환경, Studio와 운영 DB는 포함하지 않는다.

## 5. 백업·복구 실행 순서

### 백업

1. 실제 실행 프로세스의 작업 경로·커밋·실행 옵션과 사용하는 파일을 확인해 목록으로 만든다.
2. 필요한 DB·설정은 일관된 시점으로 백업한다. 서버나 로봇 중단이 필요하면 실행 담당자와 시점을 맞춘다.
3. 기준 태그·Git bundle과 별도 실행 자료를 생성한다. 파일 목록·크기·SHA-256을 기록한다.
4. `git bundle verify`로 Git 묶음을 확인하고, 파일 체크섬과 필수 자료 누락을 점검한다.
5. 다른 디스크로 사본을 복사하고 체크섬을 다시 대조한다.

### 별도 폴더 복구 검증

1. 기존 실행 경로를 덮어쓰지 않는 새 폴더에 bundle을 복원한다.
2. 실행용·게시용 기준 커밋을 각각 복원해 예상 SHA와 일치하는지 확인한다.
3. 백업한 티칭·보정·영역·locator·모델을 복원하고 필요한 환경을 구성한다.
4. Studio 자료는 별도 복구 대상에서 확인한다. 운영 컨테이너와 볼륨을 시험용으로 덮어쓰지 않는다.
5. 로봇 명령이 연결되지 않은 설정으로 화면, 저장 사진 분석, 참조 DB 조회를 확인한다.
6. 모의 로봇 경로에서 시퀀스·HOME 처리를 확인한다. 기존 시험 결과와 이번 복구 시험 결과를 구분해 기록한다.
7. 실제 팔을 연결하는 확인은 별도 실물 검증으로 수행한다. 복구나 프로세스 시작만으로 자동 이동하지 않는다.

복원된 파일의 존재뿐 아니라 분석·조회가 실행되고 코드와 데이터 버전이 맞는 것을 확인해야 복구 검증 완료로 기록한다.

- 네트워크·GPU·로봇 장치를 연결하지 않은 별도 CPU 컨테이너에서 백업한 1280×720 사진과 OWLv2/SigLIP2 모델의 실제 추론을 확인했다. 이는 물품 동일성·정확도·실물 파지 성공률 검증이 아니다.
- 실행 중 로봇 이동, USB 연결 변경, 기존 서버 재시작, main 병합은 수행하지 않았다.

현재는 같은 C: 디스크의 로컬 사본이다. 다른 물리 디스크 사본과 재원님 PC 운영 DB·메모리 상태는 포함하지 않았다.
인증 파일은 읽거나 복사하지 않았다. 과거 Qwen Windows 가상환경 두 개는 옛 인터프리터 경로로 인해 직접 실행되지 않아 패키지 메타데이터·의존성·모델을 보존했다.
V2 개발 폴더는 이번 백업 작업에서 생성하지 않았다.
