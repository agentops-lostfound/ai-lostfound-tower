# 로봇팔 ↔ DB 연결 확인 — 김건태 님 자리에서 하는 순서 (LF-21 · 11/10 변재원 → 김건태)

한줄 설명: 관제탑(변재원 PC)이 "이 물건은 몇 번 칸에 있다"고 알려 주면, 김건태 님 자리의 로봇팔이 **그 칸**으로 가서 집어 제출보관함에 놓는지를 4종 물건으로 확인한다.

받는 사람: 김건태 님과 김건태 님의 Codex. 이 문서 하나로 시작할 수 있게 썼다.
함께 볼 문서: 칸·자세 약속 `docs/contracts/robot_db_target.md` · 시퀀스 화면 사용법 `robot/README-sequence.md` · 앞선 안내 `docs/handoff/2026-11-10-robot-db-connect.md`

---

## 0. AI(Codex·Claude)가 지킬 규칙
- `.env`(비밀값)는 읽거나 출력하거나 커밋하지 않는다
- 로봇을 실제로 움직이는 명령은 **사람이 로봇 옆에서 정지 수단을 확인한 뒤에만** 보낸다. 시험 통과 ≠ 실물 확인
- main 에 직접 push 하지 않는다. force push 하지 않는다
- 이 순서는 관제탑 DB 를 **읽기만** 한다. 로봇 쪽에서 DB 를 고치지 않는다

## 1. 결론 먼저 — 어디에 무엇을 두나

| 무엇 | 어디 | 이유 |
|---|---|---|
| 관제탑 · 팀 DB · Qwen 사진 분석 | 변재원 PC(`10.10.21.21`) | 지금 그대로. 옮기지 않는다 |
| 포토박스(키오스크 카메라) | **변재원 PC 에 그대로** | 2장 참고 — USB 포트와 구조 둘 다 이쪽이 맞다 |
| 로봇팔 · Physical AI Studio · 탑뷰 카메라 · 보관판 | 김건태 님 PC·자리 | 로봇 부품이 같은 PC 의 Studio 에 붙는다. 물건을 칸에 바로 둘 수 있다 |
| 두 자리를 잇는 것 | 교육원 네트워크(HTTP, 읽기) | 김건태 님 PC 의 브라우저가 관제탑 주소를 연다 |

```
   Jaewon PC (10.10.21.21)                     Geontae PC
 +----------------------------+          +-----------------------------+
 | tower API :8100            |  HTTP    | browser: tower pages        |
 | team DB (Docker)           | <------- |  /showcase  /live           |
 | Qwen worker                |  read    |  /api/.../robot-target/ID   |
 | photo box camera (USB)     |          |                             |
 +----------------------------+          | sequence panel :8766        |
        ^                                |   -> Studio -> SO-101 arm   |
        | item photo                     | top-view camera (USB)       |
   [ photo box ]                         +-----------------------------+
                                            ^
                                            | put item in the slot by hand
                                       [ storage board  R1 R2 R3 R4 ]
```

오늘 확인하는 것은 **"DB 가 말한 칸 = 로봇이 간 칸"** 이다. 관제탑이 로봇을 직접 부르는 연결(자동)은 이 확인이 끝난 뒤에 만든다(7장).

## 2. 포토박스는 변재원 PC 에 둔다

- **구조상 문제가 없다.** 키오스크 화면은 어느 PC 에서 열든 카메라는 관제탑 PC 것을 쓴다(서버 카메라). 김건태 님 PC 에서 `http://10.10.21.21:8100/showcase` 를 열어도 포토박스 영상이 보인다
- **USB 포트가 모자란다.** 김건태 님 PC 는 포트가 4개다. 아래 표처럼 로봇 쪽 장치만으로 찬다(실제 꽂힌 장치는 김건태 님이 확인 — 아래는 추정)

  | 포트 | 장치(추정) |
  |---|---|
  | 1 | SO-101 팔로워 팔 |
  | 2 | 탑뷰 카메라 |
  | 3 | 키보드 |
  | 4 | 마우스 |

  리더 팔(티칭용)이나 포토박스까지 꽂으려면 USB 허브가 필요하다. 카메라 두 대를 허브 하나에 물리면 영상이 끊길 수 있어(대역폭) 권하지 않는다
- 조작 화면은 기계마다 하나다(#193). 김건태 님 PC 에서 키오스크 화면을 열면 **보기 전용**으로 뜬다. 그대로 두면 된다

## 3. 준비

### 3-1. 변재원 PC (변재원이 한다)
1. 관제탑을 교육원 네트워크에 열어서 켠다 — Warp → `tower` 탭(PowerShell)
   ```
   cd C:\git\ai-lostfound-tower
   ```
   ```
   git pull
   ```
   ```
   tools\start_tower.bat lan
   ```
2. Qwen 작업자가 켜져 있는지 확인한다(통합 화면 Qwen 카드에 "작업자 꺼짐"이 없으면 된다). 4-A 순서만 할 때는 없어도 된다

### 3-2. 김건태 님 PC
1. 최신 코드 받기 — Windows 터미널 → PowerShell 탭 → 저장소 폴더
   ```
   git switch main
   ```
   ```
   git pull
   ```
   - 커밋하지 않은 작업이 있으면 먼저 커밋한다. 명령이 실패하면 다음으로 넘어가지 않는다
2. Studio 를 켜고 팔을 연결한다. HOLD·녹화 꺼짐 확인. 다른 창의 텔레·이동·녹화는 끈다
3. 시퀀스 화면 켜기(실물)
   ```
   .\.venv\Scripts\python.exe -X utf8 -m robot.sequence_panel --live
   ```
   브라우저에서 `http://127.0.0.1:8766` → **Studio 연결 확인**(관절값만 받는다, 움직이지 않음)
4. 같은 브라우저에 관제탑 탭 두 개를 더 연다
   - `http://10.10.21.21:8100/live` — 로봇 작업대(칸 그림 · 시험 입력)
   - `http://10.10.21.21:8100/api/admin/storage/robot-targets` — 8칸 목록(읽기)
5. 8칸 목록에서 칸 이름·번호·자세가 아래와 같은지 본다

## 4. 물건 하나로 한 바퀴

두 가지 길이 있다. **먼저 4-A 로 로봇–DB 만 확인**하고, 되면 4-B 로 사진 접수까지 잇는다.

### 4-A. 빠른 확인 (포토박스 없이, 김건태 님 자리에서만)
1. **접수**: `/live` 의 **시험 입력** 칸에 습득 문장을 넣는다. 역 이름(서면·해운대)이 꼭 들어가야 한다
   - 예: `해운대역에서 흰색 보조배터리 주웠어요`
2. 진행판 끝에 `보관 완료(R2-1)` 처럼 **칸과 물건 번호**(예 `A-20261110-0001`)가 나온다
3. **실물 놓기**: 그 물건을 보관판의 **그 칸**에 손으로 둔다. 탑뷰 화면으로 칸 안에 들어왔는지 눈으로 본다
4. **DB 에 묻기**: 브라우저 새 탭에 아래 주소(물건 번호만 바꿔서)
   ```
   http://10.10.21.21:8100/api/admin/storage/robot-target/A-20261110-0001
   ```
   이런 답이 온다
   ```json
   {"ok":true,"item_id":"A-20261110-0001","slot_id":"R2-1","pose_name":"pose_3","number":3,"category":"보조배터리"}
   ```
   - `slot_id`·`number` 가 실물을 둔 칸과 같은지 본다
5. **로봇에 넘기기**: 답 전체를 복사 → 시퀀스 화면 하단 **DB robot-target 응답으로 시퀀스 준비** 에 붙여 넣고 적용 → 그 칸의 11단계가 준비된다
   - 실제 답에는 `outlet_sequence`·`warnings` 같은 항목이 더 들어 있다. 화면이 거부하면 위 예시처럼 `ok`·`item_id`·`slot_id`·`pose_name`·`number` 만 남겨 붙인다(전체 답을 그대로 받는지는 실물 화면에서 확인 필요)
6. **실행**: 주변을 비우고 정지 수단을 확인한 뒤, 처음에는 **선택 단계만 실행**으로 `pose_N` 까지만 → 칸이 맞으면 **처음부터 전체 실행**
7. 물건이 제출보관함(H-1)에 놓였는지 본다 → 5장 표에 적는다

### 4-B. 전체 (포토박스 촬영부터)
1. 물건을 변재원 자리 포토박스에 넣는다 → 5초 뒤 자동 촬영 → Qwen 이 품목·색을 읽는다(약 15~30초)
2. 통합 화면(`/showcase`)의 물건 카드에 품목과 `slot_id` 가 채워진다
3. 물건을 포토박스에서 꺼내 김건태 님 자리 보관판의 **그 칸**에 둔다
4. 4-A 의 4번부터 같다

### 꼭 알아 둘 것 — 가상 시연과 진짜 로봇은 아직 따로 움직인다
- 관제탑은 지금 가상 시연 모드라, 분실 문장(`흰색 보조배터리 잃어버렸어요`)을 넣으면 **화면 속 가짜 로봇이 혼자 인계 완료까지** 간다. 진짜 로봇을 기다리지 않는다
- 그래서 `robot-target` 은 **물건이 보관 중일 때**(분실 문장을 넣기 전) 읽어 둔다. 인계 완료가 되면 칸이 비어 답이 `ok: false` 로 바뀔 것으로 보인다(추정 — 한 번 눌러 확인)
- 발표 흐름처럼 보이게 하려면: 로봇 시퀀스를 준비해 둔 뒤 → 분실 문장을 넣고 → 화면이 "집기"에 올 때 **전체 실행**을 누른다(사람이 박자를 맞춤)

## 5. 확인표 (4종 · 8칸)

물건마다 4장을 한 번씩. 같은 품목을 한 번 더 접수하면 먼 칸(`-2`)이 배정된다.

| 품목 | 예상 칸(가까운 → 먼) | DB 답의 칸 | 로봇이 간 칸 | 집기 | 제출보관함 | 걸린 시간 · 메모 |
|---|---|---|---|---|---|---|
| 휴대폰 | R1-1 → R1-2 | | | | | |
| 보조배터리 | R2-1 → R2-2 | | | | | |
| 핸드크림 | R3-2 (R3-1 은 처음부터 분홍 핸드크림) | | | | | |
| 카드지갑 | R4-1 → R4-2 | | | | | |

- 분홍 핸드크림(R3-1, 처음부터 있는 물건)의 번호는 `H-오늘날짜-0001` 이다. 이 번호로도 4-A 4번부터 할 수 있다
- 결과는 이 표를 채워 변재원에게 주거나 PR 에 적는다

## 6. 안전
- 로봇 옆에 사람이 있고, 정지 수단(시퀀스 화면 **정지 / HOLD**, `Esc`, 전원)을 확인한 뒤에만 실행한다
- 정지 버튼은 Studio 의 HOLD 요청이다. 하드웨어 비상정지가 아니다
- 처음 가는 칸은 **한 단계씩**. 걸림·진동이 있으면 멈추고 위치를 본다. 도착 기준을 억지로 넘기지 않는다
- 시퀀스 도중 다른 Studio 창에서 이동·텔레·녹화를 하지 않는다

## 7. 지금 안 되는 것 · 다음 단계

| 지금 | 다음 |
|---|---|
| DB 답을 사람이 복사해 시퀀스 화면에 붙인다 | 관제탑이 김건태 님 PC 의 로봇을 네트워크로 직접 부른다(변재원이 만듦) |
| 가상 시연의 가짜 로봇과 진짜 로봇이 따로 움직인다 | 가상 시연 화면이 진짜 로봇의 도착을 기다린다 |
| 로봇이 옮긴 뒤 관제탑 기록은 가상 흐름이 채운다 | 진짜 로봇의 결과(성공·실패·멈춘 단계)가 기록된다 |
| 탑뷰는 사람이 눈으로 본다 | 탑뷰가 "그 칸에 그 물건이 있다"를 대조한다(김건태 님 비전 쪽 일정에 맞춤) |

다음 단계를 만들려면 정할 것이 하나 있다 — **관제탑이 로봇을 어떻게 부를지**
- (가) 접근 · 집기 · 전달 세 토막으로: 화면에 단계가 보이고 중간에 멈출 수 있다
- (나) 티칭 11단계를 한 번에: 지금 시퀀스와 같아 만들기 쉽다

## 8. 막혔을 때

| 증상 | 볼 곳 |
|---|---|
| `10.10.21.21:8100` 이 안 열림 | 변재원 PC 관제탑을 `tools\start_tower.bat lan` 으로 켰는지. 주소에 `:8100` 이 있는지 |
| `robot-target` 이 `no_slot` | 물건이 아직 칸에 없음(칸 대기·회수 전) 또는 이미 인계됨. `/live` 에서 물건 상태 확인 |
| `robot-target` 이 `staff_shelf` | 맞는 열이 꽉 차 직원 보관 선반으로 감 — 로봇이 집지 않는 자리 |
| `어느 역에서 주웠는지 알 수 없어요` | 습득 문장에 서면·해운대 중 하나를 넣는다 |
| 시퀀스 화면이 응답을 거부 | `pose_name` 이 `pose_1~8` 이 아니거나 자세 파일 값이 다름 — `robot/README-sequence.md` |
| DB 답의 칸과 실물 칸이 다름 | 실물을 잘못 둔 것. DB 를 고치지 말고 실물을 DB 가 말한 칸으로 옮긴다 |
| 잘못 넣은 접수를 지우고 싶음 | `/live` 의 [기록 삭제] — 그 물건에 딸린 기록이 모두 지워진다(되돌릴 수 없음) |
