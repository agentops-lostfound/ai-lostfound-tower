## 1. 실물 정지에서 확인한 것

사용자 PC의 새 SO101 팔로워를 대상으로 Studio 소유자 프로세스에 정지 관문을 적용했다. 현재 위치를 유지하는 정지와 Home 복귀를 분리하고, 정지 후 늦게 도착한 목표·이전 세대의 추론 결과가 재이동을 시작하지 못하도록 했다. 정지 요청 처리에서 긴 모터 I/O 잠금을 기다리지 않지만, 이미 시작된 I/O를 강제로 취소하는 기능은 아니다.

별도 정지 화면에서 버튼 두 번 후 명령 세대 2와 유지 명령 전송 완료를 확인했다. 이후 실제 팔의 맨 아래 좌우 회전 관절만 작은 범위로 움직이며 사용자가 버튼을 눌렀다.

| 관측 항목 | 사용자 실행 결과 |
| --- | --- |
| 시험 결과 | `MANUAL_STOP_OBSERVED` |
| 이동 목표 요청 수 | 최대 60개 중 51개. 소유자 접수 요청 수이며 모터 패킷 수 계측은 아님 |
| 최대 관측 변화 | 약 0.517 정규화 단위. 각도 단위가 아님 |
| 종료 정지 요청 | `stop_requested_after_trial=true` |
| 유지 명령 처리 | `hold_commanded_after_trial=true` |
| 정지 후 약 0.5초 관측 변화 범위 | 6개 관절 모두 `0.0` |
| 자동 원위치 복귀 | 실행하지 않음 |

이 결과는 현재 배치의 한 관절·작은 저속 이동에 대한 근거다. 정지 버튼 클릭부터 물리 정지까지의 시간을 측정한 결과, 하드웨어 비상정지 인증, 모든 관절·집기·모델 추론 중 정지 보장을 뜻하지 않는다. `hold_commanded`도 실제 속도 0을 보증하는 센서 판정이 아니다. **정지는 토크 OFF나 Home 이동과 다르다.**

## 2. Home 구현과 현재 한계

사용자가 기록한 접힌 자세를 Home 목표로 지정했다. 기본 설정은 [robot/config/home_pose.json](../../robot/config/home_pose.json), 로컬 활성 설정은 `outputs/robot-home/active.json`이며 이전 선택은 `history/`에 보존한다. 자세를 바꾸면 버전이 바뀌고 이전 경로 검증을 재사용하지 않는다. 기존 캘리브레이션 스크립트로 Home을 구현하지 않는다.

별도 Home 시험 버튼과 작업자를 추가했다. 현재 구현은 다음 조건의 **근거리 시험 경로**만 허용한다.

- Home과 맨 아래 좌우 회전 차이가 최대 1.0 정규화 단위 이내.
- 다른 관절과 집게는 Home의 0.2단위 이내이며, 복귀 중에는 출발 시 측정한 위치를 유지.
- 시작 전 정지·유지 완료 상태와 직원 확인, 동일 소유자 세션·명령 세대 필요.
- 중복 Home 실행 거부. 정지 버튼은 별도 통신으로 계속 사용 가능.
- 복귀 중 정지하면 남은 목표를 보내지 않고 자동 재개하지 않음.
- 이미 Home 범위이면 재개/이동 없이 완료. 멀거나 다른 관절 자세가 다르면 강제 복귀하지 않고 거부.

프로파일의 `path_verified=false`, `motion_enabled=false`는 **일반 복귀 경로를 승인하지 않았다는 상태**다. 별도 확인을 거치는 제한된 근거리 시험과 구분한다. 모든 작업 자세에서 접힌 자세까지 안전하게 접는 경로는 아직 없다.

실물에서 `HOME_REACHED`와 `HOME_STOPPED`가 확인됐다는 보고는 아직 받지 않았다. 현재 결과는 모의 시험과 실제 Zenoh+가짜 장비 시험까지다. 사용자는 기존 화면만 갱신해 ‘이미 Home 확인→작은 이동 후 복귀→다시 작은 이동 후 복귀 중 정지’를 연속 시험할 수 있는 상태다. 자세 변경용 편의 화면은 후속 요구이며 현재 제공되는 기능은 후보 기록·설정 교체·이력 보존이다.

## 4. 통합 전에 팀과 맞출 사항

현재 대상 소유자의 **기존 Studio `/action` 명령은 폐기**하고 전용 정지 관문을 사용한다. 기존 Teleoperate·정책/VLA를 그대로 실행해도 이 관문을 통과하는 것으로 간주하면 안 된다. 다른 장비/프로젝트 ID에 자동 적용되지 않는다. 원본 복원 도구도 함께 제공하며 적용/복원은 활성 세션·USB 사용이 없을 때만 수행한다.

| 협의 대상 | 다음 연결 작업 |
| --- | --- |
| 이순필 LF-11·12 | 실물 Home 도달/중간 정지 확인, 실제 작업대에서 출발 범위·경유점·물품 상태·복귀 경로 검증 |
| 변재원 LF-16 및 관제탑 | 팀 `robot_stop`/`robot_home` backend·직원 확인 API를 같은 실제 소유자와 연결, 반환 진행 중 Home 거부 및 중단 동작 공동 시험 |
| 김건태 LF-3·19·20·21 | 비전/개체/좌표 입력과 모델 집기 연결, 모든 실제 목표가 같은 정지 관문을 통과하도록 조정 |
| 모델/GPU 연결 담당 공동 | Qwen의 실제 모델 참조/캐시 해제와 GPU 사용권 인계, VLA 실행 중 정지 확인 |

관제탑 공통 계약이나 `main`을 이번 실험에 맞춰 임의 변경하지 않았다. 최신 main과 연결할 때 계약 및 변경점을 다시 확인해야 한다. 카메라 픽셀을 로봇 모터 위치로 바로 사용하는 기능, 좌표 보정, 집기 성공 판정, 전체 반환·직원 인계까지 구현됐다는 뜻도 아니다.

## 5. 보정·토크 관련 미확정 사항

실제 보드 조회에서 팔로워의 6관절 보정값이 Windows 최종 JSON·Studio payload와 달랐다. USB 소유권 해제와 변경 전 백업 후 최종 값으로 복원했고 사용자가 두 팔의 일치를 확인했다. 이후 토크 OFF 상태에서 현재 위치와 목표 위치를 맞추는 과정에서 첫 관절 토크 OFF 검증 실패가 한 번 있었다. 후속 조회와 토크 OFF 명령에서는 6개 모두 0, 목표=현재 위치가 확인됐다.

두 현상의 원인은 미확정이다. 사용자 환경의 쓰기/직렬화 함수에는 명시적인 토크 ON 코드가 없었고 Torque_Enable·Goal_Position·Present_Position 주소는 겹치지 않았다. 펌웨어·동시 접근·통신값 중 하나로 단정하거나 해결됐다고 보고하지 않는다. 전원 재인가 후 보정 유지, 재발 여부, 연결 시 토크 ON 절차는 후속 검증 대상이다.

## 6. 비전 속도 실험과 구매 완료

독립 사진 시험에서 CPU YOLO와 HF NF4 Qwen을 상주시키고 입력384를 사용했다. **동일 폰·동일 lowconf 설정의 후속 요청 전체 시간이 약8.10→5.68초(약29.8% 감소)**였고, 검출/시작/crop 구간은 약2.682→0.0566초였다. Qwen 구간도 실행마다 달라 전체 차이를 전부 YOLO 변경 효과로 단정하지 않는다. 단일 사진 기록이며 초기 시작 비용·운영 GPU 인계·다물품 평균/p95 성능을 포함하지 않는다. 최초22.21초와는 사진/설정이 달라 동일 조건 개선율로 비교하지 않는다. 낮은 confidence의 폰 오분류가 포함돼 검출 정확도 개선도 남아 있다. [자세한 실측](vision-latency-summary.md)을 참고한다.

구매품목 리스트업은 **2026-11-03 완료**다. 최종 엑셀 기준 상품금액255,180원, 양식의10% 가산 총액280,698원, 30만원 예산 잔액19,302원이다. USB는 샌디스크2개+액센1개, 카드지갑3개, 신지모루 허브1개 등 최종 선택을 반영했다. 실제 승인·구매·결제·수령 완료는 확인하지 않았다. [최종 구매 목록](procurement-user-selection.md)을 참고한다.

## 7. 검증 및 다음 확인 순서

코드 기준 커밋에서 `python -m unittest discover -s tests`는 **180개 실행, 2개 건너뜀**으로 통과했다. 클라우드의 가짜 장비 통신 시험은 Zenoh1.10.2, 사용자 컨테이너의 가짜 장비 통신 시험은 Zenoh1.9.0으로 수행했다. 클라우드 Home 시험은 가짜 장비이고 사용자 실물 정지 시험과 구분한다. 약0.000256초의 기존 fake 시험 RPC 시간은 실물 정지 시간으로 보고하지 않는다.
