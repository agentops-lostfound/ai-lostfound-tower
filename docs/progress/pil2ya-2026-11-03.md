# pil2ya 프로젝트 진행 기록

기록일: 2026-11-03 (한국 시간)

## 보고 범위

사용자 대화, 이전 대화 인계, 첨부된 팀 발표 HTML, 실제 Git 작업을 근거로 작성했다. 팀원이 구현한 관제탑·DB·평가 코드를 pil2ya의 성과로 계산하지 않는다. Jira 담당 배정과 완료 조건을 조회하지 않았으므로 아래 Jira 번호는 관련 영역을 찾기 위한 참고이며 업무 완료 선언이 아니다. 근거 없는 진척률(%)은 부여하지 않는다.

## 최신 인계 반영

[SO ARM 로컬 구축·보정](soarm-local-handoff.md)에서 새 SO101 보정·제한 시간 수동 조작·카메라 브리지 검증을 보고받았다. 아래 초기 표의 장비 미확인은 이 인계로 보완한다. 클라우드에서 재검증한 것은 아니며 새 환경 카메라 등록·재부팅 유지 확인·작업 녹화·학습·자율 추론은 남아 있다. [구매 조사 인계](procurement-handoff-2026-11-03.md)는 USB 128GB 3개·10인치 태블릿과 제안 계획액 271,470원을 반영한다. 실제 구매는 없다.

## 완료한 검토·정리

### 팀 발표 기준 확인

공유 링크 본문은 직접 읽지 못했으나, 사용자가 제공한 `AI 분실물 관제탑.html` 및 `AI 분실물 관제탑_files.zip`의 `saved_resource.html`에서 실제 9쪽 발표를 확인했다. 애니메이션 코드는 읽었으며 전체 브라우저 실행 검증은 하지 않았다. 이후 사용자가 해당 자료를 작업 기준으로 지정했다.

- 등록기계: 발견 장소 필수, 습득자 이름·전화번호 선택, 촬영·AI 분석·접수 결과 안내.
- 운반·보관: 본센터 직원 하루 1회 수거, 사람이 운반·중앙 입고 확인, 공용 보관함 혼합 보관. 지정 칸·규격 케이스·로봇 자동 입고를 전제하지 않는다.
- 웹: 동의 → 신분증 OCR → 분실 물품 등록 → 후보 3개·확인 질문 → 승인·수령 예약. 사용자에게 일치 점수 숨김.
- 현장: 웹 인증 정보와 실물 신분증 대조, 안쪽 색 등 제출 특징·실물 확인, 불일치 시 반환 보류·관제 알림.
- AI: 정답지 기반 코드 평가 → 오류 분석 → 개선안 비교·채택/거절. 발표 점수·회차·임계값은 예시이며 실제 측정 성과가 아니다.
- 시연 네 장면: 등록기계 접수, 웹 찾기, 본센터 수령, 디스코드 진행·알림·점수판.

최신 사용자 직접 지시는 **로봇 → 담당자 → 분실자** 전달, 담당자의 신분 이중 확인·제출 특징 대조·최종 인계 후 반환 완료다. 신분 이중 확인의 두 방법은 미확정이다. OCR 문자 추출을 진위·소유권 검증 완료로 취급하지 않는다.

### 비전·데이터 준비 이력

- 사용자 PC 경로는 `C:\00lsp\T_prj_edge`이며 클라우드 작업 공간과 별개다.
- Geti Classification / Single-label과 `wallet / watch / phone / earphone / pen` 라벨 구성을 안내했다. 실제 생성·업로드·학습 완료를 확인하지 않았다.
- PACO-LVIS 주석에서 관련 5종을 선별하고 COCO 이미지 다운로드·물체 박스 크롭으로 분류 이미지를 준비하는 방법과 스크립트를 이전 대화에서 안내했다. 이 저장소에 해당 스크립트를 구현·시험한 것은 아니다.
- 사용자가 추출 이미지 품질에 우려를 제기했다. 직접 촬영 중심·PACO 보조 활용을 제안했으나 최종 데이터 계획은 미확정이다.
- 같은 실물의 유사 사진이 학습·평가에 섞이지 않도록 분리하고, 검색은 별도 시점의 사진으로 개체 식별을 평가해야 한다.
- VAW·Open Images는 검토 후보이며 실제 다운로드·연동 완료로 계산하지 않는다.
- 과거 5종 분류 검토를 팀 MVP 범위 확정으로 해석하지 않는다. 현재 팀 규칙의 MVP는 지갑 1종이며 확장은 성공 후 검토한다.

### 기록·Git 협업

- 개인 저장소 `pil2ya/Edge_Prj`에 요구사항·비교표·진행 현황·이전 인계를 문서화하고 커밋 `4a3177c`를 업로드했다. 실행 가능한 서비스 구현 완료를 뜻하지 않는다.
- 팀 저장소 `agentops-lostfound/ai-lostfound-tower`를 현재 작업 공간에서 확인하고 기존 원격 `pil2ya` 브랜치로 전환했다.
- 최신 main의 CONTRIBUTING.md·AGENTS.md·PR 템플릿을 검토했다. main 직접 push 금지, 한국어 Jira 형식 커밋·PR, 시험과 팀원 승인 규칙을 확인했다.
- 사용자의 명시적 지시에 따라 현재 작업·푸시 대상은 pil2ya다. 팀 규칙의 업무별 `LF-번호-영문-설명` 브랜치 형식과 다르므로 추후 PR에 이를 밝힌다.

## 다음 작업과 확인 기준

1. 팀과 위 차이를 검토하고 담당 Jira 업무·완료 기준을 확인한다.
2. 독립된 작동형 HTML 시뮬레이션을 제작한다. 접수·이송·입고·검색·후보 선택·로봇 담당자 전달·현장 확인·최종 인계를 직접 조작할 수 있게 한다.
3. 정상 흐름 외에도 실물 미발견·개체 불일치·집기 실패·신분/특징 불일치·최종 인계 미확인·중복 반환 차단·담당자 복구를 검증한다.
4. 모의 OCR·AI 점수·로봇·디스코드 표시와 실제 연결·실측 결과를 명확히 구분한다.
5. Geti 데이터·학습 산출물과 실제 비전 평가 결과를 확보한 뒤 학습 진척을 갱신한다.

## 이번 제출 범위

팀 진행 기록 문서와 docs 목차만 추가·수정한다. 공통 인터페이스·앱 코드·팀 설계·Jira 상태·디스코드 메시지는 변경하지 않는다. PR/팀원 확인 전 팀 업무를 최종 완료로 표시하지 않는다. 환경 게시·설정 교체·초기화도 수행하지 않는다.
