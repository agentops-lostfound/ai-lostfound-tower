# LF-11 YOLO·Qwen 전체 처리 시간 비교

기록일: 2026-11-04 (한국 시간). 사용자 Windows PC의 실행 로그를 확인한 결과이며 클라우드 직접 실측이 아니다.

처리 범위는 저장 사진 입력 → YOLO 검출 → crop 생성 → Qwen 특징 추출 → JSON 저장이다. 실제 카메라 촬영·DB 매칭·로봇 이동은 포함하지 않는다.

| Qwen만 상주 | 8.10초 | 폰 test1, CPU YOLO 매 요청 시작, HF NF4 Qwen 상주·384, 후속 요청 |

## 비교 가능한 관측

같은 폰·검출 설정·HF 모델·입력384의 후속 요청 비교는 8.0983→5.6815초로 약2.42초·29.8% 감소였다. 검출/시작/crop 구간은 2.6820→0.0566초, Qwen 추출은 5.4040→5.6216초였다. 실행 시점과 Qwen 처리 시간도 달라 전체 차이를 전부 YOLO 변경의 효과로 단정하지 않는다. 단일 사진·각 조건 후속 요청1개이며 다양한 물품의 평균·p95·운영 성능을 보장하지 않는다.

22.21초와5.68초는 사진·해상도·상주 상태가 달라 동일 조건 개선율을 산출하지 않는다. 최초 립밤 실행은 물품 박스 검출 실패도 포함해 정확도 동등 비교가 아니다. '동일 조건에서74% 개선'이라고 보고하지 않는다.

## 초기 시작과 후속 요청 구분

최신 두 모델 상주 시험에서 시작 준비10.70초, 첫 요청9.0815초, 이후 요청5.6815초였다. 따라서 이 실행의 프로그램 시작부터 첫 결과까지는 약19.78초다. 시작 준비에는 Qwen/worker 초기화가 들어가고 첫 요청에는 YOLO 최초 모델 로딩이 남아 있다. 상주는 초기 비용을 제거한 것이 아니라 반복 요청에서 재사용하는 방식이다.

현재 보고 문구: **상주 상태의 단일 폰 사진에서 검출·특징 분석·저장을 약5.7초에 처리했다.**

## 적용 범위와 남은 일

- 현재 독립 시험 도구 추천은 HF NF4·기존8키 출력·384·CPU YOLO/Qwen 상주다.
- Ollama 비교 시간은 별도이며, Ollama와 상주 YOLO를 결합한 전체 처리 시간은 아직 측정하지 않았다.
- YOLO lowconf0.10은 시험용이다. 폰을 microwave로 분류한 낮은 점수 후보이며 검출 정확도·다물품 분리·미검출 개선이 필요하다.
- 특징 JSON 성공은 시각 정답 보증이 아니다. 실제 mm 좌표 보정과 로봇 제어는 미연결이다.
- 원본 사진·로그·모델 가중치는 이 기록에 포함하지 않는다. PR·main 병합·환경 게시 없이 pil2ya에 기록한다.
