기존 두 500문항의 채점기와 정답은 수정하지 않았다. 새 여정의 첫 평가 준비에서 짧은 세션 번호와 검색 부품 연결 오류를 발견해 무효 실행을 보존했다. 날씨 범위 안내의 동등 표현, 값이 바뀌지 않은 정정의 유효 확인 전제를 제품 수정 전에 보정했고, 모호한 입력은 실제 저장값까지 검사하도록 고정했다. 그 후 동일한 문항 의미 해시로 전후를 비교했다.

자동 채점 이후 모델의 실제 답변을 읽으며 위치 질문의 결론이 뒤로 밀리고 짧은 수령 질문에서 마지막 행동이 빠진 것을 발견했다. 첫 문장의 위치 결론과 제출보관함·수령 완료 행동을 검사하도록 기준을 강화했다. 강화한 기준으로 이전 코드의 전체 여정을 다시 실행했고, Mi:dm 기준선은 저장해 둔 실제 답변에 새 구조 검사만 재적용했다. 기존 실패와 모델 호출 원본을 유지했으며 기준선 답변을 새로 생성하거나 고쳐 쓰지 않았다.

40개 추가 표현은 첫 후보 구현 뒤 작성했다. 첫 후보에서38/40, 보완 후40/40이었다. 실패 사례를 본 뒤 수정했으므로 최종40/40을 미관측 일반화 정확도로 주장하지 않는다. 253여정에는 같은 개입 질문을 서로 다른8단계에 적용한160여정이 포함된다. 서로 다른 표현1,305개나 모든 자연어에 대한100% 정확도라는 뜻은 아니다.

## 공통 처리 개선

1. **안내 질문과 정보 입력 분리:** 위치·수령·색 구별·개인정보·날씨 질문을 주운 장소나 특징으로 저장하지 않는다. `오늘 날씨 어때?`의 `오늘`을 분실 날짜로 잘못 쓰지 않는다.
2. **명시적 정정 반영:** 날짜·스티커도 버린 조건 뒤의 새 조건을 사용한다. `오늘 말고 어제 저녁`, `별 스티커는 없고 하트 스티커` 등을 처리한다. 기존 특징이 있어도 명확한 `스티커는 없어요`를 반영한다.
3. **모름 정정:** 색·역·날짜·주운 곳을 명시적으로 모른다고 고치면 해당 칸을 갱신한다. 다른 칸을 묻는 중의 단순 `모름`이 이미 채운 모든 값을 지우지는 않는다. 둘 중 어느 색인지 모르면 임의로 선택하지 않는다.
4. **분실/습득 정정:** 다른 이야기를 추가한 것과 현재 신고 종류를 정정한 것을 구별한다. 명시적으로 정정하면 물건 종류·색을 유지하고 역·날짜·본인 확인 등 이전 업무의 정보는 다시 확인한다. 별개 물건을 새로 말한 경우도 존중한다.
5. **여러 물건과 감사 표현:** 여러 물건을 한 건으로 임의 선택하지 않고 하나씩 접수하도록 안내한다. 감사에는 답하면서 원래 질문·버튼을 유지한다.
6. **접수 후 확인 질문 보존:** 소유 확인 질문 중 안내·감사·날씨 질문을 받아도 요약 승인 단계로 돌아가지 않는다. 현재 확인 질문을 재개하고 같은 분실 접수를 다시 만들지 않는다. 이 단계에서는 다른 신고로 전환하지 않는다.
7. **확인 표현의 일관성:** Python·위젯의 동의 표현을 맞추고 한글 자모를 정규화한 뒤에도 `ㅇㅋ`, `ㅇㅇ`을 처리한다. `접수 부탁드립니다`, `확인했어요. 접수해주세요` 등을 지원한다. 부정·수정·질문이 섞이면 확정하지 않는다.
8. **습득 문의/개인정보 안내:** 구어체 습득 신고 위치와 물건을 들고 가는 문의를 후보 검색으로 바꾸지 않는다. 습득자 연락처 정책 질문은 문서 근거 경로에서 거절한다. 실제 타인 정보 조회·권한 우회 요청은 보호 응답으로 거절한다.
9. **결론과 필수 행동:** 센터 위치 질문은 부산역부터 답하고 요청하지 않은 수령 순서를 앞에 붙이지 않는다. 짧은 수령 방법 질문도 신분·물건 확인, 제출보관함에서 꺼내기, [물건 받았어요]까지 안내한다. 모델이 필수 단계를 빠뜨리면 완전한 안내문으로 돌아간다. 기존 근거 목록·모델에 전달하는 대화 문맥은 유지하며 검색+안내 복합 질문과 운영시간·대리·택배·신분증 없음 질문을 일반 수령 안내로 덮지 않는다.

## 검증 근거

- 전체 `python -m unittest discover -s tests`: **1,894개, 실패0, 제외35, 82.699초**. 신규 여정은 이 안의 subTest로도 실행하지만 고유 평가 사례 수에 중복 합산하지 않았다.
- Node 위젯/창 시험 **36/36**. 공유 확인 문항은 긍정30개·부정/혼합/질문22개로 확장했다.
- 실제 Chrome의 모바일440px·PC1360px에서 합성 접수4흐름 완료. 안내 개입, 정정 전 버튼 거절, 질문형 동의의 증표 미첨부, 자모 Enter 확인, 중복 전송, 대화 삭제, 분실→습득 정정, 자연어 확인을 검사했다.
- 브라우저는 실제 합성 SimDirector·로컬 HTTP에 연결했다. NDJSON 본문을 그대로 버퍼링해 전달했으므로 스트림 도착 시점 검증과 구분한다. 화면 두 장을 눈으로 확인했다. 미리보기 부모·자식 프로세스를 종료했다.
- 실제 Mi:dm 동일20여정·86턴은 **6/20 → 20/20**이었다. 최종 실제 모델 전송266회, 전송 오류0, 123.99초. 실행 중 소스 변경 없음과 규칙·브라우저 검사와 같은 소스 해시를 확인했다. 모델을 켠 전체 경로 시험이며 모든 답변이 모델 생성인 것은 아니다. 접수와 보호 답변은 규칙이 처리한다. 첫 후보의 별도 표현20개 통과는 참고 기록이며 최종 소스의 모델 평가 수에 합산하지 않는다.

실행 원본은 작업 루트 `outputs/conversation-quality-20261112`에 남겼다. `*-before`/`journeys-baseline4` 및 `midm-baseline-structure4`가 비교 기준선이며 최종 규칙/단위 결과는 `*-final7`이다. 중간 후보의 실패와 준비 오류를 삭제하지 않았다. 소스 변경·내부 중단 표식으로 멈춘 중간 모델 실행은 최종 증거로 사용하지 않는다. `source_unchanged=true`이며 모든 소스 변경이 끝난 실행만 최종 모델 기록으로 사용한다.

품질 기준과 재실행 방법은 `docs/design/chatbot_quality_gate.md`를 따른다. 검사 성공 후 대규모 시험을 자동 반복하지 않는다.

비교 집계와 개선 전후92개 실패 사례의 실제 답변 예시는 `docs/reports/conversation-quality-results-20261112.json`에 수록했다. 모델 기준선의 재판정 이력과 각 원본 파일 해시도 보존했다.

## 적용 범위

Mi:dm 모델 가중치·프롬프트·지식·실제 인증 공급자는 바꾸지 않았다. 새 실행에 한해 사용자가 대량 검증을 다시 요청했으며 과거 작업의 stop.flag는 보존했다. 합성 데이터만 사용했고 실제 `.env`·운영 DB·스키마·로봇·외부 알림은 변경하지 않았다. 운영 DB 제외35개를 이번 변경으로 통과했다고 설명하지 않는다.

main 병합·실제 서버 반영·재시작은 아직이다. 기존 결정대로 담당자가 서버에 적용해야 하며 이전 ZIP에는 이번 일괄 개선이 없다.
