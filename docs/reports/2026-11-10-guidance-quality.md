# LF-5 안내 오류·질문 적합성 보완 결과

## 바꾼 내용

1. **필요 없는 검색 차단**: 안내 의도가 명확하고 검색 요청이 없으면 물건 이름이 있어도 planner의 추가 검색을 거절한다.
   명시적인 검색+안내 복합 요청은 그대로 유지한다. 신분증·면허증·여권 표현을 함께 처리한다.
   planner trace에 proposed_plan/validation_notes를 남긴다.
2. **필수 안내 누락 검사**: 처음 이용하는 질문에는 설명 입력 다음의 후보 검색을,
   챗봇 접수 안내에는 요약 확인·접수 절차를 빠뜨리지 않도록 검사한다.
   처음 이용 안내는 관련 문단(입력·검색)을 골라 다른 기능 설명이 길게 섞이지 않게 한다.
3. **모델에 핵심 개념 전달**: required_fact_groups로 실제 문단에 존재하는 개념만 전달한다.
   문서에 없는 사실은 요구하지 않는다. 미흡한 생성 답은 기존 근거 문장으로 대체한다.
4. **선택사항을 명확히 표현**: 연락처의 선택사항을 불분명한 이중 부정으로 설명하지 않도록 검사한다.
   남기지 않아도 됨/필수가 아님 등 의미가 같은 표현은 허용한다.
5. **문서에 없는 질문 구분**: 찾기 번호의 사용 절차와 번호를 어디에 메모·보관할지의 질문을 구분한다.
   승인 자료에 메모 방법은 없어 policy_pending으로 알리고 수령 절차나 임의 앱을 대신 안내하지 않는다.

기존 검색 권한·개인정보·접수 확인·중복 방지·supervisor 검사·GPU 보호는 유지했다.
운영값/승인 문서 원문/DB/API 공통 계약은 바꾸지 않았다.

## 제품 개선과 채점 표현 보완의 구분

기존 실패31/105/146은 불필요한 검색·다음 단계 누락·질문과 무관한 답변 문제였다.
68/138은 모델이 올바른 의미/확인 절차를 말해도 한정된 단어 때문에 자동 오답 처리될 수 있었다.

예:
- `연락처는 필수는 아닙니다` / `필수는 아니에요`는 `남기지 않아도 된다`와 같은 뜻이다.
- `요약 확인 후 접수 버튼을 눌러야 합니다`는 승인 문서의 접수 확인 절차와 맞는다.

이 두 문항의 정답 표현에 해당 경어체 활용·확인 절차 표현을 추가했다. 질문500개/고정50개/출력 형식은 유지했다.
생성기 chat_eval_build.py도 같은 정의로 맞췄다.
연락처가 반드시 필요하다거나 확인 없이 접수됐다는 반대 답은 실패하는 회귀 시험을 추가했다.

기존 실제500문항495/500과 원본 실패 기록은 고치지 않았다.
정답 기준을 바꾼 효과를 모델 성능 개선으로 포장하지 않기 위해 동일 저장 답변의 재채점을 별도 기록했다.

## 검증 결과

| 검증 | 결과 |
|---|---:|
| 기존 실패5개 실제 Mi:dm 재실행(보완 기준) | 5/5 |
| 기본 실제 모델20문항 | 20/20 |
| 위20문항 감독 제안 | 62/62 수락 |
| 추가 회귀10개 실제 실행 원점수 | 9/10 |
| 추가10개 동일 답변의 표현 활용 보완 후 재채점 | 10/10 |
| 가상500문항: 규칙/첫 후보/마지막 후보/악성 제안 | 각각500/500 |
| 전체 unittest | 1326개 실행,18개 skip,실패0 |

추가10개는 새로운 표현과 기존 핵심 질문을 포함하며, 기본/실패 문항과 일부 중복한다.
9번의 실제 답은 `연락처는 남겨도 되지만 필수는 아니에요`로 의미는 정확했다.
추가 실행이나 원답 변경 없이 표현 활용 기준으로 재채점한 것이다.

동일 저장 답변 기준:
- 실패5개 검증의 원점수3/5 → 표현 범위 검토5/5.
- 추가10개 원점수9/10 → 표현 활용 검토10/10.
원점수와 검토점수/문항 정의 해시는 guidance-rubric-review.json에 각각 보존했다.

실제 Mi:dm500개 전체는 이번 수정 후 재실행하지 않았다. 따라서 새 전체 점수를500/500이라고 주장하지 않는다.
가상500×4는 회귀 검사이며 실제 모델 성능 점수와 구분한다.

## 실행 환경과 속도 제한

- Mi:dm 2.0 Mini, supervisor 활성화, Langfuse 끔, 코드 기본 프롬프트, 가상 DB/로컬 HTTP.
- .env/실제 팀 DB/로봇/외부 전송은 사용하지 않았다.
- 마지막 실행 중 Ollama /api/ps의 size_vram=0, 모델 CPU 적재를 확인했다.
  당시 GPU 사용권은 비어 있었고 CPU 적재의 근본 원인은 확정하지 않았다.
- 마지막 기본20문항은203.57초, 응답 중앙8.06초였다. 이전 GPU 결과와 직접 속도 비교하지 않는다.
  GPU 보호를 끄거나 Ollama 서버를 재시작하지 않았다.
- 실제 production 프롬프트/서버 배포 검증은 아니다. 실행별 소스/문항 해시는 JSON meta에 보존한다.

## 증거

- midm-guidance-final.json: 실제 실패5개 최종 재실행.
- midm-live-guidance.json: 최종 기본20문항.
- midm-guidance-novel.json: 추가10개 실제 실행 원점수(9/10).
- guidance-rubric-review.json: 동일 답변 재채점과 원본/문항 해시.
- midm-guidance-before-rubric.json: 표현 보완 이전 점수/답변 원본.
