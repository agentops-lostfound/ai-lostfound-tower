# LF-9 장소 추천·관리 로컬 검증 및 오류 처리

기준 main `59ee0a9`. 운영 DB 전환과 스키마 변경 없이 기존 장소 관리 서비스/API를 보완했다.

## 수정한 동작

- 추가 시 호선·역·장소를 정규화하고 개인정보를 거절한다. `중앙`/`중앙역` 입력을 기존 등록기계의 DB 표기로 연결해 추천에서 보이지 않는 별도 역 기록을 만드는 문제를 막는다.
- 등록기계가 없는 호선/역에는 추가하지 않는다. DB에 두 표기의 기계가 함께 있어 범위가 모호하면 추측하지 않고 담당자 확인을 요청한다. 기존 장소/기계 데이터는 자동으로 고치지 않는다.
- 기계 번호와 목록 위치를 검증하고, 기계의 호선/역 정보가 없으면 정상 빈 목록 대신 오류로 알린다.
- 장소 추가의 불필요한 필드를 실제 API에서도 거절한다. 비정상 본문 검증 응답은 원문을 되돌려주지 않는다. DB 조회/저장 실패는503이며, 저장 결과가 불명확하면 목록 확인 후 같은 내용으로 재시도하도록 안내한다.
- 시연 오류 문구에서 제거된 기계 B를 뺐다. 실제 장소 편집 화면을 새로 만들지는 않았다.

## 검증

- 전체 Python:1,946개, 실패0, 조건부 제외26. PostgreSQL은 로컬 전용 일회용 `lf_support_test`만 사용했다.
- PostgreSQL 센터 통합13개 통과: 동시 중복 추가8회에 같은 장소ID/한 행, 한글 역 접미사/전각 호선 정규화, 다른 역 제외, 사용 횟수 순서/3페이지/빈 목록, 누락/모호한 기계 범위, 기존 접수 API의 place_id 참조를 확인했다.
- 새 API/서비스 경계6개: 비정상 입력, 권한 없는 읽기/추가, 추가 필드/잘못된 페이지, DB 오류 비노출, 연결 없음과 빈 목록 구분, 검증 응답의 원문 비노출.
- 기존 시연 장소 시험과 센터 관리자 인증 시험도 통과했다. 원장·실물 물건의 누락0건이나 운영 권한 확인을 의미하지 않는다.

반환 JSON 형식과5개 단위 offset 계약은 유지한다. 조회 사이 사용 횟수/장소가 바뀌면 offset 목록 순서도 달라질 수 있다. 실제 기계 매핑/운영 데이터/권한은 팀 확인 후 적용한다. 미도착 외부 알림·로봇 명령·운영 DDL은 실행하지 않았다.
