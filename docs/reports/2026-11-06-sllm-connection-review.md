# LF-5 로컬 소형 모델 연결 검토 및 적용

## 결론

기존 구조에서 연결 가능하다. 전면 재작성 없이 설치된 `qwen3-vl:2b-instruct`를 실제 연결했다. 별도 모델 학습·다운로드·외부 유료 API 사용은 하지 않았다. 이 모델은 소형 멀티모달 모델이며 이번 채팅 연결은 텍스트만 사용한다.

## 적용 범위

- `tools/run_chat_widget_demo.py`에 명시적 `--model` 옵션을 추가했다. 기본 실행은 기존처럼 모델 없이 작동한다.
- 실제 구동: `python -m tools.run_chat_widget_demo --port 8112 --model qwen3-vl:2b-instruct`.
- 안내 문서 검색 후 모델이 근거 문단 ID를 선택하며, 프로그램이 ID와 주제·필수 설명을 검증해 원문 문단을 출력한다. 답변 출처를 유지한다.
- 미확정 정책은 모델에 보내지 않는다. 물건 후보는 기존 가상 DB에서만 조회한다. 실제 인증·팀 DB·로봇 연결을 추가하지 않았다.
- 모델 HTTP 응답 제한을 20초로 줄여 위젯 30초 제한 전에 문서 안내로 대체할 여유를 두었다. 이 값은 HTTP 소켓 제한이며 전체 처리 시간의 엄격한 상한은 아니다.
- `/chat/health`의 설정 여부와 실제 응답 `generation_used`를 구분한다. 모델 설치·연결 성공은 health 설정값만으로 보장하지 않는다.

## 검증

- 실제 Ollama API + FastAPI HTTP 경로 + 임시 가상 DB: `python -m tools.check_chat_sllm --model qwen3-vl:2b-instruct`, 10/10 통과.
- 사진·글 입력·수령·개인정보·첫 이용·습득 신고 6건은 `generation_used=true`. 모델 준비 후 해당 실행에서 약 0.23~0.52초. 별도 첫 직접 호출은 약 5.25초. 다른 PC의 속도를 보장하지 않는다.
- 운영시간·보관기간 2건은 `policy_pending`, 모델 미사용. 물건 검색 1건은 가상 DB 후보 반환·예약 없음. 가상 전화번호 입력 1건은 422 차단.
- 회귀 시험: LF-5 791건, 실패 0, 건너뜀 13. 회수 관리 통합 작업 폴더 795건, 실패 0, 건너뜀 14. 실제 PostgreSQL용 설정을 주입하지 않아 해당 시험은 이번에 건너뛰었다.
- 추가 HTTP 모의 시험: 선택 모델 전달, 모델 장애·시간 초과 시 근거 유지, 오류 세부정보 미노출, 미확정 정책·DB 검색·개인정보 질문에서 모델 미호출.
- 실행 중인 `http://127.0.0.1:8112/chat-widget/demo`에서 HTTP 200, 실제 `/chat/questions` 응답에 해당 모델과 `generation_used=true`를 확인했다. GUI 조작 시험은 하지 않았다.

## 남은 범위와 한계

연결 검증은 안내 문단 선택 방식에 대한 것이다. 자유로운 대화·문장 생성 성능을 검증한 것이 아니며, 기존 규칙 기반 의도 분류·검색이 이해하지 못하는 모든 표현을 해결하지 않는다. 자연어 의도 해석, 문서의 의미 기반 검색, 근거를 지키는 답변 재작성은 별도 개선 범위다. 실제 물건 존재·본인 소유·본인인증·예약 승인을 모델 판단으로 대체하지 않는다.

화면 사용법 변경 때문에 담당 외 `web/chat-widget/README.md`도 수정했다. 공유 계약은 변경하지 않았다. GitHub·Jira 갱신과 main 병합은 하지 않았다.

API 형식 참고: [Ollama 공식 Chat API](https://docs.ollama.com/api/chat).
