# LF-5 저장 후 응답 유실 보호 결과

2026-11-11 정연우 / 로컬 `LF-5-jeongyeonwoo-integration-validation`

## 변경

저장 창구가 이미 처리했는데 응답 전에 끊기면 기존에는 ‘접수하지 못했어요’로 단정하고 세션을 지웠다. 그 뒤 다시 접수할 수 있었다.

이제 명시적인 서비스 업무 거절과 완료 불명 장애를 구분한다. 접수·찾기 요청 취소·확인 질문 답변 후속 저장의 예상하지 못한 예외와 불완전 응답은 `intake_uncertain`으로 남긴다. 같은 대화의 재전송·새 접수·취소 문구는 저장 도구를 부르지 않고 기존 안내를 반환한다. 감독은 재계획하지 않고 결과 확인 안내로 끝낸다.

빈 값·공백·잘못된 타입의 접수/찾기/대기 식별자를 성공 번호로 보여 주지 않는다. 업무 거절은 실제 서비스의 RequestError·NotFound·Conflict 타입만 신뢰하고, 이름만 같은 임의 오류는 신뢰하지 않는다.

불명 상태에서는 입력 초안·신분 정보·확인 토큰을 버리고 안전한 안내만 보관한다. 일반 대화 TTL로 자동 삭제하지 않아 만료 직후 같은 요청이 다시 실행되는 경로를 막는다. 위젯은 ‘처리 결과 확인 필요’로 표시하고 재시도/확인 버튼을 만들지 않는다.

## 복구 범위와 한계

현재 창구에 요청 ID 기반의 공통 결과 조회가 없어 자동 성공 판정·결과 복구를 구현하지 않았다. 비슷한 물건을 조회해 성공으로 추정하지 않는다. 사용자는 다른 화면에서도 같은 요청을 다시 보내지 말고, 받은 번호가 있다면 본센터 직원에게 처리 여부를 확인하도록 안내받는다.

이번 보호는 현재 프로세스의 같은 세션 범위다. 재시작·새 세션·다른 화면까지 중복을 막으려면 영속 작업 기록과 창구의 idempotency가 필요하다. 불명 상태의 운영상 확인·해제·보관 정책도 남아 있다. 세션 위조 방지·실제 인증을 이 기능이 대신하지 않는다.

전체 실제 모델500문항, 클라우드 staging, 실제 운영 DB·로봇·브라우저 실기기는 미검증. 데이터는 가상이며 실제 모델은 로컬 코드 프롬프트를 사용했다. 원격 GitHub/Jira·main·팀 서버는 변경하지 않았다.
