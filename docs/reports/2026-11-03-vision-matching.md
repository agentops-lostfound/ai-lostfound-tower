## 요약

물품 특징과 사용자 설명을 비교하는 매칭에 속성 필터와 보류 판단을 추가했다. 저장 특징 기반 평가에서는 초기 정책의 불필요한 보류가 줄었지만, 실제 사진 시험에서는 Qwen의 특징 오류가 매칭으로 이어졌다.

한국어 입력 연결을 위해 직접 특징 추출, 전체 영어 번역 후 코드 추출을 차례로 시험했다. 현재 로컬 통번역 기본값은 OPUS-MT다. 같은 20문장에서 기존 Qwen 텍스트 모델보다 빠르고 조건 보존도 나아졌지만 오역과 부정문 처리 문제가 남아 있다. 한국어 전처리는 실험 기능으로 두고 자동 확정을 제한했다. DeepL API 연결 코드는 추가했으나 키가 없어 실제 API 평가를 수행하지 않았다.

## 1. 매칭 기능 개선

### 이전 상태와 문제

기존 MiniLM은 전체 특징 문장과 영어 설명의 코사인 유사도 순위만 반환했다. 색이나 스티커 유무가 반대여도 문장 전체가 비슷해 점수 차이가 작을 수 있었다. 순위 1위는 물품 확정이나 정답 확률이 아니었다.

### 추가한 동작

```text
구조화된 사용자 조건
 → 코드로 품목·색 비교 및 후보 필터
 → 남은 후보의 자유 특징을 CPU MiniLM으로 비교
 → 속성 점수와 의미 유사도 결합
 → 일치 / 확인 필요 / 일치 없음
```

- 코드 비교: category, colors, sticker_status. 미언급과 unknown은 명확한 불일치로 제외하지 않는다.
- 품목 관계: wallet↔card_wallet을 호환 관계로 비교한다.
- 유사색 관계: navy↔dark blue 등 부분 점수를 설정한다.
- 임베딩 비교: 모양·재질·글자·스티커 세부 정보·파손 등 자유 특징을 비교한다.
- 판정 기준: 최소 점수, 후보 간 점수 차이, 관찰 정보 충족도와 속성별 하한을 확인한다.
- 가중치·관계·기준은 [matching.yaml](../../matching/configs/matching.yaml)에서 조정한다.
- 로봇 동작과 실제 확인 질문 UI는 연결하지 않았다.

### 저장 특징 기반 재평가

실행 그룹 10개, 특징 기록 17개에서 정상 설명 17개·모순 설명 17개를 사용했다. 한국어 설명에 대응하는 영어 조건과 자유 문장은 사람이 작성했다.

| 지표 | 초기 속성 정책 | 개선 정책 |
|---|---:|---:|
| 정상 설명의 목표 후보 확정 | 10/17 | 16/17 |
| 정상 설명 보류 | 7/17 | 1/17 |
| 정상 설명 오선택 | 0/17 | 0/17 |
| 모순 설명 일치 없음 | 17/17 | 17/17 |

품목 관계를 적용해 3건, 유사색의 무조건 보류를 조정해 3건이 확정으로 전환됐다. 남은 보류는 실제 폰을 Qwen이 other로 기록한 경우다.

질문은 Qwen 저장값을 참고한 약한 정답이며 단일 후보·중복 실행이 포함된다. 품목 관계·판정·임베딩 입력을 함께 바꿨으므로 각 조치의 독립 효과나 실제 사용자 정확도를 입증한 결과는 아니다.

근거: [매칭 개선 상세](../../matching/reports/MATCHING_UPDATE.md), [질문별 비교](../../matching/reports/HYBRID_COMPARISON.md).

## 2. vpu.jpg 실제 사진 풀시퀀스

YOLO 검출·크롭 → Qwen 특징 추출 → 통합 JSON 저장을 실행했다.

| 항목 | 결과 |
|---|---|
| 검출·크롭 | 5개 |
| Qwen JSON 저장 | 5개, 처리 실패 0개 |
| YOLO 검출·크롭 시간 | 약 4.1초 |
| 시퀀스 전체 | 약 84.2초 |
| Qwen 실행 | Qwen3-VL-2B-Instruct, RTX 3050, NF4 4-bit |
| 좌표 | 픽셀 좌표 기록. ArUco 미검출로 실측 좌표 없음 |

대상 폰·보조배터리·USB 외에 가장자리 케이스와 배터리 끈도 검출됐다. 처리 성공은 특징의 시각적 정확성을 뜻하지 않는다. USB를 unknown·진초록/갈색으로 읽었고, 보조배터리에 스티커가 있다고 기록하는 오류가 있었다.

사진을 보고 작성한 설명 7개를 사람이 영어 조건으로 변환해 후보 전체와 비교했다.

| 사례 | 결과·관찰 |
|---|---|
| 흰색 아이폰·애플 로고·카메라 두 개 | 폰 선택 |
| 검은 보조배터리·VOVA | 보조배터리 선택 |
| 검정·빨강 USB | 실제 USB가 잘못된 Qwen 색 때문에 제외되고 최종 보류 |
| 보조배터리·스티커 없음 | Qwen 기록과 충돌해 보류 |
| 노란 카드지갑 | 일치 없음 |
| 검은 물건, 추가 정보 없음 | 여러 후보가 동점이라 보류 |
| 가장자리 폰 케이스 | 품목 관찰 부족으로 보류 |

MVP에서는 외형 차이가 명확하고 현재 촬영 조건에서 안정적으로 읽히는 물품을 선정하는 방향을 논의했다. 이는 시연 범위를 제한하는 운영 방안이며 일반 물품 인식 오류를 해결한 것으로 보지 않는다.

## 3. 한국어 입력 전처리 실험

### A. Qwen3-0.6B가 영어 조건 JSON을 직접 생성

별도 CPU 텍스트 모델에 한국어 특징 추출·영어 변환을 한 번에 요청했다. 기존 사진용 Qwen과는 다른 모델이다. JSON 검증, 독립 CLI, 매칭 연결, 실제 프롬프트·출력·기대값·후보 점수를 보는 HTML 데모를 추가했다.

8개 수작업 예문에서 category/colors/sticker_status/확인 필요 여부 전체 일치는 2/8, 변환 중앙값은 약 12.12초였다. 미언급 색·스티커 추가, 부정 오해가 발생했다. 검사 필드가 맞아도 자유 문장에 스티커를 임의 추가하는 사례가 있었다. 자동 확정용으로 채택하지 않았다.

근거: [직접 추출 시험](../../matching/reports/QUERY_PARSER_TRIAL.md).

### B. 전체 영어 번역 후 코드로 조건 추출

```text
한국어 전체 문장
 → 번역 모델 호출 1회
 → 영어 품목·색·스티커 조건을 코드로 추출
 → 번역문 전체를 MiniLM 자유 문장 입력으로 사용
 → 기존 매칭 판정
```

조건 추출용 모델을 다시 호출하지 않는다. 번역문 전체에는 색·품목도 포함되므로 자유 특징만 비교하는 경로와 점수 분포가 달라질 수 있다.

20개 문장을 기존 감사 그룹 10개와 vpu 그룹 1개에 각각 비교했다. 그룹 11개, 특징 기록 22개, 모델별 매칭 비교 220회다. 주 평가 그룹과 기대 대상은 실행 전에 지정했고 다른 그룹은 탐색용으로 기록했다.

| 항목 | Qwen3-0.6B 통번역 | OPUS-MT ko-en |
|---|---:|---:|
| 실행 완료 | 20/20 | 20/20 |
| 품목·색·스티커 조건 전체 일치 | 10/20 | 14/20 |
| 변환 중앙값 | 약 2.52초 | 약 0.51초 |
| 제한 전 정책 상태 | 선택 8·보류 6·일치 없음 6 | 선택 10·보류 8·일치 없음 2 |

두 모델 모두 CPU float32, 2 threads다. 시간은 모델 로딩·다운로드·MiniLM·파일 저장을 제외한다. 직접 추출 8문장 시험과 통번역 20문장 시험은 데이터 구성이 달라 정확도·속도를 동일 조건의 비교로 해석하면 안 된다. 두 통번역 모델끼리는 같은 문장과 규칙을 사용했다.

조건 전체 일치는 번역 정확도가 아니다. 예를 들어 의미가 틀려도 세 속성만 같으면 통과할 수 있다. 선택 건수 증가도 정답률 증가가 아니다. 모든 한국어 실험 경로는 requires_review를 적용해 실제 자동 확정을 막았다.

### 발견한 실패 원인

| 단계 | 실제 관찰 |
|---|---|
| 번역 | 남색→분홍, 보조배터리→side battery, 균열의 금→gold, 구어체 파손 표현 변형 |
| 코드 추출 | 본체·화면 색 구분 부족, side 같은 단어에 의한 스티커 부정 범위 오판 |
| 매칭 | “파손 없는 흰색 아이폰”을 파손된 폰으로 선택하는 제한 전 정책 오류 |

특히 자유 특징의 부정은 번역 API로 바꾸는 것만으로 해결되지 않는다. 현재 임베딩과 가중 평균이 반대 의미를 충분히 구별하지 못할 수 있다.

근거: [20문장 결과 해석](../../matching/reports/TRANSLATION_20_TRIAL.md), [OPUS-MT 비교](../../matching/reports/OPUS_TRANSLATION_COMPARISON.md), [입력 20문장](../../matching/configs/translation_20_cases.json).

## 4. API 번역 검토와 구현 상태

DeepL API 어댑터와 데모·20문장 평가 선택 경로를 구현했다. 사용자 문장만 전송하고 사진·Qwen 후보는 요청에 넣지 않도록 구성했다. 키 누락, HTTP 오류, 응답 형식 검증과 비밀값 미기록을 가짜 응답으로 테스트했다.

사용 가능한 API 키가 없어 실제 API 번역은 실행하지 않았다. DeepL 품질·레이턴시·비용 실측 결과는 없다. Google 번역·Papago의 가입·무료 제공량을 조사했지만 해당 API 어댑터는 아직 구현하지 않았다. 비용 없는 로컬 모델과 무료 웹 번역 수동 비교 방안도 논의했으며, 웹 번역 결과를 실제로 수집한 시험은 하지 않았다.

사용법: [DeepL 설정](../../matching/API_TRANSLATION.md), [전처리·데모 실행](../../matching/QUERY_PARSER.md). 서비스 요금은 별도 최신 확인이 필요한 정보라 이 보고서에 고정하지 않는다.
