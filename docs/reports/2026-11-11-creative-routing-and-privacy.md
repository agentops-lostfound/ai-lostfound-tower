## 실제 모델에서만 재현된 분기 누락

`bfea961`의 실제 모델 전체 실행은 **498/500**, 물리 모델 호출 1,692회·오류0이었다. 규칙만의 실행은 500/500이어서 실제 모델 실행으로 아래 차이를 확인했다.

- 218번: 새 휴대폰으로 보상하는지 물었는데 planner가 후보 검색만 선택해 보상 정책 질문을 답하지 않았다. 실제 보상 약속을 한 것은 아니며, 질문을 검색으로 잘못 분류한 결함이다.

## 거절될 개인정보가 기록 경계에 들어가는 문제

실제 개인정보 대신 저장소 시험용 숫자를 전각으로 바꾼 합성 값을 사용했다. 외부 기록기는 메모리 대역으로 교체했고 Langfuse는 껐다.

- 수정 전: 개인정보 질문이 ValueError로 거절되지만, 그보다 먼저 root observation에 입력 원문이 전달되는 경로를 재현했다. 기존 마스킹 표현식은 이런 Unicode 표기를 모두 처리하지 못하므로 기록 연결이 켜지면 위험할 수 있었다. 외부 전송을 실제로 수행하거나 확인한 것은 아니다.
- 수정 후: `Chatbot.ask`가 질문을 정규화·검증한 뒤에만 기록 문맥을 연다. 동일 시험에서 거절=True, 기록 시작=False, 기록 입력 전달=False를 확인했다.
- 조작된 assistant 이력도 전각 신분번호를 필터링하지 못하고 모델 문맥으로 넘길 수 있었다. assistant 답변을 먼저 정규화한 뒤 개인정보 모양을 검사해 해당 답변을 비운다. 서버 인증·확인 증거로 이력을 신뢰하지 않는 기존 제한은 유지한다.

회귀 시험은 기록기의 호출 여부, 정규화된 이력의 빈 답변, 모델이 잘못된 검색 작업만 제안하는 상황을 검사한다. 최종 전체 Python **1,779개·실패0·제외35**를 통과했다. 질문·개인정보 원문·토큰은 보고서에 저장하지 않았다.
