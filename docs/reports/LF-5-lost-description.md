# LF-5 말·사진 설명 입력 구현 및 RAG 보류

## 범위

분실인 설명을 `description(category·color·shape·mark·visible_text·material)` 및 lost_date/lost_line/lost_station으로 정리하고, 사용자의 수정·확인을 거친 검색 전달용 데이터를 만든다. 기존 claim 생성, 인증, 후보 검색, 예약 또는 로봇 동작은 수행하지 않는다.

| 입력 | 동작 | 실제 확인 범위 |
|---|---|---|
| 글 | 명시한 품목·색상·형태 및 일부 특징을 규칙으로 추출. 복수 품목/색상·부정문은 보류 | 한국어 예시, 부정·모호한 표현, 개인정보 거절, 사용자 수정 시험 |
| 음성 | 기존 speech.KoreanTranscriber → 인식 문장 → 동일 추출 → 사용자 확인 | 모델을 대신한 시험 입력으로 연결·종료·무음 처리 시험. 실녹음 정확도와 모델 캐시는 미검증 |
| 사진 | 로컬 Ollama에 품목·주요 색을 각각 질문. 재질·문자·손상은 추측하지 않음 | 기존 회색 보조배터리 사진1장 실제 실행 → 보조배터리/회색 |

문장 전체를 자유롭게 이해하는 LLM 텍스트 추출기가 아니라 현재 팀 품목과 일부 표현을 지원하는 초기 규칙 기반 구현이다. 인식 실패를 사용자 수정으로 해결할 수 있게 했으며 임의의 특징을 채우지 않는다. 팀 계약의 `모형폰`에 휴대폰 표현을 매핑하고 기존 계약은 변경하지 않았다. 사진에서 여러 물건이라고 응답하면 한 물건 사진을 요청하지만 모델의 복수 물건 판단 정확도는 별도 검증이 필요하다.

LangGraph는 명시 특징 추출 → 분실 날짜·장소 수집 → 사용자 검토 준비의 세 단계로 구성했다. 최종 확인 API는 필수 날짜·호선·역 및 알려진 품목을 요구한다. 확인 결과는 identity_verified=false이며 실제 본인 인증을 대신하지 않는다. 음성·사진 원본은 메모리/임시 파일로만 처리하고 전송 후 저장하지 않는다. 검토 자료는 프로세스 메모리에서 30분, 최대100건이다. 음성 원본 임시 파일은 처리 후 삭제한다.

## 실행

```powershell
python -X utf8 -m pip install -r agents/requirements_support.txt
$env:LF_OLLAMA_MODEL='qwen3-vl:2b-instruct'
python -m uvicorn agents.lost_api:app --host 127.0.0.1 --port 8111
```

브라우저에서 `http://127.0.0.1:8111/input`을 열어 글/사진/녹음 파일 → 설명 정리 → 수정 → 확인을 시험한다. 모델 이름은 현재 PC에 설치한 것을 지정한다. Ollama 연결은 localhost로 고정했다. 다른 분석 서버에 자동 전송하지 않는다.

음성은 `speech/requirements.txt` 설치와 small 모델 캐시 준비 후 LF_STT_ENABLED=1로 명시적으로 켠다. CPU/int8 및 offline=True로 실행하므로 요청 중 모델을 자동 다운로드하지 않는다. 60초 이하16kHz 모노PCM16 WAV만 받는다. 모델·라이브러리가 없으면 503과 글자 입력 안내를 반환한다. 실제 마이크 녹음은 자동 시작하지 않는다.

| API | 내용 |
|---|---|
| GET /input | 설명 입력·수정 시연 화면 |
| GET /health | 사진/음성 연결 설정 상태 및 RAG 보류 상태 |
| POST /descriptions/text | text 및 분실 날짜·호선·역(선택) |
| POST /descriptions/photo | photo: data URL, 분실 날짜·호선·역(선택) |
| POST /descriptions/audio | audio_base64: WAV, 분실 날짜·호선·역(선택) |
| POST /descriptions/{proposal_id}/confirm | confirmed=true, 수정 description과 분실 날짜·호선·역 |

확인 응답의 description/lost_date/lost_line/lost_station을 기존 웹 검색 요청에 연결할 수 있다. 이 변경에서는 기존 분실인 웹의 인증 흐름을 자동 수정하지 않았고, 실제 검색 에이전트 호출과 DB claim 저장은 하지 않았다. 운영 배포에는 세션별 접근 제어·속도 제한·실제 웹 화면과 검색 API 연결이 추가로 필요하다.

## 안내 챗봇 보류 근거

사용자 지시에 따라 문서를 찾았으나 확인 가능한 자료에서 확정된 운영 안내 문서를 찾지 못해 RAG는 구현·활성화하지 않았다.

- Jira LF-5: ‘안내 문서 내용(값)은 팀이 작성(TBD)’.
- GitHub docs/progress/pil2ya-2026-11-03.md: 원본 이미지 삭제·보관 기간·동의 정책 확정 필요.
- web/lost-person-claim.html: 실제 운영기관의 개인정보 처리방침에 따름. 습득자 연락처30일 규칙은 분실인 동의 항목에 적용하지 않는다고 명시.
- architecture.md: RAG·통계는 관제탑과 별개. 해당 아키텍처에 맞춰 별도 API로 구성.
- Jira 통합 검색은 일부 검색원 경고를 반환했으므로 모든 외부 문서의 부재를 단정하지 않는다.

임의의 운영시간·보관기간을 만들거나 모델 지식으로 답하지 않는다. 확정 문서가 제공되면 출처를 붙이는 검색·답변 부분을 별도 연결해야 한다.

## 시험 및 변경 범위

tests/test_lost_input.py:13개 시험(글·음성 연결·사진 어댑터·API·확인·개인정보·보류·LangGraph). 실제 사진 연동 결과는 작업 폴더의 support_live_preview.json에 보관했고 원본 사진이나 그 결과를 Git에 넣지 않았다.

추가 파일은 agents/lost_input.py, lost_photo.py, lost_api.py, requirements_support.txt, web/lost-input/index.html, tests/test_lost_input.py, 이 문서. 공통 계약·기존 관제탑 API는 변경하지 않았다. LF-5 브랜치는 LF-9 구현 커밋을 기반으로 쌓았으며 두 작업은 별도 커밋이다.

최종 저장소 전체 시험: 350개, 실패0, 별도 환경 조건9개 건너뜀. 이 중 일회용 PostgreSQL용5개는 별도 실제 DB 실행에서 모두 통과했다. 입력 화면 경로 응답 시험과 JavaScript 문법 검사를 통과했다. 실제 브라우저 클릭·화면 배치 검증과 실제 녹음 정확도 시험은 수행하지 않았다. 지라 상태를 완료로 바꾸거나 깃허브에 푸시하지 않았다.

## 후속 보완: 키링 특징과 검색 어댑터

- ‘햄스터 키링 달린 검은색 휴대폰’ → category=모형폰, color=검정, mark=햄스터 키링. 키링·열쇠고리와 일부 캐릭터/스티커 표현을 명시 원문으로 보존한다. 모든 자유 문장의 특징을 이해하는 기능은 아니며 부정문은 사용자 확인으로 넘긴다.
- 화면에 특징 수정 칸을 추가하고 결과 위치로 자동 이동한다. 검은색 안의 은색 부분 문자열을 잘못 색상으로 읽던 오류를 수정했다.
- 확인 응답에 matching_query를 추가한다. 위 예시는 category=phone, colors=[black], sticker_status=unknown, free_text=햄스터 키링이다. 키링·흠집만으로 스티커 있음이라고 추론하지 않도록 matcher_part 변환도 보완했다.
- agents/lost_search.py의 preview_candidates는 사용자 확인 후 서버가 제공한 후보를 기존 matching.policy로 비교하는 개발용 연결 함수다. 정책상 제외된 후보를 걸러 최대3개 번호만 반환하고 비공개 특징·점수·좌표는 반환하지 않는다. 자유 특징 유사도는 기존 낱말 겹침 방식이며 의미 임베딩이 아니다.
- 공개 입력 화면에서 실제 DB 후보를 조회하거나 검색을 자동 실행하지 않는다. 실검색 연결에는 기존 웹의 동의/인증 및 서버 후보 공급을 결합해야 한다. 반환·예약 관문은 변경하지 않았다.
- 후속 전체 시험353개, 실패0, 조건부9개 건너뜀. 키링 보존·스티커 구분·확인 전 검색 차단·다른 품목 후보 제외·비공개 특징 비노출을 확인했다.

## 후속: 실제 음성 모델 준비

- speech/requirements.txt를 별도 지원 환경에 설치하고 다국어 small 모델을 로컬 .cache/speech/small에 준비했다. 가중치는 Git에 포함하지 않는다.
- 배포 모델에는 vocabulary.txt가 있어 기존 로더의 vocabulary.json 전용 캐시 검사를 통과하지 못했다. 두 형식을 허용하도록 speech/transcriber.py를 수정하고 다운로드를 유발하지 않는 회귀 시험을 추가했다.
- 실제 CPU/int8 오프라인 모델로 2초 무음 WAV를 처리해 no_speech/빈 문장을 확인했다. 이는 한국어 발음 정확도 시험이 아니다.
- 입력 화면에 사용자 클릭 시 시작하는 녹음 버튼을 추가했다. 마이크 권한을 요청하고 최대60초 뒤 종료하며, 16kHz 모노PCM16 WAV로 변환한다. 사용자가 설명 정리하기를 누르기 전 서버에 전송하지 않는다. 페이지 이탈/녹음 종료 시 마이크 트랙을 해제한다. VS Code 내장 브라우저가 마이크 권한을 막으면 일반 브라우저나 WAV 업로드를 사용해야 한다.
- 로컬 실행 서버에서 LF_STT_ENABLED=1을 켰다. 실제 브라우저 마이크 캡처와 한국어 인식 정확도는 아직 사용자 녹음으로 확인해야 한다.
- 전체 자동 시험354개, 실패0, 조건부9개 건너뜀. 임시 DB를 포함한 이전 검증 결과와 독립적인 음성 준비 단계다.
- 기존 claim 저장은 후보 선택·확인 질문·예약 이후 구조이므로 검색 전 인증 세션 공급이 별도로 필요하다. 공개 입력 화면의 클라이언트 체크값으로 인증을 우회해 실물 후보 목록을 공개하지 않았다. 실검색 연결은 해당 세션 규격 확정 후 진행한다.

## 후속: 문서 검색형 안내 챗봇

후속 사용자 요청에 따라 문서 기반 프로젝트 절차 안내를 구현했다. 운영시간·보관기간의 확정 운영값은 계속 보류한다. 상세는 docs/guidance/README.md, 코퍼스는 docs/guidance/knowledge.json, 실행 코드는 agents/guidance.py다. 기존 입력 화면에서 안내 질문과 출처를 확인할 수 있다. 생성형 LLM/자동 임베딩 방식이 아닌 폐쇄 주제 검색 + 작성된 문서 근거 안내 문단 반환 방식이다. 원본 근거 변경 검사와 물건 검색 분리 시험을 포함해 전체362개 실패0(조건부9개 건너뜀). 재질·글자 직접 수정 칸과 지명/재질 오인식도 보완했다.
