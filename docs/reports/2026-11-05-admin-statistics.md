# LF-9 관리자 접수 통계 화면 — 정연우, 2026-11-05

## 구현

회수 관리 화면 아래에 읽기 전용 접수 통계를 연결했다. ‘오늘 등록기계 A에 들어온 USB 몇 개?’를 입력하면 건수·날짜·등록기계·품목·조회 시각과 실행 SQL·매개변수를 확인할 수 있다. 자주 쓸 예시 3개와 실제 0건 표시를 제공한다.

기존 PostgreSQL 질문 해석기와 응답 구조를 재사용하고, 별도의 SQLite `demo_stats_item` 뷰를 조회한다. SQL은 제한된 템플릿이며 사용자 SQL을 실행하지 않는다. 기존 파서에서 해석되지 않은 색상·역·브랜드 조건을 조용히 무시할 수 있어, 남은 미해석 조건은 거절하도록 보완했다. 미래 날짜도 거절한다.

접수 시각은 UTC 마이크로초 정수로 저장하고 한국 시간 하루 범위를 변환해 집계한다. 시작 포함·다음 날 시작 제외이며 마이크로초 경계를 유지한다. 기존 가상 물건의 접수 시각 누락은 기능 최초 실행 시각으로 한 번 채우고, 재시작 시 보존한다. 회수·도착 상태·이력·시연 버전은 변경하지 않는다. 새 가상 데이터를 초기화하면 접수 시각도 새로 생성한다.

조회 전용 거래에 SQLite authorizer를 더해 통계 뷰를 통한 공개 집계 열만 허용한다. 기본 물건 표 직접 조회·색상 열·시연 버전·상태 이력·쓰기·뷰 삭제·PRAGMA 접근을 거절한다. 통계 요청은 현재 시연 버전을 검사한다. 질문을 고치거나 데이터 버전이 바뀌면 예전 숫자를 숨기며, 지원하지 않는 질문은 회수 기능을 잠그지 않고 안내한다. 통신·저장소 실패는 기존의 최신 데이터 확인 절차를 따른다.

## 검증

- 신규 Python 9개: SQL 조회 1건, 상태 변경 후 접수 건수 유지, 한국 자정 전후와 마이크로초 경계, 미지원 조건 거절, 개인정보·SQL 차단, 뷰 전용 권한, 재시작 보존, API·이전 버전 거절, 전각 입력 정규화.
- 전체 Python **522개 실행, 실패 0개·환경 조건 14개 생략**. 이번 실행은 실제 PostgreSQL 미연결이다.
- 신규 통계 화면 Node 4개: 0건·SQL 텍스트 출력, 실패한 질문의 이전 결과 숨김, 질문 수정/초기화 무효화, 작업 중/오래된 상태 조회 차단. 기존 회수·자동완성과 합계 **14개 통과**. JavaScript 문법 검사 통과.
- 실행 중인 실제 로컬 API: 오늘 A USB **1건**, 오늘 전체 **6건**, 어제 전체 **0건**, 파란 USB 조건 **422** 확인. 조회 전후 회수·도착·알림·이력과 데이터 스냅샷 동일함을 확인했다.
- PC의 사용자 입력과 겹쳐 이번 새 통계 패널의 수동 화면 조작 검증은 중단했다. UI 동작은 Node 기반 자동 회귀로 검증했다.
