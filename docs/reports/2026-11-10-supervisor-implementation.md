# LF-5 혼합 구조 1순위 구현 보고 (2026-11-10)

## 결과

팀 main fd8d1cb 기준, 로컬 브랜치 LF-5-jeongyeonwoo-supervisor-validation에서
감독의 모델 제안과 실행 검사를 분리했다. production 활성화·외부 게시·main 병합은 하지 않았다.

1. LLM supervisor는 action/step/agent만 제안한다. 허용 행동은 run_step/ask_user/add_step/replan/finish.
2. 코드 정책이 현재 업무 상태에서 허용할 후보를 만들고, 독립 검사기가 출력 형식과 후보 일치를 검사한다.
3. 감독은 독립적인 문서/검색의 처리 순서를 바꿀 수 있다. 미완료 필수 단계를 버리고 정리하는 것은 거절한다.
4. 접수/직원 분석 경로는 서버의 기존 시작·권한 조건 없이는 열리지 않는다. 감독 제안은 저장 확인이 아니다.
5. 결과 종류 수를 호출 횟수로 착각하던 상한을 실제 dispatch 횟수로 바꿨다. 한 요청에서 업무 일꾼 최대 6회.
6. 모델 제안/검사 결과/이유/실제 선택을 supervisor trace와 API supervisor_checks에 남긴다.
7. 모델 장애·구버전 출력·악성 제안은 코드 후보로 대체한다. 감독 하위 generation trace도 임의 문자열을 버린다.

## 검증

- 새 감독 검사 12개 통과: 잘못된 JSON, bool/float 번호, 조기 종료, 완료 단계 재호출, 권한 없는 접수/관제,
  단계 상한, 사용자 대기, 추가/재계획 제한, 장애 대체, 로그 민감값, 그래프 순서 변경 등.
- 기존 프롬프트 검사 22개 통과. 예전 choice JSON으로 필수 안내를 생략하는 기대값은 새 안전 계약에 맞춰 수정했다.
- 챗봇 시험 묶음 246개 실행, 6개 skip, 실패 0 (추가 trace 시험 전 중간 검증).
- 최종 전체 unittest 1,313개 실행, 18개 skip, 실패 0 (실제 성공 실행 1,295개).
- Windows 첫 전체 실행에서 기존 가상 키보드 Node 출력의 cp949 디코딩 오류 1건 발생.
  제품 코드는 바꾸지 않고 PYTHONUTF8=1로 다시 실행해 통과했다.
- 최종 가상 500문항의 규칙/첫 후보/마지막 후보/악성 감독 대역은 각각 500/500, 총 2,000문항 실행에서 실패 0.
  결과는 `2026-11-10-supervisor-check.json`에 별도 보존한다.
  이는 Mi:dm 실측 점수가 아니며 기존 공식 채점표/엑셀을 덮어쓰지 않는다.

## 아직 하지 않은 것

- 이 PC의 Ollama에는 midm-2.0-mini가 없어 실제 Mi:dm 시험은 미실행. 설치 모델 이름만 읽었으며 임의 교체·설치는 하지 않았다.
- Langfuse production 프롬프트·설정·실행 서버를 변경하지 않았다. 기존 supervisor use_llm 기본 꺼짐 유지.
- 구버전 production 프롬프트는 choice를 내므로 새 계약을 쓰려면 staging 평가 후 함께 전환해야 한다.
- 단계 추가/재계획은 기존 정책이 허용한 업무만 지원한다. 모델이 임의의 새 작업을 작성하는 기능은 없다.
- 접수 초안 버전과 확인 버튼 결합, 재시작 복구, 실제 인증/동의, 실제 DB 운영 adapter는 별도 후속이다.
- 현재 실측은 대역으로 구조·기능 회귀를 확인한 결과다. 실물 로봇·팀 DB 종단 완료나 실제 언어모델 정확도를 보장하지 않는다.
