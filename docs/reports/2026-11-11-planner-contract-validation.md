# LF-5 Planner 구조화 읽기 지시 검증

## 최종 동작

Planner는 v2의 일꾼·읽기 작업·입력 참조 조합을 제안하고, 코드가 조합·개수·필수 업무·입력 범위를 검사한다.
SQL·임의 지시문·인증·접수·저장·직원 관제는 이 계획의 허용 작업이 아니다.
검색을 추가하거나 제거한 뒤에는 최종 계획에 맞게 질문 전체/검색 부분/안내 부분을 확정한다.
그래프의 실제 일꾼 입력에 연결했으며, 단계 경계에서도 다시 검사한다. 외부 화면은 기존 한국어 계획 문장을 사용한다.

기존 프롬프트의 일꾼 목록은 제한적으로 변환하고 `bounded_legacy_v1`으로 기록한다. v2 성공과 구분한다.
생성 trace는 허용 필드나 거절 코드만 기록한다. 모델의 알 수 없는 원문 필드는 버린다.
세부 계약은 `docs/design/planner_instruction_contract.md`다. 실제 업무 저장·인증 권한은 별도 계약이다.

## 검증

- 계약/그래프 집중 시험 **10개 통과**. 원본 7문항의 복합·단일 입력 범위 회귀를 포함한다.
- 전체 Python **1,723개 검사, 실패 0, 제외 35개**, 57.893초. 로그 `identity-evidence-work/planner-unit-02.log`.
- 최종 규칙 **628/628**, JSON/CSV 50개 오류 0. 무결성 검사 당시 실행 중이던 대역 결과 1개는 partial_run으로 구분했다. 원본 `planner-rules-20261111-02.json`.
- 기존 프롬프트 설정·단계 동작 시험 **22개 통과**. 클라우드/Ollama 대역 시험이다.
- 기존 정답·배점·데이터 분할·엑셀 점수는 수정하지 않았다.

### 실제 planner 모델 출력에서 찾은 중복

`ffed307`의 실제 전체 평가 01회는 초반 중복 일꾼 제안이 반복돼 **18문항까지 18개 통과로 중단·보존**했다.
`planner-midm-500-20261111-01.json`은 state=stopped이며 **500문항 완주 기록이 아니다**.

단계 객체 각각의 enum에 더해, 최상위 스키마를 완성된 유효 계획 3개 중 하나로 제한했다.
모델이 같은 안내 일꾼을 두 번 조합할 수 없도록 생성 범위를 좁혔다. 코드의 중복 거절과 규칙 대체는 유지했다.
