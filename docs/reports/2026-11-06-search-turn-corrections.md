# LF-5 색상 부정·정정과 추가 특징 대화 검증

## 제보와 원인

`휴대폰 잃어버렸다 → 검정색 아니다 → 원숭이 키링 달렸다`에서 색상 부정 이후 검색 품목을 잃어버리고, 추가 특징을 습득 신고로 잘못 분류했다. 단순 문장 분류만으로는 색상 정정과 부속품 설명을 안전하게 처리하기 어려워 별도 검색 대화 처리 `agents/chat_search_turns.py`를 추가했다.

## 보완

- 최근 사용자 질문과 확인된 폼 조건에서 품목·색상·색상 확인 필요 상태를 복원한다.
- ‘검정색 아니다’는 재검색하지 않고 실제 색상을 확인한다. 제외 색상 SQL 검색은 구현하지 않았으며 다른 색상이나 색상 없는 검색으로 임의 확대하지 않는다.
- ‘검정 아니고 흰색’처럼 명확한 정정은 검증된 표준 품목·색상으로만 조회한다. 복수 색상·이중 부정은 확인을 요청한다.
- 키링·스티커·케이스·재질 등의 추가 설명은 현재 물건의 특징으로 안내한다. 원숭이 키링을 습득 신고로 보내지 않는다. 상세 특징 검색은 아직 지원하지 않는다고 명시하며 조회·일치 판정을 하지 않는다.
- 부속품 색상은 물건 색상으로 자동 적용하지 않는다. 예를 들어 검정 휴대폰에 빨간 키링을 추가 설명한 뒤 재검색해도 휴대폰을 빨강으로 바꾸지 않는다.
- 뒤이어 실제 물건 색상을 주면 원래 품목과 분실 날짜·호선·역을 유지해 검색한다. 새로운 안내 주제나 습득 신고로 전환하면 이전 검색 대상을 되살리지 않는다.
- 공유 검색 계약·SQL·인증 권한은 변경하지 않았다. 정정 후에도 실제 DB는 서버의 인증 확인이 없으면 조회하지 않는다.

## 검증

- 회귀 시험 9건: 제보 대화, 특징 이후 색상 정정, 명확한 긍정 정정, 부정 후 재시도 정지, 부속품 색상 분리, 장소·날짜 유지, 안내/습득 신고 전환, 폼 조건 유지, 실제 DB 인증 제한.
- 기존 78개에 28개 대화 턴을 추가해 실제 `qwen3-vl:2b-instruct`+임시 가상 DB 시뮬레이션 106/106 통과. 상태뿐 아니라 물건 종류·색상·검색 미실행·필수 답변 문구·출처를 검사했다. 신규 주요 답변도 읽어 검토했다.
- 통합 Python 전체 838건 실패 0·건너뜀 14. LF-5 전체 833건 실패 0·건너뜀 13. 실제 PostgreSQL 설정이 없어 해당 환경 의존 시험은 실행하지 않았다.
- 두 실행 서버 8111·8112를 재시작했다. 각 서버에서 인사→휴대폰→검정 부정→원숭이 키링→흰색 정정 5턴을 실제 HTTP로 요청해 답변·상태·검색 조건이 검증 기록과 일치함을 확인했다.
- 전체 질문과 실제 응답: `2026-11-06-chat-search-turn-transcript.md`.
