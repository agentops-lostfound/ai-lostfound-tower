# LF-5 챗봇 레드팀 점검 및 보완 보고

점검 대상: `ef359b5`의 로컬 설명 입력·RAG·검색·음성 기능. 실제 이용자 정보와 팀 DB는 사용하지 않았다. 공격 입력에는 합성 데이터만 사용했고 반복 요청 시험은 독립 시험용 앱에서 진행했다.

## 결론

로컬 API의 호스트·출처 검증, 요청 크기·횟수 제한, 숨은 문자 개인정보 검사, 안내 자료의 답변 변조 탐지가 부족함을 재현하고 수정했다. 인증 토큰의 그래프 상태 포함 등 조건부 위험도 보강했다. 이번 시험에서 실제 인증 우회, SQL 실행 조작, HTML 실행, 로봇 동작이나 반환 승인으로 이어지는 공격은 확인되지 않았다. 모든 공격에 대한 안전성을 보증하는 결과는 아니다.

## 재현·수정한 주요 문제

| 항목 | 수정 전 증거 | 조치 | 수정 후 결과 |
|---|---|---|---|
| 임의 호스트·출처 허용 | 합성 외부 Host와 Origin을 붙인 HTTP 요청이 각각 200 | 루프백 호스트 허용 목록, 동일 출처 검사, 중복 중요 헤더 거절, 위조 forwarded 헤더 미사용 | 실행 서버에서 Host 400, Origin 403 |
| 요청 자원 제한 부족 | 정상 질문에 20KB 무관 필드를 더해도 200. 독립 앱에 짧은 요청 35회가 모두 200 | 경로별 본문 한도, 본문 수신 시간 제한, 동시 요청 4개, 요청 횟수 제한 | 과대 질문 413, 한도 초과 반복 429. 분할 전송으로 크기 우회 불가 |
| 숨은 문자 개인정보 검사 우회 | 숨은 문자를 삽입한 합성 전화번호가 입력 검사와 검색 API를 통과 | NFKC, 제어·방향·숨은 문자 정리, 유사 대시와 숫자 사이 구분자 검사. 검색·설명·음성에 공통 적용 | 실행 서버에서 422. DB와 모델 호출 전에 거절 |
| 안내 답변 변조 미탐지 | 원문 근거를 그대로 둔 채 임시 안내 JSON의 답변을 바꾸면 오염 답변이 채택됨 | 검토된 안내 JSON 전체 내용의 SHA-256 대조 | 답변·출처 URL·주제 변경 시 로딩 거절 |

Host·Origin 시험은 요청 처리 경계의 검증이다. 실제 외부 사이트의 브라우저에서 CORS를 우회해 데이터를 탈취한 시험은 아니다. 안내 JSON 변조는 해당 파일을 바꿀 권한이 있는 상황을 가정했다. 코드와 해시까지 함께 변경하는 공격자를 막는 장치는 아니다.

## 설계 점검으로 함께 보완한 부분

| 항목 | 보완 내용 | 검증 범위 |
|---|---|---|
| 인증 토큰 기록 가능성 | 토큰을 LangGraph 상태에서 제거하고 요청별 비공개 문맥으로 전달. 이 흐름의 LangSmith 추적도 명시적으로 비활성화 | 그래프 입력에 토큰 없음, 인증 검증기에는 전달됨, 종료 후 문맥 해제. 실제 외부 유출을 실행하거나 관찰한 것은 아님 |
| 오류 응답의 입력 반사 | JSON·요청 검증 오류에서 거절한 원문을 반환하지 않음 | 비정상 JSON과 합성 비밀 문자열이 포함된 잘못된 자료형 시험 |
| 복잡한 JSON·중복 필드 | 깊은 중첩, 과도한 항목, 중복 키, NaN·무한대 수치 거절 | 작은 본문 안에 깊은 배열을 넣어도 500 대신 422 |
| 모델 HTTP 경계 | 고정 루프백 주소만 사용. 환경 프록시·HTTP 리다이렉트 비활성화. 응답 32KiB 한도 | 리다이렉트와 응답 폭탄 모의 시험. 실제 외부 주소 호출 없음 |
| LLM 응답 검증 | 예상 필드 외 내용, 과대 응답, 잘못된 문단 번호·중복·필수 주제 누락은 문서 답변으로 대체 | 합성 모델 응답 변형과 실행 서버의 지시문 우회 질문 |
| 음성 컨테이너·처리 시간 | WAV 길이·프레임 검증, 추가 데이터 거절, 메타데이터 제거 후 PCM 재생성. 실제 STT를 별도 프로세스에서 실행하고 75초 제한 | 손상·61초·추가 데이터·JUNK 메타데이터 시험. 시간 초과 모의 시험 및 실제 무음 파일 경로 |
| 브라우저 및 로그 | 외부·인라인 스크립트를 제한하는 CSP, 캐시 금지, nosniff, referrer 차단. 실행 도구의 프록시 헤더 신뢰와 접근 로그 비활성화 | 정상 UI 동작 및 HTML 삽입 문자열이 글자로만 표시됨을 확인 |

## 적용한 요청 한도

- 질문·일반 API: 본문 8KiB. 설명 입력·확인은 16KiB.
- 사진: JSON 본문 7,100,000바이트. 기존 사진 자체의 5MiB 한도도 유지한다.
- 음성: JSON 본문 2,600,000바이트. 16kHz 모노 PCM16, 최대 60초만 처리한다.
- 본문 수신 최대 15초. 처리 중 POST 요청은 최대 4개.
- 클라이언트 주소별 60초당 일반 요청 30회, 사진·음성 요청 6회. 전체 POST는 60초당 120회.
- 제한 상태에서 429와 재시도 안내를 반환한다. IP와 시각의 일시적 집계만 보유하고 질문 원문을 집계에 저장하지 않는다.

이 한도는 로컬 단일 프로세스 시연 기준이다. `tools/run_lost_assistant.py`는 루프백으로만 실행하고 프록시 헤더를 신뢰하지 않는다. 다중 서버·공개 서비스의 분산 속도 제한을 구현한 것은 아니다.

## 검증 결과

- 신규 공격 회귀 시험: `tests/test_chat_redteam.py` 33개 통과. 일부 시험은 여러 변형 입력을 하위 사례로 검사한다. 33개를 독립 침투 성공·실패 건수로 해석하지 않는다.
- 전체 Python 시험: **423개 실행, 실패 0개, 환경 조건으로 9개 생략**.
- 자동완성 Node 시험: **4개 통과**.
- 기존 안내 질문 회귀: **62/62 통과**. 작성한 질문 기준의 상태·근거 검사이며 전체 답변 의미 정확도를 보증하지 않는다.
- 실제 실행 서버: 외부 Host 400, 외부 Origin 403, 과대 질문 413, 숨은 문자 개인정보 422 확인. 정상 RAG와 검색은 200으로 유지했다.
- 실제 로컬 모델: 사진 이용 방법 답변에서 `generation_used=true`. 수령 절차 질문에 승인 강요 지시를 붙여도 근거 문단만 출력하고 승인·예약 동작은 하지 않았다.
- 실제 별도 STT 프로세스: 무음 파일은 약 1.84초 후 422 재입력 안내. 실제 마이크·사람의 한국어 발화 정확도를 새로 검증하지는 않았다.
- 실제 브라우저: `<img ... onerror=...>` 입력이 텍스트로만 표시됨. 채팅 안의 삽입된 img/script/onerror 요소 0개, 경고창 없음, 브라우저 오류 로그 없음.

```powershell
python -m unittest discover -s tests -p test_chat_redteam.py -v
python -m unittest discover -s tests
node --test tests/test_guidance_suggestions.cjs
```

## 남은 경계

1. 실제 팀 DB용 인증·필수 동의 세션 연결은 아직 없다. 연결 전 실제 후보 조회는 닫힌 상태다. 단순 `id_verified`, `consent`, `database_mode` 본문 값이나 위조 토큰으로 열리지 않음을 시험했다.
2. 개인정보 검사는 흔한 형식과 문자 우회를 줄이는 검사다. 이름·주소·모든 언어의 숫자 표기나 임의 암호화를 완벽히 찾아내는 DLP가 아니다. 질문의 대화 문맥이나 정식 보유 정책도 이번 범위에서 새로 만들지 않았다.
3. 운영시간·보관기간의 미확정 값은 계속 보류한다. 문서 발췌형 RAG의 답변 범위도 유지한다. 안내 자료를 바꿀 때는 근거·답변·출처를 함께 검토하고 코드의 승인 해시도 갱신해야 한다.
4. 이번 검증은 로컬 앱의 정해진 공격 경계에 대한 회귀·실행 시험이다. 의존성 전체 CVE 감사, 인터넷 공개 환경 침투, 실제 인증 서비스 침투, 실제 개인정보·팀 DB 조회는 수행하지 않았다.

## 변경 범위

LF-5의 HTTP·RAG·음성·입력 코드를 보완하고 `agents/support_security.py`, `agents/local_model.py`, `agents/chat_speech_worker.py`, 공격 회귀 시험을 추가했다. 기존 기능 시험은 실제 루프백 주소를 사용하도록 조정했다. 공통 특징 계약·팀 DB 스키마·로봇 실행 흐름은 변경하지 않았다.
