# LF-5 확인 요청의 초안·세션 연결 구현 결과

2026-11-11 정연우 / 로컬 `LF-5-jeongyeonwoo-integration-validation`

## 해결한 문제

기존에는 요약3 뒤에 내용4로 바뀌어도 늦은 ‘접수할게요’가 내용4를 저장할 수 있었다.
확인 요청에 사용자가 본 버전이 없었기 때문이다. 이번에는 분실 접수·습득 신고·찾기 요청 취소 모두 확인 시 초안 버전과 세션별 무작위 토큰을 검사한다.

- 요약이 바뀌면 토큰도 바뀐다. 이전 초안·다른 세션·토큰 누락·만료는 저장하지 않는다.
- 단순 확인 문구만으로는 저장할 수 없다. 현재 요약의 버튼을 다시 안내한다.
- 같은 성공 요청의 재전송·동시 요청은 한 번만 저장하고 기존 결과를 반환한다.
- 위젯은 각 요약의 확인 값을 복사해 해당 버튼과 실패 재시도에 유지한다. 값 없는 구형 버튼은 비활성화한다.
- HTTP의 confirm action을 엄격히 검증한다. 일반 JSON과 NDJSON 최종 응답 모두 확인 값을 전달한다.
- 토큰은 그래프·모델·trace 밖의 ContextVar와 엔진 메모리로만 처리한다. 그래프 입출력에서 토큰 비노출을 검사했다.

## 시험 호출부와 기존 창 시험 보완

기존 시험과 평가 실행기는 확인 문구만 보내던 방식을 실제 화면처럼 확인 값을 함께 보내도록 옮겼다.
누락·공격 시험은 도우미를 사용하지 않고 실제 엔진/HTTP를 직접 호출한다. 검사 거부권을 완화하지 않았다.

별도 창 표시 시험4개는 수정 전 HEAD의 위젯으로도 같은 실패를 재현했다(11/15 통과).
가짜 타이머 실행 때 시계를 전진시키고, 완료 표시180ms와 비동기 렌더를 기다리도록 시험을 보완했다.
같은100%를 두 번 그리는 동작은 한 표시로 취급하되 숫자 건너뛰기 금지 검사는 유지했다. 제품 애니메이션은 바꾸지 않았다.

## 한계와 다음 작업

- 확인 토큰은 본인 인증·동의·접근 권한을 대신하지 않는다. session_id 위조 방지는 별도 미완료다.
- 현재 한 번 저장 보장은 동일 프로세스·세션 기억이 남은 동안이다. 재시작·새 대화까지 보장하려면 영속 idempotency 저장소가 필요하다.
- 창구가 저장한 후 응답 전에 실패하면 해당 확인 재전송은 다시 쓰지 않지만, 성공 결과를 복구하지 못한다. 현재 안내의 완료 불명 표현과 조회·복구 계약 보완이 필요하다.
- 클라우드 staging·실제 인증/운영 DB·로봇·브라우저 실기기는 미검증. 실제 모델 시험은 가상 데이터와 로컬 코드 프롬프트다.
- 로컬 구현·커밋만 완료했다. GitHub/Jira 후속 게시·main 병합·팀 서버 적용은 하지 않았다.

다음 우선순위는 저장 완료 여부 불명 상태의 안내·복구, 이후 세션 무결성과 영속 중복 방지다.
