# 정연우 후속 개선 일괄 반영·로컬 프로젝트 적용

## 기준

팀 main `3b68761`까지 반영했다. 이전 #61·#76·#64의 기능을 팀이 통합한 사실과 역할 인수인계를 보존하고, 그 이후 사용자 지시로 진행한 개선만 후속 초안 PR로 제출한다. main 병합이나 강제 push는 하지 않는다.

## 이후 추가한 내용

- 위젯의 잘못된 메시지 삭제, 재시도 맥락 변경, 미전송 초안 손실, 응답 무기한 대기, 긴 원문 절단, 닫힌 창의 포커스 이동, 비정상 응답 후 전송 잠금을 보완했다.
- 대기 중 대화 삭제·브라우저 요청 취소와 늦은 응답 격리, 연결 실패 후 재열기 복구를 추가했다. 위젯 회귀 시험은 13개다.
- 촬영 장면과 접수 번호의 내부 검사 연결을 준비했다. 명시적인 일대일 대응·해시·세션·시각·만료·선택 후보 재고 재확인을 검사하며 공개 응답에는 ID를 포함하지 않는다. 팀 공통 계약 확정이나 실제 물품 정체/소유권 보장을 뜻하지 않는다.
- 글·합성 사진·합성 음성의 확인→검색과 동일 임시 PostgreSQL의 HTTP 검색·촬영 연결·회수·도착·통계를 이어 검사했다. 모델/STT/인증은 시험용 대체 객체를 명시 사용했다.
- 실제 팀 DB·로봇을 켜지 않고 위젯을 확인할 수 있는 `python -m tools.run_chat_widget_demo`를 추가했다. 별도 가상 SQLite와 승인 문서만 사용한다. Host·Origin·요청 제한을 유지하며, 위젯 생성 스타일을 위해 미리보기 HTML의 CSS만 허용한다. 공유 보안 설정과 스크립트 정책은 변경하지 않았다.
- 팀 관리자 키 시험 서버의 종료 시 소켓 미종료 경고를 정리했다. 인증 처리 자체는 변경하지 않았다.

## 로컬 적용

- 설명 입력: http://127.0.0.1:8111/input
- 회수 관리: http://127.0.0.1:8110/collection-desk
- 새 위젯 미리보기: http://127.0.0.1:8112/chat-widget/demo

세 서버를 루프백에서 재시작했고 입력 화면 HTTP 200, 위젯 health ready=true·demo_sqlite, 최신 삭제/재시도 코드 제공을 확인했다. 회수 시연 물건 6개·회수 묶음 2개의 재시작 전후 대시보드가 동일함을 확인했다. 실제 팀 DB·로봇·LAN/방화벽 설정은 변경하지 않았다.

## 검증 범위

최신 팀 main 반영 후 통합 Python 784개 실패 0·환경 조건 1개 생략, 화면 Node 38개 통과를 확인했다. LF-5 작업 브랜치 전체는 780개 실패 0·환경 조건 13개 생략이다. PostgreSQL 검증은 직접 만든 임시 컨테이너만 사용하고 정리했다.

촬영 연결은 내부 검사이며 현재 위젯·공개 HTTP에 연결하지 않는다. 실제 모델 정확도·실제 인증·운영 DB·예약·반환·로봇·실제 브라우저/모바일/스크린리더 검증은 대기다. 현재 통과한 합성 시험과 서버 응답 검증을 실제 운영 환경의 무오류 보장으로 해석하지 않는다.
