# LF-5 PostgreSQL 인증 종단 시험 준비

운영 DB를 변경하지 않고, 준비된 인증 원본·필수 동의·세션 계약을 네이티브 PostgreSQL에서 확인할 선택 시험을 추가했다.

## 변경

- `tests/test_chat_identity_postgres.py`: 검토용 원본 DDL을 UUID 시험 스키마로 옮겨 실행하는 9개 시나리오.
- 지정 연결과 실제 연결의 DB 이름을 각각 확인해 `lf_chat_access_test` 이외에는 스키마를 만들지 않는다.
- 원본 DDL과 고정 SQL의 이름 공간만 시험용으로 변경한다. 인증 제공자나 정책 기본 승인 행을 운영 데이터로 추가하지 않는다.
- 검증 대상: 인증 저장/세션 발급, 시연 인증 차단, 동의 거절, 원본 철회, 제공자/정책 변경, 동시 단일 증거 소비, 중복 원본 불변, 외래 키, 읽기 전용 거래.
- `docs/design/identity_evidence.md`와 DB 연결 계약에 시험 방법과 제한을 반영했다.

## 결과와 한계

- DB 대상 보호 시험 **2개 통과**: 다른 DB 이름은 연결 전에 차단하며, 실제 접속 DB가 다르면 DDL 전에 차단한다. 모의 연결로 확인했다.
- 네이티브 PostgreSQL 시험 **9개 제외**: `LF_CHAT_ACCESS_TEST_DSN`이 없다. SQL·드라이버·잠금이 실제 PostgreSQL에서 통과했다고 주장하지 않는다.
- 전체 Python: **1,713개 검사, 실패 0, 제외 35개**, 59.427초. 이전 제외 26개에 위 네이티브 9개가 추가됐다. 원본 로그 `identity-evidence-work/latest-team-unit-03.log`.
- 추적 Python 소스 416개 AST 구문 검사 오류 0. 실행/의존성 시험과 구분한다. 원본 `latest-team-python-syntax-20261111-01.json`.

명시적으로 준비한 폐기용 PostgreSQL이 있을 때만 기존 환경 변수 이름으로 선택 실행한다. `.env` 파일은 읽지 않으며, 값과 연결 정보를 로그에 남기지 않는다.
현재 운영 활성화·실제 본인인증 수집기·토큰 전달·네이티브 DB 시험은 여전히 미완료다.
