# 11/4 최종 개발 기준과 통합 현황

이 문서는 같은 날짜의 이전 보고서와 인수인계에 기록된 기본값을 갱신한다. 상세 실험의 과거 수치는 덮어쓰지 않는다.

## 채택한 기본값

- YOLO26m (`models/yolo26m.pt`), confidence .25, 입력640. 로컬에서는 CPU 추론.
- 나무색 책상/트레이 배경. 종이 배경 대비 개선을 관찰했지만 통제된 배경 단독 실험은 아니다.
- Qwen3-VL-2B-Instruct, NF4 4bit, GPU 격리 프로세스. 최대 입력 변512.
- 스티커 상태와 목록만 모순되면 unknown/빈목록으로 제외하고 해당 스티커 자유 설명도 제거한다. 나머지 필드 검증은 유지한다. 경고·원문은 로컬 로그에 보존한다.
- ArUco DICT_4X4_50, ID0 왼쪽 위·ID1 오른쪽 아래, 마커14mm. 마주 보는 꼭짓점 간격 X324/Y150mm. ID0 물리 왼쪽 위 원점, +X 오른쪽/+Y 아래.
- 카메라 계획 높이 작업대 위400mm. 로봇 접근 Z280mm는 변경 가능한 제안이며 아직 로봇 제어에 적용하지 않았다.

새 PC에는 가중치가 포함되지 않는다. 현재 YoloDetector의 자동 다운로드는 n에만 한정되므로 m은 공식 가중치를 먼저 준비해야 한다. 예를 들어 저장소 루트에서 비전 환경으로 `python -c "from ultralytics import YOLO; YOLO('models/yolo26m.pt')"`를 실행하면 공식 자산을 다운로드한다. 네트워크 접근이 필요하며 모델은 Git 제외다.

## 실행 완료와 정확도는 구분

Downloads/A 48장, 기존 n/.25/640 배치: 결과를 하나 이상 낸 사진29장, 검출0개19장, 총43박스. 박스43개는 Qwen·Adapter 처리 완료, mm 전달39개, other/unknown4개 차단. 스티커 모순2개는 정보 제외 후 진행. 총791.8초. 이29장은 모든 실물을 검출한 사진 수가 아니다. 독립 정답 라벨이 없어 검출률·정답률을 산출하지 않았다.

미검출5장을 n/s/m/l/x로 검사했다. 큰 모델도 종이 전체를 laptop/refrigerator로 검출하고 USB를 누락했다. l/x를 포함해 모델 크기가 커질수록 일관되게 개선된 결과는 아니다. 첫 사진을 제외한4장 CPU predict 평균은 n18.4/s31.8/m73.2/l95.3/x208.0ms. 모델 로드·다운로드·결과 이미지 저장은 제외했고 샘플4개뿐이다.

최신 책상 사진 WIN_20261104_17_41_52_Pro.jpg에서는 n이 USB1개, m이 지갑·보조배터리·USB3개 박스를 잡았다. m 클래스는 모두 cell phone이지만 원본 bbox/크롭을 사용한다. m의3박스를 재사용해 Qwen을 실행한 결과:

| 관찰 물품 | Qwen category | 작업대 중심 mm | Adapter mm |
|---|---|---|---|
| 지갑 | unknown | (288.2,82.6) | 차단 |
| 보조배터리 | power_bank | (62.3,88.2) | 전달 |
| USB | usb / SanDisk | (179.5,92.7) | 전달 |

Qwen 단계 포함 처리31.1초, complete·오류0개. YOLO 검출 재실행 시간은 포함하지 않는다. 지갑 오분류와 unknown 상태의 자유 특징 스티커 언급 등 의미 불일치는 남아 있어 JSON 통과를 정답으로 간주하지 않는다.

## 소프트웨어 통합

`run_pipeline.py`: 사진 또는 기존 결과 + 한국어 텍스트/파일 또는 음성 → 독립 STT 종료 → 필요 시 비전/Qwen → 한국어 규칙·OPUS → CPU MiniLM 하이브리드 매칭 → 후보 최대3개·특징·픽셀/작업대 mm 좌표·검토 판정 저장.

기존 JSON+텍스트4.55초, 사진부터+텍스트36.10초, 실제음성+기존JSON10.49초로 실행 확인했다. 각 실행은 다른 경로 시험이고 정확도 비교가 아니다. 카드 구절이 전처리에서 빠져 두 후보 동점, OPUS의 포켓몬→pocket 번역 오류가 남는다. 항상 직원 검토이며 로봇·DB를 호출하지 않는다.

LF-20 브리지는 canonical vision_id와 기존 object_id를 지원하고 충돌 ID를 거부한다. canonical 반올림 좌표와 원본의 동일성을 검사한 뒤 원본 Qwen 특징을 사용한다. 한국어의 미지원 품목·품목 불명·“휴대폰처럼”을 보류하는 원문 제약을 추가했으며 색/품목 점수·가중치는 변경하지 않았다.

192개 실험에서 질의 제약 적용 후 내부 matched12·보류87·no_match45·비전불완전48이었다. 실제 관제탑 결과192회 모두 uncertain. 미지원 “우산”은 정확한 부재 판별로 승격하지 않고 보류한다. 인간 정답 검수는 하지 않았으므로 정확도 목표 달성을 선언하지 않는다.

## 보정과 로봇 경계

책상 빈 사진 보정:8대응점/8inlier, 최대 재투영 오차 .468mm, 코드 검사 통과. 이는 같은 마커 점의 잔차이지 독립 위치 오차가 아니다. 작업대→로봇 베이스 변환, 독립 실측, 작업영역·자세·고정Z 적용, SO-101 접근·SmolVLA 집기, 직원 확인 UI·실제 메인 운영 연결은 미완료다. 로봇은 움직이지 않았다.
