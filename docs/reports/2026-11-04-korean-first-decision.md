# 한국어 선추출 방식 잠정 채택 및 실험 경과

결정일: 2026-11-04. 사용자와 합의한 현 단계 기준이다. 품질 검증 완료나 정식 배포 확정이 아니라, 이후 실험·연결을 진행할 기본 방식을 결정했다.

## 잠정 채택한 흐름

```text
사용자 한국어 설명
 → 한국어 사전·규칙으로 특징 추출 + 원문 근거 저장
 → 품목·색·스티커 유무를 표준 영어 값으로 변환
 → 손상·위치·정도·스티커 설명의 연결 구절만 OPUS-MT로 번역
 → 기존 속성 필터 + MiniLM 자유 특징 비교
 → 정책 판정과 검토 필요 여부 반환
```

한국어 추출에는 추가 언어 모델을 호출하지 않는다. 단어를 하나씩 번역하지 않고 관계를 보존하는 원문 절을 번역한다. 자유 구절이 없으면 번역 호출을 생략한다. SanDisk·VOVA 같은 원문 라틴 문자와 아이폰 브랜드 정보는 직접 보존한다.

## 선택 근거

| 비교 방식 | 같은 20문장의 품목·색·스티커 전체 일치 | 변환 중앙값 |
|---|---:|---:|
| Qwen3-0.6B 통번역 → 영어 규칙 | 10/20 | 약 2.52초 |
| OPUS-MT 통번역 → 영어 규칙 | 14/20 | 약 0.51초 |
| 한국어 규칙·사전 → 자유 구절 OPUS 번역 | 20/20 | 약 0.26초 |

후보 그룹 11개·기록 22개에 문장별 비교를 수행해 방식별 220회 매칭 결과를 기록했다. 새 방식에서는 20문장 중 16문장만 번역을 호출했다. 중앙값에는 호출 생략 문장도 포함하며 모델 로딩·후보 비교·파일 저장은 제외한다.

한국어 속성을 번역 전에 결정하므로 남색→분홍, 균열의 금→gold 같은 오역이 정형 속성에 들어가는 일을 이번 예문에서 피했다. 다만 기존 예문과 실패를 알고 규칙을 작성했다. **20/20은 개발에 노출된 문장 세트의 세 필드 일치이며, 일반 정확도·번역 정확도·검색 성공률이 아니다.**

## 현재 남은 문제

- 자유 구절에는 포켓몬·손상 위치·심한 파손 표현의 오역이나 누락이 남는다.
- 한국어 원문 근거와 위치가 있어도 특징 의미의 정확성과 추출 완전성이 자동 보장되지는 않는다.
- Qwen이 USB 색이나 스티커 상태를 잘못 추출한 데이터는 그대로 남는다.
- “파손이 없다”는 설명에 파손된 폰을 선택하는 제한 전 정책 오류도 남아 있다.
- 단순 규칙은 복잡한 부정·조건·본체와 부품의 관계·새 어휘에 취약하다.

최신 20문장 주 그룹의 제한 전 결과는 목표 있는 14문장 중 목표 선택 11·보류 3, 정답 없는 4문장 중 거절 2·보류 1·오선택 1, 모호한 2문장 보류였다. 실제 최종 결과는 requires_review 제한으로 모두 보류한다. 잠정 채택을 이유로 이 제한이나 매칭 가중치를 해제·변경하지 않았다.

## 코드 적용 상태

구현은 이미 로컬 코드에 반영했다. 이번 결정에 맞춰 다음 기본값도 변경했다.

| 진입점 | 현재 기본 동작 |
|---|---|
| matching.demo_query_parser | mode=korean-first |
| matching.rank_items --parse-korean | parser-backend=korean-first |
| matching.evaluate_translation | translator=korean-first |

기존 direct Qwen, Qwen 통번역, OPUS 통번역, DeepL API 경로는 비교 옵션으로 남겼다. 영어 직접 입력과 수동 조건 JSON은 계속 지원한다. API 평가에는 키가 필요하며 실제 API 비교는 아직 하지 않았다. 현재 로컬 방식은 키·호출 비용 없이 실행한다.

### 직접 실행

matching/configs/query_demo.txt를 저장한 뒤 저장소 루트에서 실행한다.

```powershell
$env:PYTHONIOENCODING = 'utf-8'
& ..\.venv-query\Scripts\python.exe -u -m matching.demo_query_parser `
  --offline `
  --output-dir outputs/matching/korean_first_demo `
  --candidates matching/configs/vpu_candidates.example.json
```

출력 HTML에서 한국어 원문 → 추출 근거 → 번역 → 조건 → 후보 점수 → 정책·최종 판정을 확인한다. 기본값을 명시하려면 --mode korean-first를 추가한다.

## 후속 검증 및 문서 관리

다음 단계는 이번 규칙을 수정하는 데 사용하지 않은 신규 사용자 문장으로 품질을 확인하는 것이다. 특히 부정·불확실성·색의 대상·같은 품목과 색의 후보 간 자유 특징 구별을 평가한다. 속성 검사, 자유 문장 보존, 오선택·보류·거절, 처리 시간은 나눠 집계한다.

후속 실험은 [방식별 실험 색인](matching-experiments/README.md)에 등록하고, [상세 실험 보고서](../../matching/reports/KOREAN_FIRST_TRIAL.md)와 원본 결과를 연결한다. 기존 결과를 지우거나 서로 다른 세트의 수치를 하나의 정확도로 합치지 않는다.

이 보고서와 한국어 전처리 코드는 LF-3-yolo-aruco 브랜치의 공유 범위다. 이전 2026-11-03 보고서는 당시 상태를 기록한 문서로 유지하고 이번 결정을 별도로 기록했다.

## 팀원 재현용 자료

[비교 결과 JSON](../../matching/reports/translation_comparison_results.json)에 세 방식의 20개 실제 번역·추출 조건·주 그룹 판정을 보존했다. [평가 후보 스냅샷](../../matching/configs/evaluation_candidates.json)은 사진·좌표·로컬 경로를 제외한 기존 11그룹·22개 특징 기록이다. 개발 세트이며 중복과 Qwen 오류를 그대로 포함한다. 평가 스크립트의 기본 입력을 이 파일로 바꿔 로컬 outputs가 없는 팀원도 실행할 수 있도록 했다. 모델 가중치와 실제 사진은 Git에 포함하지 않는다.

사진 없이 데모를 재현하려면 --candidates matching/configs/vpu_candidates.example.json을 사용한다. 새 PC는 matching/requirements-query.txt로 별도 Python 환경을 구성하고 최초 모델 다운로드 후 --offline을 지정한다. 다른 PC의 환경 경로는 현재 PC의 ..\.venv-query와 다를 수 있다.
