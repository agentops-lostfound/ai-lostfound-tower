# A4 마커 배치 설정 및 첫 보정 계산 확인

> 아래 A4 배치는 과거 실험 기록이다. 현재 기본 설정은 문서 끝의 책상 배치로 변경됐다.

## 배치와 좌표 기준

2026-11-04 사용자 확인을 바탕으로 vision/configs/vision.yaml에 다음 배치를 입력했다.

- A4 가로: 297×210mm. 종이 왼쪽 위가 (0,0), +X는 오른쪽, +Y는 아래쪽.
- 검정 테두리를 포함한 마커 크기: 14×14mm. 인쇄물의 명목 크기보다 사용자 실측값을 우선했다.
- ID 0은 왼쪽 아래, ID 1은 오른쪽 위. 바깥쪽 종이 경계까지 여백은 각각10mm라는 사용자 배치 설명을 사용했다.
- 서로 마주 보는 꼭짓점: ID 0 오른쪽 위 (24,186), ID 1 왼쪽 아래 (273,24).
- 두 점의 가로 간격249mm(297−48), 세로 간격162mm(210−48). 대각 거리는 약297.06mm로, A4 긴 변을 맞대 보인 약297mm와 부합한다. 대각 거리를 세로 거리297mm로 입력하지 않았다.

마커 회전을 반영해야 한다. 아래 좌표는 이미지상의 왼쪽 위부터 나열한 것이 아니라 OpenCV가 디코딩한 마커 코너 순서에 맞춘 것이다. 이번 사진에서는 각 마커의 디코딩 순서가 종이 기준 왼쪽 아래→왼쪽 위→오른쪽 위→오른쪽 아래다.

```yaml
aruco:
  dictionary: DICT_4X4_50
  markers_mm:
    0: [[10, 200], [10, 186], [24, 186], [24, 200]]
    1: [[273, 24], [273, 10], [287, 10], [287, 24]]
  ransac_threshold_mm: 3.0
  max_reprojection_error_mm: 3.0
  min_inlier_ratio: 0.75
```

## 해석과 남은 작업

성공한 것은 마커 검출, 설정 좌표에 대한 Homography 계산, 관제탑의 보정 수치 검사다. 0.54mm는 입력 마커 점에 대한 재투영 잔차이며 물건 위치 오차0.54mm나 로봇 접근 정확도를 뜻하지 않는다. 배치 치수는 사용자 설명 기반이며 독립 측량으로 확인하지 않았다.

현재 사진에는 물건이 없어 객체별 center_world_mm→Adapter center_mm 전달은 아직 이 사진으로 확인하지 못했다. 다음에는 마커를 고정한 채 물건을 놓고 촬영해 YOLO→Qwen→좌표 변환→Adapter를 검사한다. 종이 여러 지점에 독립 기준점을 두어 실측 위치와 비교하는 검증도 남아 있다.

작업대→로봇 베이스 변환, 카메라 왜곡·물체 높이 시차·파지점 보정은 미완료다. 종이 좌표를 로봇 좌표로 간주하지 않는다. 마커를 이동·회전하거나 배치 치수를 바꾸면 설정도 다시 확인해야 한다. 로봇은 움직이지 않았다.

설정 변경 후 전체 unittest236개 실행:235통과·DB1스킵. 이번 기록 시점에는 설정 및 보고서 변경을 커밋·푸시하지 않았다.

## 후속: 나무색 책상 배치로 변경

사용자가 ID0 왼쪽 위·ID1 오른쪽 아래 배치, 마커14mm, 서로 마주 보는 꼭짓점의 가로 간격324mm·세로 간격150mm를 확인했다. 원점은 ID0 검정 사각형 물리 왼쪽 위, +X 오른쪽·+Y 아래로 정했다. ID0 오른쪽 아래(14,14)와 ID1 왼쪽 위(338,164)의 차이가(324,150)이다. 종이 원점·로봇 베이스 원점과 구별한다.

최신 사진 WIN_20261104_17_37_42_Pro.jpg에서 실제 검출 코너 순서는 두 ID 모두 물리 BL,TL,TR,BR로 확인했다. 현재 vision.yaml:

```yaml
markers_mm:
  0: [[0, 14], [0, 0], [14, 0], [14, 14]]
  1: [[338, 178], [338, 164], [352, 164], [352, 178]]
```

ArUco 전용 검사:8대응점·8inlier, valid=true, 최대 재투영 오차0.4679347935278543mm. 출력 outputs/vision/fc1665c548e74f3c99b8dab53941fac8/result.json. 독립 지점 실제 오차 검증은 아직 없다. 빈 장면이라 객체 mm 좌표 전달 시험은 하지 않았다. 전체 테스트240개 중239통과·DB1스킵. YOLO 기본 모델은 n 그대로이며 m으로 설정을 바꾸지는 않았다.

## 후속 결정: YOLO26m + 책상 배치 잠정 고정

사용자가 최신 실사진 결과를 확인한 뒤 현재 조합을 기본값으로 채택했다. vision.yaml의 기본 모델을 models/yolo26m.pt로 변경했다. confidence=.25, imgsz=640, 마커 좌표는 위 책상 설정을 유지한다. Qwen 최대 변 기본값512, 스티커 필드 모순은 해당 정보만 unknown/빈목록으로 제외하는 처리를 유지한다. CPU YOLO·격리 GPU Qwen 구조는 동일하다.

WIN_20261104_17_41_52_Pro.jpg에서 n은 USB1개, m은 보조배터리·USB·지갑3개를 검출했다. m의 검출 클래스는 모두 cell phone이지만 bbox와 크롭 용도로 사용한다. 모델 가중치는 models에 다운로드돼 있으며 Git 제외다. 새 환경에서는 공식 yolo26m.pt를 별도로 준비해야 한다(기존 다운로드 자동 처리는 n만 지원).

그3개 박스를 재사용해 Qwen을 실행한 결과 outputs/vision/fd0ff8b9f6bf4b4abf9fb3dac1062f7a/result_with_qwen.json에 complete·실패0개로 기록됐다. 약31.1초는 검출 재실행 없이 저장된 박스로 크롭한 후 Qwen을 실행한 시간이며 새 사진 전체 검출 포함 시간이 아니다.

| id | 실제 물품 관찰 | Qwen category | 작업대 mm | Adapter mm |
|---|---|---|---|---|
| 0 | 지갑 | unknown | (288.2,82.6) | 차단 |

이 선택은 현재 촬영 조건의 개발 기준이며 모든 물품·배경에서 검출/특징 정확도가 검증됐다는 의미는 아니다. 독립 위치 오차 및 로봇 베이스 변환은 여전히 미검증이다. 카메라 계획 높이는 작업대 위400mm. 로봇 접근 Z=280mm는 변경 가능한 제안값이며 아직 실제 제어 설정이나 실행에 적용하지 않았다. 이번 사용자 승인은 설정 고정이며 커밋·푸시는 별도로 하지 않았다.
