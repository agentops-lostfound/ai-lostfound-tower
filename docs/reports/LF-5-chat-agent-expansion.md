# LF-5 웹 안내 챗봇 에이전트 확장

## 구현 결과

| 요구 | 이번 구현 | 현재 한계 |
|---|---|---|
| 문서 기반 RAG | 로컬 근거 검색 → Ollama LLM의 관련 단락 선택·답변 구성 → 근거 범위 검증 → 출처 표시 | 키워드 검색과 문서 발췌형 RAG이다. 임베딩 검색·자유로운 요약 생성·전체 문서 질의응답은 아니다. |
| 에이전트 추가 | LangGraph가 이용 안내와 DB 물건 검색으로 분기한다. 복합 질문은 둘 다 실행한다. | Langmanus 자체를 도입하지 않았다. 기존 프로젝트의 LangGraph를 사용한다. |
| DB 연결 | 가상 물건 6종을 SQLite에 저장하고 실제 SQL로 조회한다. PostgreSQL용 고정·매개변수 SELECT도 구현했다. | 실행 화면은 가상 DB이다. 실제 팀 DB와 인증 세션은 아직 연결하지 않았다. |
| 물건 정보 안내 | 품목·색상에 맞는 공개 후보 최대 3개를 카드로 표시한다. | 날짜·역·키링 등은 필터에 반영하지 않으며 답변에 이 범위를 명시한다. 소유권 확정·예약·반환은 실행하지 않는다. |
| 채팅 음성 입력 | 마이크 녹음 또는 WAV 업로드 → 기존 오프라인 STT → 입력창에서 확인·수정 → 직접 전송 | 실제 마이크·사람의 한국어 발화는 이번에 확인하지 못했다. |
| 미확정 운영 정책 | 운영시간·보관기간 등은 기존 보류 응답을 유지하고 LLM으로 보내지 않는다. | 팀의 확정 문서가 필요하다. |

## RAG 구현 방식

검증된 로컬 문서의 근거와 답변 문단을 검색한다. 로컬 LLM은 검색된 문단 ID를 선택해 질문에 맞는 답을 구성한다. 선택된 문단을 통째로 표시하여 예외 조건·주의 문장을 잘라내지 않는다. 허용되지 않은 문단 ID, 중복, 누락된 필수 주제, 잘못된 JSON이면 원래 문서 답변으로 돌아간다. 새 운영값이나 후보 정보를 모델이 만들어 표시하는 구조가 아니다.

`generation_used`와 `generation_status`로 실제 모델 사용과 대체 응답을 구분한다. 모델 미설정·접속 실패·혼잡 시에도 근거 문서 안내는 유지한다. 대화 이력은 모델에 보내지 않으므로 '그럼 그건?' 같은 문맥 의존 후속 질문은 아직 지원하지 않는다.

## DB 및 인증 경계

- 가상 DB에는 `DEMO-001` 등 합성 물건만 들어 있다. 화면에 가상 DB임을 표시한다. 실제 DB 조회 실패를 가상 결과로 대체하지 않는다.
- PostgreSQL 조회는 읽기 전용 거래와 3초 쿼리 제한을 사용한다. 공개 품목·색상·상태·물건 번호만 SELECT하고 `private_features`, 연락처, 신분정보, 사진 경로는 조회하지 않는다.
- 실제 DB 모드는 서버가 소유한 `SearchAgent(authorize=...)` 검증기가 유효한 인증·필수 동의 세션을 확인해야 실행된다. 클라이언트의 `id_verified: true`나 `consent: true`로는 열리지 않는다. HTTP의 Bearer 토큰만 검증기에 넘긴다.
- 현재 환경 설정만으로 켜는 실제 DB 모드에는 검증기가 연결되어 있지 않아 인증 연계 필요 응답을 한다. 인증 담당 웹의 서버 검증 함수를 연결해야 실제 이용자에게 제공할 수 있다.

## 로컬 재현

지원 의존성과 기존 로컬 모델·음성 모델이 준비된 저장소에서 실행한다. 모델을 자동 다운로드하지 않는다.

```powershell
python tools/run_lost_assistant.py --demo --rag-model qwen3-vl:2b-instruct --speech
```

화면: `http://127.0.0.1:8111/input`

- `LF_CHAT_RAG_MODEL`: 설치된 Ollama 모델 이름
- `LF_CHAT_DEMO_DB`: 가상 SQLite 파일 경로
- `LF_CHAT_DATABASE_URL`: 실제 PostgreSQL 연결값. 가상 DB 설정보다 우선하며 인증 검증기가 별도로 필요하다.
- `LF_STT_ENABLED=1`: 기존 오프라인 small 음성 인식 사용

새 API는 `/chat/questions`, `/chat/transcriptions`이다. 기존 `/guidance/questions`는 문서 안내 호환용으로 유지한다. 음성 변환 API는 질문 전송·설명 접수를 하지 않고 확인할 글만 돌려준다.

## 검증 결과

- 전체 Python 시험 390개 실행, 실패 0개, 환경 조건에 따라 9개 생략. 자동완성 Node 시험 4개 통과. JavaScript 문법 검사 통과.
- 실제 로컬 Ollama와 서버에서 안내·사진 입력 방법·일치 후보·빈 결과·복합 질문·미확정 정책 포함 복합 질문 6건을 확인했다. 수령·사진 이용 안내는 `generation_used=true`를 확인했다.
- 기존 안내 질문 회귀 시험 62/62 통과. 작성한 질문 기준이며 독립 성능 평가가 아니다.
- 독립 임시 PostgreSQL 16에서 인증 전 차단, 허용된 서버 시험 티켓의 후보 조회, 인계 완료 물건 제외, 색상 생략 조회, 비공개 특징 제외를 확인했다. 시험 중 발견한 NULL 매개변수 자료형 문제를 수정했다. 임시 DB는 종료했고 팀 DB는 변경하지 않았다.
- 브라우저에서 검색 카드, 문서 근거 펼치기, 복합 답변, 음성 파일의 무음 거절을 확인했다. 무음 파일의 직접 API 처리 재측정은 약 1.08초였다. 정상 음성 변환 이후 직접 전송하는 흐름은 가짜 STT로 시험했다. 실제 마이크 인식 정확도를 검증한 것은 아니다.
- 1440×1000과 375×812 화면을 확인했다. 작은 화면에서 가로 넘침 없이 채팅 내부 스크롤과 음성 입력 버튼을 사용할 수 있었다.

## 변경 범위

`agents/chatbot.py`, `agents/chat_rag.py`, `agents/chat_search.py`를 추가하고 `agents/lost_api.py`, `agents/lost_input.py`, `agents/guidance.py`를 연결했다. `web/lost-input/`과 `docs/guidance/`를 갱신하고 로컬 실행 도구를 추가했다. 팀 공통 특징 계약·팀 DB 스키마·로봇 실행 흐름은 수정하지 않았다.
