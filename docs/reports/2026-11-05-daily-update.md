# 2026-11-05 비전·SO-101 작업 정리

공유 브랜치: `LF-3-yolo-aruco`. 관련 Jira: LF-3(비전), LF-21(사전 접근), LF-11(작업대·반환 경로 연동).

오늘의 최종 결정은 **YOLO26l로 검출·크롭을 수행하고, 로봇은 직접 티칭한 커스텀 자세 5개를 선택해 이동하는 것**이다. YOLO 중심/XYZ를 입력해 고정 Z에서 관절값을 자동 계산하는 개발은 중단했다. 저장 자세 사이의 경로와 실제 반복 재현 성능은 추가 검증 대상이다.

## 1. YOLO 모델을 m에서 l로 변경

`vision/configs/vision.yaml`의 기본 모델을 `models/yolo26l.pt`로 변경했다. confidence0.25, imgsz640, crop padding0은 유지했다. 모델 가중치는 로컬 `models/`에 있으며 Git에는 포함하지 않는다.

현재 흰색 폰·현재 검정 지갑·과거 검정 지갑 사진 3장을 같은 원본 픽셀로 비교했다. CPU에서 모델/입력별 warm-up 후 사진마다 3회 추론의 중앙값을 사용했다. 아래 confidence는 지정 물체 ROI와 IoU0.5 이상 겹치는 최고 점수로, 품목 정확도나 검출률이 아니다.

| 모델 / 입력640 | 현재 흰색 폰 | 현재 검정 지갑 | 과거 검정 지갑 | CPU 추론 중앙값 범위 |
|---|---:|---:|---:|---:|
| YOLO26m | 0.231 | 0.182 | 0.572 | 91.0~96.0ms |
| YOLO26l | 0.578 | 0.447 | 0.890 | 115.9~118.5ms |
| YOLO26x | 0.855 | 0.276 | 0.748 | 271.2~278.7ms |

이 세 장에서는 l/640이 m/640보다 검출 임계값을 안정적으로 통과했고 x보다 CPU 비용이 낮아 기본값으로 선택했다. 입력1280과 채도 조절도 비교했지만 모든 사진을 일관되게 개선하는 설정으로 확인되지는 않았다. 기본 채도 보정은 추가하지 않았다. 사진 3장에 한정한 결과이며 실제 품목 전체의 성능 평가나 학습 완료를 뜻하지 않는다.

새 1280×720 탑뷰에서 l/640으로 흰색 폰을 검출했다. 16:02 사진은 confidence0.897, YOLO→Qwen→매칭 보고서 생성까지 약28.1초였다. 16:34 새 사진은 confidence0.861로 검출했고 이번 좌표 시험에서는 Qwen을 다시 실행하지 않았다. YOLO는 폰을 `remote`로 분류했으므로 이 점수로 품목 정답률을 주장하지 않는다. 빈 보관함 사진에서 검출0이 나온 실행도 별도로 구분했다.

원본 비교: 로컬 `outputs/photo_spec_comparison_20261105/model_size_test/REPORT.md`. 전체 시퀀스 예: `outputs/pipeline/white_phone_large_20261105_160238/`. 원본 사진·크롭·로그는 Git 제외다.

## 2. 좌표/IK 시험과 운영 방향 전환

SO-101 공식 URDF, 기존 관절 캘리브레이션, 저장 entry 자세, 설치 치수를 함께 검토했다. 사용자 최신 높이 실측은 내부 바닥 위190mm이며, 기존 바닥 높이7mm를 적용하면 잠정 설치면 기준197mm다. entry의 실물 XY는 좌우 중앙·사각형 먼 변 밖 약40mm라는 확인을 사용해 잠정 `(0,333,197)mm`로 계산했다.

단일 entry 대응점으로 임시 평행이동 보정을 만들고, 손목을 entry에 고정한 3관절 IK로 폰 중심의 접근 자세를 계산했다. 사용자가 GUI로 실행해 관절 목표 근처 도달은 확인했지만, 영상으로 집게의 목표 정렬을 확인하지 못했고 사용자에게서 실제 자세 방향에 대한 문제 제기가 있었다. **모델의 IK→FK 잔차가 작거나 모터가 목표값에 도착한 사실을 실제 물체 위 정렬 성공으로 해석하지 않는다.**

단일점의 Z 잔차 약31.09mm나 손목 이동 역변위는 최종 실물 보정값으로 채택하지 않았다. 현재 각도·영점·축·TCP의 독립 대조가 부족하고, 기존 관절 직선 보간으로는 일정 Z 경로를 보장하지 않는다.

뉴로메카 공식 SDK와 ROS2 소스도 참고용으로 받았다. SDK의 `movel`/`inverse_kin`은 Indy 제어기를 호출하는 gRPC 클라이언트이고, 공개 ROS2는 MoveIt/KDL 및 Indy 드라이버를 사용하는 구조였다. SO-101용 IK 엔진을 확보·설치·이식한 결과는 아니다. 참고 소스는 로컬 outputs에 보존했다.

이후 사용자 결정으로 **XYZ 자동 계산 개발을 중단하고 저장 자세 방식으로 전환**했다. 기존 비전·Qwen·매칭은 유지하며, 오프라인 좌표/IK 코드와 실험 결과는 이력으로 남긴다. 기존 API 계약을 임의 변경하거나 main에 병합하지 않았다. 자세한 결정은 [고정 자세 전환 기록](2026-11-05-fixed-pose-decision.md)을 따른다.

## 3. 텔레옵으로 커스텀 자세 5개 기록

Studio의 기존 리더·팔로워 설정을 이용해 사용자가 자세를 맞췄다. 각 자세에서 텔레옵을 HOLD로 바꾼 뒤, 읽기 전용 관측 WebSocket으로 팔로워 6관절을 5Hz·10회 읽었다. 다섯 기록 모두 해당 관측 구간의 관절값이 일치했다. 마지막 실제 관측을 대표값으로 저장했다.

| 이름 | 기록 시각(KST) | 관측 수 | 관측 구간 최대 변화 |
|---|---|---:|---:|
| `pose_1` | 17:41 | 10 | 0 normalized |
| `pose_2` | 17:42 | 10 | 0 normalized |
| `pose_3` | 17:43 | 10 | 0 normalized |
| `pose_4` | 17:44 | 10 | 0 normalized |
| `pose_5` | 17:46 | 10 | 0 normalized |

이는 읽기 전용 기록이며 각 기록에 `robot_motion_command_sent=false`를 남겼다.

기록 원본은 `outputs/robot_poses/teleop_teaching_20261105/`에 있다. 각 자세의 `pose.json`과 `observations.csv`, 전체 자세의 `poses.json`과 `poses_summary.csv`를 저장했다. 단위는 기존 GUI와 같은 `studio_normalized`이며 degree나 mm가 아니다. 10회 값의 일치는 자세 사이 이동 경로·충돌 회피·재현 정확도의 증명이 아니다.

## 4. GUI에 커스텀 1~5 버튼과 열 정렬 추가

`robot/teaching_gui.py`에 커스텀 1~5 버튼을 추가해 각각 `pose_1`~`pose_5`를 불러오도록 했다. 버튼 선택은 미리보기이며 `Review target → Approve ONE stage`를 거쳐 이동한다. 자세가 없는 PC에서는 해당 버튼을 비활성화한다. 집게 개폐는 현재값 유지이며 기존 STOP·Repair·CSV·5/4/3초 시간 정책을 유지한다.

헤더와 각 모터 행이 따로 Frame을 사용해 열 너비가 달라지던 문제를 공통 grid로 수정했다. 관절명·실측값·목표 입력·오차·조그·Apply 열을 맞추고 숫자 표시와 입력을 오른쪽 정렬했다.

다섯 티칭 자세는 `outputs/robot_panel_live/poses.json`에 병합했다. 기존 `home/raised/entry/observe` 네 자세의 값을 보존했고 병합 전 파일도 백업했다. 따라서 현재 로컬 GUI 목록은 기존4개+커스텀5개다. 커스텀 번호를 기존 home/raised/entry/observe와 같은 역할이라고 임의 지정하지 않았으며, 기존 forward/reverse 순서에도 추가하지 않았다.

## 5. 실물 연결과 포트 충돌 정리

새 GUI 연결 시 Studio가 포트를 점유해 `Serial port busy`가 발생했다. 기록용 읽기 연결을 해제하고 Studio의 정상 세션 종료 API를 호출한 뒤 실제 두 시리얼 포트의 해제를 확인했다. 설치 SO-101 드라이버의 정상 팔로워 연결 해제는 현재 자세 유지·토크 유지 경로임을 소스로 확인했다. 프로세스 강제 종료나 캘리브레이션/PID 변경은 하지 않았다.

새 GUI가 `so101-control` 드라이버로 실측6관절을 수신하는 상태를 확인했다. GUI에서 이동이 수행된 뒤 완료/HOLD 상태도 관찰했다. 당시 GUI가 보고한 최대 잔여 관절 오차 표본은 약2.99°였고 이후 다른 완료 상태에서는 약2.46°였다. 이는 전체 자세의 반복 오차 통계나 mm 단위 TCP 정확도가 아니다. 이번 업데이트 작업에서 별도 자세 명령을 자동 전송하지 않았다.

## 6. 소프트웨어 검증과 공유 범위

전체 명령: `python -m unittest discover -s tests -v` (UTF-8 출력 환경).

**295개 실행, 294개 통과, PostgreSQL 미연결 시험1개 스킵.** 커스텀 버튼의 올바른 자세 선택·선택만으로 이동하지 않음·집게값 유지, 실제 Tk 위젯 좌표 기반 헤더/행 정렬을 모의 환경에서 검증했다. 실제 로봇의 충돌 회피나 집기 성능 시험은 아니다. 로컬 로그: `outputs/custom_pose_gui_unittest.log`.
