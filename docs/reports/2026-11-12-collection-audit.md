# LF-9 회수 원장 읽기 전용 정합성 점검

## 완료 내용

사용자가 서버 담당자를 기다리지 않고 진행할 작업으로 회수 기록 정합성 점검을 선택했다. 기존 LF-9 PR #249의 `12ee8fe`를 기반으로 별도 `LF-9-jeongyeonwoo-collection-audit` 브랜치·작업 폴더를 만들고 팀 main `3e21faa`를 통합했다. 기존 전달 ZIP과 PR #249는 보존한다.

- 실제 PostgreSQL 원장 점검 모듈, `CollectionStore.audit()`, 관리자 GET API와 화면, 읽기 전용 CLI 구현.
- 불일치12종·담당자 확인2종, 총14종. 정상 후속 반환 상태와 과거 품목 기록은 오류로 오인하지 않는다.
- 고정 SQL과 단일 읽기 전용 스냅샷. 전체 건수와 제한된 샘플을 구분하고, DB 실패를 정상 0건으로 숨기지 않는다.
- 마감/도착 검토 정보 부족, 과거·복수 회수의 이력 귀속 미확정 범위를 명시한다.
- 점검은 기록을 수정하거나 외부 알림·반환 승인·로봇 동작을 실행하지 않는다. 실제 `.env`·팀 DB·실물 장치는 변경하지 않았다.

## 검증

- 독립 PostgreSQL 집중 시험 **29개 통과 / 실패0 / 제외0 / 8.403초**. 새 시험17개와 기존 센터 통합12개였다. 이후 autocommit 연결 거절과 회귀2개를 추가했다.
- 독립 PostgreSQL 포함 최종 전체 unittest **1,909개 / 실패0 / 제외21 / 73.337초**. 내부에서 `python -X utf8 -m unittest discover -s tests`를 실행했다. 제외는 환경 조건 미충족이며 성공한 실제 시험으로 세지 않는다. autocommit 보완 전 전체는 1,907개 / 실패0 / 제외21 / 75.424초였다.
- 새 실제 PostgreSQL 시험14개: 정상 회수·부분/전체 도착·정상 반환 후 상태, 기계/상태 불일치, 알림/이력 누락, 복수 회수, 과거 기록, 55건 중5건 표시, 열 단위 읽기 역할, 권한 부족, 손상된 가져오기 표본, 인증 GET 및 입력 한도, autocommit 연결의 미완료 처리.
- `item`의 공개3열과 원장 관련4표에만 SELECT 권한을 준 임시 역할로 성공했다. 운영 역할은 만들지 않았다. 고아 항목 손상 표본은 DB 이름이 제한된 임시 DB·해당 연결에서만 만들었다.
- 단위 시험5개: 잘못된 한도의 연결 전 거절, 실패 비노출/미완료, 전체 건수와 안전한 식별자, CLI 종료 코드/적용 명령 부재, autocommit 연결에서 SQL 실행 전 중단.
- 실제 Chrome UI: 합성 HTTP 점검 응답으로 불일치·전체건수/표시 제한·503 실패 후 이전 결과 제거·새로고침 및 결과 불명 쓰기 요청 후 무효화·PC1280/모바일390 가로 넘침 없음·페이지 JS 오류0 확인. 브라우저 시험은 실제 PostgreSQL UI 종단 시험과 구분한다.
- 첫 브라우저 검사에서 비동기 실패 응답이 끝나기 전에 상태 문구를 검사한 문제가 있어 대기 조건을 정정했다. 제품 코드를 해당 기대값에 맞춰 바꾸지 않았다. 최종 검사 통과.
- JavaScript 구문·`git diff --check` 확인. 임시 PostgreSQL 컨테이너와 미리보기 서버는 종료했다. 실제 모델 대규모 평가는 실행하지 않았다.

로컬 실행 증거는 작업 루트 `outputs/collection-audit-20261112/`의 focused01.log·full01/02.log·ui-result.json·PC/모바일 PNG에 보존한다. 기존 중단 표식과 챗봇 평가 원본을 유지한다.

## 운영 상태

로컬 개발·임시 DB 검증 결과다. 운영 데이터에서 불일치0건이나 실제 물건 누락0건을 확인한 결과가 아니다. 관리자 화면 적용은 선행 PR #249의 검토·운영 DB 모드/스키마 확인과 함께 담당자가 수행해야 한다. 기존 전달 ZIP에는 이번 추가 기능이 없다. 자동 데이터 복구·운영 스키마 적용·main 병합은 하지 않는다.
