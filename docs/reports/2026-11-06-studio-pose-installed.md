# Studio 저장 자세 통합 설치 결과 · 2026-11-06

사용자의 “진행 ㄱㄱ” 요청에 따라 연결 준비 및 통합 패치 설치를 수행했다.

## 2026-11-09 후속 적용

- 녹화·Model Run 화면에서 기존 RuntimeSession으로 저장 자세 이동과 어프로치 복귀를 수행한다. 녹화 없이 텔레 집기 후 복귀도 지원한다.
- 저장 자세는 `home`, `pose_1`~`pose_8`, `close`, `open`, `outlet_return_1`의 12개다. `raised`, `entry`, `observe`를 제거했고 그리퍼를 포함한 저장 6축 값을 적용한다.
- 리더·팔로워 실시간 6축 값과 차이를 표시한다. 리더 자동 정렬은 구현하지 않았다.
- 이동 시간 3·4·5초 선택(기본 3초)을 직접 이동·복귀에 적용한다. 선택 시간은 보간 시간이며 도착 제한 시간이 아니다. 보간 종료 후 목표값을 계속 유지한다. 추종 오차 10 초과·관측 중단·이동 중 heartbeat 소실은 별도로 정지한다.
- 목표값 유지 중 다음 자세·텔레 전환을 허용한다. 실제 도착 확인과 녹화 시작 조건은 구분한다.
- 저장소 테스트 312개 실행·303개 통과·9개 skip, Studio 통합 25개 및 UI 17개 통과. 타입 검사·변경 UI lint/format·production build 통과.
- 서버 재시작 후 로봇·리더·두 카메라가 있는 세션이 연결됐고 HOLD·녹화 꺼짐을 확인했다. 제공되는 UI 해시가 테스트 빌드와 같으며 서버의 시간 계약이 `Literal[3, 4, 5]`임을 확인했다.
- 백업: `outputs/studio_pose_integration/backup-move-duration-20261109-105051/`. 최신 옵션별 실제 소요 시간 및 물건을 든 전체 반환 반복 검증은 후속이다.

아래는 11/6 최초 설치 당시의 기록이다. 현재 사용법은 [통합 README](../../robot/studio_extension/README.md)를 따른다.

## 완료

- USB 시리얼 대조 후 팔로워 `1-10 / COM4 / 5B3D044791`, 리더 `1-11 / COM5 / 5B3D044199`, 탑뷰 `1-4`를 WSL에 attach.
- WSL 및 컨테이너 매핑은 팔로워 `/dev/ttyACM0`, 리더 `/dev/ttyACM1`, 탑뷰 `/dev/video2`.
- 손목 icspring `1-3`은 Windows에 유지. `http://localhost:8765/health`가 정상 응답하고 프레임 카운터가 증가했다.
- 설치기의 묶음 SHA256, 기존 소스 해시, 이미지 revision, 활성 세션 없음, 장치 경로 검사를 통과했다.
- 원본 백업 후 패치를 적용하고 컨테이너 `physical-ai-studio-cuda`를 재시작했다.
- 백업은 `outputs/studio_pose_integration/backup-20261106-165140/`.
- backend에서 `StudioActionSource`가 새 mixin을 사용하는 것, 자세 15개, `stop_saved_pose` 계약 import를 확인했다.
- 웹 루트와 새 JS `/static/js/index.8267c487c2.js`가 HTTP 200을 반환했다.
- 실제 브라우저에서 프로젝트와 Datasets 화면이 정상 표시되는 것을 확인했다. 현재 데이터셋은 0개다.
- 탑뷰의 재연결 후 fingerprint가 `usb-vhci_hcd.0-4`에서 `usb-vhci_hcd.0-3`으로 달라져 API로 현재 값에 맞췄다.
  원본 설정은 백업 폴더의 `topview-before.json`. 1280×720@30 설정은 유지했다.

## 아직 확인하지 않은 것

- 로봇 runtime 세션을 시작하지 않았다. 설치 후 조회도 `[]`였다.
- 실제 모터 응답·토크·이동·정지·텔레 전환·물건을 든 복귀는 시험하지 않았다.
- 카메라 두 영상의 실제 내용과 설정 해상도로의 스트림 시작은 미확인이다. 브리지 health와 장치 검색 확인까지만 했다.
- 데이터셋이 없어 녹화 화면의 새 컨트롤을 실물 세션에서 확인하지 않았다. 단위 테스트·빌드와 배포 자산 확인은 완료했다.
- 리더 자동 정렬은 여전히 미구현이며 하드웨어 가능성 미확인이다.

## 다음 단계

Datasets에서 이 환경을 사용하는 집기·들어 올리기 데이터셋을 만든 후, 사용자가 팔 주변을 준비한 상태에서 녹화 화면을 연다.
HOLD와 두 카메라를 확인하고 빈 집게로 짧은 자세 이동부터 시험한다.
그 후 리더 수동 정렬 → 텔레 → 짧은 녹화 → 저장 후 복귀를 확인한다.

설치·복구 방식은 [통합 README](../../robot/studio_extension/README.md)를 따른다.
이 패치는 기존 컨테이너에 적용했으므로 컨테이너 삭제/재생성 시 재적용이 필요하다.
이전 이동용 ZIP은 설치 전 상태를 기록한 묶음이므로, 다른 담당자에게는 이 설치 결과도 함께 전달한다.
