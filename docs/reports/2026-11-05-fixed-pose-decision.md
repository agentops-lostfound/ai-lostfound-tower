# SO-101 고정 커스텀 자세 방식 전환

결정일: 2026-11-05. 사용자 결정: 좌표를 찍어 모터값을 자동 계산하는 방식은 진행하지 않고, home·raised·entry·observe 같은 커스텀 자세 약 5개를 고정하여 사용한다.

## 변경한 방향

로봇 제어 입력은 실물에서 티칭한 **저장 자세 이름과 관절 목표값**이다. YOLO 중심/XYZ에서 고정 높이 경로·IK·관절값을 자동 생성하는 개발은 중단한다. 현재 라이브 GUI는 이미 저장 관절값을 `so101-control.move_to_joints()`로 전달하는 방식이며, XYZ/IK 실행기는 연결되어 있지 않다. 따라서 모터 제어 코드를 커밋 단위로 되돌릴 필요는 없고 운영 계획과 사용 기준을 갱신했다.

비전의 검출·크롭·Qwen 특징 추출·매칭 기능은 유지한다. 선택 물품과 저장 자세를 연결하는 규칙은 아직 정하지 않았다. YOLO 좌표가 계산되어 보고서에 남더라도 그 숫자로 로봇 관절값을 자동 생성하지 않는다.

## 현재 저장된 자세

저장 위치: `outputs/robot_panel_live/poses.json`. 기존 네 자세를 보존한 채, 이후 텔레옵으로 티칭한 `pose_1`~`pose_5`를 병합했다. 병합 전 원본을 `poses.backup-before-custom-buttons-*.json`으로 백업했다.

| 자세 | 현재 상태 |
|---|---|
| `home` | 저장됨 |
| `raised` | 저장됨 |
| `entry` | 저장됨 |
| `observe` | 저장됨 |
| `pose_1`~`pose_5` | 텔레옵 티칭·기록 완료. GUI 커스텀 1~5 버튼과 연결 |

새 커스텀 5개는 각각 Studio HOLD 상태에서 팔로워 모터값을 10회 관측했고 각 기록 구간에서 값이 일치했다. 원본은 `outputs/robot_poses/teleop_teaching_20261105/`에 있으며 JSON·CSV를 보존했다. 이는 저장 자세 사이 경로나 실제 재현 이동의 검증을 뜻하지 않는다. 커스텀 번호와 home/raised/entry/observe의 역할을 임의로 동일시하지 않는다.

## 사용하는 기존 기능

- 모터 목표값 편집 및 조그.
- 실제 측정 관절값을 이름으로 저장·덮어쓰기, 덮어쓰기 시 백업.
- 자세 목록/이름 입력과 `Load preview`.
- `Review target` → `Approve ONE stage`의 한 단계 실행.
- 소프트웨어 STOP, Repair HOLD, CSV 기록.
- 단계 시간 1=5초 / 2=4초 / 3=3초, 최종 목표 유지 구간 포함.

실제 자세를 맞춘 후 새 이름을 입력하고 `Save measured / overwrite`로 저장한다. 이 기능은 입력란의 목표값이 아니라 실제 측정값을 저장한다. 기존 네 자세를 덮어쓰지 않으려면 새 이름을 사용한다. 저장한 커스텀 자세는 이름 목록에서 선택하고 `Load preview`로 불러온다.

현재 GUI는 시작할 때 파일을 읽으며, 실행 중 외부 파일 수정은 자동 반영하지 않는다. GUI 저장 기능을 사용하면 실행 중 목록도 갱신된다. 저장 자세 선택·미리보기만으로는 움직이지 않는다.

## 현재 단계에서 포함하지 않는 것

- XYZ 입력 또는 YOLO 중심 클릭에 따른 자동 모터 계산.
- 집게 Z=190mm의 자동 유지. 해당 실측은 과거 시험의 참고값이다.
- 기존 `approach` IK 시험값의 운영 자세 승격.
- 뉴로메카 SDK/MoveIt 설치 및 SO-101 이식.
- 약 5개의 자세 전체를 한 번에 자동 실행하는 기능.

현재 GUI의 고정 순서 미리보기는 `home → raised → entry → observe` 네 이름이다. 커스텀 1~5는 별도 선택 버튼으로 제공하며 이 순서에 자동 추가하지 않는다. 사용자 지정 자세 저장과 순서 편집/전체 자동 실행은 별개다. 각 번호의 역할과 필요한 전환 순서는 추후 합의한다.

## 적용 범위와 남은 일

이번 갱신은 운영 결정과 문서에 한정했다. 기존 모터 통신·저장 자세·캘리브레이션·비전 모델 설정을 변경하지 않았고 로봇 명령을 보내지 않았다. 실행 중 GUI에 과거 계산 목표가 남아 있다면, 다음 실행 전에 사용할 저장 자세를 `Load preview`로 불러와 목표를 다시 검토해야 한다. GUI 상태를 자동 초기화하거나 세션을 재시작하지 않았다.

오프라인 IK 코드, 임시 보정 결과, 뉴로메카 참고 소스는 실험 이력으로 보존한다. 현재 운영에 연결하지 않는다. Git reset/checkout으로 관련 없는 변경을 되돌리거나 과거 파일을 삭제하지 않았다.

후속 UI 갱신에서는 커스텀 1~5 미리보기 버튼을 추가하고 헤더·모터 행을 같은 grid에 배치해 입력칸 정렬을 수정했다. 저장 자세 병합은 사용자 요청으로 진행했으며 이전 문단의 변경 없음은 최초 운영 결정 기록의 범위다. UI·파일 갱신 중 실제 팔 명령은 보내지 않았다.

다음 작업은 다섯 커스텀 자세의 역할 결정, 필요한 전환 경로 확인, 선택 물품과 저장 자세의 연결 규칙 합의다. 실제 이동은 기존 사용자 단계별 승인 방식을 유지한다.
