# LF-9 장소 목록·통계 최종 정리 — 정연우, 2026-11-05

## 완성한 범위

회수 관리에 관리자 통계와 습득 장소 목록 관리를 추가했다. 통계는 [상세 보고서](2026-11-05-admin-statistics.md)를 참고한다.

장소 목록은 등록기계 A/B/C의 호선·역을 기준으로 5개씩 보여주고 이전/다음 페이지, 새로고침, 장소 추가를 제공한다. 역 이름의 마지막 ‘역’과 앞뒤 공백을 정규화하고 같은 장소를 중복 저장하지 않는다. 동시 등록도 거래와 고유 제약으로 한 건만 저장한다. 추가·중복 확인 후 해당 장소가 있는 페이지를 표시한다.

기본 장소는 3개 역에 각 6개씩 만든 ‘가상 장소’다. 실제 장소 목록이나 이용 빈도를 주장하지 않으며 등록 순서로 표시한다. 현재 시연의 호선·역만 관리하고 같은 역 내에서 추천한다. 실제 팀 Places 구현의 접수 검증 범위와 맞춘 준비 화면이며 팀 장소 표는 변경하지 않았다.

버전 검사를 거쳐 초기화 전 저장 요청을 막고 알려진 전화번호·신분번호 등의 기존 개인정보 패턴을 거절한다. 이 검사는 이름·주소 등 모든 개인정보를 자동 판별한다는 뜻이 아니다. 입력 안내도 함께 표시한다. SQL은 매개변수로 전달하고 화면은 텍스트로 표시한다. 저장 성공 후 목록만 실패하면 성공 응답을 보존하고 새로고침을 안내한다.

시연 초기화는 가상 장소도 기본 목록으로 돌리므로 확인 문구를 갱신했다. 기존 사용자 시연 기록을 지우는 초기화는 이번 검증에서 실행하지 않았다.

## 최종 검증

- 신규 장소 Python 5개: 역별 분리·5개 페이지, 정규화·동시 중복 방지, 잘못된 역/개인정보 패턴/페이지 범위 거절, API 버전·초기화, 재시작 보존·SQL 문자열 매개변수 처리.
- 통계 9개·장소 5개 신규 메서드를 포함해 전체 Python **527개 실행, 실패 0개·환경 조건 14개 생략**. 실제 PostgreSQL 시험은 이번 실행에서 생략했다.
- 회수 6개·통계 4개·장소 2개·기존 자동완성 4개: Node **16개 통과**. 장소는 초기 5개·다음 페이지 1개 표시와 저장 성공/목록 실패 구분 검증.
- 실행 중인 API: USB 1건·전체 6건·어제 0건·미지원 조건 422, 장소 첫 페이지 5개·추가 장소의 해당 페이지 표시·동일 장소 재시도 중복 방지 확인.
- 실행 API에서 ‘가상 안내 데스크 옆’ 장소를 추가했다. 회수·도착·알림·이력 스냅샷은 검증 전후 동일하게 유지했다.
- 수동 UI 조작은 PC 사용자 입력과 겹쳐 중단했다. 새로운 화면 동작은 Node 기반 자동 검사로 검증했으며 수동 검증을 완료했다고 표시하지 않는다.

## 실제 연결 전 남은 것

직원 로그인·권한, PostgreSQL 통계 읽기 전용 계정·스키마 연결, 팀 확정 장소 데이터와 추천 순서, 운영 알림 기준과 전송 정책을 연결해야 한다. 가상 화면 완성과 실제 운영 완료는 구분하며 메인에 병합하지 않는다.
