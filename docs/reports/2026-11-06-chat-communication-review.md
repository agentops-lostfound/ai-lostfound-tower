# LF-5 안내 챗봇 의사소통·범위 제한·실제 응답 검증

## 구현 결과

기존에 규칙과 일치하지 않으면 바로 일반 재질문을 하던 경로에 로컬 sLLM 의미 해석을 연결했다. 인사·감사·분실로 속상한 표현, 다양한 사이트 이용 표현, 짧은 물건 설명과 이어 묻기를 처리한다. 분실물 서비스와 무관한 요청에는 지원하는 기능이 아니라는 문장과 지원 범위를 명확히 안내한다.

### 동작 구조

- 검증된 규칙과 기존 검색을 유지한다. 이해하지 못한 표현은 설치된 `qwen3-vl:2b-instruct`가 승인 문서 주제·검색·인사·미정 정책·무관한 요청·추가 확인 중 하나로 분류한다.
- 소형 모델이 복합 JSON의 분류·주제 조합을 잘못 생성하는 문제를 실제 시험에서 발견했다. 출력은 단일 `decision` 선택값으로 단순화하고 허용 목록·완료 상태를 검증한다. 임의 답변·SQL·접수 번호·인증 권한을 출력 인터페이스에 넣지 않는다.
- 의미 기반 안내도 승인 문서 원문 문단과 출처를 사용한다. 이미 확인된 정책 공백을 의미 검색으로 덮어쓰지 않는다. 물건의 품목·색상은 검증된 파서가 처리하고 실제 후보는 기존 읽기 전용 검색만 사용한다.
- `semantic_interpretation_used`는 의미 분류 사용, `generation_used`는 답변 근거 문단 선택에 모델을 사용했다는 뜻이다. 모델이 자유로운 안내 사실을 생성하는 구조는 아니다.
- 의미 분류는 8초 소켓 제한, 문단 선택은 기존 20초 제한을 사용한다. 같은 챗봇의 모델 사용 잠금을 공유하며, 장애·혼잡·형식 오류는 기존 안내·질문 확인으로 돌아간다. 전체 시간의 엄격한 상한을 보장하는 설정은 아니다.

## 발견하고 보완한 오류

| 문제 | 보완 |
|---|---|
| ‘사진 대신 키보드로 적기’를 신분증 사진 대체로 오해 | 신분증 대체 규칙의 범위를 좁혔다 |
| 같은 질문에 사진 업로드 문단을 안내 | 글 입력 선호를 먼저 확인하고 맞지 않는 모델 문단 선택은 대체한다 |
| ‘신원 검사’·‘그거 못하면?’를 잘못 이해 | 본인인증 표현 정규화와 이어 묻기 처리 보완 |
| ‘돈 내야 하나요?’에 비용 정책 공백을 안내하지 못함 | 비용 질문 표현 보완, 미정 정책 유지 |
| 분실 지갑을 소재로 한 랩 창작을 물건 검색으로 오해 | 창작·무관한 명령의 범위 확인 추가 |
| 무관한 질문에도 ‘더 구체적으로’ 배지 표시 | 두 채팅 화면에 지원 범위 밖 표시 추가 |

날씨가 언급됐다는 이유만으로 정상적인 물건 설명을 거절하지 않도록 ‘날씨가 안 좋아서 사진으로 먼저 설명하려고 해’도 시험했다. 감사와 속상함에는 서로 다른 응답을 제공한다.

## 실제 모델 시뮬레이션

실행: `python -m tools.check_chat_communication --model qwen3-vl:2b-instruct --output .cache/chat-communication-results-final.json --report docs/reports/2026-11-06-chat-communication-transcript.md`

- 합성 질문 62개, 임시 가상 DB 사용. 최종 기준 62/62 통과.
- 15개 질문에서 실제 sLLM 의미 해석을 사용했다. 모든 질문이 모델을 호출한 것은 아니다. 18개 무관한 질문·우회 요청은 거절했다.
- 인사·감정·사이트 안내·사진/글/음성 안내·개인정보·미정 정책·후보 검색·색상 변경·문맥 전환·개인정보 입력 차단·우회 요청을 포함한다.
- 상태와 출처만 맞아도 통과시키지 않도록 답변 문장 일부, 승인 문서의 근거·경로·URL, 후보 색상, 검색 미실행, 예약·로봇·인증 권한 미생성을 함께 검사했다. 출력된 의미 기반 안내와 주요 정책·복합 질문 답변도 읽어 관련성을 검토했다.
- 최초 50개 시험에서 13개 실패를 확인했고 수정했다. 이후 추가 표현 12개를 더해 보완했다. 이 질문들은 수정에 사용된 회귀 사례이며 독립적인 성능 평가나 모든 질문에서의 정확도 100%를 뜻하지 않는다.
- 최종 실행에서 준비된 모델의 질문별 최대 처리 시간은 약 0.55초였다. 초기 모델 적재·다른 GPU 작업·다른 PC 속도는 보장하지 않는다.
- 전체 질문과 실제 응답: [시뮬레이션 기록](2026-11-06-chat-communication-transcript.md).

## 회귀 시험·로컬 적용

- 통합 Python: 820건, 실패 0, 건너뜀 14.
- LF-5 Python: 815건, 실패 0, 건너뜀 13.
- Node 화면 로직: 39건 통과. 설명 입력 채팅 JS 구문 검사 통과.

- 화면의 범위 밖 요청 배지와 사용 안내를 위해 `web/chat-widget/widget.js`, `web/lost-input/assets/chat.js`, `web/chat-widget/README.md`도 변경했다. 공유 계약은 변경하지 않았다.

## 유지되는 한계

자유로운 범용 대화·창작·상식 답변은 제공하지 않는다. 모델을 사용할 수 없으면 모르는 표현의 의미 분류는 제한되며 확정 문서 안내·질문 확인과 알려진 범위 밖 요청 차단은 유지한다. 복합적인 모든 표현과 공격을 막는다는 보장은 아니다.

현재 후보는 가상 DB이고 실제 인증·필수 동의 확인·팀 DB·로봇 반환 연결은 기존 미완료 상태다. Docker가 꺼져 있어 실제 PostgreSQL 시험은 이번에도 건너뛰었다. GitHub·Jira·main은 변경하지 않았다.
