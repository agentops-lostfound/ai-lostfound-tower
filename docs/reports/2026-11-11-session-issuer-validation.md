# LF-5 사용자 세션 발급 기반 검증

2026-11-11 정연우. 사용자 응답 ‘인증 서버는 모름’에 따라 기존 외부 발급 서버를 가정하지 않고 서버 내부 발급 기반을 추가했다.
시작 HEAD `5686970`, 원본 브랜치/커밋 보존. 새 브랜치는 `LF-5-jeongyeonwoo-session-lifecycle`.

## 구현

- 신뢰된 서버 본인인증 결과와 최신 필수 동의 원본을 확인한 뒤 세션 발급.
- 무작위 토큰의 해시만 저장, 동일 증거 단일 사용, 명시 TTL/권한/정책.
- 단일 세션 및 사용자 전체 세션 철회, 발급/철회 직렬화와 저장 직전 재검증.
- PostgreSQL 쓰기 연결과 검토용 DDL. 기존 읽기 검증기와 같은 토큰/소유자 결합 규칙.
- 실제 운영 DB/스키마/.env/로봇/클라우드/원격 게시에는 변경 없음.

| 검증 | 결과 |
|---|---|
| 독립 작업 폴더 집중 시험 | 최종 18개 통과, 0.529초 |
| 원본 저장소 전체 Python 시험 | 1636개 검사 / 실패 0 / 환경 조건 제외 26개, 49.077초 |

집중 시험은 임시 파일 SQLite와 PostgreSQL 연결 대역만 사용했다.
발급→기존 검증기 조회→재시작, 토큰/원본 비저장, 동시 증거 재사용, 잘못된 증거·동의 거절,
발급 중 철회/만료, 다른 세션 보호, 사용자 전체 철회, 발급 커밋 응답 유실을 확인했다.
동의 조회 자체가 지연되어 증거가 만료되는 경우도 저장 전에 차단하는 것을 확인했다.
실제 PostgreSQL 및 실제 본인인증 원본과의 종단 검증은 하지 않았다.

전체 시험은 PYTHONUTF8=1, PYTHONDONTWRITEBYTECODE=1, LF_LANGFUSE=0, TOWER_SEND=0을 적용했다.
실제 DB 시험용 DSN들과 운영 검색/인증/영수증 DB·키 설정을 비워 실제 서비스에 접속하지 않았다.
위젯/프롬프트/모델은 수정하지 않아 실제 모델 평가나 위젯 시험을 반복하지 않았다.

상세: `docs/design/find_session_lifecycle.md`.
발급 API를 공개하거나 실제 본인인증을 구현한 것은 아니다. 안전한 실제 인증/동의 결과 조회와 철회 이벤트 연결은 남아 있다.
`center/schema.sql`이나 자동 마이그레이션은 수정하지 않았고 검토용 DDL은 실행하지 않았다.
