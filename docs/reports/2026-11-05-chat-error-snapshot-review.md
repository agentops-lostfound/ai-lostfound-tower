# 정연우 · 챗봇 보조 범위 오류 재현과 개선

## 범위와 작업 방식

팀원 도움 없이 확인할 수 있는 챗봇 실패 처리·검사 일관성을 점검했다. 사용자 지시에 따라 작업 중 GitHub·Jira 갱신 없이 로컬에서 재현·수정·시험을 완료하고 마지막에 묶어 기록한다. 실제 인증·DB·로봇 연결은 변경하지 않는다.

## 재현한 오류 1: 내부 실패 메시지 노출

`LazyChatbot` 생성기가 합성 비밀 문자열을 포함한 예외를 던지면 `/chat/health`가 해당 문자열을 그대로 반환했다. 실행 중 챗봇의 RuntimeError도 질문 응답의 503 detail로 노출될 수 있었다. 실제 자격증명은 사용하지 않았다.

준비 실패는 고정된 설치·설정 안내로, 실행 실패는 고정된 재시도 안내로 변경했다. 예외 원문을 상태 객체에 보관하지 않는다. HTTP 503과 생성 재시도 동작은 유지한다. 사용자가 잘못 입력한 값에 대한 기존 422 안내는 유지한다.

## 재현한 오류 2: 검사 도중 원본 장면 변경

검정 지갑 검사에서 파서가 실행 중일 때 생산자가 원본 장면의 색상을 흰색으로 바꾸면 후보가 사라졌다. 잠금은 같은 검사기의 동시 실행만 막았으며 외부 생산자의 버퍼 변경까지 막지는 못했다.

검사 크기·JSON 유효성을 확인한 직후 JSON 왕복으로 독립 장면 복사본을 만든다. 파서와 매처는 이 복사본만 사용하므로 이후 원본 갱신과 분리된다. 복사본은 요청 동안만 보유하며 파일로 저장하지 않는다. 기존 개인정보 차단·장면 크기 제한·NaN 거절·단일 검사 잠금·승인 금지를 유지한다.

## 검증과 판단

- 수정 전 두 신규 회귀 시험이 모두 실패하는 것을 확인했다.
- 수정 후 챗봇 API·특징 검사 관련 시험 17개 통과.
- LF-5 전체 Python 712개 실행, 실패 0·환경 조건 11개 생략.
- 위젯 파일 검사에서 발견한 파일 핸들 미종료 경고도 with 문으로 정리했다.

현재 혼자 계속할 수 있는 범위는 합성 질의 평가, 동시성·실패 복구·출처 회귀 검증이다. 실제 사진 성능 평가는 정답지·접수 ID 연결과 모델 준비가 필요하고, 실제 검색·예약·반환은 팀 인증 계약이 필요하다. 현재 검사가 실서비스 연결 완료를 뜻하지 않는다.
