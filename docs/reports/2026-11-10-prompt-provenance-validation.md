## 구현 내용

감독 모델은 서버가 허용한 행동 객체 중에서 제안하고, 코드 검사기가 업무 순서·권한·확인 대기·호출 상한을 확인한다. 모델 출력 형식이 맞더라도 코드 검사는 생략하지 않는다.

안내만 요청한 문장에서 불필요한 물건 검색을 추가하는 경로와 안내 핵심 절차 누락을 보완했다. 문서에 없는 정책은 미확인으로 처리한다.

프롬프트는 production/staging 라벨별로 분리하고 본문과 모델 설정을 같은 조회 결과에서 가져온다. 실제 모델 호출 직전에 역할·라벨·버전·본문 해시·모델·설정 출처·호출 수를 기록한다. staging을 못 가져왔다고 production을 대신 가져오지 않는다. 읽기 전용 프롬프트 조회와 trace 전송을 분리했다. 실제 SDK와 로컬 모의 API 시험도 포함했다.

## Langfuse 검증 범위

이번 500문항은 요청 라벨이 staging이지만 **클라우드 staging 프롬프트를 사용한 시험은 아니다**. 모든 3,780회는 로컬 코드 기본 프롬프트였으며 version=null이다. 혼합 버전 기록과 기록 잘림은 없었고, `staging_provenance_complete=false`로 정확히 남았다.

사용자가 2026-11-11 클라우드 검증은 나중에 진행하도록 지정했다. 실제 클라우드 조회·고정 50문항 trace·production 승격은 보류한다. 연결 키나 .env는 읽지 않았다. 팀 서버·실제 DB·로봇·Langfuse production은 변경하지 않았다.
