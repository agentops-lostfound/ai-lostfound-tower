# LF-5 관측 없는 챗봇 운영 보고 보완

## 발견과 변경

Planner 보완 버전 `f489afd`의 실제 전체 평가는 **499/500**으로 완료됐다.
원본 `planner-midm-500-20261111-02.json`을 보존했다. planner v2 제안 393회는 모두 수락됐고, 실패는 직원 관제 474번 한 건이었다.

474번은 질문 관측이 없는데도 모델이 실패율 0%, 평균 응답 시간 0ms, 정상 작동·우수한 품질이라고 썼다.
기존 숫자 검사는 다른 집계의 0과 같은 숫자인지만 검사해, 관측 부재를 정상으로 해석하는 오류를 막지 못했다.
정답 문구만 덧붙이지 않고 데이터 전제 조건을 코드에서 보완했다.

- 명시적인 챗봇 운영 요청의 초점을 다른 관제 영역으로 바꾸지 못하게 했다.
- 챗봇 질문 관측 수가 양의 정수가 아니면 보고 문장 생성을 호출하지 않는다.
- 지표 조회 불가, 관측 0건, 잘못된 관측 수를 구분하고 품질·오류율·응답 시간을 판단할 수 없다고 표시한다.
- 정상적인 관측이 있으면 기존 숫자 검사를 통과한 모델 보고는 계속 허용한다.
- 챗봇뿐 아니라 반환·처리·경보·챗봇 관측이 모두 없는 경우에도 생성 보고를 호출하지 않고 관측 부재와 코드 집계만 안내한다.

운영 DB·수집 값·평가 정답·배점은 변경하지 않았다.

## 검증

- 관제 집중 시험 **17개 통과**. 관측 없음/조회 불가/잘못된 수에서 생성 차단, 초점 보존, 양의 관측에서 모델 보고 허용을 포함한다.
- 전체 Python **1,726개 검사, 실패0, 제외35**, 57.669초 (호출 집계 후속 시험 추가 전).
- 규칙 **628/628**, 무결성 56개 파일 오류0. 당시 실행 중인 모델 결과1개는 부분 실행으로 구분했다. `planner-rules-20261111-03.json`.
- 실제 모델 직원 관제 **30/30**, 124.75초. 원본 `planner-midm-staff-20261111-01.json`.
- 474번 실제 응답은 관측 기록이 없어 응답 품질·오류율·응답 시간을 판단할 수 없다고 안내했다.

30문항 재검사를 전체 500문항 점수로 합쳐 설명하지 않는다. 최신 전체 재측정과 보충 실제 모델 검증을 별도로 진행한다.

## 모델 호출 집계 정정

검증 도구가 AgentBrain을 미리 import하면서 해당 모듈의 전송 함수 별칭이 기록기를 우회했다.
영향을 받은 위 planner 01/02회와 직원 관제01회의 `model_calls`는 일부 관측치이며 전체 호출 수로 사용할 수 없다.
문항 점수·응답·실행 시간과 논리적 planner/supervisor 판정은 영향을 받지 않는다. 원본을 덮어쓰지 않고 `model-accounting-correction-20261111-01.json`에 해석을 기록했다.

두 전송 경로를 함께 감싸도록 보완했고, 실제 연결을 차단한 전송 대역 시험에서 보고서 호출 수가 전송 횟수와 일치함을 검증했다.
다음 실제 평가부터 이 기록기를 사용하며 관제 분석 소스 SHA256도 추가한다.
별도 통합 버전 `latest-team-midm-500-20261111-01.json`은 지연 import하던 이전 도구로 측정돼 이 집계 누락의 영향을 받지 않았다.
