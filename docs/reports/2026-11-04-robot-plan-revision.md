# 로봇 연동 계획 수정 — 팀원 의견 수용

작성일: 2026-11-04. [로봇 연결 계획](../design/vision-robot-integration-plan.md)에 팀원 의견을 반영한 경과와 차이를 기록한다. 사용자와 검토한 수정 방향이며 팀 전체 계약 확정·실물 검증·로봇 코드 적용 완료를 의미하지 않는다.

## 수용한 방향

1. 마커는 작업대 좌측 상단 1개로 먼저 시작하고, 작업대 여러 위치에서 좌표 오차를 측정한다. 정확도·가림 대응이 부족할 때 추가한다.
2. robot_stop은 정지만 수행하는 의미로 분리한다. Home 복귀는 직원이 상태를 확인한 뒤 별도 버튼/명령으로 요청하는 방향으로 계획한다.

## 본래안과 수용안 비교

| 항목 | 본래안·기존 표 | 팀원 제안 | 수용 후 계획 |
|---|---|---|---|
| 마커 배치 | 네 모서리에 마커 4개를 배치하는 안 | 좌측 상단 마커 하나로 원점을 인식 | 1개로 시작하되 실측 검증 결과에 따라 추가 |
| 원점 의미 | 작업대 원점·축을 합의하고 좌표 변환 | Arm의 원점이 필요하다는 관점 | 마커 기준점과 로봇 베이스 원점의 관계를 측정해 연결. 두 점이 자동으로 같다고 가정하지 않음 |
| 보정 허용 | 표에는 4개 모두 검출·오차 5mm 제안 | 단일 기준 마커 중심의 간단한 구성 | 4개 강제 대신 독립 지점 실측 시험. 현재 코드의 재투영 3mm와 실제 접근 오차를 구분하고 허용 실측 오차는 합의 후 결정 |
| 정지와 복귀 | 현재 도구 계약에는 즉시 정지·Home 복귀가 결합돼 있음. 앞선 검토에서는 분리를 제안 | 전달 후 복귀 의미인지 질문하고 직원 복귀 버튼 제안 | 실패 정지와 복귀 이동을 분리하는 방향은 양쪽 의견이 일치. 직원 요청 Home을 계획에 구체화 |
| 정상 전달 후 동작 | 정지·복귀 용어가 혼재 | 원점이 기억돼 있으면 매번 복귀가 필요하지 않을 수 있음 | 매번 Home 복귀를 필수로 가정하지 않고, 정상 전달 후 대기 자세·다음 동작은 별도 운영 흐름으로 결정 |

정지 분리는 새로 뒤집은 결정이 아니라 기존 검토와 팀원 의견이 같은 방향임을 확인한 것이다. 기존 계약의 robot_stop은 실패 경로에서도 호출되므로 '물품 전달 후 복귀'만으로 해석하면 안 된다.

## 마커 1개 시험에 필요한 조건

- ArUco는 마커 하나에 모서리 4점이 있어 현재 보정 코드의 대응점 조건을 충족할 수 있다. 중앙 점 하나만 사용해 좌표 변환을 완성하는 방식이 아니다.
- 마커 ID·실제 크기·방향·원점으로 삼을 중심/모서리·작업대와 로봇 베이스의 관계를 정한다.
- 마커 근처·작업대 중앙·가장 먼 쪽을 포함한 독립 측정점의 오차를 기록한다. 마커에서 멀어질 때 정확도가 유지되는지 확인한다.
- 마커 자신의 모서리 4점에 잘 맞는 것만으로 전체 영역 검증을 끝내지 않는다. 마커 미검출·가림·카메라/마커 이동 때 무효화 조건을 정한다.
- 물체 높이, bbox 중심과 파지점 차이, 접근 높이·그리퍼 자세는 별도 검증한다.

## 원점과 Home의 구분

작업대 원점은 물체 위치를 표현하는 기준, 로봇 베이스 원점은 로봇 좌표계 기준, Home은 특정 관절/말단 자세다. 관절 기준을 설정하는 호밍·초기화도 별도 절차다. 좌표계 원점을 기억한다고 현재 위치와 초기화 상태가 보장되거나 모든 상황의 복귀가 불필요해지는 것은 아니다.

Home 버튼은 복귀 요청 경로로 계획하며, 실제 이동 허용 여부는 로봇 상태·장애물·직원 확인 등 담당자가 정한 조건을 따른다. 정지 명령은 자동 복귀를 시작하는 트리거로 사용하지 않는 방향으로 합의한다.

## 변경 범위와 남은 합의

다음 확정 항목은 마커의 실제 설치 지점·크기·원점·축, 작업대→로봇 변환, 독립 실측 시험과 허용 오차, 실제 정지 구현, Home 복귀 계약·버튼·허용 조건이다. 촬영 유효시간·GPU 대기·집기 재시도 계획은 기존 문서대로 별도 검증한다.
