# 정연우 · 최신 팀 위젯 오류 점검과 로컬 보완

## 작업 기준

main `319f631`(PR #77)의 다른 PC 접속 설정·화면 설명을 로컬 작업 브랜치에 반영했다. 네트워크 공개 설정·방화벽·실제 DB는 변경하지 않았다. GitHub·Jira 반영은 사용자의 하루 종료 지시 전까지 보류한다. 역할은 변재원 챗봇/위젯 담당, 정연우 보조이며 팀 위젯의 동작 오류만 보완했다.

## 재현·수정

1. 실패한 예전 질문의 재시도가 가장 최근 사용자 메시지를 삭제했다. 이제 해당 요청의 메시지만 참조해 교체한다.
2. 다른 질문을 전송 중인데 예전 재시도 버튼을 누르면 메시지만 삭제됐다. 전송 중에는 재시도가 대화를 수정하지 않는다.
3. 응답이나 응답 본문이 끝나지 않으면 전송이 무기한 잠겼다. AbortController로 본문 처리까지 30초 제한을 두고 재시도 안내와 잠금 해제를 보장한다.
4. 창을 닫은 뒤 응답이 도착하면 숨겨진 입력란으로 포커스를 가져왔다. 창이 열려 있고 사용자가 위젯 안에서 작업하는 경우에만 입력란에 포커스를 돌린다. 열기 직후 닫아도 지연된 포커스를 실행하지 않는다.
5. 500자가 넘는 질문을 자동으로 잘라 보내 원문 끝의 조건을 잃을 수 있었다. 입력을 유지하고 사용자가 줄이도록 안내한다.
6. 잘못된 성공 응답(예: sources에 null)이 화면 렌더링 오류와 전송 잠금을 일으켰다. 응답 구조를 먼저 확인하고 실패 응답처럼 재시도 가능하게 처리한다. 정리 작업은 finally에서 실행한다.

## 검증

새 Node 시험 7개 중 수정 전 6개 실패·1개 통과를 확인했고, 수정 후 7개 모두 통과했다. 요청 성공 시 시간 제한 타이머 정리와 전송 중 작성한 다음 질문 유지도 포함한다. 실제 위젯 스크립트를 모의 DOM에서 실행하는 시험이며 브라우저 실기기·스크린리더·모바일 표시 검증은 아니다.

기존 본인인증·개인정보 검사·검색 권한·단일 장면 매칭 검사의 승인 금지는 변경하지 않았다. 새로운 서비스 기능·실제 인증·예약 연결을 완료한 것으로 해석하지 않는다.

## 후속: 삭제·실패 복구와 재시도 맥락

- 응답 대기 중 ‘대화 지우기’가 아무 일도 하지 않는 것을 재현했다. 브라우저 요청을 중단하고 메시지·미전송 초안·대화 맥락을 지우며 즉시 새 질문을 허용한다. 이전 요청의 늦은 성공·실패·정리 작업이 새 대화에 메시지를 추가하거나 전송 잠금을 풀지 못하게 요청 식별자로 구분한다. 서버에서 이미 수행한 처리를 취소·삭제한다고 주장하지 않는다.
- 예전 실패 질문의 재시도가 작성 중인 새 질문을 지우던 문제를 수정했다. 같은 입력을 직접 전송할 때만 입력란을 비운다.
- 지갑의 색상 질문 실패 후 USB를 검색하고 색상 질문을 재시도하면 USB 맥락으로 해석되는 것을 재현했다. 각 실패 질문의 원래 질문 이력을 보존해 재시도하고, 성공하면 해당 흐름을 다음 이어 묻기의 기준으로 사용한다. 화면의 다른 질문은 삭제하지 않는다.
- 일시적인 초기 연결 실패 후 다시 열어도 상태를 확인하지 않았다. 실패·준비 중인 경우 다음 열기에서 재시도하며, 같은 상태 조회가 진행 중이면 중복하지 않는다.
- 신규 6개 회귀 시험을 추가했다. 수정 전 해당 시험이 실패하는 것을 확인했고 수정 후 위젯 총 13개가 모두 통과했다. 대화 삭제 후 늦은 성공·실패 격리와 다음 대화 맥락도 검증한다. 실제 브라우저 조작·서버 처리 취소 검증은 아니다.

변경은 로컬에만 보존하며 하루 종료 지시 전에는 GitHub·Jira에 반영하지 않는다.
