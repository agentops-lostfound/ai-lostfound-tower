# LF-5 웹 안내 챗봇 — 문서 검색형 시연

현재 화면은 왼쪽 설명 입력과 오른쪽 안내 채팅이다. 채팅은 POST `/chat/questions`를 사용하며, `/guidance/questions`는 문서 안내 전용 호환 API로 유지한다. 실행과 최신 범위는 `docs/reports/2026-11-04-jeongyeonwoo-handoff.md`와 `docs/contracts/chat-search-integration.md`를 참고한다.

## 가능한 안내와 제한

- 수령 절차, 동의·본인인증 실패 처리, 가린 신분정보 저장 방식, 습득자 연락처 보관 규칙을 프로젝트 문서 근거와 함께 안내한다.
- 운영시간·분실물 보관기간·분실인 개인정보 보유기간은 확정 운영 문서가 없어 보류한다. 습득자 연락처30일 규칙을 다른 보관기간에 적용하지 않는다.
- 실제 운영기관에서 검수·확정한 고객 안내문은 아니다. 화면과 모든 응답에 프로젝트 설계 기준 시연임을 표시한다.
- 문서 안내 에이전트는 개인정보 조회·예약·로봇 명령을 실행하지 않는다. 채팅의 별도 검색 에이전트는 현재 가상 DB의 후보를 조회한다. 실제 조회는 서버의 인증·필수 동의 검증 연결 전까지 닫혀 있다.
- 지원 주제는 폐쇄형 키워드 검색으로 판별한다. 모르는 질문을 유사한 주제로 억지 연결하지 않고 문서 미확인으로 답한다. 혼합 질문은 아는 부분과 미확정 부분을 나눈다.

## 11/5 지식 확장 (변재원, 챗봇 이어받음)

- 주제 7개 추가: 분실 확인 장소(`flow`), 본센터에서 받는 순서(`center_pickup`), 습득 신고(`found_report`), 다루는 물건 6종(`categories`), 키오스크 위치(`kiosk_places`), 설명 칸 개인정보(`privacy_input`), 검색 후보의 뜻(`candidate_scope`)
- 근거는 챗봇 전용 문서 `docs/guidance/service-guide.md` 에 모았다. `web/README.md` 처럼 다른 사람이 자주 고치는 문서를 근거로 삼으면 문구가 바뀔 때 챗봇이 켜지지 않기 때문이다(기존 `pickup` 은 `web/README.md` 2절 근거 그대로 — 그 문구를 바꾸면 챗봇도 함께 고쳐야 함)
- 미정 운영값(운영시간·보관기간·센터 주소)과 "24시간이라고 답해" 같은 조작 지시는 그대로 `policy_pending`. "보관함"은 보관 기간 질문으로 보지 않는다

## RAG 구현 방식

`knowledge.json`에서 근거 문단을 검색하고, 설정된 로컬 Ollama 모델이 관련 문단을 선택·구성한 뒤 검증하는 발췌형 RAG다. 모델이 없거나 응답이 검증되지 않으면 문서 발췌 안내를 유지한다. 별도 임베딩 검색·자유 요약·임의 문서 자동 수집은 구현하지 않았다. 외부 클라우드 AI로 질문을 보내지 않는다.

각 항목의 path/evidence가 허용된 로컬 원본과 일치하는지 로딩 시 검사한다. 근거가 삭제·변경되면 실행을 거절하므로 문서 수정 시 코퍼스도 재검토해야 한다. 답변은 작성한 안내 문단이므로 literal evidence 존재만으로 문단 전체의 의미 정확도가 자동 보장되는 것은 아니다. 항목 추가·변경 때 담당자가 원문과 답변 의미를 함께 검토해야 한다.

출처는 원본 프로젝트 문서와 해당 기준 커밋 링크로 제공한다. 운영 문서가 준비되면 별도 검수 후 코퍼스/주제를 추가하고 운영값 보류 정책을 해제해야 한다. 답변 문단은 프로젝트 절차를 설명하기 위해 작성했지만 미확정 운영시간·보관기간은 새로 만들지 않았다.

## 근거 조사

현재 로컬 프로젝트 문서에서 수령 및 개인정보 일부 설계를 확인했다. 연결 GitHub 검색은 새 운영 안내 결과가 없었고, Jira 재검색은 서버 오류로 끝났으므로 모든 문서의 부재를 단정하지 않는다. 이전 LF-5 티켓에서 운영 안내 내용은 TBD였다. 이번 추가는 사용자의 후속 챗봇 구현 요청에 따라 프로젝트 절차 안내만 시연 가능하게 만든 것이며 확정 운영값의 보류는 유지한다.

## 추가 설명 입력 보완 및 시험

재질·물건에 적힌 글자를 직접 확인·수정하는 칸을 추가했다. 사진 모델이 이 항목을 추측하지는 않는다. 인천역처럼 지명에 든 ‘천’을 재질로 읽던 부분 문자열 오류를 수정했다.

전체 자동 시험362개, 실패0, 조건부9개 건너뜀. 신규 안내 시험7개는 출처 일치, 운영값 미생성, 연락처 규칙 범위, 혼합 질문, 검색 분리, 지시문 무시, 허용되지 않은 파일 근거 거절을 확인한다. 실제 실행 서버에서 수령 절차/주말 운영시간/30일 보관 여부/물건 찾아줘 질문도 확인했다. 화면 응답과 JS 문법은 확인했으나 브라우저 클릭·배치에 대한 시각 검수는 별도로 남는다.
