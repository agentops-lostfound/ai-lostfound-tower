# Qwen 속도 개선 실험 순서

2026-11-04. 사용자 요청에 따라 실험 답변 상단에 단계 번호·상태, 하단에 다음 행동·단계를 표시한다. 각 변경은 한 번에 하나씩 비교하고 결과가 나쁘면 기존 동작을 유지한다.

1. **압축 출력**: 기존 특징 내용을 유지하면서 키 반복·중첩 구조 생성량 감소 시험.
2. **반복 생성 억제**: 정상 특징을 손상시키지 않으면서 반복·재시도와 긴 지연 감소 시험.
3. **추론 엔진 검토**: 해당 Qwen VL·NF4·Windows·RTX 3050 호환 공식 근거를 확인한 뒤 별도 환경에서 비교. 지원이나 속도 향상을 미리 보장하지 않는다.
4. **YOLO 상주 검토**: 검출 정확도와 별도로 프로세스·모델 초기화 비용 계측/재사용 비교. 필요성과 기대 이득을 먼저 확인한다.

변하지 않은 장면 특징 재사용은 이후 시스템 최적화 후보이며 이번 네 단계에 포함하지 않는다. 실물 교체·이동을 놓치면 잘못된 반환이 될 수 있어 무조건 캐시하지 않는다.

## 1/4 압축 출력 — 실험 종료·채택 보류

사용자 자동 폰 crop 384 결과는 7.3158/6.7063/6.7254초(중앙값 6.7254), 3회 모두 재시도·누적 65토큰. baseline 5.2082초·86토큰·재시도 없음 대비 약 29% 느리다. 최종 category=unknown, colors/materials에 의미 없는 문자열 0,0, shape=null, 구별 특징 빈 배열로 정보 품질이 악화됐다. 원래 스키마는 문자열 배열을 검사하므로 0,0도 자료형상 통과하지만 유효한 색·재질 정답이 아니다. 형식 통과를 의미 정확도로 보지 않으며 운영에 적용하지 않는다. 압축 변환기 자체가 데이터를 임의 보정한 것은 아니고 모델 원출력·첫 실패 로그는 추가 확인 전 미확정이다.

## 2/4 반복 생성 억제 — 실험 종료·기본 적용 보류

정상 384에서 옵션 적용 3회 6.1312/5.6727/5.6220초(중앙값 5.6727), 출력 86토큰·동일 특징·첫 시도 성공. 과거 무옵션 5.2082초 대비 약 8.9% 느린 관측이며 별도 세션 변동 가능성으로 전부 옵션 비용이라고 단정하지 않는다. 실패 조건의 긴 지연 억제 효과는 있으나 정상 경로 가속 근거가 없어 기본 적용하지 않는다.

## 현재: 3/4 추론 엔진 검토 — 공식 호환 확인·로컬 설치 상태 확인 전

2026-11-04 공식 자료 확인: https://ollama.com/library/qwen3-vl:2b-instruct 에 2B Instruct 모델과 Ollama 0.12.7 요구 안내가 있다. https://docs.ollama.com/windows 는 네이티브 Windows·NVIDIA 지원, https://docs.ollama.com/gpu 는 RTX 3050 지원 목록을 제공한다. 사용자 보고 드라이버 610.88은 확인한 Windows 최소 요구 551.61보다 높다. 실제 메모리 배치·버전·추론 성능 검증은 남아 있다.

우선 Ollama의 기존 설치 버전·보유 모델·로드 상태를 조회한다. 기존 HF NF4 환경은 보존하고 다른 GPU 모델을 동시에 로드하지 않는다. Ollama 후보는 동일 Qwen3-VL 2B Instruct 계열이나 가중치 변환·양자화·processor·template이 달라 엔진 하나만 바꾸는 엄밀한 실험이 아니며 기존 NF4 캐시를 그대로 쓰는 것도 아니다. 모델 정보·실제 GPU 배치·입력/출력 토큰과 원래 8키 검증·정확도를 기록한 뒤 비교한다. 새 엔진이 더 빠르다고 미리 주장하지 않는다. 다음 사용자 행동은 ollama --version / ollama list / ollama ps의 출력 확인이며 설치 유무 확인 전 기존 설정을 변경하지 않는다.

현장 시험 1 결과: 같은 자동 폰 crop 256·no_repeat_ngram_size=12에서 요청 7.3138/6.8951/6.9442초(중앙값 6.9442), 3회 모두 첫 시도 JSON 성공·119 출력 토큰. 원래 실패 조건 27.2057초·2회 생성·598 누적 토큰 대비 긴 반복/잘림·재시도는 감소했다. 그러나 distinctive_features에 three circular camera lenses의 중복과 표현 변형이 남아 의미 반복 해결로 보지 않는다. 12-token 정확 반복 억제는 짧은 문구나 바꿔 쓴 의미 반복을 막지 못한다. 정상 384 baseline 5.2082초보다 느리므로 전체 기본 적용은 보류한다. 다음은 같은 384에서 옵션 유무를 비교해 정상 경로 회귀를 확인한다. 후처리 중복 제거만으로 이미 소모한 생성 시간을 되돌릴 수 없으며 무조건 짧은 n-gram을 추가 적용하지 않는다.

baseline 프롬프트·8키 JSON·토큰 상한·재시도를 유지하고 no_repeat_ngram_size=12만 추가하는 실험이다. 실제 실패가 재현됐던 동일 자동 폰 crop·256에서 원래 약 27.21초·2회 생성·598토큰과 비교한다. --compact/--concise는 동시 사용을 거부한다. --profile --max-edge 256 --no-repeat-ngram-size 12로 3회 입력한다. 12는 확정 최적값이 아니라 시험값이다. 반복 억제가 합법적인 반복·위치·문자 등을 손상하거나 다른 잘못된 표현으로 변하게 할 수 있어 시간·JSON뿐 아니라 특징도 확인한다. 성공하면 정상 baseline 384 조건에서 회귀 확인 후 채택 여부를 정한다. 효과 미확정 상태이며 옵션 생략 시 기존 generate 동작이다. source-root 파일·공통 계약은 변경하지 않는다.

## 압축 출력 실험 구성 참고

tools/qwen_session.py --compact --profile --max-edge 384를 사용한다. 원본 source-root와 모델·384·deterministic 생성·재시도·토큰 상한은 기존과 같다. --concise와 동시 사용은 거부한다. 자동 폰 crop의 기존 baseline 중앙값 5.2082초·출력 86토큰·3회 첫 시도 성공을 참고하되 별도 세션 비교의 한계를 유지한다.

실험에서는 출력이 [category,colors,shape,materials,logos_or_text,sticker_status,stickers,distinctive_features] 순서의 8칸 배열이다. stickers는 [shape,position] 쌍들의 배열이며 나머지 자료형·불확실값·가시 근거 원칙은 유지한다. Python 변환기가 이를 기존 8키 dict로 바꾸고 upstream validate_response로 다시 검증한다. 누락·자료형 오류를 임의 보정하지 않는다. 공통 contracts·기존 source-root 파일·운영 시퀀스는 수정하지 않는다.

프롬프트는 압축 형식을 설명하도록 교체되므로 순수 키 토큰 제거만의 효과로 귀속하지 않는다. 원래 최종 JSON 생성 뒤 키를 지우는 후처리는 가속이 아니며 이 실험과 다르다. 입력 토큰·출력 토큰·generate 시간·요청 시간·재시도·변환된 특징을 함께 비교한다. 정상 종료·JSON 검증이 정확도를 입증하지 않는다.

사용자는 git pull 후 기존 qwen_session 명령 끝에 --profile --max-edge 384 --compact를 붙여 실행한다. 검증된 자동 폰 crop을 3회 입력한 뒤 exit하고 로그를 공유한다. 개선 시에도 지갑·립밤 및 같은 외형 물품에 필요한 특징이 유지되는지 다음 확인을 거친다. 오류/회귀면 --compact를 빼면 원래 baseline으로 돌아간다. 자료형 변환·오류 거부·원본 검증 전달은 GPU 없이 시험하며 실제 속도·형식 준수는 현장 실행 전 미확정이다.
