# LF-5 Planner 구조화 읽기 지시 계약

Planner는 사용자의 원문을 임의 명령으로 만들지 않고, 서버가 허용한 읽기 작업과 입력 참조를 고른다.
저장·접수·취소·인증·직원 관제의 실행 권한은 이 계약으로 열리지 않는다.

## 모델 제안과 코드 검증

`agents/chat_planner.py`의 v2 계약은 `{version: 2, steps: [...]}`다.
단계는 다음 조합 중 하나만 허용한다. 작업은 최대 2개이며 같은 일꾼은 중복될 수 없다.

| worker | task | input_ref |
|---|---|---|
| guidance | answer_guidance | question 또는 guidance_part |
| item_search | search_candidates | question 또는 search_part |

JSON 스키마의 단계 enum과 코드 검사기가 **전체 조합**을 검증한다. 안내 일꾼에 검색 작업·검색 입력 참조를 붙이는 교차 조합도 거절한다.
생성 스키마의 최상위 enum은 안내 단독·검색 단독·검색 후 안내의 완성 계획 3개로 제한한다.
실제 Mi:dm이 단계 enum만 사용할 때 같은 일꾼을 반복한 문제를 막기 위해 배열 전체를 제약한다.
버전 bool, 추가 필드, SQL·자유 지시문·입력 원문 필드, 미등록 일꾼·작업·입력 참조는 받지 않는다.
모델 입력의 `required_workers`는 코드가 정한 필수 업무이며, 누락하면 코드가 보완한다. 기존 검색 의도·품목·습득자/주제 밖 검사도 계속 적용한다.

`input_ref`는 텍스트가 아니라 코드 소유 참조다. `question`은 검증된 현재 질문, 나머지는 기존 `sub_question`이 분리한 안내/검색 부분이다.
모델이 새 문장·DB 인자·사용자 ID·권한·확인 토큰을 지정할 수 없다.
최종 실행 계획이 검색·안내 복합 작업이면 각 질문 부분, 단일 작업이면 질문 전체로 입력 참조를 코드가 확정한다.
필수 검색을 추가하거나 잘못 제안된 검색을 제거한 뒤에도 최종 계획에 맞는 참조를 사용한다.
제안과 달라진 참조는 `input_refined`에 일꾼 이름만 기록한다. 범위가 잘못된 안내 입력 때문에 핵심 답이 빠지는 것을 막는다.
실행 단계 경계에서도 `WorkInstruction`을 다시 검사하고, 잘못된 내부 지시는 코드의 기본 지시로 대체한다.

## 흐름과 호환

`AgentBrain.plan_contract`는 검증된 `PlanningDecision`을 반환한다. 기존 `plan()` 목록 API도 같은 검사 결과를 사용한다.
그래프는 검증된 지시를 단계에 연결하고, supervisor가 선택한 단계의 입력을 실제 일꾼에게 넘긴다.
외부 화면에는 기존 한국어 계획 문장을 사용하며 계약 코드·입력 참조를 새로 노출하지 않는다.

기존 production 프롬프트의 `{steps: ["guidance", ...]}`는 정확한 필드·허용 일꾼·개수 검사를 통과한 경우만 제한적으로 변환한다.
이 호환을 `bounded_legacy_v1`으로 기록하며 v2 성공으로 세지 않는다. 잘못된 출력·모델 장애는 기존 규칙 계획을 사용한다.
접수·직원 관제 경로는 기존 코드가 선택하며 planner의 읽기 지시 제안으로 전환하지 않는다.

## 기록과 모델 평가

Planner 모델 생성 trace는 검증된 상수 필드나 거절 사유 코드만 남기고 알 수 없는 원문 필드는 버린다.
그래프에는 계약 판정과 기존 검색 경계 판정을 기록한다. 전체 모델 원문을 감사 결과에 붙이지 않는다.
지시 객체 출력을 위한 planner 생성 상한은 192토큰이고, 다른 역할의 기존 상한은 유지한다.

`tools/check_chat_planner.py`는 기존 500문항에 구조화 단일/복합·구버전·악성 제안 대역을 적용한다.
`tools/validate_chat_midm.py`는 실제 로컬 모델에서 v2 수락·이전 형식 변환·거절 횟수를 분리해 보존한다.
규칙 점수나 대역 점수가 실제 v2 모델 준수율을 대신하지 않는다.

클라우드 프롬프트 게시·production 전환은 하지 않았다. 운영 인증·DB 저장·영속 작업 복구는 별도 계약이다.
