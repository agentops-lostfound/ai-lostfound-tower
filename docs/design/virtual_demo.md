# 전체 가상 시연 — 디스코드 한 줄로 습득부터 인계까지 (LF-29, 11/4)

> 한줄 설명: 등록기계·Qwen·탑뷰 카메라·로봇팔을 **움직임까지 보이는 가상 부품**으로 바꿔 끼우고, 디스코드 분실물 채널에 쓴 메시지 한 줄로 관제탑 전체 흐름(습득 → 회수 → 찾기 → 반환 → 인계)을 돌린다.
> 관제탑 자체(서비스·반환 흐름·김건태 매칭 정책·안전 규칙·GPU 사용권·정지 버튼)는 **진짜 코드 그대로** 지나간다. 진짜 부품이 생기면 그 부품만 바꿔 끼우면 된다.

코드: `agents/sim_world.py`(가상 세계·부품) · `agents/sim_director.py`(연출기) · `agents/live.py`(진행 기록판) · `web/live/index.html`(실시간 화면) · `tools/lostfound_bot.py`(분실물 봇) · 시험 `tests/test_sim_demo.py`

## 1. 보이는 장면

```
[디스코드 #분실물] "서면역 5번 출구 앞에서 검정 카드지갑 주웠어요"
  봇: 📥 습득물 접수 S-20261104-0001 · 서면역 5번 출구 앞 (KIOSK-C) · 지갑 · 검정 · 직사각형
  진행판(메시지 하나가 단계마다 바뀜)
    ✅ 등록기계 접수 → ✅ Qwen 특징 분석 → ✅ 본센터로 회수 → ✅ 보관함 배치(5번 칸)

[디스코드 #분실물] "검정 카드지갑 잃어버렸어요, 서면역에서요"
  봇: 📝 찾기 요청 C-20261104-0001 → 후보 S-20261104-0001 · 확인 질문 통과
  진행판
    ✅ 찾기 요청·확인 질문 → ✅ 메인 AI 승인 → ✅ 방문·직원 확인 → ✅ 탑뷰 촬영(물건 5개)
    → ✅ 매칭 → ✅ 사전 접근 → ✅ 집기 → ✅ 제출보관함 전달 → ✅ 인계 완료
```
- 같은 시간에 **실시간 화면 `/live`** 에서 보관함 탑뷰 그림 위로 물건이 놓이고, 로봇팔이 물건으로 다가가 집어 H-1 제출보관함으로 옮기는 모습이 보인다
- 관제 채널(#관제-진행·#관제-알림)에는 지금과 같은 단계 메시지가 간다(`TOWER_SEND=1` 일 때)
- 확인 질문: 고른 후보에 비공개 특징(보이는 글자·스티커)이 있으면 봇이 먼저 묻는다. 예) 보조배터리 → "물건에 적힌 글자가 있다면?" → `VOVA`

## 2. 구조 — 무엇이 가상이고, 무엇이 진짜인가

```
 디스코드 #분실물 ──> 분실물 봇(tools/lostfound_bot.py) ──HTTP──> 관제탑 API (TOWER_SIM=1)
                                                                  │
            ┌────────────── 연출기(sim_director) ─────────────────┤ 사람·화면이 하던 일을 대신
            │  create_item · set_item_features · create_claim       │ (진짜 화면과 같은 입구만 부름)
            │  start_return · handover                              │
            v                                                       v
   관제탑 서비스·반환 흐름·매칭 정책·안전 규칙 (진짜)  ──부품 연결판──> 가상 부품
                                                                    ├ SimWorld  : 접수 저장 + DB 부품
                                                                    ├ SimTopview: 탑뷰 → result_with_qwen.json 모양 → 진짜 변환기
                                                                    └ SimRobot  : mm 좌표로 움직이는 팔(정지·원점 복귀)
   모든 관제 메시지 ──> 진행 기록판(LiveBoard) ──> 실시간 화면 /live · 봇 진행판
```

| 단계 | 가상 시연에서 하는 것 | 지키는 약속(함수 모양) | 진짜로 바꿀 때 |
| --- | --- | --- | --- |
| 등록기계 접수 | 연출기가 `create_item` 호출 | `POST /items` | 김재민 등록기계 화면(PR #48)이 같은 주소로 보냄 → 연출기 ① 생략 |
| Qwen 특징 | 메시지 글 → Qwen 모양 JSON(`sim_qwen`) → `set_item_features` | `POST /items/{id}/features` `{"qwen": …}` | 김건태 Qwen 작업이 같은 주소로 보냄 |
| 회수·보관함 배치 | 세계에서 물건을 옮기고 상태 `회수 중 → 본센터 보관` | `db_set_status(changed_by="staff")` | 직원 상태 변경 화면(TBD) |
| 찾기 요청 | 후보 카드(공개 특징) → 확인 질문 → `create_claim` | `POST /claims` | 분실인 웹(김재민 LF-2·4·6) |
| 반환 시작 | `start_return(claim_id + 현장 관문 3개)` | `POST /returns` | 직원 화면 "반환 시작" |
| 탑뷰 | 보관함을 "찍어" `result_with_qwen.json` 모양 → **진짜 `adapt_report`(보정 관문 포함)** | `vision_topview()` | `.env TOWER_VISION_FILE=결과 폴더` 만 넣으면 가상 시연 중에도 진짜 탑뷰로 바뀜 |
| 매칭 | **진짜** 김건태 정책(`PolicyMatcherPart`) | `match_item()` | 이미 진짜 |
| 로봇팔 | 작업대 mm 로 움직임·집기·제출보관함·정지·원점 | `robot_approach(center_mm, center_px)` 외 5개 | 로봇 부품(LF-11·19·21)을 `robot=` 에 꽂음 |
| 인계 | 3초 뒤 자동 `handover`(또는 `#수동인계`) | `POST /returns/{case}/handover` | 직원 화면 "분실인에게 건넴" |

- `/health` 의 `sources` 에서 함수마다 가상(`SimRobot` 등)인지 진짜인지 보인다
- 세계(SimWorld)는 관제탑 상태와 별개로 **물건이 실제로 어디 있는지**(등록기계·이동 중·보관함 칸·그리퍼·제출보관함)를 기억한다 → 매칭이 엉뚱한 물건을 고르면 화면에서도 엉뚱한 물건이 제출보관함으로 간다(숨기지 않음)

## 4. 켜는 법 (교육원 PC)

### 4-1. 분실물 봇 만들기(처음 한 번, 변재원이 직접 — 토큰은 채팅·문서에 쓰지 않는다)
1. 브라우저에서 디스코드 개발자 포털(https://discord.com/developers/applications) → **New Application** → 이름 `분실물봇`(예시) → Create
2. 왼쪽 **Bot** → **Reset Token** → 나온 토큰을 복사해 바로 메모장 `.env` 의 `LOSTFOUND_BOT_TOKEN=` 뒤에 붙여 넣고 저장
3. 같은 **Bot** 화면 아래 **Privileged Gateway Intents** → **MESSAGE CONTENT INTENT** 켜기 → Save Changes
4. 왼쪽 **OAuth2** → **URL Generator** → Scopes `bot` → Bot Permissions `View Channels` · `Send Messages` · `Read Message History` → 아래 주소 복사 → 새 탭에서 열어 팀 서버에 추가(서버 관리 권한이 필요하면 서버 관리자에게 부탁)
5. 디스코드 앱 설정 → 고급 → **개발자 모드** 켜기 → 분실물 채널 오른쪽 클릭 → **채널 ID 복사** → `.env` 의 `LOSTFOUND_CHANNEL_ID=` 에 붙여 넣기

### 4-2. 매번 켜기
```powershell
# 관리자 PowerShell(작업 탭)
cd $HOME\ai-lostfound-tower        # 저장소 폴더(PC 마다 다를 수 있음)
git pull
.\.venv\Scripts\Activate.ps1
pip install -r tools/requirements-bot.txt     # 처음 한 번
python -m unittest discover -s tests          # 통과 확인
```
- `.env` 에 `TOWER_SIM=1` 을 넣고 저장 → `tools\start_tower.bat` 로 관제탑 켜기(가상 시연에서는 DB 를 쓰지 않음)
- 브라우저 `http://127.0.0.1:8100/live` → 위 칩에 **모드 가상 시연** 이 보이면 준비 완료
- 새 PowerShell 탭: 같은 폴더·`.venv` 켠 뒤 `python tools/lostfound_bot.py` → `[분실물 봇] 연결됨` 이 나오면 디스코드에서 메시지 보내기
- 디스코드 없이 연습: `/live` 왼쪽 **시험 입력** 또는 `python tools/lostfound_bot.py --try "서면역 5번 출구 앞에서 검정 카드지갑 주웠어요"`
- 끝나면 `.env` 의 `TOWER_SIM=` 을 비우고 관제탑을 다시 켜면 원래(진짜 부품·DB) 모드

- 개발 모드(11/5): `tools\start_tower.bat dev` — `agents/`·`robot/`·`discord_ops/` 의 .py 가 바뀌면 관제탑이 스스로 다시 켜진다(가상 시연 기록은 초기화). `lan` 과 같이 써도 됨(`start_tower.bat dev lan`). 발표 때는 기본 모드

### 4-2-1. 다른 PC 에서 화면 열기 (교육원 네트워크, 시험할 때만, 11/5)
관제탑은 기본으로 이 PC 안(127.0.0.1)에서만 열린다. 팀원 PC 에서 화면을 보려면 두 가지를 같이 한다.
1. 관제탑을 `tools\start_tower.bat lan` 으로 켠다(0.0.0.0 — 같은 네트워크 누구나 접속)
2. 관리자 PowerShell 에서 방화벽 허용 규칙을 교육원 대역으로만 연다
   ```powershell
   New-NetFirewallRule -DisplayName "LostFound 8100 (2jo, 10.10.21.0/24)" -Direction Inbound -Protocol TCP -LocalPort 8100 -RemoteAddress 10.10.21.0/24 -Action Allow
   ```

| 누가 보나 | 주소(관제탑 PC 주소:8100) |
| --- | --- |
| 습득자(등록기계) | `/intake?machine=KIOSK-A` · `/kiosk?machine=KIOSK-A` |
| 분실인 | `/lost` |
| 본센터 직원 | `/staff` |
| 관제 | `/live` |

- 로그인이 없다 → 직원 화면의 정지·인계 버튼도 누구나 누를 수 있다. 가상 시연(`TOWER_SIM=1`)일 때만, 시험하는 동안만 연다
- 끝나면: 관제탑 Ctrl+C → `tools\start_tower.bat`(기본) · 관리자 PowerShell `Get-NetFirewallRule -DisplayName "LostFound*" | Remove-NetFirewallRule`
- Windows 방화벽 자체는 끄지 않는다(11/4 꺼져 있던 것을 다시 켬)
- 팀 DB(5434)·화면 앞문(8080)도 다른 PC 에서 쓰려면: `web/README.md` 5-1 (`.env` `DB_BIND=0.0.0.0`, 비밀번호 먼저 변경)

## 4-3. 로봇팔 구성 — SO-101 리더·팔로워 (11/4 실물 사진 확인)

| | 리더(검정) | 팔로워(흰색) |
| --- | --- | --- |
| 쓰임 | 사람이 손으로 움직여 학습 에피소드 녹화(텔레오퍼레이션) | 학습된 정책(SmolVLA, ACT 비교)이 움직임 — **시연 때 움직이는 쪽** |
| 모터 | STS3215 6개 | STS3215 6개 |
| 끝부분 | 손잡이(트리거) | 집게(그리퍼) + 손목 카메라 |

관절 번호(팀 저장소 docs/progress/soarm-local-handoff.md 와 같음): 1 좌우 회전 `shoulder_pan` · 2 앞뒤 숙임 `shoulder_lift` · 3 두 긴 팔 접힘 `elbow_flex` · 4 끝부분 위아래 `wrist_flex` · 5 끝부분 회전 `wrist_roll` · 6 집게 `gripper`
→ **움직이는 축 5개 + 집게 1개 = 모터 6개**

- 학습 흐름: 리더로 팔로워를 움직이며 에피소드 녹화(관절 값 6개 + 탑뷰·손목 카메라 영상) → 정책 학습 → 시연 때는 팔로워만 정책으로 움직임(리더는 쓰지 않음)
- 실시간 화면 `/live` 오른쪽 **로봇팔 SO-101 카드**: 관절 6개 값·집게 높이·들고 있는 물건. 가상 시연의 각도는 화면용 가상 계산(추정)이고, 진짜 부품을 꽂으면 로봇 부품이 보정값(homing·min·max)으로 읽은 값으로 바꾼다(TBD: 로봇 부품이 관절 값을 돌려주는 함수 — 이순필·김건태와 협의)
- 가상 팔은 사전 접근(물건 위 90mm, 집게 열림) → 내려감(15mm) → 집게 닫음 → 들어 올림 → 제출보관함 위 → 집게 엶 순서로 움직인다. 제출보관함에 내려놓으면 결과를 먼저 알리고 원점 복귀는 뒤에서 한다

### 화면의 로봇팔 모양 = 실제 SO-101 (11/4)
- 모양 출처: SO-ARM100 공식 저장소의 MuJoCo 모델 `Simulation/SO101/so101_new_calib_camera.xml`(팔로워 + 손목 카메라, Apache-2.0)
  - `tools/so101_shape.py` 가 부품 STL 19개에서 겉모양 점만 뽑아 `web/live/so101_shape.js` 로 저장한다(다시 만들 때만 실행, numpy 필요)
  - 화면은 관절 각도로 부품을 돌려(정방향 기구학) **탑뷰(위에서)** 와 **옆모습(팔 평면, 실제 크기 mm)** 두 곳에 그린다. 흰색 = 3D 프린트 부품, 검정 = STS3215 모터
- 각도 계산(`agents/sim_world.py` `so101_joints`): 공식 모델 치수로 푼다 — 어깨 축 높이 116.6mm, 위팔 116.0mm, 아래팔 135.0mm, 손목→집게 끝 159.5mm. 관절 한계(°): 좌우 ±110, 숙임 ±100, 접힘 ±96.8, 손목 ±95, 회전 -157~163
  - 각도 부호는 공식 모델과 같다(0° = 위팔 거의 수직·아래팔 수평인 'ㄱ' 자세). 진짜 로봇의 보정값과는 다를 수 있다(추정) — 실물 연결 때 확인
  - `python tools/so101_shape.py <SO-ARM100>/Simulation/SO101 --check`: 가상 각도를 3차원 모델에 넣어 집게 끝이 목표에 오는지 검사(11/4 최대 오차 0.52mm)
- **배율 1.6배**: 가상 작업대(640×420mm)가 실제 팔보다 커서 화면·계산 모두 팔을 1.6배로 키웠다(화면에 표시)
  - 실제 크기 팔은 받침에서 약 **288mm(추정)** 까지만 집게를 수직으로 바닥에 내릴 수 있다(화면 주황 점선). 11/7 화면 배치(받침 아래쪽 가운데)로는 R1-2(296mm)·R4-2(305mm)·H-1 제출보관함(435mm)이 그 바깥이다
  - → 화면 그림은 배치 설명용이다. 실물 로봇은 건태님이 가르친 포즈(R1-1~R4-2 = pose_1~8, 제출은 outlet_return_1)로 움직이므로 거리 계산이 아니라 **포즈가 실제로 닿는지**를 시연 전에 확인한다

## 4-4. 발표 흐름 — 분실인 웹 → 본센터 키오스크 → 직원 교차 검증 (11/7)
디스코드 대신 **화면으로** 처음부터 끝까지 보여 줄 때(가상 시연 `TOWER_SIM=1`).
```
① 키오스크 습득(/kiosk?machine=KIOSK-A) 또는 /live 시험 입력 [습득 신고]
② 분실인 웹 /lost : 종류·색·역·가상 신분증(이름·뒤 첫 자리) → [분실 신고하기]
   → (필요하면 확인 질문) → 찾기 번호 C-… + 가린 신분 번호 ******-N****** 표시, 진행 상황 실시간
③ 진행기는 방문을 자동으로 하지 않고 "본센터 방문 대기"에서 멈춤
④ 부산역 본센터 키오스크 /kiosk?machine=CENTER → [물건 찾으러 왔어요(회수)] → 찾기 번호 + 가린 신분 번호
   → 로봇 반환(실시간 화면 /live·/admin) → 제출보관함
⑤ 직원 화면 /staff → 제출보관함 교차 검증(물건·신분증·비공개 특징) → [확인 결과 저장]
   → 분실인 웹 진행 상황의 "인계 완료"까지 갱신
```
- 웹 신고는 `/sim/lost` 에 `{"visit": "kiosk", "name_masked", "id_no_masked"}` 를 붙여 보낸다(가린 값만, 원문은 보내지 않음)
- 키오스크에서 신분 번호가 다르면 반환을 시작하지 않고 계속 기다린다(3번 틀리면 잠금 → 역무실)
- 디스코드 분실물 채널·`/live` 시험 입력의 [분실 신고]는 예전처럼 방문까지 자동으로 진행한다
- 보관함 시연 물건 5개는 "본센터 직접 접수"라 역을 **해운대·서면**으로 고르면 장소 확인 질문이 틀린다 → 시연 물건으로 할 때는 역을 "부산역" 또는 "잘 모르겠어요"로, 습득부터 보여 줄 때는 습득한 역과 같은 역으로

## 4-5. 키오스크 사진 습득 — 사진 분석만 진짜 Qwen (11/7)

한줄 설명: 발표 ①장면(해운대역 키오스크에서 습득 등록)을 가상 시연 그대로 쓰되, 사진 속 물건 종류·색은 관제탑 PC 그래픽카드의 진짜 Qwen3-VL 이 정한다.

- 고친 허점: 키오스크에서 사진으로 접수하면 특징을 채울 프로그램이 없어 '접수'에서 멈췄다(가상 시연·실제 모드 모두)
- 흐름: 키오스크 사진 접수(`POST /api/kiosk/items`, photo) → `/live` 이야기 "습득 신고(키오스크)" · Qwen 특징 분석 중 → 작업자가 `GET /api/admin/intake/pending-photos` 로 가져가 분석 → `POST /api/kiosk/items/{번호}/features` → (가상 시연) 회수 → 보관함 칸
- 작업자 켜기(관제탑 PC, 저장소 폴더, 관제탑을 먼저 켠 뒤 새 탭):
  1. 연결만 확인: `.\.venv-qwen\Scripts\python.exe tools\intake_qwen_worker.py --check` → "관제탑 연결 OK · 사진 분석 대기 N건"
  2. 켜기: `.\.venv-qwen\Scripts\python.exe tools\intake_qwen_worker.py` (끄기 Ctrl+C). 첫 사진에서 모델을 올리느라 수십 초(추정) 걸리므로 시연 전에 사진 한 장으로 미리 데워 둔다
  - `.venv-qwen` 설치는 `qwen/INTEGRATION.md`. 관리자 로그인을 켰다면 `.env` 의 `LF_ADMIN_API_KEY` 가 있어야 한다(없으면 401)
- 작업자가 꺼져 있거나 결과가 늦으면 `TOWER_SIM_QWEN_WAIT`(기본 180초) 뒤 "사진 분석 결과 없음 — 직원 확인"으로 끝난다. **가짜 특징으로 진행하지 않는다**. 물건은 등록기계 보관 그대로
- Qwen 이 종류를 모르겠다고 하면(unknown) "물건 종류 확인 불가 — 직원 확인"
- 그래픽카드(RTX 3050 6GB)를 Qwen3-VL-2B(약 2~3GB, 추정)와 챗봇 모델이 나눠 쓴다 — 함께 켰을 때 메모리 부족이 나는지 시연 전에 확인(TBD)
- 시험: `tests/test_kiosk_qwen_worker.py`(모델 대신 정해진 특징을 돌려주는 대역)

## 5. 알아둘 점
- **서면역 기계 KIOSK-C 를 새로 추가했다**(공통 약속 `agents/contracts.py` 변경, DB `center/migrations/005`). 접수 번호 앞글자는 **S** — `C` 로 하면 접수 번호가 찾기 번호(`C-날짜-순번`)와 똑같아진다
- 보관함에는 **실제 구매 목록 기준** 시연 물건 5개(번호 `H-…`)가 실물 보관판과 같은 칸에 미리 있다(11/7, `agents/sim_world.py` SEED_ITEMS): 화이트폰 R1-1 · 블루폰 R1-2 · USB 두 개 R2-1·R2-2 · 갈색 지갑 R4-1. 빈 칸은 R3-1·R3-2(립밤 행)·R4-2. 디스코드 `초기화` 로 처음 상태
- 11/7부터 가상 작업대와 보관함 정답지(`/storage`)가 **같은 칸**을 보인다: 습득 물건이 칸에 놓이면 정답지에도 같은 칸으로 들어가고(`link_storage`), 직원이 보관 화면에서 칸을 고르면 가상 작업대도 그 칸으로 옮긴다

  | 보관함에 있음 | 디스코드로 신고해 볼 물건(보관함에 없음) |
  | --- | --- |
  | 카드지갑 브라운 · 핑크샌드 | 카드지갑 **블랙** |
  | 목업폰 화이트 · 블루 | 목업폰 **블랙** |
  | USB 샌디스크 은색 **2개(같은 제품)** | USB 액센 |
  | 보조배터리 스피디 흰색 1개 | 보조배터리 스피디 2번째 |
  | 핸드크림 흰색 | 립밤 |

  - 지갑 색은 구매서에 "색 다르게 3개"만 있어 블랙·브라운·핑크샌드로 임시 설정했다(실물 도착 뒤 바뀔 수 있음). USB·보조배터리·핸드크림 색은 (추정)
  - 핑크샌드는 공통 색 목록에 **분홍**을 추가해 구별한다(11/4, `agents/contracts.py` COLORS)
  - 같은 제품 장면: `은색 USB 잃어버렸어요, 글자 SanDisk` → 보관함에 똑같은 USB 2개 → **직원 확인**(사진으로 구별 불가). 습득 신고로 같은 물건을 하나 더 넣어도 같은 장면
- 가상 시연은 메모리에만 기록한다(관제탑을 끄면 사라짐). 찾기·반환 번호는 초기화해도 이어진다(같은 번호 재사용 방지)
- 메시지 원문은 저장하지 않는다. 장소 글·물건 특징만 남고, 관제 메시지는 기존 개인정보 검사를 그대로 지난다
- 봇은 교육원 PC 에서 켜 둔 동안만 동작한다. 2조봇과 다른 봇이므로 2조봇 허용 목록(access.json)은 바꾸지 않는다
- 가상 Qwen 은 낱말 표로 색·품목·글자를 읽는다(사진 아님). 표에 없는 말(예: "자주색")은 `기타`·`확인 불가` 로 남는다
- 시간: 반환 한 번 약 20초(`TOWER_SIM_SPEED=1`). 발표 때 더 빠르게 하려면 `0.5`
