# 교차 검수 — 모순 표 (11/3, 고치기 전)

> 수업 방식대로 **발견만** 했다. 어느 쪽을 고칠지는 사람이 고른다.
> 대조 축: 컴포넌트↔인터페이스 / 시퀀스·코드↔인터페이스 / ERD↔유스케이스 (+ 약속 문서↔코드)

| 번호 | 어느 것과 어느 것 | 어떻게 어긋나나 | 고칠 쪽(제안) | 중요도 |
| --- | --- | --- | --- | --- |
| 1 | 인터페이스(약속) ↔ 코드 | `db_set_status` 는 "실패하면 로봇을 움직이지 않음"인데, 흐름이 반환값을 보지 않아 상태 변경이 실패해도 `robot_approach` 를 부른다 | 코드: approach 앞에서 `{ok}` 확인, 실패면 직원 확인 | 높음(안전) |
| 2 | 인터페이스(약속) ↔ 코드 | `robot_stop` 은 "실패하면 직원 호출"인데 반환값을 보지 않는다 | 코드: 정지 실패면 알림 문구에 "정지 실패 — 직원 즉시 호출" 추가 | 높음(안전) |
| 3 | MCP 공개 범위 ↔ 공용 약속 | MCP `db_get_item` 이 비공개 특징(`mark`·`visible_text`, 확인 질문 정답)까지 그대로 돌려준다. 외부 AI가 확인 질문 정답을 볼 수 있다 | 코드: MCP 쪽은 `public_card()` 로 거른 특징만 반환 | 높음(보안) |
| 4 | 컴포넌트 ↔ 인터페이스 | "부품 묶음"의 계약이 가짜 부품 클래스(MockBackend)에만 있고, 진짜 부품이 맞출 공식 틀이 없다 | 코드(뼈대): `Backend` Protocol(함수 이름·타입만) 추가 | 중간 |
| 5 | 문서 ↔ 코드 | llm_reviewer 설명은 "공개 특징·매칭 점수까지 보낸다"인데 실제로는 사례 번호·접수 번호·상태만 보낸다 | 문서: 설명을 코드에 맞춤(보낼 값을 늘리는 건 별도 결정) | 낮음 |
| 6 | 인터페이스 ↔ 인터페이스 | 알림 함수 모양이 셋: MCP `notify(channel, text)` / `Reporter.send(channel, title, body)` / `tools.notify(title, body, env_key)` | 문서: interfaces.md 에 관계(MCP → Reporter → tools.notify) 명시 | 낮음 |
| 7 | 시퀀스 ↔ 코드 | 그림의 집기 반복은 매번 `robot_verify_grasp` 를 부르지만, 코드는 집기 성공일 때만 확인한다 | 시퀀스: loop 안에 opt 추가 | 낮음 |
| 8 | ERD ↔ 유스케이스 | 반환 사례·단계·개선 회차 기록을 저장하는 컴포넌트가 없다(디스코드 글로만 남음). RETURN_CASE 를 관제탑이 가질지 DB 담당이 가질지 미정 | 결정 필요: 소유자(관제탑 vs 정연우 LF-8) | 중간 |
| 9 | 유스케이스 ↔ 코드 | `MAX_GRASP_ATTEMPTS = 2` 는 추정값(LF-19 시험 후 확정) | 그대로 둠(시험 후) | 낮음 |
