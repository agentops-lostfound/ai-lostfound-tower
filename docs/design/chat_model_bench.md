# 챗봇 모델 비교 도구 (LLMOps, LF-5 · 11/5 변재원)

한줄 설명: 챗봇에 어떤 Ollama 모델을 쓸지 정하기 전에, **같은 질문 77개**를 모델별로 돌려 정확도·모델 사용률·속도를 표 하나로 비교한다.

- 코드 `tools/chat_model_bench.py` · 시험 `tests/test_chat_model_bench.py`(가짜 모델, Ollama 없이)
- 질문 묶음: `evaluation/guidance_questions.json`(이용 안내 평가 질문, 정답 상태·주제가 적혀 있음)
- 결과를 보고 `.env` 의 `LF_CHAT_RAG_MODEL`(이름만)을 정한다. 비우면 모델 없이 승인 문서 문단 그대로 답한다

## 1. 왜 필요한가
- 챗봇 답변(RAG)은 모델이 **승인된 문단 번호만 고르는** 방식이라 엉뚱한 정책을 지어낼 수 없다. 대신 모델이 형식을 틀리거나 너무 느리면 문서 원문으로 대체된다
- 그래서 "어떤 모델이 똑똑한가"보다 **"형식을 잘 지키고(모델 사용률), 빨리(p95) 답하나"**가 고르는 기준이다
- 한줄 설명 — **RAG(검색 증강 생성)**: 먼저 관련 문서를 찾아 붙이고, 모델은 그 문서 안에서만 답하게 하는 방식
- 한줄 설명 — **p95**: 응답 시간을 짧은 순으로 줄 세웠을 때 95% 위치의 값. "느린 쪽 5%를 뺀 최대 대기 시간"

## 2. 실행 (교육원 PC)
1. Windows 터미널 → PowerShell 탭 → 저장소 폴더로 이동, `.venv` 켜기
2. Ollama 가 켜져 있는지, 모델이 있는지 확인: `ollama list`
3. 비교 실행(모델 이름은 `ollama list` 에 보이는 그대로):
   ```powershell
   python tools/chat_model_bench.py --models qwen3-vl:2b-instruct,qwen3-vl:4b-instruct --out data/reports/chat_bench.md
   ```
   - 빨리 맛만 볼 때: `--limit 10`
   - 숫자 전체 저장: `--json data/reports/chat_bench.json`
   - 모델 하나당 질문 30개쯤이 실제로 모델을 부른다. 큰 모델은 몇 분 걸릴 수 있다(추정)

## 3. 표 읽는 법
| 칸 | 뜻 |
| --- | --- |
| 상태 일치 | 정답 상태(answered·policy_pending …)와 주제를 지킨 질문 수. **기준선(없음)보다 낮으면 그 모델은 탈락** |
| 모델 호출 | 실제로 모델을 부른 질문 수(운영값 미정·주제 밖 질문은 모델을 부르지 않음) |
| 모델 사용 | 모델이 고른 문단이 검증을 통과해 답에 쓰인 수와 비율. 높을수록 좋음 |
| 대체 | 모델이 꺼졌거나 형식이 틀려 문서 원문으로 답한 수 |
| 평균·p50·p95 ms | 모델을 부른 질문의 응답 시간(첫 질문 예열 시간은 뺌) |
- "모델 답을 한 번도 쓰지 못함" 이 나오면 Ollama 가 꺼졌거나 모델 이름이 틀린 것 → `ollama list` 확인

## 4. 고른 뒤
1. `.env` 에 `LF_CHAT_RAG_MODEL=고른모델` (값은 채팅·디스코드에 쓰지 않아도 되는 모델 이름)
2. 관제탑 다시 켜기 → 위젯에서 질문 몇 개
3. 운영 중에는 `GET /chat/metrics`(또는 `python tools/ops_report.py "챗봇 답변 상태 요약해줘"`)로 p95·대체 건수를 지켜본다
