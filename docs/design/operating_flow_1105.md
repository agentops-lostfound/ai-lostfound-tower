# 11/5 셀프서비스 운영 흐름

## 운영 범위
이번 MVP에서는 직원 화면·직원 승인 단계를 사용하지 않는다. 모든 역 키오스크는 습득 신고와 분실 확인을 제공하고, 회수·본인 확인·로봇 인계는 본센터 키오스크에서만 제공한다.

## 채널별 권한과 동선

| 채널 | 습득 신고 | 분실 확인 | 신분 확인 | 실물 회수 |
|---|---:|---:|---:|---:|
| 일반 역 키오스크 | 가능 | 가능 | 불가 | 불가 |
| 본센터 키오스크 | 가능 | 가능 | 셀프 확인 | SO-101 인계 |
| 분실인 웹 | 불가 | 가능 | 온라인 분실 확인 절차 | 불가 |
| 챗봇 | 불가 | 확인 화면/웹으로 연결 | 불가 | 불가 |
| 관제탑 /live | 관제 | 관제 | 진행 상태 관제 | 카메라·로봇 상태 관제 |

일반 역 키오스크에서 일치 후보가 확인되면 회수 버튼을 노출하지 않고 **“물건이 본센터에 보관되어 있습니다. 본센터 키오스크에서 본인 확인 후 수령해 주세요.”** 를 안내한다. 웹·챗봇도 후보 확인 후 같은 방문 안내를 제공한다.

## 물품 이동·회수 흐름
1. 어느 역 키오스크에서든 사진·발견 장소를 받아 습득 신고를 생성한다.
2. 관제탑은 품목·특징을 분석하고 물건을 본센터 보관함으로 입고 처리한다.
3. 분실인은 어느 역 키오스크, 웹 또는 챗봇에서 분실 확인을 진행한다.
4. 후보가 있으면 물건 위치가 본센터임을 알리고 본센터 방문을 안내한다.
5. 본센터 키오스크에서만 셀프 신분 확인 및 소유자 확인을 완료한다.
6. 관제탑은 보관함 탑뷰 카메라에서 대상 물건 위치·상태를 확인하고 SO-101에 픽업 작업을 요청한다.
7. 로봇팔이 물건을 인출해 인계 위치에 놓는다. 키오스크는 완료/실패를 표시한다.
   - 11/11: 분실인이 인계 위치(제출보관함)에서 물건을 꺼내고 키오스크 [물건 받았어요]를 누르면 인계 완료(`POST /api/kiosk/handover`). 11/6~11/10 사이 넣었던 직원 교차 검증은 예외(확인 질문 미통과·직원 보관 선반)에만 남긴다
8. 관제탑 /live 는 접수부터 보관, 분실 확인, 본인 확인, 로봇 픽업, 인계 결과까지 한 흐름으로 보여 준다.

## 관제 이벤트 단계(권장 공통 식별자)
`found_reported` → `center_received` → `lost_search_matched` → `center_visit_guided` → `identity_verified` → `robot_pick_started` → `robot_pick_completed` → `handover_completed`

실패·불일치는 성공으로 위장하지 않고 `identity_rejected`, `vision_uncertain`, `robot_stopped`, `handover_failed` 등 별도 이벤트로 기록한다. /live 는 `story_id`, `item_id`, `claim_id`를 연결해 사건 단위로 표시한다.

## 본센터 판별 규칙
키오스크의 `machine_id`를 서버에서 조회하고 DB의 `machine.kind = 'center'`인 경우에만 본센터 회수 API를 허용한다. 브라우저가 보내는 `is_center` 같은 값은 신뢰하지 않는다. 본센터 키오스크 식별자는 기존 DB의 CENTER 기계를 사용하며, 배포 환경에서 실제 터치 키오스크 ID를 CENTER에 매핑한다.

## 품목 6종
| YOLO 번호 | 내부 클래스 | 화면 표시 | 물건 ID |
|---|---|---|---|
| 0 | `card_wallet` | 지갑 | W |
| 1 | `usb` | USB | U |
| 2 | `lip_balm` | 립밤 | L |
| 3 | `phone` | 모형폰 | P |
| 4 | `hand_cream` | 핸드크림 | H |
| 5 | `power_bank` | 보조배터리 | B |

- 기준: `vision/config.py` `CLASSES`(11/6 LF-3 #90 고정), 한국어는 `agents/contracts.py` `CATEGORIES`. 0~3번은 예전 4종과 같은 번호라 기존 라벨을 다시 매기지 않는다
- 모형폰의 내부 이름은 `phone` 으로 둔다. 실제 스마트폰과 헷갈리지 않게 `model_phone` 으로 바꾸자는 안(11/5)이 있었지만, Qwen 특징(`vision/item_features.py`)·변환(`agents/vision_adapter.py`, `agents/lost_photo.py`, `agents/matcher_part.py`)·매칭(`matching/`)이 모두 `phone` 을 모형폰으로 쓰고 있어 이름을 바꾸면 여러 변환표가 함께 틀어진다. 한국어 품목 값도 `모형폰` 그대로 둔다(계약·DB·비전·매칭·API JSON)
- 11/8: 사람에게 보이는 글(화면·디스코드·챗봇 문장)에는 **"휴대폰"** 으로 표시한다. 파이썬은 `agents/contracts.py` `category_label()`(표 `CATEGORY_LABEL`), 화면 JS 는 `{모형폰: "휴대폰"}` 표시 사전을 거친다. 사용자 입력은 `모형폰`·`휴대폰`·`핸드폰` 모두 알아듣는다
- 클래스 인덱스는 데이터셋 라벨·학습 결과와 함께 관리하며, 기존 학습 데이터 라벨을 재매핑하지 않고 이름만 바꾸어 배포해서는 안 된다

## 구현 경계와 안전
- 현재 /live 에 탑뷰 작업대·SO-101 시각화·정지·원점 복귀 제어가 있다. 실물 픽업은 카메라 보정·물체 좌표·로봇 안전 검증이 통과한 경우에만 실행한다.
- 본 문서는 요구사항/화면 정책이다. 실물 신분증 리더, 카메라 스트림, SO-101 하드웨어 연결이 이 문서 추가만으로 구현되거나 검증되는 것은 아니다.
- 직원 단계는 화면 동선에서 제외하지만, 긴급 정지·오류 대응 등 하드웨어 안전 인터록은 제거하지 않는다.
