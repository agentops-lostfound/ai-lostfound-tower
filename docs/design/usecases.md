# ① 유스케이스 — AI 관제탑

형식: UC-번호 / 액터 / 목적 / 사전조건 / 기본 흐름 / 예외 흐름. PRD(docs/project-spec 기준)에 없는 것은 "제안:"으로 분리했다.

## UC-1 분실물 반환 처리
- 액터: 분실인(웹·방문), 본센터 직원, 메인 AI
- 목적: 본인 확인을 통과한 분실인에게 맞는 물건만 로봇팔로 돌려준다
- 사전조건: 물건이 `본센터 보관` 상태로 DB에 있고 접수 특징 JSON이 저장돼 있다
- 기본 흐름: 동의 → 본인인증 → 확인 질문 → 메인 AI 승인·수령 예약 → 방문 신분증 대조 → 안쪽 특징 확인 → 직원 최종 확인 → 탑뷰 촬영 → 매칭 → 사전 접근 → 집기·집기 확인 → 바구니 전달(`인계 대기`) → 직원이 분실인에게 건넴 → `인계 완료`
- 예외 흐름
  1. 동의 거부·본인인증 실패 → 반환 거절(안내 후 종료)
  2. 확인 질문 오답 → 거절 + #관제-알림
  3. DB에 물건 기록 없음 → 직원 확인 + 알림
  4. 방문 신분증·안쪽 특징 불일치 → `반환 보류` + 거절 + 알림
  5. 탑뷰에서 물건 0개 / 매칭 불확실·없음 → 자동 반환 안 함, 직원 확인 + 알림
  6. 사전 접근·바구니 전달 실패 → 로봇 정지 + 알림
  7. 집기 실패 → 1번만 다시 시도, 또 실패하면 정지 + 직원 호출
  8. LLM 검토가 보류하거나 응답 없음(시간 초과) → 직원 확인(승인 권한 없음, 더 안전한 쪽으로만)

## UC-2 관제 알림
- 액터: 메인 AI, 관제 담당(팀원·직원)
- 목적: 반환 진행·이상·점수를 디스코드 관제 채널 3곳(#📊관제-진행, #🚨관제-알림, #📈평가-점수)에서 실시간으로 본다
- 사전조건: `.env` 에 채널별 웹후크(없으면 공용 웹후크 하나)
- 기본 흐름: 단계 끝 → 진행 알림 / 예외 → 이상 알림 / 회차 끝 → 점수판
- 예외 흐름
  1. 글에 개인정보 모양(전화·주민·카드번호·이메일) → 보내지 않고 막은 기록만 남김(안전 위반으로 셈)
  2. 웹후크 없음·전송 실패 → 반환 흐름은 멈추지 않고 계속(알림만 실패)
  3. 채널별 웹후크가 비어 있음 → 공용 웹후크로 "[채널 이름]"을 붙여 보냄

## UC-3 시험 사례 채점
- 액터: 개발자(변재원), 메인 AI
- 목적: 정해진 사례 10개(정상·비슷한 물건·똑같은 쌍·거절)를 흐름에 넣어 결정·안전 위반·로봇 결과를 점수로 확인
- 사전조건: evaluation/test_cases.json, 가짜 부품(MockBackend) 또는 진짜 부품
- 기본 흐름: 사례 읽기 → 반환 흐름 실행 → 결정 비교 → 안전 위반 검사 → 메인 AI·로봇 점수 → 점수판
- 예외 흐름
  1. 결정은 맞는데 다른 물건을 집음 → `wrong_object` 로 바꿔 틀린 것으로 셈
  2. 안전 위반이 1건이라도 있으면 → 점수와 별도로 경고 목록 출력
  3. LLM 검토를 켰는데 Ollama가 꺼져 있음 → 모든 사례가 직원 확인으로 넘어감(잘못된 보류로 보임) → 측정 전 모델 미리 올리기

## UC-4 AI 자기 개선 회차
- 액터: 개선안 작성자(규칙 또는 LLM), 채택 판정(코드)
- 목적: 비전 특징 추출 설정을 한 번에 하나씩 바꿔 검증 점수가 오를 때만 채택
- 사전조건: 정답지(개선용·검증용·최종 시험용으로 나눔), p95 응답 시간 한도
- 기본 흐름: 개선용 오차 보기 → 허용 도구 범위 안에서 개선안 2개 → 검증용으로 비교 → 채택 판정(+3점, 핵심 항목 안 떨어짐, 지어내기 안 늘어남, p95 한도 안) → 기록
- 예외 흐름
  1. p95 한도가 없음 → 자동 채택하지 않음
  2. 정답지가 덜 채워짐 → 자동 채택하지 않음
  3. 3회 연속 거절 / 목표 도달 / 남은 개선안 없음 → 멈춤
  4. 최종 시험용 정답지는 `--final` 없이 보지 않음(새어 나감 방지)

## UC-5 디스코드 시연·질의
- 액터: 팀원·청중(부산7기 #2조), 2조 봇(Claude Code 세션)
- 목적: 디스코드에서 시험·시연을 실행하고 결과를 묻고 답한다
- 사전조건: 교육원 PC에서 봇 세션이 `--add-dir` 로 팀 저장소를 함께 열고 켜져 있음, 허용목록 5명
- 기본 흐름: 멘션 → 봇이 `tools/tower_demo.py` 실행 → 2000자 이하 요약 답변 → (요청 시) 관제 채널 3곳 전송
- 예외 흐름
  1. 봇 세션이 꺼짐 → 사람이 PowerShell에서 직접 실행해 출력 붙여 넣기
  2. 요약에 개인정보 모양 → 출력하지 않음
  3. 코드 수정·push 요청 → 봇은 하지 않음(개발 세션에서)

## UC-6 AI 도구 접근(MCP)
- 액터: 외부 AI 클라이언트(Claude, LangGraph 에이전트)
- 목적: 관제탑 도구를 표준 방식으로 읽고·비교하고·알린다
- 사전조건: `mcp` 패키지, `python agents/mcp_server.py`
- 기본 흐름: 도구 목록 → 탑뷰 검출 → 매칭 → 물건 기록 읽기 → 알림
- 예외 흐름
  1. 로봇·상태 변경 요청 → 열려 있지 않아 부를 수 없음
  2. mcp 패키지 없음 → 설치 안내 후 종료

## 제안 (PRD 밖, 확정 아님)
- 제안: 반환 사례·단계 기록을 DB에 남기기(지금은 디스코드 글과 화면 출력에만 남음) → erd.md 의 RETURN_CASE·RETURN_STEP
- 제안: 디스코드도 실패할 때 대체 알림(예: 본센터 화면 경고)
- 제안: 로봇 정지 자체가 실패할 때의 처리(지금은 결과를 확인하지 않음)
