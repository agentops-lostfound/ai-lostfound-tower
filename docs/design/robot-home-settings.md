# LF-11·12 Home 자세 설정

2026-11-04. 사용자가 기록한 접힌 자세를 Home 목표로 지정했고, 추후 편하게 다른 자세로 바꿀 수 있는 기능을 요청했다.

## 현재 지정

robot/config/home_pose.json은 팀 저장소에 남기는 기본 설정이다. 실제 후보 home-candidate-cdcea465ae8943daa36edd2d76a46a81.json의 6관절 값을 반영했다. 장비는 New SO101 Follower, ID 0f876b83-64cd-4bb9-9630-963eaeb3c0b7, 시리얼 5B91030622다. 단위는 각도가 아닌 normalized다.

현재 설정명은 ‘접힌 대기 자세’, 기준 버전은 1이다. pose_selected=true는 사용자가 이 목표 자세를 선택했다는 뜻이다. path_verified=false, motion_enabled=false는 현재 위치에서 해당 자세까지의 복귀 경로를 아직 검증하지 않아 실행을 활성화하지 않았다는 뜻이다. 설정 저장 자체로 장비나 토크·목표 레지스터를 바꾸지 않는다. 이전 home_new_follower.py 등의 캘리브레이션 도구를 호출하지 않는다.

## 로컬 설정 및 변경

```powershell
py -3.11 .\tools\configure_robot_home.py set --candidate "기록한 home-candidate JSON 전체 경로"
py -3.11 .\tools\configure_robot_home.py status
```

활성 설정은 outputs/robot-home/active.json에 저장하고 이전 선택은 history에 보존한다. 이 로컬 폴더는 Git에서 제외하여 이후 git pull이 사용자 설정을 덮어쓰지 않도록 한다. 로컬 활성 설정이 없으면 저장소 기본값을 읽는다. 손상된 로컬 설정을 발견했을 때 이전 기본값으로 조용히 되돌아가지 않고 오류를 반환한다.

다른 후보를 지정하면 장비·관절 순서·정규화 범위·보정 기준 해시·기록된 자세 안정성을 검증하고, 위치 또는 이름이 바뀌면 버전을 증가시킨다. 동일 후보를 반복 지정하면 이력을 중복 생성하지 않는다. 기존 파일은 원자적으로 교체하며 저장 실패 시 현재 활성 설정을 보존한다. 협력하는 설정 프로세스 간에는 잠금 파일로 동시 교체를 차단한다. 이력 파일이 남았어도 active.json 교체 실패 시 해당 이력이 활성화된 것으로 해석하지 않는다.

## 추후 편한 설정 화면 요구

아래 화면은 요청사항이며 아직 구현하지 않았다.

1. 현재 Home 이름·자세·버전을 표시한다.
2. 로봇을 정지하고 사용자가 원하는 자세를 준비한다.
3. ‘현재 자세 기록’으로 후보를 읽는다. 녹화·학습·재보정과 구분한다.
4. 사용자가 미리 본 뒤 ‘이 자세를 Home으로 저장’을 누르면 위 설정 계층으로 선택한다.
5. 다른 자세로 바뀌면 기존 복귀 경로 검증을 무효화하고 새 경로를 확인한다.
6. Home 실행은 별도 직원 확인 버튼이며, 일반 정지 버튼은 자동 Home을 시작하지 않는다.

## 남은 검증

접힌 자세를 목표로 선택하는 것과 모든 시작 자세에서 안전하게 돌아오는 것은 별개다. 다음 작업은 검증할 시작 범위·중간 자세·간섭·물품 상태를 정하고 같은 정지 관문을 사용하는 복귀 경로를 구현하는 것이다. 현재 구조는 경로 없는 목표 설정을 실행 가능으로 승인하지 않는다. 향후 경로는 선택된 설정의 버전 및 보정 기준과 연결하고, 설정 변경 후 이전 경로를 자동 재사용하지 않는다.

후속 구현: `tools/robot_home_return.py`는 Home 근처에서 맨 아래 좌우 회전만 복귀하는 실험을 제공한다. 기존 프로파일의 일반 실행 승인을 바꾸지 않고, 별도 직원 확인 후 회전 차이 1.0·다른 관절 차이 0.2 정규화 단위 이내만 허용한다. 정지 화면의 별도 Home 작업자와 독립 정지 통신을 사용한다. 정상 도달·중간 정지 모의/실제 Zenoh 가짜 장비 시험은 통과했으며, 실제 장비 시험 및 그 밖의 시작 자세 복귀 경로는 후속 검증한다.
