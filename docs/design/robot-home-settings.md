# LF-11·12 Home 자세 설정

2026-11-04. 사용자가 기록한 접힌 자세를 Home 목표로 지정했고, 추후 편하게 다른 자세로 바꿀 수 있는 기능을 요청했다.

## 현재 지정

robot/config/home_pose.json은 팀 저장소에 남기는 기본 설정이다. 실제 후보 home-candidate-cdcea465ae8943daa36edd2d76a46a81.json의 6관절 값을 반영했다. 장비는 New SO101 Follower, ID 0f876b83-64cd-4bb9-9630-963eaeb3c0b7, 시리얼 5B91030622다. 단위는 각도가 아닌 normalized다.

현재 설정명은 ‘접힌 대기 자세’, 기준 버전은 1이다. pose_selected=true는 사용자가 이 목표 자세를 선택했다는 뜻이다. path_verified=false, motion_enabled=false는 현재 위치에서 해당 자세까지의 복귀 경로를 아직 검증하지 않아 실행을 활성화하지 않았다는 뜻이다. 설정 저장 자체로 장비나 토크·목표 레지스터를 바꾸지 않는다. 이전 home_new_follower.py 등의 캘리브레이션 도구를 호출하지 않는다.

## 로컬 설정 및 변경

```powershell
py -3.11 .\tools\configure_robot_home.py set --candidate "기록한 home-candidate JSON 전체 경로"
py -3.11 .\tools\configure_robot_home.py status
```

활성 설정은 outputs/robot-home/active.json에 저장하고 이전 선택은 history에 보존한다. 이 로컬 폴더는 Git에서 제외하여 이후 git pull이 사용자 설정을 덮어쓰지 않도록 한다. 로컬 활성 설정이 없으면 저장소 기본값을 읽는다. 손상된 로컬 설정을 발견했을 때 이전 기본값으로 조용히 되돌아가지 않고 오류를 반환한다.

다른 후보를 지정하면 장비·관절 순서·정규화 범위·보정 기준 해시·기록된 자세 안정성을 검증하고, 위치 또는 이름이 바뀌면 버전을 증가시킨다. 동일 후보를 반복 지정하면 이력을 중복 생성하지 않는다. 기존 파일은 원자적으로 교체하며 저장 실패 시 현재 활성 설정을 보존한다. 협력하는 설정 프로세스 간에는 잠금 파일로 동시 교체를 차단한다. 이력 파일이 남았어도 active.json 교체 실패 시 해당 이력이 활성화된 것으로 해석하지 않는다.

## 버튼으로 현재 자세 기록 및 Home 저장

2026-11-05 구현: 정지·Home 화면에 ‘현재 자세 읽기’와 ‘이 자세를 Home으로 저장’을 추가했다. 현재 Home 이름·버전 표시, 6개 관절 위치 미리보기, 이름 입력과 확인창을 제공한다. 저장은 기존 파일 설정 계층을 사용하고 이전 설정 이력을 보존한다. 실제 장비 UI 적용 결과는 후속 확인 대상이다.

아래 요구 중 현재 자세 기록·미리보기·저장·버전 표시는 구현했으며 임의 자세로 로봇을 움직이는 조작과 일반 복귀 경로 검증은 별도다.

1. 현재 Home 이름·자세·버전을 표시한다.
2. 로봇을 정지하고 사용자가 원하는 자세를 준비한다.
3. ‘현재 자세 기록’으로 후보를 읽는다. 녹화·학습·재보정과 구분한다.
4. 사용자가 미리 본 뒤 ‘이 자세를 Home으로 저장’을 누르면 위 설정 계층으로 선택한다.
5. 다른 자세로 바뀌면 기존 복귀 경로 검증을 무효화하고 새 경로를 확인한다.
6. Home 실행은 별도 직원 확인 버튼이며, 일반 정지 버튼은 자동 Home을 시작하지 않는다.

## 남은 검증

접힌 자세를 목표로 선택하는 것과 모든 시작 자세에서 안전하게 돌아오는 것은 별개다. 다음 작업은 검증할 시작 범위·중간 자세·간섭·물품 상태를 정하고 같은 정지 관문을 사용하는 복귀 경로를 구현하는 것이다. 현재 구조는 경로 없는 목표 설정을 실행 가능으로 승인하지 않는다. 향후 경로는 선택된 설정의 버전 및 보정 기준과 연결하고, 설정 변경 후 이전 경로를 자동 재사용하지 않는다.

후속 구현: `tools/robot_home_return.py`는 Home 근처에서 맨 아래 좌우 회전만 복귀하는 실험을 제공한다. 기존 프로파일의 일반 실행 승인을 바꾸지 않고, 별도 직원 확인 후 회전 차이 1.0·다른 관절 차이 0.2 정규화 단위 이내만 허용한다. 정지 화면의 별도 Home 작업자와 독립 정지 통신을 사용한다. 정상 도달·중간 정지 모의/실제 Zenoh 가짜 장비 시험은 통과했으며, 실제 장비 시험 및 그 밖의 시작 자세 복귀 경로는 후속 검증한다.


## 접힌 대기 자세의 도달 기준 · 2026-11-05 사용자 선택

양방향 실물 시험에서 목표 기록 및 토크 ON이 확인됐지만 4~5틱 잔류 오차가 관측됐다. 사용자는 접힌 대기 자세 용도로 맨 아래 회전 관절만 약 6틱까지 허용하고 실제 복귀 움직임도 확인하는 기준을 선택했다. 구현은 pan 오차 6틱 이내와 Home 방향 오차 감소 2틱 이상을 함께 요구한다. 2틱은 단일 틱 변화만으로 실제 복귀를 인정하지 않기 위한 시험 기준이다. 다른 관절 기준 0.2와 pan 시작 범위 1.0은 그대로다. PID·데드존·보정값·Home 목표 자세는 바꾸지 않았다.

현재 pan 보정 범위 846~3553(2707틱)이므로 6틱은 약 0.4433 정규화 단위다. 이 변환은 해당 보정 해시에 고정하고, 다른 보정 해시이면 실행을 거부한다. 이미 모든 관절이 기존 0.2 범위 안이면 HOME_ALREADY_REACHED와 이동 없음으로 표시한다. 이 판정은 실제 복귀 시험 통과와 구분한다.

HOME_REACHED는 이동 후 pan 오차 6틱 이내와 Home 쪽 진척 2틱 이상을 만족하고, 종료 정지·유지 이후에도 같은 조건과 다른 관절 오차를 다시 확인했을 때만 반환한다. 범위 안에서 가만히 있거나 한 틱만 변한 경우 성공으로 바꾸지 않는다. 결과의 pan_error_ticks, pan_progress_ticks, actual_return_observed, movement_required로 근거를 확인한다. 이는 근거리 단일 관절 시험 기준이며 일반 복귀 경로나 물리적 정지 시간의 승인이 아니다. 이 변경의 실물 시험은 아직 미실행이다.


## 버튼 동작의 경계

- 기존 팔로워 소유자의 정지·유지 완료 상태에서만 읽는다. 화면의 session/epoch를 캡처 시작부터 저장까지 대조하고, 바뀌면 다시 읽어야 한다.
- 읽기는 후보만 생성한다. 사용자가 미리본 후보 ID와 이름을 확인한 뒤 저장한다. 브라우저에서 파일 경로를 전달해 임의 파일을 선택할 수 없다.
- Home 이동과 읽기·저장을 같은 작업 잠금으로 분리한다. 저장 중에도 정지 전송은 독립 작업자를 사용한다. 저장 버튼은 재개·토크 변경·목표 레지스터 기록을 하지 않는다.
- 저장 후 다음 Home 요청은 새 설정을 읽는다. 이전 일반 경로 검증을 재사용하지 않으며, 새 자세가 현 근거리 경로 밖이면 이동을 거부한다.
- 사용자 PC의 활성 파일은 outputs/robot-home/active.json, 후보는 기존 trial의 backup 폴더, 이력은 outputs/robot-home/history에 보존한다. 실제 물품 사진이나 로컬 활성 Home은 Git에 올리지 않는다.
- 현재 적용된 정지 시험 소유자는 Studio의 기존 /action을 버린다. 따라서 일반 Studio Teleoperate를 켜도 리더 동작이 전달되지 않을 수 있다. 이 기능은 Teleoperate 연결을 복원하거나 캘리브레이션 원점을 변경하는 기능을 포함하지 않는다. 리더를 통한 새 자세 배치에는 정지 관문과 호환되는 조작 연결이 필요하다.

적용은 pil2ya 갱신 후 패널 프로세스 재시작만 필요하다. 소유자 패치·보정·정지 기초시험을 다시 설치하거나 반복하지 않는다.

## 수동 자세 변경과 현재 자세 유지

사용자가 토크 때문에 자세를 바꾸지 못한다고 보고해, 기존 정지(토크 ON 유지)와 별도로 ‘자세 변경 시작 · 토크 OFF’, ‘현재 자세 유지 · 토크 ON’을 추가했다. 일반 Studio Teleoperate 연결을 해제/우회하지 않고 기존 소유자 스레드에서 명시적인 사용자 준비 확인 후 처리한다. 이 변경의 실물 UI 동작은 아직 미확인이다.

1. 빈 집게와 팔 받침을 확인하고 자세 변경 시작을 누른다.
2. 6개 관절 토크 0을 읽어 확인한 뒤에만 수동 상태를 표시한다. 이 상태에서는 Home·이동·재개를 거부하며 정지 버튼도 토크를 다시 켜지 않는다. 보정 범위와 토크를 주기적으로 읽고, 오래되거나 범위 밖의 상태에서는 기록/유지를 차단한다.
3. 사용자가 손으로 배치한 안정된 자세를 읽고 미리본 뒤 Home으로 저장한다. 캡처·저장은 토크 OFF 상태도 지원한다.
4. 받침과 손 위치를 확인하고 현재 자세 유지를 누른다. 약0.2초간 원시 위치 안정성을 확인하고, 보정 범위 안의 현재 위치를 6개 목표에 기록해 각각 읽기 검증한 뒤 토크 ON을 확인한다. 목표 기록 자체가 토크를 켤 수 있어 이 전체 단계는 구동 가능 작업으로 취급한다. 전환 중 정지를 받거나 검증이 실패하면 토크 OFF를 시도하고 이동 차단을 유지한다.

수동 상태에서는 driver.torque_on_disconnect=false로 두어 연결 종료 시 드라이버가 토크를 다시 켜지 않도록 한다. 토크를 끄기 전에 영구 볼륨에 중단 기록을 남기며, 그 기록이 남은 새 소유자는 driver.connect() 이전에 시작을 거부한다. 중간에 창/프로세스가 종료돼도 자동 재연결로 예전 목표를 구동하지 않는다. 정상 현재 자세 유지의 목표/토크 검증이 끝나면 기록을 제거한다. 수동 모드 중 Studio/Docker를 재시작하지 않고 현재 자세 유지로 종료해야 한다. 중단 기록이 남은 연결은 자동 해제하지 않고 별도 현재 위치 정렬 복구가 필요하다.

원래 모터 보정·PID·데드존·Home 도달 기준·기존 Studio /action 차단은 유지한다. 소유자 갱신은 기존 telemetry-upgrade가 원본과 이전 버전을 보존하며 연결부 및 연결 전 중단 확인만 업데이트한다. 적용 작업 자체는 로봇을 연결하지 않는다. 구문·가짜 장비 시험과 실제 원본 ZIP의 패치 루프 검증을 구분하고, 실물 성능은 별도로 확인한다.
