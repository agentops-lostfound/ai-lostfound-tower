# LF-5 서버 내부 사용자 세션 발급·철회

2026-11-11 정연우. `5686970`의 인증 읽기 연결에 이어 세션을 발급/저장/철회하는 서버 내부 기능을 추가했다.
기존 일반 사용자 인증 발급 서비스가 코드/Jira에서 확인되지 않아 외부 서비스가 있다는 가정을 제거했다.
사용자에게 인증 서버 정보를 다시 찾아오도록 요청하지 않는다.

## 구현과 신뢰 경계

`agents/chat_session_issuer.py`의 `FindSessionIssuer`는 다음 **신뢰된 서버 부품**을 명시 주입받는다.

- `verify_identity(proof_ref)` → `IdentityProof(subject_id, proof_id, verified_at, expires_at, purpose)`.
  실제 인증 원본을 조회하고 `purpose=lostfound.find`인 미만료·최근 증거를 반환해야 한다.
- `lookup_consent(subject_id, consent_ref)` → `RequiredConsent(subject_id, policy_version, consented_at, accepted, revoked)`.
  같은 사용자와 현재 필수 동의 정책에 대한 최신 권위 기록을 조회해야 한다.
- 세션 쓰기 저장소, 고정 HMAC 키, 동의 정책 버전, 세션 TTL, 증거 최대 유효 시간, 허용 권한.
  수명·권한·정책은 서버 설정이며 사용자 입력으로 선택하지 않는다.

dict/True/가린 신분 값/본문의 `id_verified`·`consent`는 인증 증거가 아니다.
이 Python 자료형 자체가 본인인증을 수행하는 것도 아니다. 클라이언트 값을 자료형으로 감싸 반환하는 검증기는 사용할 수 없다.
현재 LF-4의 실제 인증 원본 조회 부품은 미연결이며 발급기를 기본 생성자·공개 HTTP에 붙이지 않았다.
`/chat/health`나 화면에 인증 성공 버튼도 추가하지 않았다.

## 발급·저장·철회 순서

1. 서버가 인증/동의 증거를 조회·검증한다. opaque ID만 사용하며 이름/번호/사진을 받지 않는다.
2. 256비트 무작위 Bearer 토큰과 무작위 인증 세션 ID를 만든다.
3. 쓰기 거래에서 사용자별 잠금을 잡은 뒤 증거·동의를 다시 조회한다.
   그 사이 철회/만료/정책 변경이 있으면 저장하지 않는다.
4. 증거 소비(`proof_hash` 고유 제약)와 세션 저장을 같은 트랜잭션에 남긴다. 같은 증거로 두 번 발급하지 않는다.
5. 커밋 성공 후에만 토큰을 서버 내부 호출자에게 한 번 반환한다.
6. 기존 `FindSessionAuth`가 저장된 해시로 세션을 확인한다. 재시작해도 같은 DB/키라면 검증 가능하다.
   만료 시간에 도달하면 거절한다.
7. `revoke(owner)`는 해당 인증 세션만, `revoke_subject(subject_id)`는 해당 사용자의 현재 세션 전체를 철회한다.
   발급과 철회가 같은 사용자 잠금을 사용하므로 진행 중인 발급 뒤에도 철회가 반영된다.

필수 동의/본인인증 철회 원본을 먼저 갱신한 뒤 `revoke_subject`를 호출하는 서버 이벤트 연결이 필요하다.
필수 동의 정책을 변경할 때도 기존 세션 철회 또는 권위 읽기 뷰의 최신 정책 검사가 필요하다.
증거·동의 조회는 최신 권위 원본을 읽어야 한다. 철회 원본과 세션을 함께 바꿀 수 있는 경우 같은 거래로 연결하는 것이 우선이다.
지연된 복제본·캐시를 사용하면 이 부품만으로 즉시 철회를 보장할 수 없다.
인증/동의 조회 부품에는 자체 연결·응답 제한도 필요하다. SQL statement_timeout은 Python 콜백 실행 시간까지 제한하지 않는다.
`revoke_subject` 자체는 앞으로 발급될 모든 세션을 영구 차단하는 사용자 정지 기능이 아니다.

## 저장 내용과 장애

Bearer 원문은 저장하지 않는다. 토큰과 인증 증거는 도메인을 분리한 HMAC-SHA256으로 결합한다.
토큰 해시는 이전 `find-token-v1` 계약과 같아 기존 PostgreSQL 읽기 검증기와 호환된다.
실제 이름·신분 번호·사진·콜백 오류 원문·HMAC 키를 저장/출력하지 않는다.
DB에는 서버의 불투명 사용자 ID/세션 ID, 검증/동의/만료/철회 시각, 동의 정책, 허용 권한이 남는다.
반환 객체의 repr에도 토큰을 넣지 않는다. 반환 객체 전체를 HTTP/trace/로그로 직렬화하면 안 된다.

커밋 응답 유실 때는 발급 실패를 단정하거나 같은 증거로 다시 토큰을 만들지 않는다.
원래 토큰은 복구할 수 없으므로 운영자의 기록 확인·기존 세션 철회 또는 새로운 본인인증 절차가 필요하다.
증거 소비 기록을 지우면 재발급 차단도 사라지므로 임의 TTL 정리/삭제를 추가하지 않았다. 보관 정책은 별도 합의다.

## PostgreSQL 연결

`PostgresFindSessionWriter`는 명시한 쓰기 연결만 사용한다. 읽기 전용 검증기 계정에 쓰기 권한을 주지 않는다.
자동 커밋을 끄고, 3초 statement_timeout 및 사용자별 트랜잭션 advisory lock 아래에서 처리한다.
제안 DDL은 `docs/contracts/chat-session-storage.sql`이다. 팀 DB 스키마/마이그레이션을 바꾸거나 DDL을 실행하지 않았다.
기존 `chat_find_session_access` 읽기 뷰 이름과 충돌하면 팀 담당자와 매핑부터 맞춘다.

실제 활성화 전에는 인증 결과/동의 권위 조회 부품, 철회 이벤트, 읽기/쓰기 역할 분리, DDL 검토,
폐기용 PostgreSQL 통합 시험, 안전한 토큰 전달 경로를 연결해야 한다.
이번 구현을 실제 본인인증 완료·운영 인증 활성화로 설명하지 않는다.

11/11 후속: `docs/design/identity_evidence.md`에 원본 저장/조회와 발급기 연결을 추가했다.
세션 조회 뷰가 현재 원본과 직접 결합하므로 원본 철회/정책 변경은 별도 세션 철회 호출 없이도 기존 토큰을 차단한다.
이 동작은 임시 DB 대역에서 검증했으며 실제 인증 수집기와 운영 DB 배포는 미완료다.
