# 에이전트 대화 — 메인 AI 아래 요청·답·확인·채점·도움 (LF-14 · 11/9 변재원, 11/11 채점 실제 검사로)

한줄 설명: 키오스크 AI·DB 에이전트·보관 칸 에이전트·로봇팔 에이전트가 **메인 AI 를 거쳐** 필요한 정보를 묻고 답하며,
채점 에이전트가 그 답을 **다른 기록(보관함 정답지·등록기계 역 표·운영 품목·탑뷰 위치)으로 다시 맞춰 보고**, 어긋나면
무엇이 왜 문제인지 알려(도움) 직원 확인을 부른다.

> 11/11 사용자 결정(채점 에이전트 존재 의의 검토 → **2번 '실제 검증 위주'**): 예전에는 DB 에이전트의 첫 답을 **일부러** 덜 채워
> '점수 낮음 → 도움 → 되돌아보기 → 배운 점' 장면을 매번 연출했다. 실제로 잡는 것은 개인정보 모양·위치 불일치뿐이라
> 발표 질문에 약했다. 이제 연출(되돌아보기·다시 답·배운 점)을 없애고, 실제로 틀릴 수 있는 것을 검사한다.

- 코드: `agents/agent_talk.py` (대화·채점·도움), 연결 `agents/sim_director.py`(습득), `agents/supervisor.py`(반환 — 로봇 접근 전 확인), `agents/tower_brain.py`(매칭이 애매할 때 메인 AI 대화도 같은 곳에)
- 보이는 곳: `/live` 오른쪽 **🤖 에이전트 대화** 패널(말 하나씩) · 디스코드 **#🤖에이전트-대화**(대화 하나가 끝나면 한 번에)
- 켜기: 가상 시연(`TOWER_SIM=1`)은 기본으로 켜짐. 끄려면 `.env` `TOWER_AGENT_TALK=0`. 실제 관제탑은 `TOWER_AGENT_TALK=1` 일 때만
- 시험: `tests/test_agent_talk.py`

## 1. 용어
| 말 | 뜻 |
|---|---|
| 메인 AI | 요청을 나누고, 받은 답을 확인하고, 다음 할 일을 정하는 지휘자. 모든 말은 메인 AI 를 거친다 |
| 채점 에이전트 | 답을 다른 기록과 맞춰 보는 검사관. 점수(0~100)는 보여 주기용이고, 빠지거나 어긋난 항목이 **하나라도** 있으면 도움 + 직원 확인 경보 |
| 도움(coach) | 채점 에이전트가 "무엇이 · 왜 문제인지(틀리면 무슨 일이 생기는지)"를 메인 AI 에게 알리는 말. 실제로 어긋날 때만 나옴 |
| 보관함 정답지 | `agents/storage.py`(팀 DB `storage_assignment` 와 같은 규칙). 가상 작업대가 고른 칸과 **다른 코드**로 다시 계산해 맞춰 봄 |

## 2. 방식 — 정해진 틀 + 규칙 채점 (11/9 사용자 결정 '가')
- 말은 정해진 문장 틀에 **실제 흐름의 실제 값**(물건 번호·역·품목·칸·좌표)을 넣어 만든다. 미리 녹화한 대본이 아니다
- 채점 = 필요한 항목을 다 채웠나(70점) + 다른 기록과 맞나(30점). 개인정보 모양(전화·주민·카드·이메일)이 있으면 0점
- 그래픽카드(LLM)를 더 쓰지 않는다 → 빠르고 늘 같은 결과. 관제탑 GPU 6GB 는 챗봇(Mi:dm)·사진 분석(Qwen)이 쓴다

### 무엇을 검사하나 (11/11)
| 답한 에이전트 | 검사 | 어긋나면 생길 일 |
|---|---|---|
| DB 에이전트(습득 기록) | 품목·색이 채워졌나 | 사진 분석(Qwen)이 못 읽음 → 칸 열을 못 고르고, 분실인이 색으로 못 찾음 |
| DB 에이전트(습득 기록) | 품목이 운영 품목(목업폰·보조배터리·핸드크림·립밤)인가 | 받는 열이 없음 |
| DB 에이전트(습득 기록) | 습득자가 적은 장소의 역 = 등록기계 역 | 장소 확인 질문·검색이 어긋남 |
| 보관 칸 에이전트 | 품목 맞는 열인가 · 정답지에서 빈 칸인가 · 같은 열 먼 줄(-1)이 비었는데 -2 를 골랐나 | 엉뚱한 칸에서 집음 · 한 칸에 두 물건 · 11/11 오전 'R3-1 비었는데 R3-2' 문제 |
| 보관 칸 에이전트(칸 대기) | 칸 대기라고 했는데 정답지에는 그 열에 빈 칸이 있나 | 11/11 오전 '빈 칸이 있는데 칸 대기' 문제 |
| DB 에이전트(반환 칸) | 탑뷰가 본 물건 중심이 DB 칸 범위 안인가 | 다른 물건을 집음 → 로봇을 움직이지 않음(반환 흐름이 직원 확인) |

- 다른 물건이 회수하려고 잡아 둔 칸(정답지에는 아직 안 보임)은 빈 칸으로 치지 않는다 — 오경보 방지
- 못 잡는 것(한계): **사진 분석 자체가 틀린 경우**(분홍 크림을 립밤으로 읽음 등). 품목도 색도 같은 Qwen 결과라 비교할 다른 기록이 없다. 다음 후보 6장

## 3. 흐름
```
[습득]  키오스크 AI -> 메인 AI       : 초량역 등록기계 접수 · 장소 '…' · 사진 분석 지갑·검정 — 등록 확인 부탁
        메인 AI -> DB 에이전트       : 기록 알려 줘(역·품목·색·상태)
        DB 에이전트 -> 메인 AI       : 물건 번호, 역, 품목, 색, 상태
        채점 에이전트 -> 메인 AI     : 모두 채웠고 다른 기록과도 일치 [100점]
          (어긋나면) 채점 에이전트 -> 메인 AI : (도움) 품목: 사진을 직원이 봐야 해요 …  + 직원 확인 경보
        메인 AI -> 키오스크 AI       : (확인) 요청과 DB 기록이 맞아요
        메인 AI -> 보관 칸 에이전트  : 핸드크림이 들어갈 빈 칸 → R3-1
        채점 에이전트 -> 메인 AI     : 보관함 정답지와 맞춰 봄(열·빈 칸·먼 줄 먼저) [100점] → (결정) 회수해서 그 칸에

[반환]  매칭 에이전트 -> 메인 AI     : 탑뷰 물건 n개 중 k번(점수·차이)
        로봇팔 에이전트 -> 메인 AI   : 집으러 가기 전에 칸·칸 범위 알려 줘(탑뷰 좌표와 맞춰 볼게)
        메인 AI -> DB 에이전트       : 칸 번호와 칸 범위
        DB 에이전트 -> 메인 AI       : R2-1 칸, 범위 x … y …
        로봇팔 에이전트 -> 메인 AI   : (확인) 물건 중심이 칸 범위 안 ✓
        채점 에이전트 -> 메인 AI     : 위치 일치 [100점] (밖이면 도움)
        메인 AI -> 로봇팔 에이전트   : (결정) 사전 접근 시작 / 범위 밖이면 로봇을 움직이지 않고 직원 확인
```
매칭이 애매할 때 도는 관제탑 메인 AI(매칭·보관 칸·비전 에이전트, `docs/design/tower_main_ai.md`)의 대화도 같은 패널·채널에 이어서 보인다.

## 4. 안전 원칙 (바꾸지 않음)
- 로봇을 움직일지는 코드가 정한다. 에이전트 대화가 할 수 있는 것은 "멈추고 직원 확인"으로 **더 조심하게** 만드는 것뿐(칸 범위와 탑뷰 위치가 다르면 멈춤). 칸 기록·범위가 없으면 원래 기준(매칭 결과)대로
- 대화 글은 개인정보 모양이면 내용을 숨긴다. 로그인 없는 주소(`/sim/stories/…`, 분실물 봇)에는 에이전트 대화를 내보내지 않는다 — 관리자 `/live` 와 디스코드 에이전트 채널에서만
- 디스코드는 대화 하나가 끝날 때 한 번(1900자 안, 넘으면 "/live 에서 보기") — 웹후크 전송 한도에 걸리지 않게. `DISCORD_WEBHOOK_AGENT` 가 비면 보내지 않는다(시험 채널로도 안 보냄)

## 5. 개인 디스코드 서버에 채널 연결(처음 한 번)
1. 디스코드 앱 → 개인 서버 → 채널 만들기(+) → 텍스트 채널 `🤖에이전트-대화`
2. 채널 편집(톱니바퀴) → 연동 → 웹후크 만들기 → 이름 `관제탑 에이전트` → 웹후크 URL 복사 → 변경사항 저장
3. 메모장으로 `.env` 를 열어 `DISCORD_WEBHOOK_AGENT=` 뒤에 붙여 넣고 저장(주소는 비밀값 — 다른 곳에 쓰지 않음)
4. 관제탑을 가상 시연으로 켜고(`TOWER_SIM=1`, 디스코드 전송은 `TOWER_SEND=1`) 습득·분실 한 번씩 → 채널에 대화가 하나씩 올라옴

## 6. 한계와 다음 단계
- 에이전트의 말은 정해진 틀이다(LLM 이 쓴 문장이 아님). 발표에서는 "규칙 기반 다중 에이전트 협업 + **다른 기록과 교차 검증하는** 채점 에이전트"라고 정확히 말한다
- 평소 흐름이 맞으면 도움 장면은 나오지 않는다(100점). 발표에서 도움을 보이려면 실제로 어긋나는 상황을 만든다(예: 사진 분석이 품목을 못 읽은 접수)
