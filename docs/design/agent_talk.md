# 에이전트 대화 — 메인 AI 아래 요청·답·확인·채점·도움·배운 점 (LF-14 · 11/9 변재원)

한줄 설명: 키오스크 AI·DB 에이전트·보관 칸 에이전트·로봇팔 에이전트가 **메인 AI 를 거쳐** 필요한 정보를 묻고 답하며,
채점 에이전트가 답마다 점수를 매기고 부족하면 그 에이전트를 도와 더 나은 답을 다시 내게 한다.
도움받은 에이전트는 무엇이 왜 부족했는지 되돌아보고 배운 점을 기억해, 다음 답부터 처음부터 제대로 답한다.

- 코드: `agents/agent_talk.py` (대화·채점·도움), 연결 `agents/sim_director.py`(습득), `agents/supervisor.py`(반환 — 로봇 접근 전 확인), `agents/tower_brain.py`(매칭이 애매할 때 메인 AI 대화도 같은 곳에)
- 보이는 곳: `/live` 오른쪽 **🤖 에이전트 대화** 패널(말 하나씩) · 디스코드 **#🤖에이전트-대화**(대화 하나가 끝나면 한 번에)
- 켜기: 가상 시연(`TOWER_SIM=1`)은 기본으로 켜짐. 끄려면 `.env` `TOWER_AGENT_TALK=0`. 실제 관제탑은 `TOWER_AGENT_TALK=1` 일 때만
- 시험: `tests/test_agent_talk.py`

## 1. 용어
| 말 | 뜻 |
|---|---|
| 메인 AI | 요청을 나누고, 받은 답을 확인하고, 다음 할 일을 정하는 지휘자. 모든 말은 메인 AI 를 거친다 |
| 채점 에이전트 | 답마다 점수(0~100)를 매기고, 80점 미만이면 무엇이 왜 필요한지 알려 주는 도우미 |
| 되돌아보기(reflect) | 도움받은 에이전트가 "제가 ○○만 보고 답해서 ○○이 빠졌네요"처럼 원인을 스스로 정리하는 말 |
| 배운 점(lesson) | 되돌아보기 뒤 기억하는 답하는 법. 다음 대화부터 처음부터 반영하고 "📚 지난번 도움 반영"이라고 말함. 가상 세계 초기화 때 지움 |

## 2. 방식 — 정해진 틀 + 규칙 채점 (11/9 사용자 결정 '가')
- 말은 정해진 문장 틀에 **실제 흐름의 실제 값**(물건 번호·역·품목·칸·좌표)을 넣어 만든다. 미리 녹화한 대본이 아니다
- 채점 = 필요한 항목을 다 채웠나(70점) + 코드가 다시 확인한 값과 맞나(30점). 개인정보 모양(전화·주민·카드·이메일)이 있으면 0점
- 그래픽카드(LLM)를 더 쓰지 않는다 → 빠르고 늘 같은 결과. 관제탑 GPU 6GB 는 챗봇(Mi:dm)·사진 분석(Qwen)이 쓴다
- 에이전트가 처음 답할 때 "가장 빨리 읽을 수 있는 표만" 보는 습관이 있다(DB 에이전트: 접수 표만 / 칸 번호만). 채점 에이전트 도움으로 필요한 표까지 읽게 되고, 그 방법을 기억한다 — 시연을 처음 켜면 첫 습득·첫 반환에서 도움 장면이 보이고, 그다음부터는 배운 점 반영이 보인다

## 3. 흐름
```
[습득]  키오스크 AI -> 메인 AI       : 초량역 등록기계 접수 · 장소 '…' · 사진 분석 지갑·검정 — 등록 확인 부탁
        메인 AI -> DB 에이전트       : 기록 알려 줘(역·품목·색·상태)
        DB 에이전트 -> 메인 AI       : 물건 번호, 상태               (접수 표만 읽음)
        채점 에이전트 -> 메인 AI     : 빠짐 역·품목·색  [58점]
        메인 AI -> 채점 에이전트     : DB 에이전트를 도와줘
        채점 에이전트 -> DB 에이전트 : 칸을 고르려면 품목이, 검색하려면 역·색이 필요해요 — 특징 표·역 표도 읽어 줘
        DB 에이전트 -> 채점 에이전트 : (되돌아보기) 접수 표만 읽어서 놓쳤네요. 앞으로는 함께 읽을게요
        DB 에이전트 -> 메인 AI       : (다시 답) 역·품목·색까지
        채점 에이전트 -> 메인 AI     : 58점 -> 100점
        메인 AI -> 키오스크 AI       : (확인) 요청과 DB 기록이 맞아요
        메인 AI -> 보관 칸 에이전트  : 지갑이 들어갈 빈 칸 → R2-1 (점수) → (결정) 회수해서 그 칸에

[반환]  매칭 에이전트 -> 메인 AI     : 탑뷰 물건 n개 중 k번(점수·차이)
        로봇팔 에이전트 -> 메인 AI   : 집으러 가기 전에 칸·칸 범위 알려 줘(탑뷰 좌표와 맞춰 볼게)
        메인 AI -> DB 에이전트       : 칸 번호와 칸 범위
        DB 에이전트 -> 메인 AI       : R2-1 칸                        (칸 번호만)
        채점 → 도움 → 되돌아보기 → 다시 답(범위 포함) → 100점
        메인 AI -> 로봇팔 에이전트   : R2-1, 범위 x … y …
        로봇팔 에이전트 -> 메인 AI   : (확인) 물건 중심이 칸 범위 안 ✓
        메인 AI -> 로봇팔 에이전트   : (결정) 사전 접근 시작 / 범위 밖이면 로봇을 움직이지 않고 직원 확인
```
매칭이 애매할 때 도는 관제탑 메인 AI(매칭·보관 칸·비전 에이전트, `docs/design/tower_main_ai.md`)의 대화도 같은 패널·채널에 이어서 보인다.

## 4. 안전 원칙 (바꾸지 않음)
- 로봇을 움직일지는 코드가 정한다. 에이전트 대화가 할 수 있는 것은 "멈추고 직원 확인"으로 **더 조심하게** 만드는 것뿐(칸 범위와 탑뷰 위치가 다르면 멈춤). 칸 기록·범위가 없으면 원래 기준(매칭 결과)대로
- 대화 글은 개인정보 모양이면 내용을 숨긴다. 로그인 없는 주소(`/sim/stories/…`, 분실물 봇)에는 에이전트 대화를 내보내지 않는다 — 관리자 `/live` 와 디스코드 에이전트 채널에서만
- 디스코드는 대화 하나가 끝날 때 한 번(1900자 안, 넘으면 "/live 에서 보기") — 웹후크 전송 한도에 걸리지 않게. `DISCORD_WEBHOOK_AGENT` 가 비면 보내지 않는다(시험 채널로도 안 보냄)

## 5. 개인 디스코드 서버에 채널 연결(처음 한 번)
1. 디스코드 앱 → 개인 서버 → 채널 만들기(+) → 텍스트 채널 `🤖에이전트-대화`
2. 채널 편집(톱니바퀴) → 연동 → 웹후크 만들기 → 이름 `관제탑 에이전트` → 웹후크 URL 복사 → 변경사항 저장
3. 메모장으로 `.env` 를 열어 `DISCORD_WEBHOOK_AGENT=` 뒤에 붙여 넣고 저장(주소는 비밀값 — 다른 곳에 쓰지 않음)
4. 관제탑을 가상 시연으로 켜고(`TOWER_SIM=1`, 디스코드 전송은 `TOWER_SEND=1`) 습득·분실 한 번씩 → 채널에 대화가 하나씩 올라옴

## 6. 한계와 다음 단계
- 에이전트의 말은 정해진 틀이다(LLM 이 쓴 문장이 아님). 발표에서는 "규칙 기반 다중 에이전트 협업 + 규칙 채점·피드백 루프"라고 정확히 말한다
- 배운 점은 관제탑 메모리에만 있다(다시 켜면 처음부터) — 시연을 되풀이해 보여 주기 좋게 일부러 그렇게 둠
- 다음 후보: 채점 점수를 Langfuse 점수로도 남기기, 실제 관제탑(`TOWER_AGENT_TALK=1`)에서 실제 보관 칸 범위(`/storage` 구역 좌표)로 확인
