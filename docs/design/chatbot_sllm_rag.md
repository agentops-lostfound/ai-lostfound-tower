# AI 챗봇 — 로컬 sLLM + RAG + 유도 질문 (LF-5 · 11/6 변재원)

한줄 설명: 질문과 관련된 **우리 안내 문서 문단을 먼저 찾고(RAG)**, **우리 PC 안의 작은 언어 모델(sLLM)** 이 그 문단만 근거로 답하거나, 정보가 모자라면 **되물어서(유도 질문)** 원하는 답까지 이끈다.

## 1. 용어
| 용어 | 한줄 설명 |
| --- | --- |
| LLM | 수백억~수천억 파라미터의 대형 언어 모델(예: ChatGPT). 보통 클라우드 API 로 빌려 씀 |
| **sLLM** | 수억~수십억 파라미터의 작은 언어 모델. 회사 PC·서버 안에서 직접 돌려 **정보가 밖으로 나가지 않고 사용료가 없음** |
| **RAG** | Retrieval-Augmented Generation. 모델이 외운 지식 대신 **우리 문서를 찾아 근거로 답하게** 하는 방식 → 환각(지어낸 답) 감소 |
| TF-IDF 검색 | 문서에 자주 나오면서 다른 문서엔 드문 글자 조각에 점수를 주는 검색(이 챗봇은 글자 2개 조각, 설치 없음) |
| 양자화 | 모델 숫자를 4비트 등으로 줄여 메모리를 아끼는 기술(EXAONE 2.4B 약 1.6GB) |
| 유도 질문 | 질문이 모호하면 선택지를 주고 되물어 필요한 정보(품목·장소 등)를 채우는 대화 방식 |

## 2. 흐름
```
질문 ─▶ ① 규칙(agents/guidance.py) — 확실한 질문은 바로 해당 주제 문단
      ─▶ ② 문서 검색(agents/chat_retrieval.py) — 규칙이 못 잡은 질문도 비슷한 문단 4개
      ─▶ ③ sLLM(Ollama, agents/chat_rag.py) — 문단만 근거로
             · 답(mode=answer): 2~4문장 + 근거 문단 번호
             · 되묻기(mode=clarify): 짧은 질문 + 선택지 2~4개(화면에 버튼)
      ─▶ ④ 검사기 — 하나라도 어기면 모델 답을 버리고 문서 문장 그대로
             · 근거 문단 번호가 실제 찾은 문단인가 · 답의 숫자가 근거 문단에 있는가(운영값 날조 차단)
             · 개인정보 모양·주소(URL)·길이 · 시연 운영 기준 주제는 '시연 기준' 문구
```
- **모델이 꺼져 있어도 대화가 끊기지 않음**: "어제 뭐 잃어버렸는데요" → "어떤 물건인가요?" + [지갑] [휴대폰] [USB] 버튼(규칙 되묻기), 관련 문단이 있으면 "혹시 이 내용인가요?" 버튼, 주제 밖(날씨 등)은 기본 메뉴 버튼
- 물건 검색(후보 찾기)은 기존대로 별도 경로(LangGraph `agents/chatbot.py`). 품목 버튼을 누르면 검색으로 이어짐
- 운영시간·보관 기간 같은 **시연 운영 기준 문장은 모델이 바꾸지 못함**(고정 문장)

## 4. 켜는 법 (관제탑 PC)
1. `ollama pull exaone3.5:2.4b`
2. `.env` 의 `LF_CHAT_RAG_MODEL=exaone3.5:2.4b` (메모장으로 저장, 값만 바꿈)
3. 관제탑 다시 켜기 → `/chat/health` 의 `rag_model_configured: true`
4. 위젯 배지가 "문서 검색 + AI 답변" 이면 모델 답, "문서 근거 안내" 면 문서 문장 그대로(모델이 꺼졌거나 검사 탈락)

## 6. 직원 관제 질문(11/6, A안) — 챗봇 안의 LangManus 구조 에이전트
한줄 설명: **관리자 화면 챗봇에서만** "오늘 반환 실패 원인 알려줘" 같은 관제 질문을 LangManus 구조 관제 분석 에이전트(`agents/ops_analyst.py`)로 보낸다. 분실인 화면은 그대로 빠른 안내·검색만 한다.

```
질문 → [route_question]  (agents/chatbot.py, LangGraph)
         ├─ 이용 안내 ─▶ document_guidance : sLLM + RAG          (분실인·직원, 1초대)
         ├─ 물건 찾기 ─▶ item_search       : DB 읽기 전용 검색     (분실인·직원)
         ├─ 둘 다 ────▶ combined_help
         └─ 관제 질문 ─▶ ops_report        : 조정 → 계획 → 감독 ⇄ 조사·분석·보고 (직원 로그인 시만)
```
- **누가 열 수 있나**: 관리자 화면(`/admin`) 위젯은 `data-mode="staff"` 로 붙어 본문에 `"mode": "staff"` 를 보낸다. 관제탑은 관리자 API 와 같은 문지기(로그인 쿠키·`X-Admin-Key`)를 통과해야만 챗봇에 `staff=True` 를 넘기고, 아니면 **401**. `/lost`·`/kiosk` 위젯은 mode 를 보내지 않으므로 관리자 쿠키가 있어도 관제 길이 열리지 않는다. `LF_ADMIN_PASSWORD` 가 비어 있으면 관리자 API 처럼 열려 있다(시연 PC 전용 — 교육원 네트워크 공개(`lan`) 때는 비밀번호를 켠다)
- **어떤 질문이 관제 질문인가**(`is_ops_question`): 원인·현황·통계·요약·보고·분석·몇 건·경보·처리 시간 같은 낱말, 또는 "실패·로봇·반환…" + "오늘·최근…" 이 같이 있을 때. "본인인증 실패하면?"·"반환 절차 알려줘" 같은 이용 안내는 직원이 물어도 안내 길
- **자료**: 조사자는 HTTP 를 다시 부르지 않고 관제탑 안에서 `/returns`·`/live/state` 와 같은 자료 + 챗봇 운영 지표를 읽기만 한다. 숫자는 분석자의 고정 계산이 만들고, 모델(`OPS_ANALYST_MODEL`, 없으면 `LF_CHAT_RAG_MODEL`)은 계획·보고 문장에만 쓰며 계산에 없는 숫자가 나오면 버린다
- **시간**: 모델을 두 번(계획·보고) 불러 몇 초~십수 초(추정). 직원 위젯은 60초까지 기다린다. 모델이 없으면 계산 보고서가 바로 나온다
- 화면 표시: 배지 "관제 분석 · AI 보고"(모델 문장) / "관제 분석 · 계산 보고"(템플릿), 아래 줄 "관제 기록 기준 · 직원 전용"
- 시험: `tests/test_chat_staff_ops.py`(분실인·로그인 안 함·mode 없음이면 절대 관제 길 아님, 오류 문구 숨김, 진짜 분석 에이전트 연결)

## 7. 11/6 저녁 보완 — 색상 오해석 차단 · 이전 질문을 모델에 전달
- **색상**: 예전엔 "연보라색 지갑"의 색을 못 알아듣고 **색 없이** 찾아 검정 지갑까지 후보로 보여 줬다. 이제 비전(`agents/vision_adapter.py`)과 같은 묶음으로 읽는다
  - 연한·진한 꾸밈말은 같은 색: 하늘색→파랑, 연두→초록, 네이비→남색, 베이지→갈색, 그레이→회색
  - 우리 색 목록 밖(보라·주황·금색·민트·카키 등) → **기타**로 찾고, 답에 "색상(기타 — 보라·주황처럼 목록 밖 색은 함께 찾음)"을 밝힌다
  - 두 가지 색(검정+빨강, 검정 바탕+보라 줄무늬)은 막연히 되묻지 않고 "가장 넓게 보이는 색 하나"를 묻는다
  - 답 끝의 조회 조건에 실제 값을 쓴다: "품목(지갑) · 색상(검정)", 색이 없으면 "색상 없음(모든 색)"
  - "자주 잃어버려요"의 '자주'는 색으로 보지 않는다
- **이전 질문**: 같은 화면의 앞선 사용자 질문(최대 4개, 개인정보 검사 통과한 것)을 sLLM 에 `previous_questions` 로 넘겨 이어지는 질문을 자연스럽게 답한다. 답의 근거는 여전히 찾은 문단만(검사기 그대로)
  - 여러 사람이 동시에 묻기 때문에 이전 질문은 객체에 저장하지 않고 함수 인자로만 넘긴다(다른 사람 질문이 섞이지 않게 — 시험으로 확인)
- 시험: `tests/test_chat_color_multiturn.py`, `tests/test_chat_model_bench.py`(평가표)
