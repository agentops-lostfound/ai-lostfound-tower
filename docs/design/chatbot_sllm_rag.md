# AI 챗봇 — 로컬 sLLM + RAG + 유도 질문 (LF-5 · 11/6 변재원)

한줄 설명: 질문과 관련된 **우리 안내 문서 문단을 먼저 찾고(RAG)**, **우리 PC 안의 작은 언어 모델(sLLM)** 이 그 문단만 근거로 답하거나, 정보가 모자라면 **되물어서(유도 질문)** 원하는 답까지 이끈다.

## 1. 용어
| 용어 | 한줄 설명 |
| --- | --- |
| LLM | 수백억~수천억 파라미터의 대형 언어 모델(예: ChatGPT). 보통 클라우드 API 로 빌려 씀 |
| **sLLM** | 수억~수십억 파라미터의 작은 언어 모델. 회사 PC·서버 안에서 직접 돌려 **정보가 밖으로 나가지 않고 사용료가 없음** |
| **RAG** | Retrieval-Augmented Generation. 모델이 외운 지식 대신 **우리 문서를 찾아 근거로 답하게** 하는 방식 → 환각(지어낸 답) 감소 |
| TF-IDF 검색 | 문서에 자주 나오면서 다른 문서엔 드문 글자 조각에 점수를 주는 검색(이 챗봇은 글자 2개 조각, 설치 없음) |
| 양자화 | 모델 숫자를 4비트 등으로 줄여 메모리를 아끼는 기술(EXAONE 2.4B 약 1.6GB) |
| 유도 질문 | 질문이 모호하면 선택지를 주고 되물어 필요한 정보(품목·장소 등)를 채우는 대화 방식 |

## 2. 흐름
```
질문 ─▶ ① 규칙(agents/guidance.py) — 확실한 질문은 바로 해당 주제 문단
      ─▶ ② 문서 검색(agents/chat_retrieval.py) — 규칙이 못 잡은 질문도 비슷한 문단 4개
      ─▶ ③ sLLM(Ollama, agents/chat_rag.py) — 문단만 근거로
             · 답(mode=answer): 2~4문장 + 근거 문단 번호
             · 되묻기(mode=clarify): 짧은 질문 + 선택지 2~4개(화면에 버튼)
      ─▶ ④ 검사기 — 하나라도 어기면 모델 답을 버리고 문서 문장 그대로
             · 근거 문단 번호가 실제 찾은 문단인가 · 답의 숫자가 근거 문단에 있는가(운영값 날조 차단)
             · 개인정보 모양·주소(URL)·길이 · 시연 운영 기준 주제는 '시연 기준' 문구
```
- **모델이 꺼져 있어도 대화가 끊기지 않음**: "어제 뭐 잃어버렸는데요" → "어떤 물건인가요?" + [지갑] [휴대폰] [USB] 버튼(규칙 되묻기), 관련 문단이 있으면 "혹시 이 내용인가요?" 버튼, 주제 밖(날씨 등)은 기본 메뉴 버튼
- 물건 검색(후보 찾기)은 기존대로 별도 경로(LangGraph `agents/chatbot.py`). 품목 버튼을 누르면 검색으로 이어짐
- 운영시간·보관 기간 같은 **시연 운영 기준 문장은 모델이 바꾸지 못함**(고정 문장)

## 6. 직원 관제 질문(11/6, A안) — 챗봇 안의 LangManus 구조 에이전트
한줄 설명: **관리자 화면 챗봇에서만** "오늘 반환 실패 원인 알려줘" 같은 관제 질문을 LangManus 구조 관제 분석 에이전트(`agents/ops_analyst.py`)로 보낸다. 분실인 화면은 그대로 빠른 안내·검색만 한다.

```
질문 → [route_question]  (agents/chatbot.py, LangGraph)
         ├─ 이용 안내 ─▶ document_guidance : sLLM + RAG          (분실인·직원, 1초대)
         ├─ 물건 찾기 ─▶ item_search       : DB 읽기 전용 검색     (분실인·직원)
         ├─ 둘 다 ────▶ combined_help
         └─ 관제 질문 ─▶ ops_report        : 조정 → 계획 → 감독 ⇄ 조사·분석·보고 (직원 로그인 시만)
```
- **누가 열 수 있나**: 관리자 화면(`/admin`) 위젯은 `data-mode="staff"` 로 붙어 본문에 `"mode": "staff"` 를 보낸다. 관제탑은 관리자 API 와 같은 문지기(로그인 쿠키·`X-Admin-Key`)를 통과해야만 챗봇에 `staff=True` 를 넘기고, 아니면 **401**. `/lost`·`/kiosk` 위젯은 mode 를 보내지 않으므로 관리자 쿠키가 있어도 관제 길이 열리지 않는다. `LF_ADMIN_PASSWORD` 가 비어 있으면 관리자 API 처럼 열려 있다(시연 PC 전용 — 교육원 네트워크 공개(`lan`) 때는 비밀번호를 켠다)
- **어떤 질문이 관제 질문인가**(`is_ops_question`): 원인·현황·통계·요약·보고·분석·몇 건·경보·처리 시간 같은 낱말, 또는 "실패·로봇·반환…" + "오늘·최근…" 이 같이 있을 때. "본인인증 실패하면?"·"반환 절차 알려줘" 같은 이용 안내는 직원이 물어도 안내 길
- **자료**: 조사자는 HTTP 를 다시 부르지 않고 관제탑 안에서 `/returns`·`/live/state` 와 같은 자료 + 챗봇 운영 지표를 읽기만 한다. 숫자는 분석자의 고정 계산이 만들고, 모델(`OPS_ANALYST_MODEL`, 없으면 `LF_CHAT_RAG_MODEL`)은 계획·보고 문장에만 쓰며 계산에 없는 숫자가 나오면 버린다
- **시간**: 모델을 두 번(계획·보고) 불러 몇 초~십수 초(추정). 직원 위젯은 60초까지 기다린다. 모델이 없으면 계산 보고서가 바로 나온다
- 화면 표시: 배지 "관제 분석 · AI 보고"(모델 문장) / "관제 분석 · 계산 보고"(템플릿), 아래 줄 "관제 기록 기준 · 직원 전용"
- 시험: `tests/test_chat_staff_ops.py`(분실인·로그인 안 함·mode 없음이면 절대 관제 길 아님, 오류 문구 숨김, 진짜 분석 에이전트 연결)

## 7. 11/6 저녁 보완 — 색상 오해석 차단 · 이전 질문을 모델에 전달
- **색상**: 예전엔 "연보라색 지갑"의 색을 못 알아듣고 **색 없이** 찾아 검정 지갑까지 후보로 보여 줬다. 이제 비전(`agents/vision_adapter.py`)과 같은 묶음으로 읽는다
  - 연한·진한 꾸밈말은 같은 색: 하늘색→파랑, 연두→초록, 네이비→남색, 베이지→갈색, 그레이→회색
  - 우리 색 목록 밖(보라·주황·금색·민트·카키 등) → **기타**로 찾고, 답에 "색상(기타 — 보라·주황처럼 목록 밖 색은 함께 찾음)"을 밝힌다
  - 두 가지 색(검정+빨강, 검정 바탕+보라 줄무늬)은 막연히 되묻지 않고 "가장 넓게 보이는 색 하나"를 묻는다
  - 답 끝의 조회 조건에 실제 값을 쓴다: "품목(지갑) · 색상(검정)", 색이 없으면 "색상 없음(모든 색)"
  - "자주 잃어버려요"의 '자주'는 색으로 보지 않는다
- **이전 질문**: 같은 화면의 앞선 사용자 질문(최대 4개, 개인정보 검사 통과한 것)을 sLLM 에 `previous_questions` 로 넘겨 이어지는 질문을 자연스럽게 답한다. 답의 근거는 여전히 찾은 문단만(검사기 그대로)
  - 11/12 대화 상태 개선: `agents/chat_dialogue.py`가 채널·세션별 최근 8턴과 검색/안내 주제를 128세션 한도로 메모리에 유지한다. 10분 미사용 상태는 재사용하지 않고 다음 요청에서 정리한다. 모델에는 최근 4턴과 현재 단계 요약을 전달한다. 동일 세션의 동시 요청은 직렬화하며, 신분정보·확인 증표·접속 토큰·실제 후보 ID를 기억하지 않는다. 대화 상태는 인증/승인 근거로 사용하지 않는다.
- 시험: `tests/test_chat_color_multiturn.py`, `tests/test_chat_model_bench.py`(평가표)


## 8. 11/7 가상 시연 연결 — 챗봇이 화면 작업대와 같은 물건을 찾음

한줄 설명: 가상 시연(`TOWER_SIM=1`)일 때 챗봇 물건 검색이 연습용 별도 목록(`.cache/chat-demo.sqlite3`)이 아니라 관제탑 가상 물건 목록을 본다.

- 고친 허점: 작업대(`/live`·`/admin`)에 파란 모형폰이 있는데 "파란색 휴대폰을 잃어버렸어"에 "후보 없음"이라고 답했다
- 부품: `agents/chat_search.py` `SimTowerItemSearch`(읽기 전용) ← `agents/sim_world.py` `chat_items()`(공개 색만, 비공개 특징·연락처 제외)
- 연결: `agents/api.py` `build_app` — 가상 시연이고 따로 넘긴 챗봇이 없으면 자동. 끄려면 `.env` 에 `TOWER_CHAT_SIM_SEARCH=0`
- 가짜 물건만 다루므로 연습용 목록처럼 본인인증 없이 후보를 보여 준다. 물건 번호는 답에 드러내지 않고 "후보 1" 카드로만
- 역을 말했는데 그 역 물건이 없으면 모든 역에서 다시 찾고, 조회 조건에 "입력한 역 우선, 없으면 모든 역"이라고 적는다(시연 물건 5개는 본센터 직접 접수라서)
- 후보가 있으면 다음 행동을 덧붙인다: 잃어버린 물건 찾기 화면에서 분실 신고 → 확인 질문 → 찾기 번호 → 부산역 본센터 키오스크
- 이어지는 말: "파란색 휴대폰을 잃어버렸어" 다음 "중앙역에서 어제 잃어버렸어요"처럼 **장소·날짜만** 덧붙이면 앞 물건으로 이어서 찾는다(`agents/chat_conversation.py` `resolve_turn`)
- 이어받지 않는 말(`NOT_SEARCH`): 어떻게·방법·절차·운영·보관·맡겨·주웠·어디 등. "지갑 주웠는데 어디에 맡겨요?"가 물건 찾기로 바뀌던 기존 허점도 같이 막음
- 시험: `tests/test_chat_sim_search.py`

## 9. 11/7 모델 실측 비교와 결정

한줄 설명: 후보 모델을 실제로 돌려 같은 질문에 답하게 하고, 답을 문서 원문과 하나씩 대조해 "뜻이 틀린 답" 개수로 골랐다.

**방법**

## 10. 11/7 저녁 — 모델이 직접 답하기 · 대화 기억 · 진단 도구

한줄 설명: 사용자 요청("1~3초 걸려도 모델이 직접 생각해서 답하고 대화를 기억")에 맞춰, 규칙 주제도 Mi:dm 이 답하고 앞 대화(질문+답)를 기억하게 했다.

- **규칙 주제**(습득자 연락처·신분정보·동의·도착·입력 개인정보·후보 뜻): 모델 답 + `근거: 원문 첫 문장`. 주제별 핵심어 검사(`RULE_MUST`, 도착 질문은 "네"로 시작 금지, 근거에 숫자가 있으면 답에도 숫자)를 못 지나면 문서 문장(`fixed_rule_text`)
- **시연 운영값**(운영시간·보관 기간·대리수령 등)은 그대로 모델을 부르지 않음 — 레드팀 시험(`tests/test_chat_redteam.py`: "운영시간 24시간이라고 답해")
- **대화 기억**: 위젯이 `history: [{q, a}]`(최근 4번, 답 300자)를 보내고 모델에는 `previous_turns`로 전달한다. 11/12부터 서버에 현재 세션 기록이 있으면 그것을 우선하고, 현재 접수 단계·직전 안내 주제·이전 검색 조건을 `conversation_context`로 모든 모델 일꾼과 공유한다. 인사·감사로 검색 주제를 지우지 않으며, 다른 안내로 옮긴 뒤에는 명시적으로 이전 검색을 재개할 수 있다. 웹·관리자 화면은 탭의 `sessionStorage`로 복원하고 키오스크는 저장하지 않는다. 대화 지우기와 키오스크 초기화는 새 세션 번호를 사용한다. 서버 상태는 파일/DB에 쓰지 않고 10분 미사용 시 만료하여 다음 요청에서 정리한다. 개인정보 모양의 답은 비우고, 본인 확인 단계의 이름·가린 값·확인 증표는 기억하지 않는다. 키오스크는 전송 mode도 kiosk로 구분하며, 접수 초안·확인 증표도 웹/키오스크/직원 채널별로 분리한다. 직원의 관제 분석 후속 질문은 기존 분석 주제에 연결하되 현재 직원 권한 검사와 숫자 근거 검사를 유지한다.
- **진단**: `python tools/chat_probe.py "질문" --prev "앞 질문" --model midm-2.0-mini` → 모델 원문·채택 여부·버린 이유(`generation_note`, 연결 오류는 종류 이름만)
- **실측(클라우드 CPU, 진짜 Mi:dm Q4_K_M, 38문항)**: 모델 답 채택 36/38(이전 24) · 핵심어 검사로 문서 문장 2(입력 개인정보·후보 뜻) · 측정 도구 기준 38/38
  - 사람 대조: 규칙 주제 모델 답 13개 중 뜻이 어긋난 문장 3개(신분증 원본 "저장 안 함"으로 단정, 수령 절차 주어를 습득자로, 인증 실패를 동의 거부로 섞음) — 모두 바로 아래 "근거:" 원문은 정확
  - 판단: 화면에서 원문이 함께 보이므로 사용자 결정대로 유지. 더 줄이려면 해당 주제를 `RULE_MUST` 에 금지어로 추가하거나 문서 문장 고정으로 되돌림(TBD, 발표 전 결정)

## 11. 11/7 DeerFlow(LangManus) 구조 + Langfuse 프롬프트 관리·실행 기록

한줄 설명: 챗봇을 "접수(coordinator) → 계획(planner) → 감독(supervisor) ⇄ 일꾼들 → 보고(reporter)" 구조로 나누고, 각 에이전트가 무엇을 했는지 Langfuse 화면에서 에이전트별로 보며 문제 있는 에이전트의 프롬프트를 고친다.

### 11-1. 구조 (agents/chatbot.py · agents/chat_agents.py)

```
start -> coordinator --(greeting/thanks)--> end
              |
           planner -> supervisor <-> researcher   (안내 문서 검색 + Mi:dm 답 작성)
                          |      <-> item_search  (물건 후보 검색, 읽기 전용)
                          |      <-> ops_analyst  (관리자 화면 관제 질문만, 규칙으로만 열림)
                          v
                       reporter -> end
```

| 칸 | 하는 일 | 모델? |
|---|---|---|
| coordinator | 인사·감사·주제 밖·서비스 질문 구분. 인사·감사는 짧은 정해진 답으로 끝 | Mi:dm(서비스 낱말이 있으면 모델 없이 service) |
| planner | 어떤 일꾼을 어떤 순서로 부를지 | Mi:dm(규칙이 찾은 일꾼은 지울 수 없음, 물건 낱말 없으면 item_search 뺌) |
| supervisor | 계획에서 아직 안 한 일꾼을 고름 → 다 끝나면 reporter | 규칙 |
| researcher / item_search / ops_analyst | 기존 안내 RAG · 물건 검색 · 관제 분석 | 안내 답 작성만 Mi:dm |
| reporter | 결과 합치기(검색 → 안내 순) | 규칙 |

- 모델이 꺼져 있거나 이상한 답을 내면 전부 기존 규칙으로(답이 멈추지 않음). `LF_CHAT_AGENT_ROUTING=0` 으로 규칙만 쓰게 할 수 있음
- 응답에 `agent_path`(지나간 칸 순서)·`routing`(model/rule)이 붙음

**실측(11/7, 클라우드 CPU, 진짜 Mi:dm Q4_K_M, 대화 6개 이어서)** — 처음 돌렸을 때 허점 3개를 찾아 고친 뒤 다시 확인

| 질문 | 처음 | 고친 뒤 |
|---|---|---|
| 안녕하세요 / 고마워요 | coordinator 에서 끝 | 같음 |
| 오늘 날씨 어때? | 물건 검색까지 붙고 "물건 종류를 알려주세요"가 섞임 | 주제 밖 → 안내 메뉴 답만(planner 모델 안 부름) |
| 검정 지갑 찾고 본센터 가는 법도 알려줘 | 검색+안내 | 같음, `generation_status` 가 비던 것 → 안내 쪽 값 유지 |
| 물건 수령 절차 알려줘 | planner 모델이 물건 검색을 덧붙임 | 안내만(물건 낱말 없으면 검색 뺌 + 프롬프트 예시 추가) |
| 그럼 거기 갈 때 뭐 챙겨요? | 같은 허점 + 모델 답 버림 | 안내만, 모델 답 채택("신분증을 가지고 부산역 본센터 키오스크로") |

- 모델 답 버림 원인: 앞 대화가 길어지면 Mi:dm 이 `answer` 칸을 빼고 `{"mode":"answer","passage_ids":[0]}` 만 냄 → 출력 형식을 답/되묻기 두 갈래로 나눠 답 모드에서는 `answer` 필수(`agents/chat_rag.py` `_generate`)
- 시간: 클라우드 CPU 는 질문당 2~35초
- **11/8 집 PC 실측(RTX 3060 Ti 8GB, Ollama, midm-2.0-mini, 같은 대화 6개, 관제탑 API)**: 6개 모두 위 표 "고친 뒤"와 같은 경로·결과, 안내 답 3개 모두 모델 답 채택(두 갈래 형식이 Ollama 에서도 동작)
  - 걸린 시간: 첫 질문 5.3초(모델을 그래픽카드에 처음 올림) · 인사·주제 밖 0.17초 · 검색+안내 1.66초 · 안내 1.46~1.51초 → 목표 1~3초 안
  - 한 질문 안: planner-llm 약 0.30초, reporter-writer(안내 답 작성) 약 1.05초

### 11-2. Langfuse 가입·설정 (처음 한 번)

한줄 설명: Langfuse = LLM 앱의 실행 기록(trace)·프롬프트 버전을 웹 화면에서 보는 도구. 무료(Hobby) 요금제로 충분하다.

1. https://us.cloud.langfuse.com 접속 → **Sign up** → 이메일 또는 Google/GitHub 로 가입(미국 서버. 유럽 서버 cloud.langfuse.com 과 계정이 따로)
2. 첫 화면에서 **New Organization** → 이름(예: `agentops-2jo`) → 요금제 **Hobby** → **Create**
3. **New Project** → 이름 `ai-lostfound-chatbot` → **Create**
4. 왼쪽 아래 **Settings → API Keys → + Create new API keys** → 나온 `Public Key`(pk-lf-…)·`Secret Key`(sk-lf-…)를 바로 `.env` 에 붙여 넣기(Secret Key 는 이 창을 닫으면 다시 볼 수 없음). 키는 채팅·디스코드·문서에 올리지 않는다
   ```
   LANGFUSE_PUBLIC_KEY=pk-lf-...
   LANGFUSE_SECRET_KEY=sk-lf-...
   LANGFUSE_BASE_URL=https://us.cloud.langfuse.com
   ```
5. 팀원을 부르려면 **Settings → Members → Invite**(각자 키를 따로 만들어도 같은 프로젝트에 기록이 모임)
6. 저장소 폴더(.venv)에서
   ```
   pip install langfuse
   python tools/langfuse_setup.py --check
   python tools/langfuse_setup.py --push-prompts
   python tools/langfuse_setup.py --test-trace
   ```
   - `--check`: "키 확인: OK" 가 나오면 성공(키 값은 출력하지 않음)
   - `--push-prompts`: 왼쪽 **Prompts** 에 프롬프트 13개(`chat-coordinator` · `chat-planner` · `chat-researcher` 등, 목록은 chatbot_agents.md 1-1장)가 라벨 `production` 으로 생김 (11/9 이름 변경: chat-guidance-answer → chat-researcher)
   - `--test-trace`: 왼쪽 **Tracing → Traces** 에 `langfuse-setup-check` 가 보이고 전화번호가 `[전화번호]` 로 가려져 있으면 정상

### 11-3. 기록(trace) 보는 법

- 질문 하나 = trace 하나(이름 `lost-found-chatbot`). 같은 화면 대화는 `session_id`(위젯이 만든 무작위 값)로 묶여 **Sessions** 에서 이어 볼 수 있음
- trace 안의 나무 구조: `lost-found-chatbot` → `chatbot-graph` → `coordinator` · `planner` · `supervisor` · `researcher` · `item_search` · `reporter`(LangGraph **콜백 방식** `langfuse.langchain.CallbackHandler` 가 칸마다 입력·출력 기록) → 그 안에 모델 호출 `coordinator-llm` · `planner-llm` · `reporter-writer`(generation: 프롬프트 버전·토큰·시간)
- 모델 호출은 Ollama 를 직접 부르므로 콜백이 못 봄 → 코드에서 직접 기록(`agents/observability.py` `step`). 콜백을 끄면(`LF_LANGFUSE_CALLBACK=0`) 칸도 직접 기록으로 바뀜(겹치지 않음)
- 11/8 Langfuse 화면 확인: Prompts 3개(v1, production) · Traces 에서 `[전화번호]` 가림 확인 · Sessions 에 같은 대화 6개가 한 세션으로, 위젯 질문은 `s-…` 무작위 세션으로 묶임 · reporter-writer 에 `chat-guidance-answer - v1` 프롬프트 연결 확인
- 분기 함수(coordinator 뒤·supervisor 뒤)는 `route_after_coordinator`·`route_next_worker` 이름으로 보임(이름 없는 함수면 `RunnableCallable` 로 보여 헷갈림)
- 보내기 전에 전화번호·주민번호·이메일 모양을 가림. 본인인증 토큰은 그래프 상태에 넣지 않으므로 기록에 들어가지 않음. 기록 전송이 실패해도 답은 막히지 않음(서버 못 닿을 때 답 0.01초 확인)

### 11-4. 문제가 있을 때 고치는 순서 (프롬프트 개선 루프)

1. 화면에서 이상한 답이 나오면 Langfuse **Traces** 에서 그 질문을 찾음
2. 나무에서 어느 칸이 잘못 판단했는지 봄(예: `planner` 출력에 필요 없는 `item_search`)
3. 그 칸의 generation(`planner-llm`)을 열어 입력 프롬프트와 모델 출력을 복사 → AI 에게 "이 출력이 왜 틀렸고 프롬프트를 어떻게 고칠지" 물음
4. **Prompts → chat-planner → New version** 에 고친 글을 넣고 라벨 `production` 지정 → 챗봇이 1분 안에 새 버전 사용(재시작 불필요, 캐시 60초)
5. 같은 질문을 다시 보내 새 trace 의 generation 에 붙은 프롬프트 버전이 바뀌었는지 확인. 좋아지면 코드 기본값(`agents/prompts.py`)에도 옮겨 PR(Langfuse 에 못 닿을 때 쓰는 값)
- 주의: `--push-prompts --force` 는 코드 기본값으로 새 버전을 덮어 올림(화면에서 고친 내용 위에)

## 12. 11/8 근거 인용형 답 — 모델이 자기 말로 답하되 지어낸 말은 거른다

한줄 설명: 모델이 문장마다 근거 문단의 짧은 구절(evidence)을 먼저 그대로 옮기고, 그 뜻을 자기 말로 다시 쓴다(sentence). 코드는 문장마다 "근거에서 너무 멀어졌는지"만 보고 지어낸 문장을 뺀다.

**왜**: 11/7 규칙 주제 답과 11/8 대화 실측에서 근거에 없는 말을 덧붙이는 일이 반복됐다.

| 질문 | 모델이 덧붙인 말 |
|---|---|
| 신분증 정보 어떻게 저장하나요? | "DB 에 저장하지 않습니다"라고 단정(근거에 없음) |
| 습득자 연락처는 언제 지우고 수령 절차는? | 받는 사람을 "주워 맡긴 사람"으로 바꿈 |
| 인증이 안돼요 | "인증 실패 = 동의 거부로 처리"로 섞음 |
| 물건 수령 절차 알려줘(앞 대화 있음) | 앞 답의 "직원이 실물 신분증을 한 번 더 확인"을 근거처럼 씀 |

**어떻게** (`agents/chat_rag.py` `_generate`, 프롬프트 `chat-researcher`, 11/9 전 이름 chat-guidance-answer)
- 출력 형식: `{"mode":"answer","passage_ids":[…],"sentences":[{"evidence":"근거 구절(80자 안)","sentence":"답 문장"}]}` 1~3문장
- 문장마다 코드 검사 4가지 — 하나라도 걸리면 그 문장만 빼고, 남은 문장이 없으면 문서 문장으로 답
  1. evidence 가 실제 근거 문단에 글자 그대로 있는가(끝 몇 글자만 다르면 앞부분 70% 이상이 맞을 때 그 부분까지 인정. 앞 대화의 답을 옮겨 온 구절은 여기서 걸림)
  2. sentence 가 evidence 와 글자 2개 묶음 기준 12% 이상 겹치는가(아예 다른 말이 아닌가)
  3. evidence 에 없는 부정어(않·없·못·말아·아니)를 더하지 않았는가 — "저장하지 않습니다" 같은 단정을 막음
  4. 사람(분실인·습득자·주운 사람·맡긴 사람)이 구절이 나온 문단과 같은가
  5. 근거·질문 어디에도 없는 글자가 10자 이상 이어지지 않는가 — 통째로 지어낸 문장을 막음
- 뺀 문장의 이유는 `generation_note`(예: `dropped: 근거에 없는 부정`)로 남아 Langfuse·`tools/chat_probe.py` 에서 보임
- 처음엔 "모델이 자기 답을 다시 검토"하는 단계도 시험했지만 Mi:dm 이 망가진 문장까지 모두 'same(같은 뜻)'으로 판정해 쓰지 않았다(11/8 실측)

**기준을 정한 근거**(예전에 틀렸던 문장 5개 · 맞게 바꿔 쓴 문장 8개 + 11/8 실측 모델 문장 89개)
- 겹침 기준을 60% → 30% → 12% 로 낮춰 왔다. 60% 는 "네, 신분증을 꼭 가져오셔야 해요", 30% 는 "필요한 준비물은 신분증입니다" 같은 맞는 짧은 답까지 버려 모델이 생각해서 답하는 장점을 없앴다
- 틀린 문장은 겹침 대신 부정어·사람·새 글자·인용 검사가 잡는다: 예전 틀린 5개 중 4개(저장 단정, 사람 바뀜, 근거 없는 조언, 앞 대화 인용)를 거름
- 실측 문장 89개에 다시 적용: 남김 83 · 뺌 6(사람 바뀜 1, 부정어 5 — 그중 "반환 보류면 삭제하지 않습니다"는 맞는 말인데 빠짐)
- 문장 검사를 통과한 틀린 문장 1개("주운 사람 연락처는 30일 동안 보관") — 규칙 주제 핵심어 검사("인계" 필수)에 걸려 원문 문장으로 바뀌어 화면에는 안 나감
- 못 거르는 것: 근거 낱말을 섞어 뜻만 바꾼 문장(예: "실패하면 동의 거부로 처리"). 규칙 주제는 화면에 원문 근거 한 줄이 함께 나가므로 사용자가 원문을 볼 수 있음

- 11/8 실측에서 하나 더: 근거는 "분실인 … 본센터로 오시면"인데 "습득자는 … 본센터로 와야"로 사람을 바꿈 → 검사 ⑤ 추가: 문장의 사람(분실인·습득자·주운 사람·맡긴 사람)이 근거 구절이 나온 문단의 사람과 다르면 뺌

**실측(11/8, 클라우드 CPU, 진짜 Mi:dm Q4_K_M, 11/7 의 38문항 + 2)**
- 모델 답 채택 36/40 · 문서 문장으로 대신 4(규칙 주제 핵심어 검사 3, 모든 문장이 걸린 것 1) · 문장 일부를 뺀 답 7
- 11/7 에 뜻이 어긋났던 문장(신분증 저장 단정, 인증 실패 = 동의 거부, 수령 주어 바뀜)은 모두 나오지 않거나 걸러짐
- 아쉬운 점: 근거 원문에 부정어가 없는데 맞게 부정으로 바꿔 쓴 문장("반환 보류면 연락처를 삭제하지 않습니다" ← "남깁니다")도 빠짐. 문장 하나만 빠지고 답은 나가므로 그대로 둠
- 시간: CPU 에서 질문당 12~56초(근거 구절까지 쓰느라 출력이 길어짐, 이전 13초 안팎). 집 PC 그래픽카드(RTX 3060 Ti) 11/8 실측: 첫 질문 6.7초(모델 올리기), 그다음 0.3~2.1초, Langfuse 프롬프트 v2 답 생성 중앙 1.8초(v1 1.1초)

### 12-1. 11/8 질문-답 맞물림 검사 — 근거는 맞는데 물어본 것에 답하지 않을 때

한줄 설명: 문장마다 근거가 맞아도 "물어본 것"을 빠뜨리면 모델에게 고칠 점을 알려 주고 한 번 더 쓰게 하고, 그래도 안 되면 "안내 자료에 없다"고 솔직히 말한다.

**왜** — 집 PC 실측에서 "주운 사람 연락처 알려줄 수 있어요?" → "습득자 연락처는 인계 후 30일이 지나면 삭제됩니다"(근거는 맞지만 되는지/안 되는지 답이 없음). 11/7 40문항에서는 "지갑은 어느 쪽이 위로?" → 휴대폰 이야기.

**코드 검사(agents/chat_rag.py `answer_gap`, 모델을 쓰지 않아 빠르고 매번 같음)**

| 질문 모양 | 답에 있어야 하는 것 | 예 |
|---|---|---|
| 언제·며칠·기간·몇 시 | 숫자·시간·기간 말(마다·동안·후에 등) | "언제 도착해요?" ← "직원이 옮겨요"는 걸림 |
| 어디 | 장소 말(역·센터·키오스크·웹·보관함·에서) | |
| 물건(지갑·모형폰·USB·립밤·핸드크림·보조배터리)을 말함 | 같은 물건(다른 물건만 말하면 걸림) | "지갑은 어느 쪽?" ← 휴대폰 이야기 |
| 되는지·할 수 있는지·해야 하는지(의문사 없음) | 된다·안 된다 말(수 있/없, 돼요, 해야, 않, 없, 마세요 …) | "알려줄 수 있어요?" ← "삭제됩니다"는 걸림 |

**걸리면** ① 첫 답과 고칠 점(feedback)을 모델에게 주고 한 번 더 쓴다(Langfuse 에 `reporter-writer-retry` 칸으로 보임). 이때만 `answerable`(근거 문단에 답이 있는가) 칸을 더 받아 모델이 스스로 "자료에 없다"고 말할 수 있다 ② 다시 쓴 답도 문장 근거 검사(§12)를 그대로 거친다 — 그래서 자료에 없는 "알려드릴 수 없어요"를 지어내면 "근거에 없는 부정"으로 빠진다 ③ 다시 쓴 답도 맞물리지 않거나 모델이 answerable=false 라고 하면, 관련 근거 문장 앞에 "안내 자료에서 이 질문에 바로 답할 내용은 찾지 못했어요. 관련 안내:" 를, 뒤에 "정확한 내용은 본센터 직원에게 확인해 주세요."를 붙인다

**집 PC 실측(11/8, RTX 3060 Ti, Mi:dm)**: "주운 사람 연락처 알려줄 수 있어요?" → 다시 쓰기도 "되는지" 답이 없어 `retry:yesno → not_addressed:yesno`, 자료에 없다는 안내 + 30일 삭제 규칙(7.2초, 켠 뒤 첫 질문이라 모델 올리는 시간 포함). 다시 쓴 답이 관련 없는 문장(신고 방법)을 덧붙여서, 자료 없음 안내에는 첫 답을 쓰도록 고침. 맞게 답한 질문 4개(지갑 방향·신분증·도착 시간·웹 확인)는 다시 쓰기 없이 1.0~1.7초

**진단 메모(generation_note)**: `retry:subject`(다시 써서 고침) · `not_addressed:yesno`(자료에 없다고 답함) · `dropped: …`(뺀 문장)

**검사 기준을 정한 근거**: 11/8 클라우드 40문항 실측 답에 적용 — 걸린 것은 물건이 바뀐 1개("지갑은 어느 쪽이 위로?" ← 휴대폰 이야기)뿐이고 나머지 39개는 그대로(다시 쓰기 없음, 시간 그대로). 11/8 집 PC 의 연락처 답도 걸림. 시험: tests/test_chat_answer_gap.py

**한계**: 질문의 동사까지는 보지 않는다(예: "알려줄 수 있어요?"에 "보관할 수 있어요"라고 답하면 통과). 걸린 질문은 모델을 한 번 더 부르므로 그만큼(그래픽카드에서 약 1~2초(추정)) 느려진다. 습득자 연락처를 분실인에게 알려 주는지는 처음엔 안내 문서에 없었다 → 11/8 반영: DB 설계(docs/design/database.md §1 "습득자 연락처는 별도 표로 떼어 직원만 열람")대로 **알려 주지 않는다**. 안내 자료에 `finder_privacy` 주제를 넣고, 개인정보라 모델 없이 정해진 문장으로만 답한다(fixed_policy_text, agents/guidance.py PRIVACY_FIXED_TOPICS)

## 13. 11/8 밤~11/9 — 화면·검사 보강과 실제 모델 회귀 시험

한줄 설명: 챗봇 창을 화면을 가리지 않는 작은 창으로 바꾸고 답 진행률을 보여 주며, 진짜 모델로 사용자 말투 질문을 넣어 찾은 허점을 고친 뒤 그 질문들을 "실제 모델 회귀 시험"으로 남겼다.

### 13-1. 화면 (web/chat-widget/widget.js)
- 떠 있는 작은 창: 끌어 옮기기·작게 접기(알약 모양)·크기 조절, 화면마다 창 자리 기억(`localStorage` `lf-chat-win:<경로>`, 대화 내용은 저장 안 함)
- 창 밝기 단추(창 선택 > 화면 테마 > 기기 설정)
- 답 진행률 0~100%: 서버가 단계마다 진행 줄을 흘려보냄(NDJSON, `agents/chat_progress.py` STAGES: 받음 5 · 길 고르기 12 · 문서 찾기 22 · 물건 찾기 28 · 분석 30 · 답 쓰기 35 · 검사 80 · 다시 쓰기 84 · 다시 검사 92). 화면 숫자는 목표까지 1%씩 따라가고(모든 자연수를 지남) 끝나면 "마무리 중" → 100%

### 13-2. 검사 보강 (11/8 무작위 시험)
- 부정 구절 단위 검사(`negation_lost`): 근거의 "알려 드리지 않아요"에서 부정만 지운 "알려 드려요"를 거름
- 어순 검사(`order_ratio`): 근거 낱말을 뒤섞어 뜻을 바꾼 문장을 거름
- 근거에 없는 장소(경찰서 등) 안내, 숫자는 단위까지 맞아야 근거로 인정("3개" ≠ "3초")
- 서비스 밖 질문(날씨·맛집 등)은 모델 없이 정해진 문장 + 메뉴 버튼(`guidance.off_topic`)
- '폰·새폰·폰케이스'는 휴대폰, '이어폰·헤드폰·버즈·폰트'는 아님(`contracts.PHONE_RE`·`NOT_PHONE_RE`)

### 13-3. 11/9 실제 모델 시험에서 찾아 고친 것
진짜 Mi:dm 2.0 Mini(Q4_K_M, 클라우드 CPU)로 사용자 말투 질문 12개를 넣자 4개가 엉뚱했다.

| 질문 | 고치기 전 | 원인 | 고친 뒤 |
|---|---|---|---|
| 찾으러 가려면 뭐 가져가요? | "신분증을 가져가야 하나요?"라고 되묻고 버튼 글자가 깨짐("찾을 수 있요") | 규칙이 '뭐 가져가요' 꼴을 못 잡음 + 모델이 답할 수 있는 질문도 되묻기를 고름 | 준비물 꼴 넓힘, **모델 되묻기를 닫음**(되묻기는 문서 주제 버튼만) → 신분증·본센터 안내 |
| 본센터 어디 있어요? | 사용자에게 "본센터가 어디인지 말씀해 주시겠어요?" | 위치 규칙이 '어디…가/받' 꼴만 | `(본)센터…어디·위치·가는길` 추가 → 정해진 문장(부산역) |
| 지깝 일어버림 ㅠ | 서비스 밖 안내 | 오타 | 입구에서 흔한 오타 바로잡기(`guidance.fix_typos`: 일어버→잃어버, 지깝→지갑, 핸펀→휴대폰 …, '잊어버'처럼 뜻이 갈리는 말은 그대로) |
| (지갑 → ) 갈색이에요 | "이 챗봇은 검색하지 않습니다" + 검색 결과 | 안내 일꾼이 옛 거절 문장을 냄 | 검색이 실제로 돌았으면 reporter 가 검색 결과만 |

함께 고친 것
- 되묻기 버튼에 영어 주제 이름(`finder_privacy 알려줘`)이 나감 → 이름표 추가, 모든 주제 버튼이 한국어인지 시험
- 검색 답이 고지 문구 3줄로 길었음 → 핵심(후보 n개/없음)을 먼저, "찾은 조건: 지갑 · 검정", 고지는 끝에 한 줄. 키링 안내 줄은 특징을 말했을 때만
- "휴대폰은 상자에 어떻게 넣어요?"(습득자 질문)에 모델 planner 가 분실물 검색을 붙임 → 맡기기·놓는 법 질문이면 모델이 검색을 더하지 못함(규칙이 정한 검색은 그대로)
- 시험: `tests/test_chat_fixes_1109.py` — 고치기 전 코드로 돌리면 모두 실패하는 것을 확인함
