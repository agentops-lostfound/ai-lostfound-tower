# LF-5 인증·동의 원본과 세션의 지속 연결

2026-11-11 정연우. `c3f3e04` 이후 서버 내부 인증 원본 저장/조회 연결을 추가했다.
실제 신분 확인 수집기와 운영 DB 배포를 완료했다는 의미는 아니다.

## 원본과 발급기 연결

`PostgresEvidenceWriter`는 신뢰된 서버의 `IdentityProof` 결과를 저장하고 무작위 참조값을 반환한다.
공개 HTTP·모델 도구로 노출하지 않으며 클라이언트 입력을 이 자료형으로 포장해 인증시키면 안 된다.
provider와 assurance는 서버 생성자에서 고정한다. 실제 수집기가 없는 앱에는 자동 연결하지 않는다.
`simulation` 결과는 기록해도 `verified` 세션으로 사용할 수 없다.

필수 동의는 인증 참조에서 서버가 사용자를 결정한 뒤 기록한다. 클라이언트가 사용자 ID를 지정하는 경로가 없다.
거부도 원본으로 기록하지만 세션을 발급하지 않는다. 현재 정책과 일치해야 하며, 저장 잠금 대기 중 증거가 만료돼도 거절한다.
인증 참조·동의 참조·토큰 원문은 DB에 저장하지 않는다. HMAC 키/도메인 결합은 기존 계약과 호환된다.

`PostgresIdentityEvidence`가 원본을 읽고 `build_evidence_backed_issuer`가 기존 발급기의 두 검증 콜백에 연결한다.
읽기/쓰기 연결과 허용 제공자·정책·수명·권한을 명시 주입한다. `.env`를 읽거나 자동 활성화하지 않는다.

## 원본 철회가 기존 토큰을 막는 방식

제안 DDL의 `chat_find_session_access`는 세션 원본만 읽지 않고 다음 기록과 결합한다.

- 같은 사용자·같은 증거 해시·같은 검증 시각의 본인인증 원본.
- 활성 상태의 신뢰 제공자 및 `assurance=verified`.
- 같은 사용자·동의 정책·동의 시각의 동의 원본과 현재 정책 버전.
- 인증/동의 원본의 철회 여부와 동의 수락 여부.

따라서 별도 세션 철회 이벤트가 누락되어도 인증/동의 원본 철회, 제공자 비활성화, 정책 변경이 기존 토큰을 차단한다.
이미 발급된 세션에 인증 **증거의 제출 유효 시간**이 끝나는 것은 세션 TTL 만료와 구분한다.
증거 만료만으로 정상 세션을 앞당겨 만료시키지는 않으며, 원본 철회는 즉시 조회에 반영된다.
읽기는 최신 권위 DB를 전제로 한다. 비동기 복제본의 지연/연결 장애에서는 즉시 철회를 보장할 수 없다.

세션의 증거·동의 연결은 외래 키로 검증한다. 승인 제공자와 현재 정책의 기본 행은 넣지 않아 초기 상태에서 권한이 열리지 않는다.
DDL은 기존처럼 검토용 문서이며 실행하지 않았다. 이전 초안도 미적용 상태이므로 임의 ALTER/자동 마이그레이션을 추가하지 않았다.

## 거래와 검증

쓰기 잠금 순서는 사용자 잠금 → 원본 행 잠금으로 통일했다. 동의 저장/철회의 반대 잠금 순서에 의한 교착을 피한다.
동의 저장은 현재 정책을 잠근 뒤 증거 유효 시간을 다시 확인한다.
고정 SQL·파라미터·자동 커밋 꺼짐·시간 제한·원본 불변/단일 사용 규칙을 사용한다.

`tests/identity_evidence_fixture.py`는 PostgreSQL 고정 SQL의 파라미터를 실제 임시 SQLite 거래/참조 제약/동적 뷰에 연결하는 대역이다.
23개 시험에서 원본 저장→발급→재시작→HTTP, 철회/정책 변경, 교차 사용자, 시연 차단, 동시 증거 소비를 검증했다.
이는 네이티브 PostgreSQL DDL/드라이버 종단 시험이 아니다. 해당 시험과 실제 인증 수집기 연결은 남아 있다.
