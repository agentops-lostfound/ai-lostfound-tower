# 인계 교차 검증 (LF-14 · 11/6 변재원 · 11/11부터 예외 전용)

한줄 설명: (11/11부터 예외에만) 로봇이 **제출보관함(H-1)** 에 둔 물건을 분실인에게 건네기 직전에, 직원이 **AI 판단과 따로** 세 가지를 확인하고 하나라도 다르면 건네지 않는 마지막 안전장치.

## 1. 왜 이 방식인가
| 고려한 방식 | 장점 | 문제 | 결론 |
| --- | --- | --- | --- |
| A. 로봇이 움직이기 **전**에 직원이 확인(11/4 직원 화면) | 잘못 꺼내는 일이 없음 | 매번 직원이 와야 해서 셀프서비스가 아님(11/5 "직원 단계 제외"와 충돌) | 키오스크를 못 쓸 때만 남김 |
| B. 직원이 AI 결과 화면을 보고 "맞음" 버튼만 | 빠름 | AI 결론을 그대로 따라가게 됨(확인이 아니라 승인) | 쓰지 않음 |
| **C. 로봇이 제출보관함에 둔 뒤, 직원이 독립 확인 3가지** | 평소엔 AI·로봇이 처리, 사람은 건네는 순간에만. AI가 볼 수 없던 것(실물 신분증·실물 물건)을 사람이 확인 | 틀리면 물건을 다시 넣어야 함 → 칸 예약으로 해결 | **채택** |

> **11/11 바뀜 — 정상 흐름은 직원 없이(무인 인계).** 사람이 끼면 흐름이 복잡해지므로, 본센터 키오스크에서 본인 확인(찾기 번호 + 신분증 뒤 첫 자리)을 마친 분실인은 제출보관함에서 물건을 직접 꺼내고 키오스크 **[물건 받았어요]**(`POST /api/kiosk/handover`, 같은 본인 확인을 한 번 더)로 인계 완료(`changed_by = kiosk`)를 남긴다. 아래 직원 교차 검증은 **예외에만** 쓴다: ① 확인 질문이 맞지 않아 직원 대면 확인으로 진행한 요청(`staff_quiz_override`) ② 직원 보관 선반 물건 ③ 분실인이 도움을 청하거나 물건이 없을 때. 로봇 정지·원점 복귀는 그대로 사람이 한다.

핵심은 **"AI가 이미 쓴 정보로 AI를 다시 확인하지 않는다"** 이다. 직원은 AI가 직접 보지 못한 것(실물 물건, 실물 신분증, 분실인의 입)을 확인한다.

## 2. 흐름
```
분실인: 본센터(부산역) 키오스크 회수 탭 — 찾기 번호 + 가린 신분 번호
  -> 관제탑: 웹 확인(동의·신분·확인 질문) + 번호 일치 -> 로봇 시작(직원 없음)
  -> 로봇팔: 보관 칸 저장 자세 -> 집기 -> H-1 저장 자세 -> 내려놓기      [물건 상태: 인계 대기, 칸은 예약 유지]
  -> 직원 화면(/staff) "제출보관함 교차 검증"
        (1) 물건 대조   실물  vs 등록 사진·공개 특징        틀리면 -> 물건 다름(로봇·칸 오류)
        (2) 신분증 대조 실물 신분증 vs 가린 이름·방문자      틀리면 -> 본인 아님
        (3) 비공개 특징 분실인이 먼저 말함 -> 직원이 '답 보기'  틀리면 -> 물건 다름(비슷한 다른 물건)
  -> 셋 다 맞음: 인계 완료(칸 비움) -> 건넴
     하나라도 다름: 반환 보류 -> 원래 칸에 다시 넣고 "보관함으로 되돌림" -> 본센터 보관(같은 칸)
```

## 3. 규칙
- **(3)은 순서가 중요**: 분실인이 먼저 말한 뒤에만 정답을 연다(화면에서 '답 보기' 전에는 일치/불일치 버튼이 잠김). 직원이 정답을 먼저 보면 유도 질문이 되기 때문
- 비공개 특징(스티커·글자)은 **인계 대기 중에만** 관리자 API 로 보인다. 끝난 사례는 다시 보여 주지 않는다
- 보류 이유는 서버가 정한다(신분증 → 본인 아님, 물건·특징 → 물건 다름). 자유 입력 없음(기록·알림에 개인정보가 섞이지 않게)
- 신분증 번호·이름은 입력하지 않는다. 맞는지만 고른다
- 11/11(021) 로봇 보관 칸(R1~R4)은 **제출보관함에 놓이는 때(인계 대기)** 비운다 — 무인 인계에서 실물 칸은 비었는데 예약이 남아 새 물건이 2번 칸으로 가고·다음 물건이 칸 대기가 되고·[물건 받았어요]를 안 누르면 대기 물건이 안 올라왔다. 직원 보관 선반(S)은 인계 완료 때 비운다. 반환 보류된 물건은 원래 칸이 찼을 수 있어 보관 화면 '칸 배정 필요'에서 추천 칸에 넣는다(예전 011: 인계 완료 때만 비우고 원래 칸 예약). 비전 내보내기는 보관 중 상태만 넣으므로 그동안 로봇 대상이 되지 않는다
- 디스코드 관제 채널에는 결과만 남긴다: `교차 검증 · 물건 A-… · 물건 대조 O · 신분증 대조 X · 비공개 특징 O`

## 4. API (관리자 로그인 필요)
| 방법 | 주소 | 본문 | 결과 |
| --- | --- | --- | --- |
| GET | `/api/admin/handovers` | - | 인계 대기 목록(사례·물건·품목·공개 특징·가린 이름·사진 여부) |
| GET | `/api/admin/returns/{case_id}/secret` | - | 비공개 특징(정답). 인계 대기가 아니면 409 |
| POST | `/api/admin/returns/{case_id}/verify` | `{"item_match": true, "id_match": true, "feature_match": true}` | 셋 다 true → 인계 완료, 아니면 반환 보류 |
| POST | `/api/admin/returns/{case_id}/restock` | `{"staff_confirmed": true}` | 반환 보류 → 본센터 보관, 원래 칸 정보 |
| GET | `/api/admin/items/{item_id}/photo` | - | 등록 사진(사진 폴더 밖 경로는 거부) |
