# 현재 비전·매칭 구현 기준 로봇 연결 계획

> **2026-11-05 후속 결정:** 현재 로봇 접근은 직접 티칭한 커스텀 자세 5개를 선택하는 방식으로 전환했다. 아래 좌표 기반 자동 접근은 당시 검토 이력이며 현재 개발 계획으로 해석하지 않는다. 비전·특징 매칭은 유지하고 선택 물품과 저장 자세의 연결 규칙은 담당자 합의 후 정한다. [오늘 작업 정리](../reports/2026-11-05-daily-update.md)와 [고정 자세 결정](../reports/2026-11-05-fixed-pose-decision.md)을 우선한다.

검토일: 2026-11-04. 로봇 연결 전 합의 표를 현재 브랜치의 구현에 맞춰 해석한 계획이다. 아래 제안은 합의·구현 완료를 의미하지 않으며 공통 계약을 변경하지 않는다.

참조: [부품 연결 구조](integration.md), [공통 도구 계약](../contracts/mcp_tools.md), [인터페이스](interfaces.md), [한국어 전처리 잠정 결정](../reports/2026-11-04-korean-first-decision.md).

## 의견 수용 후 적용할 계획

2026-11-04 사용자 요청에 따라 아래 내용을 수정 방향으로 수용했다. 팀 전체 계약 확정이나 실물 검증 완료를 뜻하지 않는다. [본래안·수용안 비교 보고서](../reports/2026-11-04-robot-plan-revision.md)를 함께 참고한다.

| 항목 | 수정 계획 | 유지할 검증·조건 |
|---|---|---|
| 1. 좌표계 | 작업대 좌측 상단 마커 1개로 시작한다. 마커 중심/특정 모서리 중 기준점을 명시한다. | 마커 실제 크기·축 방향·로봇 베이스와의 관계를 실측한다. 마커 위치 자체가 로봇 베이스 원점이 되는 것은 아니다. |
| 2. 보정 유효성 | 마커 근처·작업대 중앙·먼 쪽의 독립 실측점으로 검증하고, 정확도·가림 대응이 부족하면 마커를 추가한다. 4개 전부 검출을 초기 필수 조건으로 두지 않는다. | 하나의 마커 모서리 4점으로 계산한 재투영 오차는 작업대 전체 정확도를 입증하지 못한다. 허용 실측 오차는 시험 후 확정한다. |
| 3. 정지·복귀 | robot_stop은 추가 이동을 시작하지 않는 정지로 분리한다. Home 복귀는 직원 확인 후 별도 버튼/명령으로 요청한다. 정상 전달 후 대기 자세는 별도로 결정한다. | 현재 도구 계약에는 정지·Home이 함께 적혀 있다. 실제 정지 방식·복귀 조건·UI·공통 계약은 담당자 합의 후 구현하며 이번에는 변경하지 않는다. |

마커 기준 원점, 로봇 베이스 좌표 원점, Home 자세, 관절 초기화·호밍은 구분한다. 원점 좌표를 저장했다고 현재 로봇 상태가 자동으로 확인되는 것은 아니다. 나머지 촬영 유효성·GPU 공유·재시도 계획은 아래 기존 검토를 유지한다.

## 현재 동작과 미연결 부분

- 파일 입력 기준 YOLO 검출·크롭, Qwen 특징 JSON, 픽셀 중심 저장을 실물 사진으로 실행했다. 사진에 따라 검출 누락·중복·특징 오인식·JSON 검증 실패가 발생한다.
- ArUco 검출·homography·실좌표 변환 코드는 있으나 markers_mm 실측 설정과 실제 로봇 좌표 검증은 하지 않았다. 현재 설정이 비어 있어 실측 좌표는 null이다.
- matching은 속성 비교·MiniLM·판정을 구현했다. 한국어 선추출은 잠정 기본값이지만 requires_review로 자동 확정을 제한한다.
- speech는 독립 한국어 전사를 구현했다. 메인 연결·음성 확인 UI는 아직 없고 실제 사용자 파일 시험에서도 누락·인식 실패가 있었다.
- 메인의 CompositeBackend와 공통 함수 모양은 있으나 현재 실험 JSON을 실제 부품으로 연결하는 어댑터는 아직 필요하다. 가짜 부품으로 흐름이 끝나는 것과 실물 로봇 연결 성공은 구분한다.

## 표 외에 필요한 연결 작업

### 비전·매칭 어댑터

현재 비전은 objects[].qwen.features, center_px, center_world_mm을 사용한다. 공통 계약은 box/center/features이며 특징 키도 category/color/shape/mark/visible_text/material/confidence로 다르다. 명시적인 변환이 필요하다.

매칭도 현재 id·selected_id·needs_confirmation/no_match와 공통 index·uncertain/none이 다르다. object ID를 배열 index와 혼동하지 않고 변환해야 한다. 코사인·결합 점수를 보정된 확률로 취급하지 않는다. 자동 확정 제한을 단순히 지워 실제 로봇으로 연결하지 않는다.

### 장면·실좌표·파지점

작업대 평면 homography, 작업대→로봇 베이스 변환, 높이·그리퍼 자세·파지점은 다른 문제다. bbox 중심은 검출 중심이며 집기 가능한 지점을 보장하지 않는다. 카메라 렌즈 왜곡·물체 높이에 따른 시차도 실제 작업 범위에서 검증해야 한다.

### 새 촬영과 모델 실행의 순서

계획 흐름은 사용자 입력·확인 → 반환 승인 관문 → 현재 장면 촬영·비전 분석 → 매칭·좌표 확인 → GPU 자원 해제·집기 직전 위치 확인 → 접근·집기·집기 검증 → 전달이다. 실제 단계 배치는 기존 반환 흐름과 담당자 계약에 맞춘다. STT 때문에 오래된 프레임이 사용되지 않도록 장면 시각은 별도로 다룬다.

## 진행 순서

1. 실제 배포 모델 경로와 입출력 어댑터 범위를 담당자와 맞춘다.
2. 좌측 상단 마커 1개로 원점·축·실측 좌표를 설정하고 작업대 여러 독립 측정점에서 검증한다. 허용 오차나 가림 대응이 부족하면 마커를 추가한다.
3. 즉시 정지와 직원 요청 Home 복귀의 분리 계약을 합의하고, 무효 좌표·불확실 매칭을 접근 차단으로 연결한다.
4. GPU 사용권·취소·대기 제한과 촬영 결과 무효화·재확인을 구현한다.
5. 물체 없이 좌표 접근을 확인한 뒤 실제 집기·검증·재시도를 단계적으로 시험한다.

이 계획은 문서 검토 결과다. 로봇을 실행하거나 공통 계약·실측 설정을 바꾸지 않았다. 기존 표의 4마커·5mm·120초·최대 대기 N초 등은 측정과 합의 전까지 확정값으로 쓰지 않는다.
