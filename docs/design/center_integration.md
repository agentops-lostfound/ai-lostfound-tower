# LF-9 관제탑 회수·통계 통합

main `9e2f827`에서 분리한 뒤 작업 중 병합된 챗봇 개선본을 포함한 main `f39c8f8`을 통합했다. 과거 PR #149의 시험·보고서는 이미 main에 있고 현재 역·품목 변경이 반영돼 있으므로 해당 브랜치 전체를 다시 병합하지 않는다. 원래 LF-5 챗봇 작업 브랜치는 보존한다.

## 활성화 조건

기본 `TOWER_CENTER=0`이다. 관리자 비밀번호가 설정된 실제 DB 관제탑에서 `TOWER_CENTER=1`, `TOWER_DB=1`, `TOWER_SIM=0`으로 명시적으로 활성화한다. 메모리 시연과 비동기 DB 미러링을 실제 회수 원장과 혼합하지 않는다. 조건이 맞지 않으면 새 회수 경로는 503으로 차단한다. 기존 관제탑 기본 동작은 유지한다.

- 회수·장소: `DATABASE_URL`.
- 통계: 별도의 `LF_STATS_DATABASE_URL`. 기본 표 권한 없는 전용 로그인에 `lf_stats_reader` 역할만 부여한다.
- 실제 `.env`를 읽거나 비밀값을 문서·화면에 복사하지 않는다.
- `center/migrations/pending/006_collection_alerts_1104.sql`은 계속 보류한다. DB 담당자가 현재 스키마와 역할을 검토해야 하며 이번 변경은 자동 설치하지 않는다.

## 화면과 API

관리자 `/admin`의 **회수·통계** 탭 → `/center` → `/api/admin/center/desk`.
기존 관리자 로그인 쿠키 및 관리자 API 키를 사용하며 `x-staff-key`는 이 통합 경로의 인증을 대신하지 않는다. 관리자 로그인 기능이 꺼져 있으면 실제 DB 경로도 열리지 않는다.

| 경로 (`/api/admin/center` 아래) | 동작 |
|---|---|
| GET `/dashboard` | 최근 물건 200·묶음 50·미도착 100개, 초과 여부. 공개 운영 필드만 단일 읽기 전용 스냅샷으로 조회 |
| GET `/readiness` | 필수 표·request_id·통계 역할·두 연결의 동일 서버/DB 여부 점검. 실제 쓰기 성공 검증이나 스키마 설치는 하지 않음 |
| POST `/collections` | 기존 `machine_id`, `item_ids`, `request_id` 계약으로 회수 |
| GET `/collections/{id}` | 표시 한도 밖의 묶음도 번호로 조회 |
| POST `/collections/{id}/arrivals` | 실제 도착한 항목만 기록. 전량 도착 전에는 미도착 유지 |
| POST `/statistics/questions` | 기존의 하루·기계·품목별 접수 건수만 지원. 임의 SQL을 받지 않음 |
| POST `/collections/overdue/check` | 시간대를 포함한 기준시각을 명시한 경우에만 큐 생성. 화면에서 자동 실행하지 않음 |
| GET/POST `/places` | 기존 장소 조회·추가 계약 유지. 이번 화면에 장소 편집은 추가하지 않음 |

브라우저 회수 요청은 결과가 불명확해도 같은 요청 번호를 유지한다. 탭 새로고침 후에도 `sessionStorage`에 남은 동일 내용으로 결과를 확인한다. 새 회수 요청을 자동 생성하지 않는다. 도착 재시도는 기존 저장소의 중복 방지 거래를 사용한다.

외부 출처의 변경 요청을 차단한다. DB 실패는 세부 연결정보 없이 503으로 응답하고 API 결과를 캐시하지 않는다. 화면은 외부 알림·가상 초기화·로봇 동작·반환 승인을 실행하지 않는다. 알림 전송은 기존 명시적 CLI 절차이며 성공 직후 DB 커밋 전 중단하면 중복 알림이 가능하다는 기존 한계가 남는다.

## 적용 순서

실행 환경이 이미 설정된 터미널에서 `python -m tools.check_center_readiness`로 동일한 읽기 점검을 할 수 있다. 이 도구는 `.env`를 불러오지 않으며 준비 완료이면 종료 코드 0, 설정 누락·스키마/권한/DB 불일치이면 1이다. 접속 주소·비밀값·행 데이터는 출력하지 않는다.

1. 현재 서버의 소스 경로·커밋·실행 방법을 확인하고 변경 파일을 보존한다.
2. DB 담당자(현재 LF-8 변재원)와 보류된 스키마·전용 통계 로그인 상태를 확인한다. 이 문서의 예전 보류 README 담당자 표기는 과거 기록이다.
3. 별도 시험 환경에서 필수 설정 이름을 연결하고 관리자 로그인·읽기 점검을 수행한다. 실제 서버의 가상 시연을 임의로 실제 DB 모드로 전환하지 않는다.
4. 회수·부분 도착·미도착·최종 도착·접수 통계·중복 요청을 동일 DB에서 확인한다.
5. 현장 인계는 LF-11·LF-12·LF-21 담당자와 수행한다. 로봇 보관 칸은 migration 021에 따라 제출보관함 도착(인계 대기)에 해제되며 직원 선반은 인계 완료에 해제된다.

## LF-7 범위

이번 작업은 회수 원장과 관제탑의 관리 입구를 연결한다. 기존 합성 설명 입력·검색·회수·통계 시험 및 반환/인계 시험을 함께 회귀 검사한다. 실제 본인인증, 실물 수량·파지 성공, 두 PC 로봇 반환 종단 검증을 대체하지 않는다. 가상 단계들의 개별 통과를 하나의 실제 운영 DB·실물 전체 시연 성공으로 합산하지 않는다.
