# LF-9 회수·도착 관리 시연

프로젝트 루트에서 의존성을 설치한 Python으로 실행한다.

```powershell
python -m tools.run_collection_demo
```

브라우저 주소: http://127.0.0.1:8110/collection-desk

1. 등록기계 A에서 지갑·USB를 선택하고 **선택한 물건 회수 기록**을 누른다.
2. 오른쪽에서 지갑만 체크하고 **도착 1개 추가 기록**을 누른다.
3. USB가 회수 중으로 남고 아래 알림 미리보기에 표시되는지 확인한다.
4. 나중에 USB도 체크해 저장하면 회수가 완료되고 미도착 미리보기가 사라진다.
5. 처음부터 다시 보려면 **시연 처음부터 → 가상 데이터 초기화**를 누른다.

가상 물건 6개는 `.cache/center-collection-demo.sqlite3`에 저장된다. 브라우저 새로고침과 서버 재시작 후에도 유지된다. 초기화는 이 파일의 `demo_*` 표만 변경한다. 사진·연락처·본인인증 정보가 없으며 팀 DB·환경 변수의 DB 접속 정보·디스코드 연결을 사용하지 않는다.

실제 `agents.center_api`의 `/collections`, `/collections/{id}`, `/collections/{id}/arrivals` 경로와 앱 팩터리를 재사용하지만 저장소는 별도의 SQLite 시연 구현이다. 실제 PostgreSQL 거래·직원 인증 연결이 끝난 화면이라는 뜻은 아니다. 실제 API의 직원 키 검증을 우회하지 않으며, 시연 모드는 고정된 `DemoCollections` 저장소에만 허용한다. 실제 API에는 초기화·시연 대시보드 경로가 없다.

회수 요청 실패 시 동일한 요청 번호로 재확인하고, 도착 체크 재시도는 이미 기록한 물건을 다시 변경하지 않는다. 도착 0개는 버튼을 한 번 더 눌러 확인한다. 저장 완료된 도착 체크는 해제할 수 없다. 자동 지연 판정 시각은 정하지 않으며 미도착 알림은 외부로 보내지 않는다.

초기화 시 시연 데이터의 버전이 변경된다. API로 회수·도착·초기화를 호출할 때는 `/collection-dashboard`에서 받은 `revision`을 `x-demo-revision` 헤더로 보내야 한다. 이전 버전·누락된 버전은 409로 거절한다. 이 값은 직원 인증 토큰이 아니라 오래된 화면의 요청을 막는 값이다. 화면은 이를 자동 처리한다. 최신 목록을 불러오지 못하면 저장 버튼이 잠기며 새로고침이 성공한 뒤 다시 사용할 수 있다. 저장 완료 응답 후 목록 갱신만 실패하면 저장 완료와 갱신 실패를 구분해서 안내한다.

## 관리자 접수 통계

화면의 **접수 통계 보기**를 누르거나 아래로 내려 통계 패널을 연다. 예시 버튼이나 다음 질문을 사용한다.

- 오늘 등록기계 A에 들어온 USB 몇 개?
- 오늘 전체 물건 접수 건수 알려줘
- 어제 전체 물건 접수 건수 알려줘
- 2026-11-05 등록기계 B 휴대폰 접수 몇 개?

건수·조회 날짜·등록기계·품목·조회 시각을 표시하며, **집계 근거 · 실행 SQL 보기**에서 실행한 SQL과 분리된 매개변수를 확인한다. 0건도 실제 조회 결과로 표시한다. 질문을 바꾸거나 시연 데이터를 초기화하면 이전 결과를 숨긴다.

접수 당시 시각을 한국 시간 하루(시작 포함·다음 날 시작 제외)로 집계한다. 회수·도착 상태를 바꿔도 접수 건수는 변하지 않는다. 새 가상 데이터의 접수 시각은 생성/초기화 시각이다. 이전 버전에서 만든 가상 물건에 접수 시각이 없으면 이번 기능을 처음 켠 시각으로 한 번 채우며, 이후 재시작에서 바꾸지 않는다. 기존 회수·도착 상태와 시연 버전은 유지한다.

PostgreSQL과 같은 제한된 질문 해석기를 사용하지만, 시연의 실제 SQL은 별도 `demo_stats_item` SQLite 뷰만 조회한다. 조회 전용 거래와 SQLite 권한 검사로 기본 물건 표·상태 이력·메타데이터·쓰기 접근을 막는다. 자유 생성 SQL이 아니며 색상·특징·역·기간·개인정보 조건은 지원하지 않는다. 통계 요청은 `/statistics/questions`에 `question`만 보내며 현재 시연 버전 헤더를 함께 사용한다.

## 습득 장소 목록

통계 패널 아래의 **습득 장소 목록 관리**에서 등록기계 A/B/C를 선택한다. 각 역의 장소를 5개씩 보고 **다음 목록·이전 목록**으로 이동한다. 새 장소를 적고 **장소 저장**을 누르면 그 장소가 있는 페이지를 표시한다. 같은 호선·역·장소는 중복 저장하지 않는다.

시연은 A(2호선 해운대), B(1호선 중앙), C(1호선 서면)의 가상 장소를 각 6개 제공한다. 실제 역의 장소 데이터나 추천 빈도가 아니다. 목록은 등록 순서이며 현재 시연의 호선·역만 관리한다. 접수 검증과 맞추기 위해 다른 역의 장소를 추천에 섞지 않는다. 장소에도 기존 개인정보 패턴 검사를 적용하며 이름·연락처·개인 주소를 입력하지 않아야 한다.

장소 저장은 현재 시연 버전을 검사하며 다른 화면 초기화 이후 이전 요청은 거절한다. 서버 재시작 후 추가한 장소를 유지한다. **시연 처음부터**는 회수·도착뿐 아니라 추가한 가상 장소도 지우고 기본 장소 목록으로 되돌리므로 확인 문구를 읽고 진행한다.

예약·반환·로봇 동작은 연결하지 않았다. 실제 팀 DB의 직원 인증·통계 전용 읽기 계정·확정 장소 목록 연결은 아직 별도 작업이다.
