# chat-widget — AI 챗봇 위젯 (LF-5, 11/5)

한줄 설명: 어떤 화면이든 **스크립트 한 줄**을 넣으면 "AI챗봇 사용하기" 버튼으로 작은 채팅 창이 열리는 부품이다.
챗봇 두뇌는 관제탑의 `/chat/questions`(정연우 LF-5 챗봇: 이용 안내 RAG + 물건 검색 에이전트, LangGraph)이고, 위젯은 화면만 맡는다.

- 담당: 챗봇·위젯·붙일 화면 모두 변재원(11/6 김재민 작업 완료 후 이어받음)
- 적용 화면(11/6): **키오스크(`web/kiosk/`, 키오스크 모드)** + **분실인 웹(`web/lost/`)** — 챗봇은 두 곳 모두에 있어야 한다(교수님 확인)
- 시험 페이지: 관제탑 켠 뒤 `http://127.0.0.1:8100/chat-widget/demo`
- 팀 DB·로봇을 켜지 않는 독립 미리보기: `python -m tools.run_chat_widget_demo` → `http://127.0.0.1:8112/chat-widget/demo`. 승인 문서와 별도 가상 DB만 사용하며 모델을 내려받지 않는다. 다른 포트는 `--port`로 지정한다.

## 1. 화면에 붙이는 법 (재민 님, 2줄)
```html
<!-- ① 원하는 버튼에 data-chatbot-open 속성 -->
<button type="button" data-chatbot-open>AI챗봇 사용하기</button>

<!-- ② </body> 바로 위에 한 줄 -->
<script src="/chat-widget/widget.js" defer></script>
```
- 버튼이 없는 화면에는 오른쪽 아래에 동그란 "AI 챗봇" 버튼이 자동으로 생긴다
- 2조봇에게 부탁해도 된다: "web/lost/index.html 의 'AI챗봇 사용하기' 버튼에 web/chat-widget/README.md 1절대로 챗봇 붙여 줘"

## 2. 옵션 (스크립트 태그에 적음, 모두 선택)
| 옵션 | 값 | 뜻 |
| --- | --- | --- |
| `data-launcher` | `auto`(기본) · `always` · `off` | 동그란 버튼: 여는 버튼이 없을 때만 / 항상 / 안 보임. 머리말에 `data-chatbot-open` 버튼이 있는 화면(키오스크·분실인 웹)은 `auto` 만으로 숨겨진다 |
| `data-spacer` | `auto`(기본) · `off` | 동그란 버튼이 보일 때 페이지 끝에 버튼 높이만큼 빈 칸을 둬 마지막 버튼·글이 가리지 않게 함 / 끔 |
| `data-title` | 글자 | 창 제목(기본 "AI 안내 도우미") |
| `data-api` | 주소 | 챗봇 API 서버(기본: 위젯을 내려준 서버 = 관제탑) |
| `data-mode` | `web`(기본) · `kiosk` · `staff` | `kiosk`: 글자·버튼을 크게(터치용), **창을 닫으면 대화를 바로 지움** · `staff`: 관리자 화면 전용, 관제 질문(반환 현황·실패 원인)을 관제 분석 에이전트로(관리자 로그인 필요, 아니면 401) |
| `data-idle-reset` | 초(0~3600) | 아무 조작이 없으면 N초 뒤 대화를 지우고 창을 닫음. `kiosk` 기본 90, `web` 기본 0(끔) — 공용 기기에서 다음 사람에게 앞사람 대화가 보이지 않게 |
- 코드에서 열고 닫기: `LostFoundChat.open()` · `LostFoundChat.close()` · `LostFoundChat.toggle()`

## 3. 동작 규칙
- 요청은 응답 본문을 받는 시간까지 최대 30초로 제한한다. 시간 초과·잘못된 JSON/응답 구조는 재시도 안내로 표시하고 전송 잠금을 해제한다.
- 실패한 예전 질문을 다시 보내도 다른 질문은 지우지 않는다. 다른 요청이 진행 중이면 재시도 버튼은 대화를 변경하지 않는다.
- 응답이 늦게 도착해도 닫힌 창이나 다른 화면에서 작업 중인 사용자의 포커스를 가져오지 않는다. 전송 중 작성한 다음 질문은 유지한다.
- 500자를 넘는 질문은 자르지 않고 입력란에 남겨 수정하도록 안내한다.
- ‘대화 지우기’는 응답 대기 중에도 작동한다. 진행 중 브라우저 요청을 취소하고 대화·입력 초안·이어 묻기 맥락을 지운다. 이전 답변이 늦게 도착해도 다시 표시하지 않는다. 서버에서 이미 시작한 처리를 되돌리는 기능은 아니다.
- 실패한 질문은 당시 맥락으로 재시도하며, 입력란에 작성 중인 다른 질문은 보존한다.
- 첫 연결 실패·준비 중 상태는 창을 다시 열 때 재확인한다.
- 채팅 창은 화면 디자인을 건드리지 않는다(Shadow DOM 안에 스타일을 가둠). 밝은·어두운 화면 모드를 따라간다
- 11/8 작은 떠 있는 창(화면 정보를 가리지 않게):
  - 한줄 설명: 채팅 창이 화면 한쪽에 떠 있는 작은 창이라, 옮기고·접고·크기를 바꿔 아래 화면을 보면서 쓸 수 있다
  - 기본 크기 360×520(키오스크 460×640). 휴대폰 폭(600px 이하)은 폭 92vw·높이 60vh로 아래쪽에 뜬다(화면을 다 덮는 시트 아님)
  - 처음 열 때: 네 구석(휴대폰은 위·아래) 중 창 아래에 놓일 버튼·입력칸이 가장 적은 곳을 고른다. 같으면 오른쪽 아래
  - 머리줄을 끌어 옮긴다(마우스·터치·펜). 끄는 동안 창이 반투명해져 아래 화면이 보이고, 화면 밖으로는 나가지 않는다
  - 머리줄 단추: 밝기(해·달 그림, 11/9) · `–` 접기(작은 알약 모양, 새 답이 오면 빨간 점·답을 기다리는 중이면 "답 준비 중 63%") · 크게/작게(두 단계, 휴대폰은 높이 60vh↔85vh) · ✕ 닫기
  - 구석 손잡이(화면 가운데 쪽 구석)로 크기를 자유롭게 바꾼다(휴대폰 폭에서는 숨기고 크게/작게 단추만)
  - 옮기거나 크기를 바꾸면 `localStorage`(`lf-chat-win:화면주소`, 휴대폰 폭은 `:phone` 따로)에 기억한다. 화면이 작아져도 안쪽으로 끌어 넣는다. 저장이 막힌 브라우저에서도 창은 그대로 동작
  - 11/9 창 밝기 단추: 누르면 **이 채팅 창만** 라이트↔다크가 바뀐다(화면 전체는 그대로). 단추 크기 44px(키오스크 56px), `aria-label` "챗봇 창 밝게/어둡게"
    - 한줄 설명: 화면은 그대로 두고 채팅 창만 밝게·어둡게 고를 수 있다
    - 우선순위: **창에서 직접 고른 값 > 화면 테마(`html[data-theme]`, `/ui/theme.js` 전환 버튼) > OS 밝기 설정**
    - 창에서 고른 값이 없으면 화면 전환 버튼을 누를 때 창도 따라 바뀐다. 창에서 고른 값이 있으면 화면을 바꿔도 창은 고른 값 그대로
    - 창 단추로 화면과 같은 밝기로 되돌리면 고른 값을 지우고 다시 화면을 따른다
    - 고른 값은 창 자리와 같은 `localStorage` 칸(`lf-chat-win:화면주소`)의 `theme` 에 기억한다(새로 고침해도 유지). 대화·질문은 저장하지 않는다
  - 어두운 막이 없다 — 창 밖 화면은 그대로 누를 수 있다. 여는 버튼(`data-chatbot-open`)은 닫힘→열기, 접힘→펼치기, 열림→닫기
  - 동그란 버튼: 아래로 내리는 동안 잠깐 숨었다가 멈추면 다시 보인다. 휴대폰 폭(480px 이하)에서는 글자 없는 작은 아이콘
- 11/8 진행률(0~100%): 답을 기다리는 동안 답 말풍선 자리에 얇은 막대 + "답 준비 중 63% · 근거 확인"과 작은 "예상" 글
  - 단계는 실제 값: 위젯이 `Accept: application/x-ndjson` 으로 요청하면 관제탑이 단계 줄을 흘려보낸다(아래 4절). 단계 사이는 최근 응답 시간(`/chat/metrics` p50·p95, 이 화면에서 잰 최근 5번, 없으면 3초)으로 부드럽게 채운다
  - 퍼센트는 줄지 않는다. 답이 오기 전에는 95%에서 멈추고, 답이 오면 100%가 된 뒤 사라진다. "답 쓰기" 중에는 "근거 확인"(80%) 바로 아래까지만 채운다
  - 0.3초 안에 끝나는 답(모델 없는 규칙 답)은 막대를 그리지 않는다(깜박임 없음). 화면 읽기 프로그램용 `role="progressbar"`·`aria-valuenow`
  - 서버가 스트림을 모르면(예전 관제탑) 한 번에 받은 JSON 을 그대로 쓰고, 막대는 시간으로만 채운다
- Enter = 보내기, Shift+Enter = 줄바꿈, 한글 조합 중 Enter 는 글자 확정만, Esc = 닫기(창 밖에 초점이 있어도)
- 이전 질문 4개까지 함께 보내 "그건요?" 같은 이어 묻기를 이해한다. 대화는 화면에만 있고 저장하지 않는다(새로 고침하면 사라짐)
- 물건 후보는 품목·색·후보 번호만 보인다(접수 번호·역·사진 없음). "후보는 본인 물건 확정이 아니에요"를 항상 표시
- 지금 물건 검색은 **가상 물건 DB**(배지 "가상 DB 시연"). 실제 팀 DB 검색은 본인인증 세션 검증기(LF-6)가 연결돼야 열린다 — `docs/contracts/chat-search-integration.md`

## 4. 관제탑 쪽 (agents/chat_api.py)
| 주소 | 하는 일 |
| --- | --- |
| `POST /chat/questions` | `{question, history?, suggestion_id?}` → `{answer, agent, status, sources, candidates?, …}`. 11/8: 본문 `"stream": true` 또는 `Accept: application/x-ndjson` 이면 한 줄짜리 JSON 을 여러 번 흘려보냄(NDJSON) — `{"stage":"received","pct":5}` → `retrieve`(22) → `write`(35, 모델) → `check`(80) → (`rewrite` 84 → `recheck` 92) → 마지막 줄 `{"done":true, ...기존 응답 그대로}`. 오류는 마지막 줄 `{"done":true,"error":true,"status_code":422/503,"detail":…}`. 단계 알림은 `agents/chat_progress.py`(동작은 그대로, 알림만) |
| `GET /chat/suggestions` | 추천 질문 |
| `GET /chat/health` | 준비 상태(`ready`, `search_mode`) — 준비 안 되면 창 위쪽에 "준비 중" |
| `GET /chat/metrics` | 운영 지표(LLMOps): 질문 수·응답 시간 p50/p95·결과 비율. 질문 원문은 저장 안 함. 관제 분석 에이전트 "챗봇" 초점이 읽음 |
| `GET /chat-widget/widget.js` · `/chat-widget/demo` | 위젯 파일 · 시험 페이지 |
- `.env`(이름만): `LF_CHAT_RAG_MODEL`(Ollama 로컬 sLLM, 11/6 추천 `exaone3.5:2.4b` — 비우면 문서 문장 + 규칙 되묻기, `docs/design/chatbot_sllm_rag.md`) · `LF_CHAT_DATABASE_URL`(실제 DB, 인증 연결 전엔 닫힘) · `TOWER_CHAT_DEMO_DB`(가상 DB 파일, `0` 이면 물건 검색 끔)
- 챗봇 부품(langgraph)은 첫 질문 때 만든다. 설치가 안 돼 있어도 관제탑은 켜지고 챗봇 주소만 503

## 5. 재민 님 서버를 따로 세운다면
- 화면을 관제탑(8100)·Docker 앞문(8080)이 열어 주면 그대로 동작한다(같은 주소)
- 다른 서버에서 화면을 연다면 그 서버가 `/chat/` 과 `/chat-widget/` 을 관제탑으로 넘겨야 한다(nginx `location /chat` → 관제탑). 이때는 변재원과 맞춘다
