# 한국어 특징 추출 초기 시험

2026-11-03. 매칭 전처리의 입출력·검증·CLI·연결을 구현하고 CPU 텍스트 모델을 실제 실행했다. **연결 구현과 모델 품질은 구분해야 하며, 현재 모델은 자동 확정용으로 채택하지 않는다.**

## 구현 범위

- QueryParser: 한국어 원문 → category/colors/sticker_status/영어 free_text.
- 후보 특징을 프롬프트에 넣지 않으며 별도 번역 모델 없이 추출과 영어 변환을 한 번에 요청.
- 표준 색 이름 정규화, JSON 키·형식·허용 품목 검증, 오류 시 종료.
- standalone CLI와 기존 매칭 CLI의 --parse-korean 선택 경로.
- 원문, 추출값, 경고, CPU 시간, 출력 토큰 수 기록.
- requires_review=true로 실험 추출 결과의 자동 확정을 차단. 기존 영어·수동 조건 경로는 유지.

## 환경

Qwen/Qwen3-0.6B, Transformers 4.57.6, CPU float32, 2 threads. 비전 환경을 변경하지 않도록 별도 .venv-query를 사용했다. 모델 캐시는 Git 제외다. 모델은 학습하지 않았으며 3개 변환 예시를 프롬프트에 제공했다.

## 8개 수작업 예문 결과

품목·색·스티커 상태·확인 필요 여부가 모두 기대값과 일치한 경우는 **2/8**이었다. 이는 자유 문장의 의미까지 정확하다는 뜻이 아니다. 초기 예시 없는 프롬프트는 0/8이었고, 프롬프트 조정 후 같은 예문으로 다시 확인했으므로 독립된 최종 평가가 아니다.

| 문장 요약 | 실제 출력 문제 |
|---|---|
| 곤색 카드지갑, 뒷면 별 스티커 | 검사 필드와 자유 문장 모두 예문 의도에 부합 |
| 파란색 아니고 검정 폰, 스티커 없음 | 검정을 navy로 오변환 |
| 지갑 잃어버림 | 언급하지 않은 black 추가 |
| 파랑인지 검정인지 모르는 지갑 | 불확실 경고는 냈으나 black을 확정 조건에 넣고 자유 문장에 스티커 없음 추가 |
| 검정 몸체·빨간 테두리 USB | 색 navy로 오변환, 미언급 스티커 present 추가 |
| 흰 아이폰·애플 로고·카메라 두 개 | 미언급 스티커 present 추가 |
| 검은 보조배터리·VOVA | 검사 필드는 맞지만 자유 문장에 'sticker'를 임의 추가 |
| 지갑 뒷면에 스티커 없음 | white 임의 추가, 부분 부정을 전체 absent로 확대, 확인 필요 누락 |

모델 초기화는 약 1.92초, 같은 인스턴스에서 8개 문장의 변환 중앙값은 약 **12.12초**였다. 모델 다운로드·프로세스 시작·MiniLM 매칭은 변환 시간에서 제외다. 양자화나 추출 전용 모델을 비교한 결과는 아니다.

## 판단

형식이 맞는 JSON도 내용이 틀릴 수 있어 출력 스키마 검사만으로는 충분하지 않다. 단순한 특징에서도 색 환각과 부정·미언급 오류가 나타났고 CPU 지연도 발생했다. 자동 매칭에 바로 채택하지 않고, 출력 확인이 필요한 실험 경로로 남긴다. requires_review는 평가 후 추가한 운영 제한이며 모델 추출 정확도를 높인 조치는 아니다.

다음 비교에서는 더 강한 한국어 이해 모델 또는 추출 전용 모델/규칙 조합을 동일 예문과 별도 신규 예문으로 평가해야 한다. 자유 문장의 정보 추가·누락도 사람이 검사하고, 품질·CPU 지연·메모리를 함께 판단한다. 현재 시험 결과만으로 모델 크기 증가가 해결책이라고 확정할 수는 없다.

실행 방법은 [QUERY_PARSER.md](../QUERY_PARSER.md), 입력 예문은 [query_parser_cases.json](../configs/query_parser_cases.json)에 있다. 원본 평가 출력은 outputs/matching/query_parser/results.json에 로컬 저장했다.
