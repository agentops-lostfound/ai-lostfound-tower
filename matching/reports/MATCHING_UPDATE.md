# LF-3 매칭 기능 개선 보고서

작성일: 2026-11-03  
대상 브랜치: `LF-3-yolo-aruco`  
구현·평가 자료 푸시 커밋: `382b144`

## 요약

영어 설명과 Qwen 특징의 전체 문장 임베딩 순위만 반환하던 기능에 **속성 필터 → 자유 특징 임베딩 → 확정·보류 판정**을 추가했다. 기존 MiniLM 모델은 유지했다. 저장 특징 기반 34개 질문 재평가에서 초기 정책 대비 정상 설명 확정이 10건에서 16건으로 늘었고, 모순 설명 17건은 모두 일치 없음으로 유지됐다. 이후 실제 사진 기반 시험에서는 Qwen 특징 오류 때문에 정답 후보가 제외되거나 보류되는 한계도 확인했다.

## 변경 배경

기존 임베딩은 문장 전체 의미를 비교하므로 색이나 부정 표현이 달라도 높은 점수를 줄 수 있었다. 기존 감사 보고서의 진한 파란색·캐릭터 스티커 폰 사례에서 맞는 설명은 약 0.432, 노란색·스티커 없음이라는 모순 설명은 약 0.405로 차이가 작았다. 기존 코드는 순위만 제공했으며, 1위라는 사실이 물품 확정을 의미하지는 않았다.

같은 종류의 물품을 구별하려면 명시한 색·품목 조건을 별도로 비교하고, 정보 부족이나 후보 간 근소한 차이를 보류할 필요가 있었다.

## 추가한 기능

| 추가 항목 | 실제 동작 | 관련 파일 |
|---|---|---|
| 속성 정규화 | 일부 색·품목 동의어를 표준값으로 통일. 파랑과 남색은 별도 유지 | `policy.py` |
| 품목·색 필터 | 명확한 불일치 후보를 임베딩 전에 제외. unknown은 불일치로 제외하지 않음 | `hybrid.py`, `policy.py` |
| 품목 관계 | wallet↔card_wallet을 점수 0.8의 호환 관계로 비교 | `configs/matching.yaml` |
| 유사색 비교 | navy↔dark blue 등 등록한 색 관계를 부분 점수로 비교 | `configs/matching.yaml` |
| 자유 특징 임베딩 | 통과 후보의 모양·재질·글자·특징·스티커 세부 설명을 기존 CPU MiniLM으로 비교 | `hybrid.py`, 기존 `embedding.py` |
| 조건만 있는 질문 | free_text가 없으면 모델 로딩 없이 속성 점수만 사용 | `hybrid.py` |
| 판정 상태 | matched / needs_confirmation / no_match 반환. matched일 때만 selected_id 제공 | `policy.py` |
| 판정 근거 | 후보별 속성 점수, 코사인, 최종 점수, 제외·관찰 부족·보류 이유 기록 | `rank_items.py` |
| 기준 외부화 | 가중치, 품목·색 관계, 최저 점수, 순위 차이, 속성 충족 기준을 YAML에서 조정 | `configs/matching.yaml` |
| 회귀 테스트 | 필터 순서, 모호한 후보, 정보 부족, 설정 변경 등의 동작 확인 | `tests/test_matching_*.py` |

category/colors 필드와 스티커 없음 문장은 자유 특징 임베딩에서 제외한다. 다만 distinctive_features 안에 섞여 있는 색 표현까지 자동 제거하지는 않는다. 원본 Qwen 특징은 수정하지 않는다. 자유 특징이 요청됐는데 후보에 해당 관찰 문장이 없으면 보류한다.

## 실험 1: 기존 질문 재평가

### 조건

- 특징이 있는 실행 10개, 후보 특징 17개, 질문 34개(정상 17개·의도적 모순 17개).
- 실행별 후보 전체와 비교했으며 단일 후보 실행과 중복된 물품·사진이 포함된다.
- 질문은 저장된 Qwen 특징을 참고해 작성한 약한 정답이다.
- 영어 질문에서 속성 조건과 자유 문장을 사람이 분리했다. 자동 번역·조건 추출은 평가하지 않았다.
- 초기 정책과 개선 정책을 비교했고, 모델 학습이나 교체는 하지 않았다.

### 결과

| 지표 | 초기 속성 정책 | 이번 개선 정책 |
|---|---:|---:|
| 정상 설명의 목표 후보 확정 | 10/17 | 16/17 |
| 정상 설명 보류 | 7/17 | 1/17 |
| 정상 설명 오선택 | 0/17 | 0/17 |
| 모순 설명 일치 없음 | 17/17 | 17/17 |

불필요한 보류가 6건 줄었다. 초기 정책에서 card_wallet과 wallet을 다른 품목으로 처리하던 3건과, 유사색이면 무조건 보류하던 3건이 확정으로 전환됐다. 품목 관계·판정 조건·임베딩 입력을 함께 변경했으므로 각 변경의 독립적인 효과를 입증한 결과는 아니다.

남은 1건은 검은 폰의 Qwen category가 other였던 사례다. 사용자는 실제 폰이라고 확인했으나 시스템 입력에서는 품목이 불명확하므로 보류를 유지했다.

## 실험 2: vpu.jpg 실제 사진 시험 — 푸시 이후 추가 확인

### 시퀀스 실행

- YOLO 검출·크롭 → Qwen 특징 추출 → 통합 JSON 저장 완료.

### 사람 설명 매칭

사진을 보고 한국어 설명 7개를 작성한 뒤 영어 조건과 자유 문장으로 직접 옮겼다. 모든 질문은 동일한 Qwen 후보 5개와 비교했고 Qwen 출력과 판정 설정은 수정하지 않았다.

## 확인한 효과와 남은 한계

**확인한 효과:** 조건을 명시적으로 비교하고 근거가 부족하면 확정을 멈출 수 있다. 품목 관계와 유사색 기준을 적용해 초기 정책의 불필요한 보류를 줄였다.

**남은 한계:** Qwen이 색·품목·스티커를 잘못 기록하면 코드 필터가 정답을 제외할 수 있다. 임베딩 모델을 유지한 이번 변경으로 시각 특징 추출 오류까지 해결한 것은 아니다. 한국어 번역, 자동 조건 추출, 실제 확인 질문 UI, 로봇 동작 연결은 아직 구현하지 않았다. 점수는 정답 확률이 아니고 임계값은 실험값이다.

MVP에서는 외형 차이가 분명하고 현재 촬영 조건에서 Qwen이 일관되게 읽는 물품을 선정할 계획이다. 이 방법은 시연 범위를 제한하는 운영 방안이며 일반 물품 인식 문제의 해결로 보지 않는다. 이후 실제 사람이 작성한 질문과 같은 종류·비슷한 색의 물품으로 추가 검증이 필요하다.
