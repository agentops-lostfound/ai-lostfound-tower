# Field Vision 초기 베타 0.1

작성일: 2026-11-10. RTX3050 6GB / RAM16GB Windows PC용 로컬 개발 콘솔.

## 지금 실행하기

현재 서버 주소: **http://127.0.0.1:8871**

서버를 껐거나 PC를 재시작했다면 `new_robot/Start-Beta.cmd`를 실행하고 위 주소를 연다. 이미 실행 중이면 같은 포트로 서버를 두 번 띄우지 않는다. 서버 창의 Ctrl+C로 종료한다. PowerShell에서는 다음으로 실행할 수도 있다.

```powershell
cd <Field Vision 폴더>
.\.venv\Scripts\python.exe -m uvicorn beta.server:app --host 127.0.0.1 --port 8871
```

현재 PC에는 필요한 패키지와 모델 가중치가 준비되어 있다. 팀 Git/Studio 파일/보정/저장 자세는 수정하지 않았다. 로봇 모터나 시리얼 포트에 명령을 보내는 기능은 없다.

## 화면 사용 순서

1. **관측**: 탑뷰와 ARM 카메라 영상 연결 상태를 확인한다. 자동 감시를 켜면 라이브 영상 위에 bbox와 품목 태그, 바로 아래에 실시간 crop이 표시된다. FPS/프레임 숫자는 주 화면에서 제거했다. 표시 스트림은 최대 약14FPS이며 AI는 매 프레임 실행하지 않는다.
2. **분석 소스**에서 카메라를 고르고 `현재 프레임 분석`을 누른다. `박스만 검출`은 OWLv2만 실행한다. `Qwen 특징 포함`을 끄면 임베딩/등록 후보까지만 처리한다.
3. 모델별 로딩/추론/해제 상태와 우측 로그를 확인한다. 모델은 동시에 상주하지 않고 순서대로 실행한다. Qwen 생성 도중 중단은 토큰 생성 종료 지점에서 적용되며 강제 GPU 선점 중단은 아니다.
4. 위쪽 **라이브 화면**은 OWLv2 검출 사이를 CPU 영상 추적으로 이어 bbox 위치를 갱신한다. 초록 실선은 검출/추적, 주황 점선은 미확정 후보이다. 아래 **분석 당시 프레임**은 촬영 당시 bbox/좌표/특징을 보존한 스냅샷이다. 표시용 그림은 모델 입력으로 사용하지 않는다.
5. `검사 통과` 항목의 **물품 등록**을 눌러 실물 ID/이름/메모를 지정한다. 같은 ID에는 다른 참조 사진을 추가할 수 있다. 기본 데모 ID는 실제 개인 물건에 대응하지 않는다.
6. **물품**에서 등록 목록을 확인하고 JSON을 내보낸다. **검색**에서 특징 문장 또는 물체 사진으로 등록 후보를 찾는다. 한국어는 기본 색상/품목만 보조 변환하며, 검색 품질은 별도 검증이 필요하다.
7. `자동 감시`는 선택 카메라에 저빈도 검출을 반복한다. 자동 특징 분석은 설정에서 별도로 켠다. 같은 track이 두 번 이상 안정적으로 보이면 1회 분석하며, 새로 등장한 track만 요청한다. 사라진 뒤 재등장은 새 관측이 될 수 있다. 관측 자동 저장과 실물 ID 등록은 별개다.
8. `중단`은 감시와 대기 작업을 취소하고 현재 연산의 종료 지점에서 모델을 해제한다. 설정 변경 전에는 감시/진행/대기 작업을 모두 중단한다.

카메라에 물건이 없거나 화각이 맞지 않으면 검출0이 정상일 수 있다. 미검출을 장면이 비었다는 확정으로 사용하지 않는다. `검증 사진으로 시험`과 사진 업로드로 장비 배치와 독립적으로 기능을 시험할 수 있다.

## 현재 PC 카메라 연결

- **탑뷰:** `device:1` — Windows의 두 번째 USB 카메라. 실제 영상 수신을 확인했다. 물건이 보이도록 카메라의 물리적 방향/높이를 맞추는 작업은 관리자가 한다.
- **ARM:** `http://127.0.0.1:8765/camera.mjpg` — 기존 Windows MJPEG 브리지를 재사용한다.
- Studio의 기존 USB 등록 경로 `usb-vhci_hcd.0-3`은 현재 WSL에 없어 검은 프레임을 반환했다. Studio 등록값을 바꾸지 않고 베타만 Windows 직접 입력으로 변경했다.
- 직접 USB 장치를 다른 앱/브리지와 동시에 열지 않는다. USB 장치 번호는 다른 PC/재연결 후 달라질 수 있다.
- 브리지가 종료되어 있으면 기존 `soarm-setup/start-camera.ps1`을 사용하거나 베타 설정에서 사용 가능한 소스로 변경한다.

지원 소스:

| 형식 | 예 |
|---|---|
| HTTP MJPEG | `http://127.0.0.1:8765/camera.mjpg` |
| Windows USB | `device:1` |
| Studio 영상 WebSocket 중계 | `studio:프로젝트UUID/카메라UUID` |

Studio 중계는 localhost:7860의 등록 정보를 읽고 영상 전용 WebSocket을 사용한다. 로봇 런타임을 연결하지 않는다. 카메라 프레임이 오래되거나 단색이면 연결/신호 경고를 표시한다.

## 모델과 판정

### 바탕색 반영 매칭 보완

사진 임베딩과 별도로 body_color(주된 바탕색)·pattern_colors(인쇄 무늬 색)를 Qwen으로 추출한다. 기존 colors 나열의 첫 색을 바탕색으로 추정하지 않는다. 명확한 바탕색 불일치에는 사진 cosine에서 개발용0.30을 감점하고, 화면에 사진 점수/최종 점수/색상 비교 이유를 표시한다. 알려지지 않은 색과 조명에 민감한 인접 색 조합은 강한 감점을 보류한다. 이 가중치는 미보정이고 최종 점수 역시 확률이 아니다.

특징 분석 완료 후에 후보 순위를 재계산한다. Qwen을 생략하거나 추출 실패하면 색상 판정은 unknown으로 남는다. 문장 검색의 명시적인 단일 색 조건과 이미지 검색에도 같은 색상 비교를 적용하며, 사진 선택 시 입력된 설명이 있으면 함께 전송한다. 작은 문자/OCR와 무늬의 임의 문자열 일치에는 아직 가중치를 부여하지 않는다.

기존 TEST_U01/TEST_U02 참조는 원본 DB 백업 후 저장 사진에서 바탕색을 다시 추출했다. 이전 관측은 초기화로 비워져 있어 수정 전후 시험은 보존된 crop을 재분석했고, 과거 결과를 새 결과처럼 덮어쓰지 않았다. 보고서는 work/hardware_benchmark_20261110/color_matching_validation.json에 저장한다.

- OWLv2: `google/owlv2-base-patch16-ensemble`, FP32
- SigLIP2: `google/siglip2-base-patch16-224`, FP32
- Qwen: `Qwen/Qwen3-VL-2B-Instruct`, FP16, SDPA, crop 최대 변448px, 최대 출력128토큰
- 대상4종: phone / wallet / hand_cream / usb
- GPU 워커1개, 대기열 최대2개, 카메라 수신은 별도 스레드
- 기본 검출 임계값0.15, 검출 시작 최소 간격3초. 모델 실행이 오래 걸리면 실제 간격은 늘어난다.
- 큰 박스/작은 박스/ROI 밖 후보를 검토 대상으로 분리하고 SigLIP2 비대상/약한 근거 crop을 보류한다. 전문적인 분할/겹침 해소 모델은 포함하지 않았다.
- 임베딩은 픽셀 crop, Qwen에는 각 방향8% 문맥 여유를 준 crop을 사용한다. 옆 물건 혼입은 실제 장면에서 확인해야 한다.
- cosine은 확률이 아니다. 실물 일치 임계값이 미보정이므로 후보가 높아도 확정 일치로 표시하지 않는다.
- 동일 픽셀 참조는 분석의 매칭 근거에서 제외하고, 같은 실물의 여러 참조는 ID별 후보 하나로 묶는다.
- Qwen 출력은 JSON/문자열 스키마를 검사한다. `parsed_unverified`는 형식 통과이지 내용 정답이 아니다. 재질·작은 문자·브랜드는 틀릴 수 있어 관리자 검토가 필요하다.
- 4비트 양자화/세 모델 동시 GPU 상주는 아직 이 베타에 적용하지 않았다.

## 저장 위치와 프로젝트 연결

```text
new_robot/
  beta/                 FastAPI·모델·카메라·DB·관리 화면 소스
  beta_data/
    settings.json       카메라/ROI/트리거 설정
    vision.sqlite3      등록 물품·참조 임베딩·관측 결과
    events.jsonl        작업 로그
    errors.log          실패 상세(발생 시)
    media/              분석 스냅샷·개별 crop
  work/hardware_benchmark_20261110/
    beta_smoke.json     실행 검증 결과
```

모델 가중치는 사용자 Hugging Face 캐시에 있다. 소스 ZIP에는 가중치/가상환경/개인 DB/로그/관측 사진을 넣지 않는다. 검증용 지갑 사진1장은 beta/assets에 포함한다.

기존 프로젝트는 이 서버를 별도 프로세스로 실행한 뒤 API를 사용하거나 `Engine/Store/Models` 모듈을 어댑터로 연결할 수 있다. GPU 모델을 여러 프로세스에서 중복 로드하지 않는다. 기본 서버는 127.0.0.1 전용이고 외부 공유용 인증 서버가 아니다.

| API | 용도 |
|---|---|
| GET `/api/state` | 모델/카메라/작업/메트릭/최근 로그 |
| GET `/api/events` | SSE 실시간 상태 |
| GET `/api/cameras/top/stream`, `/arm/stream` | 영상 스트림 |
| POST `/api/analyze` | `{camera:"top",kind:"analyze",with_features:true}` 또는 data_url 사진 |
| POST `/api/monitor` | `{enabled:true,camera:"top"}` |
| POST `/api/cancel` | 감시/대기 취소·협력적 실행 중단 |
| GET `/api/observations`, `/api/registry` | 관측/등록 목록 |
| POST `/api/register` | observation_id/index/item_id/name/notes |
| POST `/api/search` | text 또는 data_url, 선택 category |
| GET `/api/export` | 등록·관측 JSON, 관측 최대1000개 |

픽셀 bbox/중심은 로봇 좌표나 집기점이 아니다. 카메라-작업대 보정, IK, 접근 생성, 집기 성공 확인, Studio 제어 어댑터는 후속이며 이 서버로 팔을 움직일 수 없다.

## 2026-11-10 카드지갑 현장 수정·라이브 표시

자동 감지 후 지연 분석: 설정에서 **안정된 물체를 자동 분석·관측 저장**을 켜고 **물체 감지 후 자동 분석 대기(초)**를 지정한다(기본5초, 0~120초). 첫 감지 이후 시간이 경과하고 최소2회 검출된 물체가 계속 보이면 분석한다. 대기 중 검출에서 사라지면 예약이 취소된다. 실제 시작은 다음 검출 주기/진행 작업에 따라 늦어질 수 있다. 남은 대기는 우측 trigger 로그로 표시한다. 동일 track은 한 번만 분석한다.

- 실물 카드지갑이 보이는데 검출0인 문제를 재현했다. 같은 프레임에서 wallet 점수0.085가 기본 임계값0.15보다 낮았다.
- card holder/card wallet 표현을 wallet 품목에 추가했다. 같은 프레임의 card holder 점수0.258로 박스가 검출됐고, 임계값은 낮추지 않았다.
- 실제 카메라로 다시 실행해 지갑1개 bbox/crop/SigLIP2 임베딩/Qwen 특징/관측 저장까지 약21.9초에 완료했다. 색/산 무늬 등이 출력됐으나 재질과 작은 문자는 여전히 검토 전이다.
- 라이브 영상에 품목 태그·bbox와 현재 crop을 표시한다. 검출 사이에는 Lucas-Kanade 광학 흐름 및 RANSAC 변환으로 화면상 위치를 추적한다. 이는 품목을 매 프레임 재인식하거나 물리적 개체를 확정하는 기능이 아니다.
- 추적점을 잃으면 박스를 숨기고 재검출을 기다린다. 검출 갱신이 없으면 최대30초 후 숨긴다. 저텍스처/큰 가림/급격한 움직임에서 추적이 끊길 수 있다.
- **미확정 후보 표시**를 켜면 낮은 점수 후보 최대2개를 주황 점선으로 볼 수 있다. 표시 전용이며 특징 추출/물품 등록의 통과 조건으로 사용하지 않는다. 검출기가 후보 자체를 만들지 못하면 임의 박스를 생성하지 않는다.
- 탑뷰를 기본 분석 소스로 변경하고 선택 소스를 브라우저에 기억한다.
- 핵심 검증15개 통과: 기존 DB/ID/매칭·카드지갑 별칭9개 + 포함 관계 중복 박스 제거1개 + 박스 이동/대상 소실/만료/후보 표시/모델 입력 원본 보존5개.
- 같은 카드지갑을 작은 실제 박스와 넓은 배경 박스로 중복 세는 사례도 발견했다. 같은 품목의 포함 관계 박스를 중복으로 제거하고, 강한 검출 영역과 겹치는 낮은 점수 미리보기 후보도 제외했다.
- 실제 라이브 화면에서 wallet 박스·태그·crop을 확인했다. 기존 샘플 지갑 검출은 유지됐고, 비대상 천장 프레임은 강한 검출0을 유지했다. 이 소수 개발 자료로 일반적인 정확도를 주장하지 않는다.

## 다른 환경에서 준비

Python3.11 및 호환 NVIDIA 드라이버가 필요하다. 소스 묶음 루트에서 플랫폼에 맞는 가상환경을 새로 만든다. 현재 PC의 Windows .venv를 다른 PC/OS로 복사하지 않는다.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install -r beta\requirements.txt
.\.venv\Scripts\python.exe -m beta.prepare_models
.\.venv\Scripts\python.exe -m uvicorn beta.server:app --host 127.0.0.1 --port 8871
```

가중치 첫 다운로드는 약6GB 이상이며 별도 디스크 여유가 필요하다. 모델 실행은 기본적으로 로컬 캐시만 사용하므로 준비가 안 됐다면 우측 오류 로그에 캐시 누락이 나온다. 기본 카메라 번호/주소는 현재 PC 기준이므로 설정에서 조정한다.

## 실제 확인한 범위

- 두 카메라 실영상 수신. 기존 Studio USB 경로 문제를 분리하고 Windows 직접 입력으로 해결.
- UI에서 검증 사진 분석: 지갑1개 bbox/crop/768차원 임베딩/Qwen JSON/관측 저장, 약24.5초.
- UI 관리자 등록 `DEMO_WALLET_BLUE`, 문장 `파란 지갑` → `blue wallet` 후보 검색.
- 사진 검색, 동일 참조 재등록 중복 제외, SSE 상태 이벤트, JSON 내보내기.
- 모델 추론 중에도 두 카메라 프레임이 계속 증가.
- 자동 감시 약40초 반복 및 실행 중 중단 후 모델 idle 복귀.
- 단위 검증8개 통과: 다중 참조 묶기/동일 사진 제외/동일 외형 모호성/품목 충돌/검토 crop 등록 차단/벡터 비공개/중복 저장/track당1회 처리.
- 브라우저 콘솔 오류 없음, Python 구문/JS 구문/패키지 의존성 검사 통과.

4종 전체의 별도 실물 세션 정확도, 장시간 운영, 복잡한 겹침, 다른 조명, 로봇 통합은 아직 검증하지 않았다. 기능 동작 확인과 현장 정확도 검증을 구분한다.
