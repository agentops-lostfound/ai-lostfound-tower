# 검출부터 집기까지 프로토타입 연결

- 화면: http://127.0.0.1:8871/static/prototype.html. 수동 GUI/관측 화면에서도 링크한다.
- 준비자세 HOME → 도착 후 새 탑뷰 원본 프레임 → OWLv2/SigLIP2/Qwen 분석 → 해당 프레임 ArUco 좌표 → 검출 crop의 분홍 튜브 긴 축/중심 → 임시 보정 IK → 다축 접근/하강 → 실시간 ARM 흰 집게 내측/물체 외곽 간격 → 3개 새 프레임의 양쪽 접촉 후보에서 닫기 중단 → 10mm 확인 들기 → 사용자 확인 대기.
- 대상 ID를 직접 고르지 않아도 동작하도록 최근 글/사진 검색 job의 1순위와 연결 가능. 체크하지 않으면 지원되는 핸드크림 1개만 있어야 한다.
- 실제 검출 실패/복수 후보/ArUco 누락/정합 설정 변경/좌표 범위 초과/IK 실패 때는 고정 중앙 좌표로 대체하지 않는다.
- 이번 범위는 분홍색 핸드크림 제한 베타. 임의 물건의 3D 깊이/집기점 추정이나 VLA 모델이 아니다. 설정 높이와 5축 손목 방향 보정은 시험 가정이다.
- 기존과 달리 단순 부하 상승은 잡힘으로 판단하지 않는다. 하드웨어 정체만으로 종료되면 확인 들기를 하지 않는다. 카메라 프레임이 반복된 경우 접촉 연속 프레임 수에 포함하지 않는다.
- 흰 집게 경계 검출을 물체 밖의 연속된 흰 영역으로 바꿨다. 기존 실패 사진에서 양쪽 간격 약 67/85px로 나와 열린 상태를 접촉 후보로 보던 문제를 줄였다. 접촉 실측 정확도는 미검증이다.
- STOP: 자동 시퀀스 cancel 설정 + 기존 단일 직렬 소유자의 정지 명령, 이후 단계 자동 재개 없음. HOME 이동에도 적용한다. 토크를 자동 OFF하지 않는다.
- GO HOME: 처음 저장한 기준 자세를 가져온다. 집게 개폐는 현재값 유지하여 자동으로 물건을 놓지 않는다. 긴 이동은 관절 보간 구간으로 나누지만 충돌 회피 기능은 없다.
- 현재 원본 HOME(기준 자세 pose-42ce3c5b54)의 3번=3064는 상한3063 밖, 4번=953은 하한975 밖이다. 임의 클램프하지 않고 원본 보존 및 실행 거부. 사용자 수동 GUI에서 실제 준비자세를 범위 안에 맞추고 ‘현재 정지 자세를 준비자세 HOME으로 저장’으로 갱신해야 한다. 현재 집기 자세를 자동으로 HOME으로 저장하지 않았다.
- API: GET /api/prototype/state, POST /api/prototype/stop, /home/save, /home/go, /start, GET /api/prototype/edges 및 /arm.jpg.
- 다른 수동 조작은 시퀀스 중 거부하고 STOP만 허용한다. 좌표/영역/설정 변경과 자동 감시 시작도 거부한다.
- 검증: 전체 66개 unittest 통과, JS 문법 검사 통과. 서버 재시작 후 GUI HTTP200, 장비 피드백, 경계 API, STOP 응답, 범위 밖 HOME 및 전체 시작의 HTTP400 차단 확인. 실제 전체 집기 시퀀스는 새 HOME 지정 전이라 실행하지 않았다.
- 기록: beta_data/robot_actions/events.jsonl 및 grasp_trials/flow-실행ID/report.json과 단계 사진. 임시 보정 및 원본 HOME은 보존하며 갱신 HOME은 archives에 백업한다.

- 실제 경계 API에서 NumPy 정수 JSON 전송 오류를 수정하고 새 테스트 추가. 재시작 후 HTTP200 확인 완료.
