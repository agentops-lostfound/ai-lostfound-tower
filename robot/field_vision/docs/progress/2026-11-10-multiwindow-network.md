# 여러 크롬 창에서 초기 로딩이 멈추는 문제

- 사용자 관측: 수동 제어/프로토타입 두 창을 동시에 열면 연결 상태 확인 중에서 멈춤. Python 클라이언트의 서버 API는 0~0.016초 내 정상 응답했다.
- 기존 화면별 무한 MJPEG와 SSE는 같은 로컬 HTTP/1 origin의 브라우저 연결을 장시간 점유한다. 여러 창에서 이미지/스크립트/API가 연결 대기하는 증상과 부합한다. 크롬 네트워크 내부 상태는 직접 검증하지 못했으므로 유일한 원인이라고 단정하지 않는다.
- 화면 영상은 짧은 GET /api/cameras/{key}/frame.jpg로 전환했다. 이미지별 중복 진행 요청을 막고 최대 2.5초 제한을 두며 완료 후 연결을 반환한다. 내부 도구용 MJPEG endpoint는 보존한다.
- 메인 관측의 SSE를 제거하고 중복 없는 주기적 상태 조회로 변경했다. 숨겨진 화면의 영상·주요 상태 갱신 중지, 숨김 시 영상 요청 abort. 별도 크롬 창이 모두 보이는 경우에도 요청은 짧게 끝난다.
- 주요 API에 8초 timeout, 버튼 작업에 상태 갱신과 분리된 요청 성공/실패 표시 추가. 초기 로딩 무한 대기 완화.
- 각 HTML은 영상 src로 무한 stream을 먼저 로드하지 않고 network.js가 처리한다. 갱신하지 않은 기존 탭은 옛 stream을 유지하므로 사용자가 기존 창을 각각 새로고침해야 한다.
- 검증: 변경된 모든 JS 문법 검사 통과. Node 동작 시험에서 중복 프레임 요청 방지/숨김 시 정지 및 abort/짧은 blob 이미지 교체 확인. 8개 병렬 worker로 영상·상태 32건 모두 HTTP200. 세부 응답시간은 work/multiwindow_network_audit.json.
- 실제 크롬 두 창에서의 재확인은 사용자 새로고침 후 필요하다. 로봇은 움직이지 않았고 기존 HOME/보정값을 변경하지 않았다.
