# Field Vision 후속 코드 제출 계획

## 지금 올라간 것과 다음 제출

이번 반영은 [최신 현황](../handoff/2026-11-13-current-status.md)과 [팀 발표 준비](../presentation/2026-11-13-field-vision.md)를 전달하는 **문서 변경**이다. 실제 소스는 PR #266의 v0.2.80으로 유지한다. 로컬 인계가 확인한 최신은 v1.0.10 / 20261113.11이다.

다음 코드 제출은 실제 제출 시점의 최신 스냅샷을 사용한다. 위치 `robot/field_vision/`, 내부 `beta/` 유지. 팀원이 이 문서 변경을 병합해도 v1 코드·모델·자료가 자동으로 생기지 않는다.

## 반영할 변경

| 분류 | 준비할 변경 |
|---|---|
| 소스·알고리즘 | v1 정리, 타겟·파지 추정·작은 물품 높이/간격·1:1 매칭·스윕 보정 |
| UI | 정식 밝은/어두운 화면, 일반/관리자 기능·요청 제한, 카메라 새로고침·ARM 오버레이 |
| 삭제 | simple_mode/relaxed 옛 분기, local_grasp_correction, 미사용 grasp_guard/grasp_contact 및 관련 API·함수. 실제 삭제 목록은 최신 소스 diff로 확인 |
| 검증·환경 | 변경된 테스트·의존성·실행 스크립트. 최신 소스로 관련 시험·팀 루트 시험 실행, 실물 검증과 구분 |
| 문서 | 최신 원본 팀/Codex 인계·업로드 계획·v1 정리·일지·발표정보·실행/연동 안내 |

폴더 덧복사만 하면 삭제된 파일이 남는다. 반대로 무조건 미러링하면 기존 게시용 문서·환경변수 처리를 잃을 수 있으므로 원본·게시본·최신main을 대조한다. 원본 이름이 같은 인계 문서도 현재 대체 안내와 비교하고 원본을 실제 읽었는지 구분한다.

## 포함·제외

- 포함: 소스, 화면, 테스트, 의존성, 실행 스크립트, 개발·인계·작동 원리·발표 문서.
- 선택: 실제 전달되고 공개 범위를 확인한 발표 PNG. 팀 규칙의 원본 물품 사진 제외와 대조한다.
- 제외: beta_data(DB·참조사진·보정·실행 로그), models가중치, .venv, .omc, work/dist/Test_IMG, 캐시, 개인 절대 경로, 비밀값.
- 대용량MP4·가중치는 별도 공유 후 문서 링크만 제안한다. 아직 촬영·전달되지 않은 파일에 가짜 링크를 만들지 않는다.

## 반드시 보존할 게시 설정

FIELD_VISION_FOLLOWER_SERIAL / FIELD_VISION_PROJECT_ID / FIELD_VISION_STUDIO_API / FIELD_VISION_STUDIO_CONTAINER 환경변수와 자료 제외 규칙을 유지한다. 로컬 복사로 실제 장치ID·프로젝트ID·개인 경로가 재유입되는지 점검한다. 기존 팀 작업·미커밋 변경은 별도 worktree로 보존한다.

후속 Jira 번호·브랜치 명명은 사용자 요청과 저장소 규칙을 대조해 확정한다. 현재 pil2ya_02는 사용자가 지정한 이름이다. force push·main 직접push·임의 병합은 하지 않는다.

## 필요한 자료

최신 소스·화면·테스트·의존성·실행스크립트·업데이트한 원본 문서 묶음이 실제 diff와 최종 검증에 필요하다. 현황 브리핑에는 로컬 대조 인계를 사용했다. 발표에는 PNG4장, 성공 시퀀스 영상, 동일조건의 단계별 시간·실물 확인 자료가 필요하다.

v0.2.107 누적 시험을 v1.0.10 성공률로 쓰지 않고, 53~104초 전체 동작 시간을 검출→집기 시간으로 바꾸지 않는다. 완료 로그와 physical_success_verified/success/grasp_success 불일치는 먼저 정리한다.
