# Field Vision 발표 준비 — 2026-11-13

로컬 대조 인계를 정리한 팀 공유 자료다. 로컬에 있는 한글 파일명의 발표 문서를 그대로 복사한 것은 아니다. 최신 로컬 버전은 v1.0.10이고 이 저장소 실행 코드는 v0.2.80이다. [현재 상태와 근거](../handoff/2026-11-13-current-status.md)를 함께 읽는다.

## 발표 구성

본 시연은 기존 티칭8칸 방식으로 한다는 팀원 요청을 받았다. Field Vision은 **확장 단계 슬라이드1장 + 사전 녹화1개**로 소개하며 현장 실시간 구동은 하지 않는다. 성공한 범위만 표시한다.

한 줄 설명: **탑뷰 카메라가 찾은 물품 위치로 로봇이 접근 자세를 계산하고, 손목 카메라로 보정해 집은 뒤 저장된 반환대 위치로 옮긴다.**

## 구동 원리 7단계

1. 탑뷰 YOLO가 현재 물체의 위치와 품목을 검출한다.
2. SigLIP2가 사용자의 설명·사진을 등록 물품과 비교해 대상을 찾는다. 같은 품목의 여러 대상은 조건을 만족하면1:1로 대응시킨다.
3. ArUco로 픽셀 좌표를 보관함mm와 로봇좌표로 변환하고 물체 방향을 계산한다.
4. 역기구학으로 현재 위치에서 물건 위까지의 접근 자세·경로를 계산한다.
5. 손목 카메라에서 물체 경계와 고정 손가락 간격을 확인하고 보정한다.
6. 하강·닫기·상승 후 영상과 집게 상태로 잡힘을 추정한다. 추정과 실제 확인을 구분한다.
7. 반환 조건을 충족하면 저장된 반환대에 놓고 HOME으로 복귀한다.

VLA 학습 동작 구조가 아니라 **IK + 영상 보정**이다. '티칭 없이'는 대상별 접근을 계산한다는 뜻이며 HOME·반환대는 저장 자세다.

## 숫자와 실물 확인표

- YOLO train **1,743장**, val **285장**.
- 16에폭에서 중단, best12에폭(checkpoint epoch11) 배포. mAP50-95 **0.928**, mAP50 **0.995**.
- 이는 검증 데이터의 모델 지표다. 실제 물품 선택 정확도·집기 성공률과 별개다.
- 기존 **53~104초는 시작부터 반환/HOME까지**이며 팀원이 요청한 '검출부터 집기' 시간과 다르다. 새 단계별 집계는 아직 제공되지 않았다.

다음 표는 **v0.2.107 기준의 버전 혼합 개발 누적 기록**이다. 최종 v1.0.10 성공률로 나누어 발표하지 않는다.

영상은 대용량 별도 공유 후 링크를 연결한다. 실패·STOP 영상은 선택 자료다. 공개 가능한 정리된 PNG만 팀 규칙과 대조해 추후 추가한다. 원본 물품 사진·DB·보정·실행로그·가중치는 저장소에 넣지 않는다.

## 발표용 배운 점·질의응답

- 배운 점: 검출 박스가 맞아도 집기 중심·관절 부호·실제 추종·손가락 간격이 맞아야 집힌다. 모델 지표와 전체 동작 성공을 따로 검증해야 한다.
- 기존8칸과 차이:8칸은 티칭된 목표를 사용하고 Field Vision은 현재 물품 위치·방향으로 접근을 계산한다. 이번 본 시연의8칸 구성을 대체했다고 말하지 않는다.
- 고정 자세가 전혀 없나: 대상별 접근은 IK로 계산하지만 HOME·놓기 자세는 저장한다.
- 완전 자동 성공인가: 품목·실행별 확인 범위를 말한다. 립밤 자동완료 기록, 휴대폰 구간별 실행, 최근 USB/보조배터리의 완료 로그와 미확인 물리 필드를 구분한다.
- 모델은 무엇을 배우나: YOLO 검출기를 학습했다. VLA로 로봇 동작을 학습한 시스템이라고 설명하지 않는다.
- 관제탑에 바로 연결되나: 팀 A-ID↔등록ID·운영4품목·직원 확인 결과와 작업 응답 계약의 어댑터가 필요하다.
- 최종PR: 최신 소스 전달 후 v0.2.80 대비 실제 diff와 검증을 포함한 후속PR을 준비한다. 이번 게시에는 최신 소스가 없다.
- 브랜치·커밋: 현재 사용자 지정 pil2ya_02. 후속 코드 제출의 Jira 번호·명명은 요청 시 확정하고 번호를 만들지 않는다.
- 역할 표기안: **SO-ARM 구축 · 카메라 기반 집기(Field Vision) · 실물 시연**.
- 기존8칸 통합시험 가능시간: 사용자와 조율할 사항이며 이 문서에서 일정을 확약하지 않는다.
