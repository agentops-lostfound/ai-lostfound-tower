# SO-101 시퀀스 시험 화면

> 관제탑 연결은 [11/11 두 PC 동기화 절차](../docs/handoff/2026-11-11-lipbalm-tower-sync.md)를 따른다. 원격 클라이언트와 실행부는 이동 요청 전에 칸별 11단계 경로를 비교하며, 서로 다르면 집기를 시작하지 않는다.

> 11/11 재생 높이 보정: `pose_7_target`과 `pose_8_close`는 저장한 관절값을 유지하고, `config/pose_command_corrections.json`의 실측 기반 고정 오프셋을 실행 명령의 팔 5축에만 적용한다(`새 명령 = 티칭값 + 배율 × (이전 명령 − 도착 실측)`, 7번 배율 1, 8번 배율 1.155). 그리퍼와 다른 자세는 변경하지 않는다. 도착 기준은 원본 티칭값 기준 7번 target·8번 close 모두 ±5(기존 마진 복원)이며 실시간 적분 보정은 하지 않는다. 해당 자세를 다시 티칭하면 기존 오프셋은 적용 대상에서 제외되고 Studio 자세 파일을 함께 갱신해야 한다. 보정 적용 후 실제 도착 높이는 현장에서 별도로 확인해야 한다.

> 11/11 립밤 재티칭: 7·8번도 공용 11단계(`pose_N` 복귀 → `outlet_return_1` → `close` → `open`)를 사용한다. 복귀·운반 6~8단계는 `include_gripper=False`로 해당 집기의 닫힘 명령을 유지한다. 배출 9단계부터 저장 집게값을 적용한다. 7·8번 전용 return/outlet/close 자세는 백업 후 제거했으며 기본 자세 36개 + 파생 보정 7개를 설치한다. 1·2·3·7번 어깨 보정값은 유지한다. 아래 전용 자세·49개 관련 설명은 이전 이력이다. 로봇 PC의 시퀀스 코드와 관제탑의 진행 사건 검사 코드가 같은 버전이어야 한다. 립밤 접수·검색 품목 설정은 별도다.

> 이전 공유본(11/10, 이번 7·8번 변경 미포함): 당시 코드·원본 자세 40개·설치 자세 49개/프로필 9개를 담은 압축본이다. 1·2·3·7번 운반 보정을 포함한다. 이전 확장 설치는 [공유 설치 안내](../docs/handoff/studio-shared-install.md)의 `update_taught`로 갱신한다. 아래 압축본 미포함·설치 대기 기록은 당시 이력이다. 최신 원격 변경을 합친 최종 검증은 전체 unittest 1,391개·26 skip·실패 0, 공유 backend 런타임 모의 시험 28개 통과다. 실물 경로 검증은 별도다.

시작 칸 1~8 중 하나를 선택하면 홈에서 시작하는 **11단계 티칭 집기·운반 시퀀스**를 준비한다. VLA 없이 저장된 6축 자세를 차례로 실행한다.

```text
home → pose_N → pose_N_open → pose_N_target → pose_N_close → pose_N
→ outlet_return_1 → close → open → outlet_return_1 → home
```

7·8번도 위 공용 경로를 사용하며, 6~8단계에서 해당 `pose_N_close`의 마지막 그리퍼 명령을 유지한다. 물건에 막혀 벌어진 실측값을 새로운 닫힘 명령으로 사용하지 않는다.
시퀀스 원본은 [pick_sequences.json](config/pick_sequences.json)의 각 `full_sequence`이며 모터값은 `outputs/robot_panel_live/poses.json`이다.
공용 `open`의 팔 5축은 `close`와 같게 맞췄고 열림 목표 77.00067138671875는 유지한다. 낮았던 이전 배출 자세로 다시 내려가지 않도록, 값이 다르면 실행 전에 거부한다.
이 도구는 사용자 조작 시험용이다. 운영 관제탑의 파지 검증·반환 완료 처리까지 연결한 것은 아니다.

## 켜기

팀 공유 브랜치: `LF-21-geontae-tower-robot-part`. main 병합 전에는 이 브랜치를 받는다. 본인 작업은 먼저 보관하고, Git 명령이 실패하면 다음 명령을 실행하지 않는다.

```powershell
git fetch origin
git switch LF-21-geontae-tower-robot-part
git pull --ff-only
```

처음 받는 PC에서는 Python 3.12를 준비하고, `.venv`가 없을 때 `py -3.12 -m venv .venv`로 만든다.
시험 화면과 모의 실행에는 `numpy`만 추가로 필요하다. 관제탑 전체를 사용할 때는 `agents/requirements.txt`도 설치한다.

```powershell
.\.venv\Scripts\python.exe -m pip install numpy
```

현재 자세 JSON은 36개이며 파생 운반 자세 7개를 더해 Studio에는 43개를 설치한다. 고정 명령 보정은 `robot/config/pose_command_corrections.json`에서 별도로 읽는다. 이 PC의 Studio에는 현재 코드와 자세·보정을 반영했다. 다른 PC의 Studio는 현재 소스로 설치 묶음을 다시 만들어 적용해야 하며, 기존 11/10 압축본에는 이번 변경이 없다. [Studio 설치 안내](../docs/handoff/studio-shared-install.md)를 참고하되 코드 pull만으로 실행 중인 Studio가 갱신되지는 않는다.

저장소 `team-repo`의 PowerShell에서 실행한다. Studio 로봇 연결은 유지한다. 이 도구는 기존 runtime에만 붙고 별도 serial 연결·Studio 재시작·DB 상태 변경을 하지 않는다.

```powershell
# 모의 화면: 실제 팔에 연결하지 않음
.\.venv\Scripts\python.exe -X utf8 -m robot.sequence_panel

# 실물 화면: 자동 이동·자동 연결 없음
.\.venv\Scripts\python.exe -X utf8 -m robot.sequence_panel --live
```

브라우저에서 `http://127.0.0.1:8766`을 연다. 포트가 사용 중이면 `--port 8767`처럼 바꾼다.
다른 설치에서는 `--follower-id`, `--container`, `--distribution`, `--poses`로 해당 환경을 지정한다.
기본 자세 파일은 `outputs/robot_panel_live/poses.json`, 기록 폴더는 `outputs/sequence_panel/`이다.

## 조작

1. 실물 모드에서는 **Studio 연결 확인**을 누른다. 관절값 수신만 시작하며 이동하지 않는다.
2. **시작 칸**과 **이동 시간 3·4·5초**를 고르고 **다시 준비**를 누른다.
3. 표에서 시험할 단계를 클릭한다. 오른쪽에서 실측·현재 명령·선택 단계의 저장 목표·차이를 확인한다. 단위는 normalized이며 도(°)가 아니다.
4. 물품 배치·이동 경로 확인을 체크하고 **선택 단계만 실행**을 누른다. 해당 자세 하나만 실행한다. 도착 후 자동으로 다음 자세를 실행하지 않는다.
5. 경로를 확인한 뒤 **처음부터 전체 실행**을 누르면 홈부터 11단계를 순서대로 실행한다. 각 이동의 도착 응답을 확인한 뒤 다음 단계로 넘어간다.
6. **정지 / HOLD** 또는 이 화면에서 `Esc`를 누르면 정지를 요청한다. 중간 실패·정지 때 남은 단계를 진행하거나 자동 home 복귀하지 않는다. 이후 재시험은 **다시 준비**부터 한다.

시작 시간 3·4·5초는 보간 설정이며 도착 제한 시간이 아니다. 도착 응답이 없으면 목표를 유지하며 기다린다.
도착 기준은 팔 5개 관절 각각 목표 대비 ±5 normalized 이내가 0.3초 유지되는 것이다. 그리퍼 벌림은 판정에서 제외한다. 추종 오차 한도 10과는 별도 기준이다.
실물 위치가 다르거나 걸림·진동이 있으면 정지 후 위치·자세·장비를 확인한다. 이 화면에는 도착 허용오차를 강제로 늘리거나 도착 판정을 우회하는 버튼이 없다.

시퀀스 도중 다른 Studio 창에서 이동·텔레·녹화를 동시에 실행하지 않는다. 실물 실행은 HOLD·녹화 꺼짐·관절값 수신·필요 자세가 준비된 상태에서만 허용한다.
브라우저 닫힘 때 정지를 요청하며, 화면의 상태 요청이 6초 동안 끊겨도 정지를 요청한다. 이는 이동 도착 제한 시간이 아니다.
정지 응답은 기존 Studio의 HOLD 상태 확인이며 하드웨어 비상정지 보장이 아니다. 정지 미확인이 표시되면 Studio·실물을 확인해야 한다.

## DB 응답 사용

하단 **DB robot-target 응답으로 시퀀스 준비**를 펼쳐 서버에서 읽은 응답 JSON을 붙여 넣고 적용한다.
물건 ID·칸·pose 이름으로 시작 단계를 정하며, 실제 DB를 조회·수정하거나 반환 완료로 기록하지 않는다.
아래 예시는 홈에서 시작해 `R3-2`의 `pose_6` 집기·운반 시퀀스를 준비한다.

```json
{"ok":true,"item_id":"A-W31","slot_id":"R3-2","pose_name":"pose_6","number":6}
```

**현재 기록 저장**은 화면 상태와 최근 기록을 JSON으로 다운로드한다. 서버에도 시작·도착·중단·정지 응답을 JSONL로 남긴다.
터미널에서 `Ctrl+C`로 종료하면 진행 중인 시퀀스의 정지를 요청한 뒤 종료한다.

## 현재 실물 확인 상태

### 휴대폰 1·2번 운반 보정 (11/10)

**최신 후속: 같은 도착 대기를 보고한 7번(R4-1)에도 동일 보정을 확장했다.** 현재 대상은 1·2·3·7번의 6~9단계이며 설정은 어깨 명령 −2 / 원본 어깨 기준 ±8로 같다. 7번은 `pose_7_return_phone` → `outlet_return_1_78_phone` → `close_78_phone` → `open_phone`을 사용한다. 집기 close·복귀·운반·배출구 close의 그리퍼 35.574981689453125는 그대로 유지하고, 여는 단계만 원래 open 값을 쓴다. 배출 후 10단계는 보정 없는 `outlet_return_1_78`이다. 8번은 변경하지 않는다. 원본 40개+파생 9개=설치 자세 49개·프로필 9개가 최신 수치이며 아래 대상·개수 기록보다 우선한다. 새 진단 로그에서 7번 복귀의 어깨 오차 +5.45~5.87만 ±5 밖이었고 다른 팔 관절은 범위 안이었다. 실제 보정 이동은 별도 확인이 필요하다.

7번도 로컬 설치·로봇 세션 재연결·화면 갱신을 완료했다. 원본 40개 해시·런타임 소스를 보존하고 49개 자세·9개 프로필·두 팔 소유자와 전용 그리퍼를 검증했다. 전체 unittest 1,257개·23 skip·실패 0, 8개 모의 시퀀스 통과. 적용·확인 과정의 이동 명령은 0개다. 백업·결과는 `outputs/studio_connection/20261110/carry-slot7-px0rjzcf/`, 화면 확인은 `outputs/robot_db_check/carry-slot7-panel-ready.json`에 있다.

**후속 사용자 요청으로 3번(R2-1)에도 동일 보정을 적용한다.** 3번에 놓고 시험한 보조배터리가 폰과 비슷한 크기·무게라는 사용자 확인에 따른 명시적 확장이다. 보관함 품목 분류나 DB 칸 매핑을 바꾸지 않는다. 현재 적용 대상은 1·2·3번이며 어깨 명령 −2, 원본 기준 어깨 도착 마진 ±8과 적용 구간 6~9는 같다. `pose_3_phone`을 추가해 파생 자세 6개·Studio 설치 자세 총 46개가 필요하다. 아래 1·2번/45개/4~8번 제외 등의 기록 중 대상·개수는 이 후속 내용이 우선한다. 4~8번 경로와 그리퍼 값은 유지한다. 전체 시험 1,256개·23 skip·실패 0, 8개 저장 자세 기반 모의 시퀀스·JS 문법 검사 통과. 실제 3번 보정 이동은 아직 시험하지 않았다.

3번 확장도 로컬 Studio 설치·세션 재연결·화면 갱신까지 완료했다. 원본 40개 해시와 런타임 소스는 유지했고, 46개 설치 자세·6개 도착 프로필·두 팔 소유자를 확인했다. 전후 파일과 검증은 `outputs/studio_connection/20261110/carry-three-slots-w1n5t406/`, 화면 준비 결과는 `outputs/robot_db_check/carry-three-slots-panel-ready.json`에 있다. 이 적용 과정에서는 실제 이동 명령을 보내지 않았다.

`robot/config/phone_carry.json`의 초기 설정은 어깨 상하 명령 **−2 normalized**, 도착 판정은 **보정 전 원본 목표 기준 어깨만 ±8**, 다른 팔 관절은 ±5다. 추종 한도 10과 도착 안정 시간 0.3초는 유지한다. 시간 초과로 다음 단계에 넘어가거나 오차에 따라 보정값을 계속 누적하지 않는다. 보정 방향·크기는 pose_1의 하중 오차 관측을 바탕으로 한 초기 시험값이며 pose_2에서도 실물 확인이 필요하다.

- 1·2번의 11단계 중 집은 뒤 어프로치 복귀(6), 배출구 원복1(7), 배출구 close(8), 같은 자리 open(9)에만 적용한다. 처음 접근·집기 타겟·집기 close는 원본을 사용한다. 배출구 open은 close와 같은 보정된 팔 위치에서 그리퍼만 열고, 다음 원복1(10)·home(11)부터 일반 명령을 사용한다.
- 원본 `outputs/robot_panel_live/poses.json`의 40개 자세는 바꾸지 않는다. `robot/phone_carry.py`가 `pose_1_phone`, `pose_2_phone`, `outlet_return_1_phone`, `close_phone`, `open_phone`을 파생하며 Studio 설치 JSON에는 총 45개와 `motion_profiles`가 필요하다. 일반 시퀀스 표시는 원래 이름을 유지하고 실행 기록에 `command_pose`를 남긴다. 3~8번 경로와 7·8번 전용 그리퍼는 변경하지 않는다.
- 화면의 도착 기준 열은 원본, 명령 열은 Studio 수신값이다. 선택 단계가 보정 구간이면 −2·±8 설정과 실행 별칭을 표시한다. Studio의 자세·프로필 값이 로컬과 다르면 해당 실행을 거부한다.
