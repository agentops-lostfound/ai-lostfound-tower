# SO-101 시퀀스 시험 화면

시작 칸 1~8 중 하나를 선택하면 아래 6단계를 준비한다. VLA 없이 빈 집게로 저장 자세 경로를 시험하는 도구다.

```text
pose_N → outlet_return_1 → close → open → outlet_return_1 → home
```

## 켜기

팀 공유 브랜치: `LF-21-geontae-tower-robot-part`. main 병합 전에는 이 브랜치를 받는다. 본인 작업은 먼저 보관하고, Git 명령이 실패하면 다음 명령을 실행하지 않는다.

```powershell
git fetch origin
git switch LF-21-geontae-tower-robot-part
git pull --ff-only
```

처음 받는 PC에서는 Python 3.12를 준비하고, `.venv`가 없을 때 `py -3.12 -m venv .venv`로 만든다.
시험 화면과 모의 실행에는 `numpy`만 추가로 필요하다. 관제탑 전체를 사용할 때는 `agents/requirements.txt`도 설치한다.

```powershell
.\.venv\Scripts\python.exe -m pip install numpy
```

저장 자세 JSON 12개와 Studio 설치 압축본도 이 브랜치에 포함돼 있다. 실제 팔을 쓸 PC는 [Studio 설치·기존 설치 갱신](../docs/handoff/studio-shared-install.md)을 먼저 따른다. 코드 pull만으로 실행 중인 Studio가 갱신되지는 않는다.

저장소 `team-repo`의 PowerShell에서 실행한다. Studio 로봇 연결은 유지한다. 이 도구는 기존 runtime에만 붙고 별도 serial 연결·Studio 재시작·DB 상태 변경을 하지 않는다.

```powershell
# 모의 화면: 실제 팔에 연결하지 않음
.\.venv\Scripts\python.exe -X utf8 -m robot.sequence_panel

# 실물 화면: 자동 이동·자동 연결 없음
.\.venv\Scripts\python.exe -X utf8 -m robot.sequence_panel --live
```

브라우저에서 `http://127.0.0.1:8766`을 연다. 포트가 사용 중이면 `--port 8767`처럼 바꾼다.
다른 설치에서는 `--follower-id`, `--container`, `--distribution`, `--poses`로 해당 환경을 지정한다.
기본 자세 파일은 `outputs/robot_panel_live/poses.json`, 기록 폴더는 `outputs/sequence_panel/`이다.

## 조작

1. 실물 모드에서는 **Studio 연결 확인**을 누른다. 관절값 수신만 시작하며 이동하지 않는다.
2. **시작 칸**과 **이동 시간 3·4·5초**를 고르고 **다시 준비**를 누른다.
3. 표에서 시험할 단계를 클릭한다. 오른쪽에서 실측·현재 명령·선택 단계의 저장 목표·차이를 확인한다. 단위는 normalized이며 도(°)가 아니다.
4. 빈 집게·이동 경로 확인을 체크하고 **선택 단계만 실행**을 누른다. 해당 자세 하나만 실행한다. 도착 후 자동으로 다음 자세를 실행하지 않는다.
5. 경로를 확인한 뒤 **처음부터 전체 실행**을 누르면 6단계를 순서대로 실행한다. 각 이동의 도착 응답을 확인한 뒤 다음 단계로 넘어간다.
6. **정지 / HOLD** 또는 이 화면에서 `Esc`를 누르면 정지를 요청한다. 중간 실패·정지 때 남은 단계를 진행하거나 자동 home 복귀하지 않는다. 이후 재시험은 **다시 준비**부터 한다.

시작 시간 3·4·5초는 보간 설정이며 도착 제한 시간이 아니다. 도착 응답이 없으면 목표를 유지하며 기다린다.
도착 기준은 팔 5개 관절 각각 목표 대비 ±5 normalized 이내가 0.3초 유지되는 것이다. 그리퍼 벌림은 판정에서 제외한다. 추종 오차 한도 10과는 별도 기준이다.
실물 위치가 다르거나 걸림·진동이 있으면 정지 후 위치·자세·장비를 확인한다. 이 화면에는 도착 허용오차를 강제로 늘리거나 도착 판정을 우회하는 버튼이 없다.

시퀀스 도중 다른 Studio 창에서 이동·텔레·녹화를 동시에 실행하지 않는다. 실물 실행은 HOLD·녹화 꺼짐·관절값 수신·필요 자세가 준비된 상태에서만 허용한다.
브라우저 닫힘 때 정지를 요청하며, 화면의 상태 요청이 6초 동안 끊겨도 정지를 요청한다. 이는 이동 도착 제한 시간이 아니다.
정지 응답은 기존 Studio의 HOLD 상태 확인이며 하드웨어 비상정지 보장이 아니다. 정지 미확인이 표시되면 Studio·실물을 확인해야 한다.

## DB 응답 사용

하단 **DB robot-target 응답으로 시퀀스 준비**를 펼쳐 서버에서 읽은 응답 JSON을 붙여 넣고 적용한다.
물건 ID·칸·pose 이름으로 시작 단계를 정하며, 실제 DB를 조회·수정하거나 반환 완료로 기록하지 않는다.
아래 예시는 `R3-2`에서 `pose_6`으로 시작한다.

```json
{"ok":true,"item_id":"A-W31","slot_id":"R3-2","pose_name":"pose_6","number":6}
```

**현재 기록 저장**은 화면 상태와 최근 기록을 JSON으로 다운로드한다. 서버에도 시작·도착·중단·정지 응답을 JSONL로 남긴다.
터미널에서 `Ctrl+C`로 종료하면 진행 중인 시퀀스의 정지를 요청한 뒤 종료한다.

## 현재 실물 확인 상태

11/9 실제 `pose_1` 시험은 완료되지 않았다. 첫 시도는 모터 소유자 소실로 관측이 오래돼 거부됐고, 세션 재연결 뒤에는 실제 잔여 오차로 도착을 확인하지 못했다.
사용자 승인으로 도착 허용오차를 1.5 → 3 normalized로 적용했지만 이후 어깨 상하 오차 약 3.44가 남았고, 사용자는 위치 차이 또는 걸림·진동을 보고했다.
당시 시험은 현재 위치 HOLD로 종료했고 배출구 단계는 실행하지 않았다. 이 도구를 만든 것이 실물 경로 문제를 해결하거나 6단계 성공을 검증했다는 뜻은 아니다.
새 화면의 기본 5초는 이동 속도 설정이며, 기존 추종 오차 한도 10은 유지된다. 녹화 시작의 별도 어프로치 근접 조건(현재 2)은 바꾸지 않았다.
후속 요청으로 소스와 공유 설치 압축본의 도착 마진을 3 → 5로 넓혔다. 이 PC에서 실행 중인 Studio는 아직 3이며, 갱신·세션 재연결 후 반영해야 한다. 변경 후 실물 동작은 아직 검증하지 않았다.
